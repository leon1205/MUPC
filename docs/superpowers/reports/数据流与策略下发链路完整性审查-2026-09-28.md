## 四、缺口登记

> 分级：**P1** = 可能影响现场可用/安全；**P2** = 设计一致性或纵深防护；**P3** = 可观测性/整洁度；**记录** = 非缺陷，登记以防误读。

### G1｜P1（真机待验）DE/RE 方向控制在部署配置中**未启用**

- **事实**：`de_gpio` / `re_gpio` 字段存在（`config.rs:117/120` 站级、`:277/283` PCS 段），调用链完整（`port_runtime.rs:332-333` → `device.rs:753 set_dir`，`transaction:793/799`、`send_recv:916/918` 触发）；但**部署 YAML 里只有注释**（`mupc_core_config.yaml:38-39`、production `:45-46`）。
- **风险**：若 BECG-3568 板载收发器**非自动换向**，RS485 收发不可用 ⇒ **PCS 主链路与全部站级口失效**。
- **状态**：已登记 **U-111**（技术债）。**须真机 `stty` + 现场确认**。

### G2｜P2 `send_dual_param` 不 clamp `p_ref`（纵深防护不对称）

- **事实**：`PcsHandle::send_dual_param` 直写 `to_pcs_reg(cmd.p_ref)`（`pcs/mod.rs:257`），**无 clamp**；而分相通道 `send_tai_command` 逐相 `clamp_phase ±25`（`:294/299`，`regs.rs:47`）。
- **当前非活缺陷**：两个生产调用者中——① IEC104 `p_set` 路径**上游已 clamp**（`startup.rs:270` `p_raw.clamp(-p_max_kw, p_max_kw)`）；② AI 分支（`ai_integration.rs:685/726`）在 **AI 停用期不可达**。
- **为何仍登记**：`PcsHandle` 是**安全链执行端**，两个入口的边界防护应当对称；将来 AI 恢复或新增调用方即成为活缺陷。
- **附带待确认**：`REG_CONST_Q_SET` **硬编码 0.0**（`pcs/mod.rs:259`）⇒ 经 IEC104 `p_set` 下发会**切模式到恒功率(1000=0)并把 Q 置 0**；若此前处分相模式，分相设定被旁路。**是否符合设备/需求意图，待产品确认**——**其进一步的「通道争用」后果单列为 G9**。

### G3｜P3 策略路径不查 PCS 在线态

- **事实**：`PcsHandle::is_connected` 在策略/联锁路径**无消费点**（全仓仅 `display_host.rs:295/1504` 用）。PCS 离线时策略仍每拍尝试 `send_tai_command`；失败 → `warn!` + 清 `last_sent_tai`（`ai_integration.rs:432-437`）→ 下拍重试。
- **性质**：行为**诚实**（失败有日志、不谎报成功），代价是离线期间每拍一次失败 RS485 事务（超时占用口）。
- **建议**：可选"离线时不尝试、只记一次降级"，但**非必须**——须权衡"离线抖动期漏发 vs 重试浪费"。

### G4｜P2（待确认）`meter_grid` 单块故障 ⇒ 策略 phase 输入**整体断供**

- **事实**：`mapper::poll_to_result` 对 `Role::MeterGrid` 要求 p/q/pf/u/i **五块齐备**，缺任一即 `PollResult::Failed`（`mapper.rs:417-436`）；站级失败后 `run_fallback_strategies` 的数据在 **>5 s 后触发停发**（`ai_integration.rs:381-394`）。
- **风险面**：停发后 **PCS 保持最后一次设定**（分相 P/Q 是保持性设定，非脉冲）。若最后设定为"放电"而电网条件已变，将**持续执行陈旧指令**。
- **与既有条目同族**：D-2（SOC 全缺 → 拒绝下发 + 告警）已裁定"不拿假值驱动"；本条是**同一问题的另一半**——「拒绝下发」之后**保持态是否安全**未定义。**待产品/设计确认**：是否需要"停发时归零"或"保持 + 明确告警"。**本报告不预设结论。**

### G5｜记录｜控制台路由**不读存储**（与设计口径一致）

- **事实**：`console_host.rs` 11 条路由（`/v1/console/{config,config/apply,logs,logs/targets,audit,audit/ops,peripherals/*,interlock/*}`）**无 `mupc_storage` / `EventRepository` 引用**；外设端点走 `PeripheralSource`（`console_host.rs:290`）。
- **一致性**：与 03 设计「台账 CRUD / 遥测历史查询 / 导出**无实现出口**」一致；**屏上告警列表**走**读通道**的 `StorageAlarmSource` → `EventRepository::query_range`（`display_host.rs:486`）。
- **判定**：非缺陷（仍是 03 PRD R-11.6-B 的已知设计余量）。

### G9｜P2（2026-09-29 补）**两条下发通道共用同一个模式字，且无仲裁**

> 本条由 G2 的附带项**展开**而来；首次成文时只写了"切模式 + 清 Q"，**漏了"两条通道来回抢"这一层**，现补全。

  - **台区储能策略** → `ensure_mode(MODE_PHASE_SPLIT = 2)`（`send_tai_command`，`mod.rs:289`）
  - **IEC104 `p_set`** → `ensure_mode(MODE_CONST_POWER = 0)`（`send_dual_param`，`mod.rs:255`）

- **完整时序（两通道交叉时 `1000` 来回翻）**：

  ```
  T0  策略下发      → ensure_mode(2) → 写 1000 = 2（分相模式）
  T1  调度 p_set    → ensure_mode(0) → 写 1000 = 0（切走分相！）
                      + 写 1001 = p_ref
                      + 写 1002 = 0.0（**无功被清零**，:259 硬编码）
  T2  策略下一拍    → ensure_mode(2) → 写 1000 = 2（切回分相）
  T3  调度再下发    → 写 1000 = 0 …
  ```

- **附带事实**：`stop()` 会把缓存置 `0xFF`（`mod.rs:196`）⇒ 停机后下一拍**必然重写**模式字。
- **判定**：**两条通道之间无优先级、无互斥、无仲裁** —— 各写一个共享状态字，最终行为取决于调用时序。**PRD 与设计均未记载**该副作用与争用。
- **裁定（2026-09-29，用户）**：**该副作用必须写进文档**；本条即为该要求的登记。
