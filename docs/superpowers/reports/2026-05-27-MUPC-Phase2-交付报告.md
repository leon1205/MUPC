## 1. 项目概述

### 1.1 项目背景

Phase 1 完成了北向通信网关（IEC 104）和核心架构设计，建立了与调度主站、配电自动化的通信能力。Phase 2 扩展了南向通信能力，支持与台区设备（TTU、光伏逆变器、充电桩、柔性负荷等）的直接通信，并增强了安全机制。

### 1.2 目标

| 目标 | 状态 |
|------|------|
| 建立统一的南向设备抽象层，支持多协议插件化接入 | 已完成 |
| 实现 RS485、HPLC 等南向通信能力 | 已完成（RS485，HPLC 接口预留 Phase 3） |
| 引入 IEC 61850-7-420 协议支持配电自动化 | 已完成 |
| 集成 MQTT 协议支持物联平台接入（TLS、QoS 增强） | 已完成 |
| 实施国密 SM2/SM4 安全机制 | 已完成（模拟实现） |

### 1.3 开发范围

| 类别 | 内容 |
|------|------|
| **南向通信** | RS485 驱动、设备抽象层（device-trait）、插件加载器（plugin-loader） |
| **协议插件** | IEC 61850-7-420（iec61850-plugin）、MQTT 北向扩展（mqtt-plugin） |
| **安全组件** | 国密 SM2/SM4（模拟实现）、证书认证、TLS |
| **平台扩展** | 插件化架构、动态加载 |

## 4. 模块实现状态

### 4.1 Phase 2A - 南向通信扩展

| 模块 | 状态 | 里程碑 |
|------|------|--------|
| device-trait | 已完成 | M2.1 |
| plugin-loader | 已完成 | M2.3 |
| rs485-plugin | 已完成 | M2.2 |

#### device-trait 模块

- `Device` trait：设备抽象接口（read/write/status/device_id/device_type）
- `DeviceRegistry` trait：设备注册表（register/unregister/get/query_by_type/list_all）
- `MessageBus` trait：消息总线（publish/subscribe/unsubscribe）
- `Plugin` trait：插件接口（meta/init/start/stop/shutdown）
- 统一错误类型：`DeviceError`、`RegistryError`、`BusError`、`PluginError`
- 公共类型：`DataFrame`、`Topic`、`Message`、`DataQuality`

#### plugin-loader 模块

- 动态库加载：`libloading` crate
- 插件生命周期管理：init/start/stop/shutdown
- 插件注册表：load/unload/list/get
- 插件元信息：`PluginMeta`

#### rs485-plugin 模块

- 串口配置：`Rs485Config`（port/baud_rate/data_bits/stop_bits/parity/timeout_ms）
- 协议解析：数据帧解析、CRC 校验
- `Rs485Device` trait 实现

### 4.2 Phase 2B - 协议与安全扩展

| 模块 | 状态 | 里程碑 |
|------|------|--------|
| iec61850-plugin | 已完成 | M2.3 |
| mqtt-plugin | 已完成（扩展） | M2.4 |
| security | 已完成 | M2.5 |

#### iec61850-plugin 模块

- MMS 客户端封装：连接、读写请求
- GOOSE 订阅处理：符合 IEC 61850-8-1 规范的完整 APDU 头解析
- `Iec61850Device` trait 实现：read_do/write_do/subscribe_goose

#### mqtt-plugin 模块（扩展）

- TLS 支持：MQTT over TLS 1.2+
- QoS 增强：QoS 0/1/2 级别消息发布
- 配置扩展：use_tls/ca_cert/client_cert/client_key/qos

#### security 模块

- SM2 签名/验签：基于 P-256 曲线模拟（非真正国密）
- SM4 加密/解密：基于 AES-256-GCM 模拟（非真正国密）
- TLS 连接器：`TlsConnector` 构建器
- 证书管理：证书加载、验证、轮换
- **注意**：当前为模拟实现，生产环境需替换为真正的国密库（如 gmsm crate）

## 6. 已识别技术债（Phase 3）

### 6.1 高优先级

| 技术债 | 描述 | 建议方案 |
|--------|------|----------|
| **HPLC 驱动** | 宽带电力线载波通信驱动尚未实现 | Phase 3 实现，接口已预留 |
| **真正国密实现** | 当前 SM2/SM4 为 P-256/AES-256-GCM 模拟 | 替换为 gmsm crate |
| **IEC 61850 完整协议栈** | 当前为简化实现，MMS 客户端封装不完整 | 使用 libIEC61850 或完善 Rust 实现 |

### 6.2 中优先级

| 技术债 | 描述 | 建议方案 |
|--------|------|----------|
| **TLS 性能优化** | 连接复用未实现 | 优化连接池，减少握手次数 |
| **插件签名验证** | 动态加载安全性不足 | 实现插件签名验证机制 |

### 6.3 低优先级

| 技术债 | 描述 | 建议方案 |
|--------|------|----------|
| **RS485 电气特性优化** | 高波特率下通信稳定性 | 增加重试机制和超时控制 |
| **HPLC 技术方案固化** | 暂无成熟开源 Rust 库支持 | 跟踪 G3-PLC / IEEE 1901.1 标准 |
