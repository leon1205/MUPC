### Task 1: apply_soc_source 去 None-gate + 核间活读逻辑纯函数化

**Files:**
- Modify: `mupc/crates/strategy-engine/src/ai_integration.rs`

**背景**：回落分支的 None-gate 是冻结值根因。改造为 BMS 非 fresh 即无条件读核间；为可测，把「给定 bms_fresh + 核间 (soc,ts) 结果，决定最终 soc」的裁决逻辑抽纯函数。

- [ ] **Step 1: 纯裁决函数**

模块级私有纯函数（`apply_soc_source` 外）：
```rust
/// SOC 双源裁决纯逻辑（可单测）：BMS fresh → BMS 值；否则核间 soc fresh → 核间值；
/// 否则保留 data 原值（不置 None——双源皆失时沿用最近值，避免落默认 50 的语义退化）。
fn resolve_soc_source(
    bms: Option<(f64, std::time::Instant)>,
    intercore: Option<(f64, std::time::Instant)>,
    existing: Option<f64>,
    now: std::time::Instant,
    stale_after: std::time::Duration,
) -> Option<f64> {
    if let Some((soc, ts)) = bms {
        if now.duration_since(ts) <= stale_after {
            return Some(soc);
        }
    }
    if let Some((soc, ts)) = intercore {
        if now.duration_since(ts) <= stale_after {
            return Some(soc);
        }
    }
    existing
}
```

- [ ] **Step 2: apply_soc_source 改造（薄壳）**

```rust
    /// SOC 双源裁决（04 §2.11.1 R-C 实时回落，S3b-1d）：evaluate 前把 battery.soc 解析为
    /// 确定源。BMS 站 fresh → 优先覆盖；BMS 超期/无 → **无条件活读核间 latest_soc**（生产
    /// modbus 每次读 REG_SOC，非缓存；sim 缓存最近 DataUpload）——BMS 掉线后下一 dispatch
    /// 周期即用实时核间值，不再沿用 N3 冻结值。核间也超期/不可达 → 保留 data 原值
    /// （不置 None，避免双源皆失落默认 50）。
    ///
    /// 注意：evaluate 只改传入 clone 的 battery 字段，不写回 latest_data、不动 last_data_ts
    /// 闸门（C-2）。完整滞回状态机（回切连续 N 拍 + 3% 带）留后续（04 §2.11.1 I-3）。
    async fn apply_soc_source(&self, data: &mut DataPackage) {
        let bms = *self.bms_soc.read().await;
        // BMS 非 fresh（或无）→ 无条件读核间（活读；不 gate on data.battery.soc.is_none()）
        let intercore = if bms.map_or(true, |(_, ts)| ts.elapsed() > Self::DATA_STALE_AFTER) {
            if let Some(client) = &self.intercore_client {
                client.latest_soc().await
            } else {
                None
            }
        } else {
            None
        };
        let resolved = resolve_soc_source(
            bms,
            intercore,
            data.battery.soc,
            std::time::Instant::now(),
            Self::DATA_STALE_AFTER,
        );
        data.battery.soc = resolved;
    }
```
（关键改动：去掉 `if data.battery.soc.is_none()` 门——现在无论 data 是否已带保留 soc，BMS 非 fresh 就活读核间并裁决覆盖。bms_soc read 锁取值在 await 前释放（`let bms = *...read().await;` Copy f64+Instant?——(f64, Instant) 非 Copy？Instant 是 Copy，f64 Copy → tuple Copy？Rust tuple 若元素 Copy 则 Copy。**核实**：(f64, std::time::Instant) 是 Copy（两元素都 Copy）。`*self.bms_soc.read().await` 解引用 Option<(f64,Instant)>——Option<T: Copy> 是 Copy，`*guard` 得值。若编译不 Copy 则 `.clone()`。）

- [ ] **Step 3: 单测改造**

- 纯函数测（新增）：
```rust
    /// resolve_soc_source：BMS fresh 优先；BMS stale 核间 fresh → 核间；双 stale → 保留 existing。
    #[test]
    fn resolve_soc_source_prefers_bms_then_intercore_then_existing() {
        let now = std::time::Instant::now();
        let fresh_ts = now - std::time::Duration::from_secs(1);
        let stale_ts = now - std::time::Duration::from_secs(10);
        let stale = std::time::Duration::from_secs(5);
        // BMS fresh 优先于核间
        assert_eq!(resolve_soc_source(Some((65.5, fresh_ts)), Some((42.0, fresh_ts)), None, now, stale), Some(65.5));
        // BMS stale → 核间 fresh 接管
        assert_eq!(resolve_soc_source(Some((65.5, stale_ts)), Some((42.0, fresh_ts)), None, now, stale), Some(42.0));
        // 双 stale → 保留 existing
        assert_eq!(resolve_soc_source(Some((65.5, stale_ts)), Some((42.0, stale_ts)), Some(30.0), now, stale), Some(30.0));
        // 无 BMS 无核间 → existing
        assert_eq!(resolve_soc_source(None, None, Some(30.0), now, stale), Some(30.0));
    }
```
- 既有三测适配：`bms_soc_overrides_when_fresh`（fresh 覆盖，保留）；`no_bms_keeps_soc_unchanged`（无 client → apply_soc_source 活读无 client → intercore None → resolve existing/None 保持——**仍通过**，注释更新：无 client 时不活读，None/原值保持）；`bms_stale_falls_back`（无 client：超期 → 活读无 client → resolve(None) → existing None 保持——**仍通过**）。
- **新增集成测**：需 intercore_client 可测活读分支——但 IntercoreClient 具体类型难 mock。**决议**：活读分支逻辑已由纯函数测覆盖（BMS stale + 核间 fresh → 核间值）；`apply_soc_source` 薄壳的「BMS stale 才触发活读」经无 client 测（不活读）+ 代码审读确认。若想端到端测 client 活读，需 mock transport——成本高，记录为可选（不做，纯函数已锁裁决）。
