**Goal:** 修复 rs485-plugin 南向真机串口读恒失败：`open()` 带 `O_NONBLOCK`，使 `recv_frame()` 依赖的 VMIN/VTIME 阻塞弱超时读不生效（read 无数据立即 EAGAIN），任何 Modbus 真从站请求-响应恒超时。修复后南向（southd meter_grid/BMS + pv/load + 协议设备）真机采集可用。

**Architecture:** open 保留 `O_NONBLOCK` 仅防 open 本身因载波等待阻塞（惯例），**configure_port 成功后 `fcntl(F_SETFL)` 清除非阻塞标志**——此后 read 回到阻塞模式，VMIN=0/VTIME=X 弱超时（等至多 X×0.1s 或任一字节）正确生效。已核实全文件无任何 EAGAIN/poll 显式处理（grep 证实），无代码依赖非阻塞语义——纯误用。单点修改，不改发送路径（write 不受影响）与上层调用矩阵。

**Tech Stack:** Rust、libc、termios 阻塞读语义。

**执行基线（2026-09-09 master）**：cargo 一律 `cd /e/MUPC2/mupc`；Windows 低内存 `-j 2`；commit 单行、精确 `git add <path>`、禁 push/amend/`-A/-u`、勿跑 `cargo fmt --all`、勿碰 `intercore/transport/modbus.rs`（用户 dirty，与 rs485-plugin 不同文件）。

### Task 1: open 后清 O_NONBLOCK（根因修复）

**Files:**
- Modify: `mupc/crates/rs485-plugin/src/device.rs`（`open()` :135-180 区间）

- [ ] **Step 1: 插入清非阻塞代码**

读 `device.rs` `open()` 全函数（:135-180，含 `configure_port` 调用与 `port_fd` 赋值）。在 `configure_port(fd)` 成功之后、`*self.port_fd.lock() = Some(fd);` 之前，插入：

```rust
            // 清除非阻塞标志（P0-1 根因，2026-09-09 项目审查）：
            // open 用 O_NONBLOCK 仅防 open 本身因载波等待阻塞；若保持非阻塞，则
            // recv_frame 的 VMIN/VTIME 阻塞弱超时读不生效——read 无数据即返回 EAGAIN，
            // 任何 Modbus 真从站请求-响应恒超时（南向真机采集失败根因）。
            // configure_port 已置 CLOCAL|CREAD，read 回到阻塞语义后由 termios
            // VMIN=0/VTIME 控制读超时。
            let fl = unsafe { libc::fcntl(fd, libc::F_GETFL) };
            if fl >= 0 {
                let _ = unsafe { libc::fcntl(fd, libc::F_SETFL, fl & !libc::O_NONBLOCK) };
            }
```

（`F_GETFL` 失败时静默跳过——fd 已 open 成功且 configure_port 通过，失败概率极低；不引入新错误面。）

- [ ] **Step 2: 自查确认无破坏**

- 确认 `send_frame`（:285 write）路径不依赖读非阻塞（write 方向不受影响）；
