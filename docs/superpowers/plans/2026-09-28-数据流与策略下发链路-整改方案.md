## 二、类别②：**须先裁定**的 3 项（阻塞后续）

这三项**不能靠技术判断定**——它们取决于产品意图。**建议先裁这三条，再排实施**。

### Q-1（对应 G4）｜`meter_grid` 数据超期"停发"后，PCS 的**保持态**是否安全？

**事实**：`run_fallback_strategies` 在数据 > 5 s 未刷新时 **warn 并停发**（`ai_integration.rs:381-394`）。而分相 P/Q 是**保持性设定**（非脉冲）⇒ 停发后 PCS **继续执行最后一次指令**。

**待裁**：
- **(a) 现状即意图** —— 保持最后设定，靠 PCS 自身保护；则本条降为"记录"，不改代码
- **(b) 应"归零"** —— 停发时下发 `zero_command`（分相 P/Q = 0）；则须改 `run_fallback_strategies`，并复核"归零是否会被读成一次新的控制动作"
- **(c) 应"保持 + 明确告警"** —— 保持现状但补一条**可上屏/上云**的降级告警（当前只有 `warn!` 日志）

> **关联**：这与已裁定的 **D-2**（SOC 全缺 ⇒ 拒绝下发 + 告警，不拿假值驱动）是**同一问题的另一半**：D-2 定了"不发假值"，但没定"不发之后怎么办"。建议一并口径化。

### Q-2（对应 G2 附带项）｜IEC 104 `p_set` 下发会**切模式**并**清 Q**，是否符合意图？

**事实**：`send_dual_param` 先 `ensure_mode(MODE_CONST_POWER=0)`（`pcs/mod.rs:254`），再写 `1001=p_ref`、`REG_CONST_Q_SET = 0.0`（硬编码，`:259`）。若 PCS 此前处分相模式（1000=2）且有 Q 设定，**该指令会切走分相模式并把 Q 置 0**。

**待裁**：
- **(a) 符合意图** —— 调度 `p_set` 就是"接管为恒功率"，则应**在文档写明该副作用**（当前 PRD/设计未提）
- **(b) 不符合** —— 应改为"保持当前模式、只改有功"，或改为走分相通道；则属**功能变更**，须走需求流程

### Q-3（对应 G3）｜PCS 离线时，策略是否**应当停止尝试**下发？

**事实**：策略路径不查 `PcsHandle::is_connected`（该 API 仅 display 用）。离线期间每拍仍尝试下发，失败 → `warn!` + 清 `last_sent_tai` → 下拍重试。

**待裁**（**倾向不改**，但请确认）：
- **(a) 保持现状（推荐）** —— 行为诚实、失败有日志；重试的代价仅是一次 RS485 超时。**且**"离线抖动期不漏发"比"省一次事务"更重要
- **(b) 离线时跳过** —— 省带宽，但会引入"在线判据"的抖动语义（与 W1/判据统一那批整改同族），复杂度上升

## 三、类别①：可立即修的 2 项（**待 Q-1/Q-2 裁定后一并排**）

### 立项 B-1（G2 主体）｜`PcsHandle::send_dual_param` 补输入边界

- **改什么**：在 `send_dual_param` 写寄存器前对该入口的 `p_ref` 做**设备量程 clamp**（与分相通道 `clamp_phase ±25`（`regs.rs:47`）对称），越限时 `warn!` 并记录原值。
- **为什么**：`PcsHandle` 是**安全链执行端**；两个入口的边界防护应**对称**。当前唯一活调用者（IEC104）上游已 clamp（`startup.rs:270`），但这是"靠调用方自律"，新增调用方即失守。
- **范围**：1 处（`mupc-southd/src/pcs/mod.rs`）+ 1 条判别力测试（越限入参 ⇒ 线上字为 clamp 后的值）。
- **注意**：**不得**与 Q-2 的结论冲突——若 Q-2 裁为 (b)"不再走该入口"，则本项作废。
- **路径**：**B**（代码评审门禁不可省）。

### 立项 B-2（G7）｜4 个未参与编译的 `.rs` 明确标注

- **改什么**：给 `mupc/crates/strategy-engine/src/{south_command_sender,anti_reverse,demand_control,peak_shaving}.rs`（及配套 `*_test.rs`）加文件头注：**"本文件未在 `lib.rs` 声明 ⇒ 不参与编译；对应策略已于 2026-08-31 精简废弃，保留以述原设计"**。
- **为什么**：2026-09-23 的审查**曾据 `south_command_sender.rs` 的内容判定过一条"真实写静默面"**——正是因为看不出它不编译。同样的误读还会再发生。
- **替代方案**：直接 `git mv` 至 `docs/` 或归档目录（更彻底，但改动面大）。**建议取加注**（最小、可逆）。
- **路径**：**B**（纯注释，零行为变化）。

## 四、类别③：真机项 1 条（**无代码动作，只并入现场清单**）

### 现场项 M-11（G1）｜DE/RE 方向控制

- **要现场回答的问题**：BECG-3568 板载隔离 RS485 收发器**是否为自动换向**（auto-direction）？
  - 若是 ⇒ 留空配置即可，**G1 关闭**
  - 若否 ⇒ 必须按板端实际 GPIO 填 `de_gpio` / `re_gpio`（当前部署 YAML **只有注释**），否则 RS485 收发不可用
- **怎么验**：接示波器或看收发使能脚；辅助判据：`stty -F /dev/ttyS0 -a` 确认 termios 生效后做一次 `PcsHandle::tick_once`，看是否收到 FC04 应答。
- **登记**：已在 **U-111**；本方案要求其**并入 `technical-debt.md` §8.7 真机交接清单**并给出编号（M-11）。
