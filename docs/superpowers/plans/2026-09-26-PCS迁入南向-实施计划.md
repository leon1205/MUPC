# PCS 通信与控制迁入南向 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把两级式 PCS（= 实时控制模块）的 Modbus 通信与控制从 `mupc-intercore` 整体迁入 `mupc-southd`，使 `mupc-intercore` 收敛为纯核间 TCP 帧协议。

**Tech Stack:** Rust 2021 / Tokio / `rs485-plugin`（唯一 Modbus 栈）/ `async-trait` / serde / SQLite(storage，经既有 `StationSink`)。

- [ ] **Step 3: 实现 `write_single_register_from` 并抽出共享校验**

把 `device.rs:756-784` 的 `write_single_register` **整体替换**为：

```rust
    /// 写入单个寄存器（Modbus 功能码 0x06），用 `config.device_addr` 作从站。
    pub fn write_single_register(&self, addr: u16, value: u16) -> Result<(), Rs485Error> {
        self.write_single_register_from(self.config.device_addr, addr, value)
    }

    /// 写入单个寄存器（FC06），**显式从站地址**（同口多从站；与读侧 `_from` 家族对称）。
    ///
    /// 与旧实现（只判 `len < 8`）的差别：本函数**校验响应回显**——从站号、功能码、
    /// 地址、值四项必须与请求逐字一致。停机写 `REG_START_STOP=0` 属**安全动作**，
    /// "发出去了但被别的从站/错帧应答"必须能被检出（设计 §13.6 R-2）。
    /// 回显不符按 `Rs485Error::ConfigFailed` 报出，报文中含两侧从站号便于定位。
    pub fn write_single_register_from(
        &self,
        slave: u8,
        addr: u16,
        value: u16,
    ) -> Result<(), Rs485Error> {
        const FUNC: u8 = 0x06;
        let mut cmd = vec![
            slave,
            FUNC,
            (addr >> 8) as u8,
            addr as u8,
            (value >> 8) as u8,
            value as u8,
        ];
        let crc = Frame::calculate_crc(slave, FUNC, &cmd[2..], self.config.crc_mode);
        cmd.push(crc as u8);
        cmd.push((crc >> 8) as u8);

        let response = self.send_recv(&cmd, self.config.timeout_ms)?;

        // 期望从站号取自**请求帧首字节**（与读侧 `expected_slave_of` 同一取向：
        // "请求谁就校验谁"是构造关系，不是调用点约定）。
        let expected_slave = expected_slave_of(&cmd)?;

        // Modbus 异常响应必须**先于长度检查**：标准 FC06 异常帧仅 **5 字节**
        // （slave + func|0x80 + 异常码 + CRC16[2]）。若先判 `len < 8`，真实异常会被
        // 误报成"响应过短"，异常码永远看不到 —— 运维会去查线缆/成帧而不是"从站为何拒绝"。
        // 读侧 `validate_read_response` 走 `Frame::parse`（接受 ≥5 字节）能正确报异常，
        // 本处与读侧对齐。
        //
        // ⚠️ 用元组匹配而非 `matches!(response.get(1), Some(&(FUNC | 0x80)))`：
        // 后者**不要求异常码字节存在** ⇒ 2 字节残帧 `[slave, 0x86]` 会被当成异常帧、
        // 凭空报出 `异常码=0x00`，把"没收到完整帧"误诊成"从站拒绝"（两者排查方向完全不同）。
        // 元组 `(Some(&f), Some(_))` 同时表达"字段在不在"与"值对不对"，且无裸索引、
        // 无手写长度算术（该类缺陷在本 Task 已咬过一次）。
        if matches!(
            (response.get(1), response.get(2)),
            (Some(&f), Some(_)) if f == (FUNC | 0x80)
        ) {
            let code = response.get(2).copied().unwrap_or(0);
            return Err(Rs485Error::ConfigFailed(format!(
                "写 reg {addr:#06x}（请求 slave={expected_slave}）被从站 {} 拒绝，异常码={code:#04x}（{}）",
                response.first().copied().unwrap_or(0),
                modbus_exception_desc(code)
            )));
        }
        if response.len() < 8 {
            return Err(Rs485Error::ConfigFailed(format!(
                "写响应过短：{} 字节（FC06 回显应为 8）",
                response.len()
            )));
        }
        if response[0] != expected_slave {
            return Err(Rs485Error::ConfigFailed(format!(
                "写 reg {addr:#06x}：响应从站号 slave={} 与请求 slave={expected_slave} 不符（他站帧）",
                response[0]
            )));
        }
        if response[1] != FUNC {
            return Err(Rs485Error::ConfigFailed(format!(
                "写 reg {addr:#06x}：响应功能码 {:#04x} 与请求 {FUNC:#04x} 不符",
                response[1]
            )));
        }
        let echo_addr = u16::from_be_bytes([response[2], response[3]]);
        let echo_value = u16::from_be_bytes([response[4], response[5]]);
        if echo_addr != addr || echo_value != value {
            return Err(Rs485Error::ConfigFailed(format!(
                "写 reg {addr:#06x}={value:#06x}：回显为 {echo_addr:#06x}={echo_value:#06x}，与请求不符"
            )));
        }
        Ok(())
    }
```

**Files:**

**背景**：`Rs485Device::open()` 直连串口（libc `RawFd`），**无注入点**；T-L0 的 PCS 进程内 e2e（E1–E6）依赖 `intercore::transport::modbus` 的 `test_seam`（`DuplexStream`）。迁到 rs485-plugin 后若不补缝，该 e2e **无法搬迁**（设计 §13.6 R-3）。

> **⚠️ 勘误（2026-09-26，落地中回写）：缝的门控必须是 Cargo feature，不是 `#[cfg(test)]`。**
>
> 本 Task 初版把缝写成 `#[cfg(test)]`（与既有 `test_response` 同款）。**这是错的**：`cfg(test)` 只在**被测试的那个 crate 自身**编译 its test 目标时开启，**不随下游 crate 的测试构建传播**。而 Task 9 的 PCS 帧级 e2e 落在 **`mupc-southd` 的 `tests/*.rs`**（外部集成测试），那里 `rs485-plugin` 是**普通依赖** ⇒ `set_test_exchange` 等 API **不存在**，e2e 写不出来。
>
> **最终形态**（提交 `4a7bd1e` 初版 → `44ac7af` 修正）：
> - `rs485-plugin/Cargo.toml` 加 `[features] test-seam = []`（**默认关闭** ⇒ 产线构建仍编译期消除，与 `test_response` 同款）
> - 缝自身门控改 `#[cfg(any(test, feature = "test-seam"))]` —— **共 6 处**：类型别名 `TestExchangeFn`、字段 `test_exchange`、`new()` 初始化、两个 setter、`send_recv` 的缝分支。⚠️ **别名也必须门控**，否则 feature-only 构建报 `cannot find type TestExchangeFn`。**改一处须同改其余五处**（Rust 无法把 `#[cfg]` 归并到字段+初始化+方法三类语法位置）
> - **缝的类型是 `Arc<dyn Fn(&[u8]) -> Vec<u8> + Send + Sync>`（不是 `Box`）** —— 收口时发现 `if let Some(f) = self.test_exchange.lock().as_ref()` 的 scrutinee 临时量会把 `MutexGuard` 延长到 then 分支，**闭包执行期间仍持锁**；闭包内回调本设备（如 `clear_test_exchange()` 实现"回一帧就撤缝"）即**静默死锁**（已实测复现：重入挂死、`timeout` 返回 124）。改 `Arc` + `lock().clone()` 使锁在调用前释放 ⇒ 结构化消除，而非钉注释。**故所有 `set_test_exchange` 调用点用 `Arc::new(...)`**
> - `send_recv` 内缝分支与 `test_response` 分支**必须拆成两个独立块**：前者 `any(test, feature)`，后者保持 `#[cfg(test)]`（下游测试场景下 `test_response` 字段不存在，不能合并门控）；顺序 `test_exchange > test_response > 真 IO` 不变
> - `mupc-southd` 的 **`[dev-dependencies]`**（不是 `[dependencies]`）开 `features = ["test-seam"]`
> - 新增 `mupc-southd/tests/seam_visibility.rs` 作**编译期护栏**：任何人把门控改回 `cfg(test)`、或从 dev-deps 撤掉 feature，该文件立即编译失败（已用探针实证：退回后 `E0599: no method named set_test_exchange`）

**缝的层次选择**：既有 `test_response`（`send_recv` 层，返回**整段响应字节**）不足以测"请求帧被真正构造 + 回帧被真正解析"。本 Task 新增 **`send_recv` 层的"请求→响应"交换缝**：拿**请求帧原文**，返回**响应帧原文**。这样 `build_read_frame` / `write_single_register_from` 的成帧与 `parse_regs_response` 的解析**全部在环**，从站侧由 `pcs/sim` 的同步帧处理函数驱动。

**为什么不复用 `DuplexStream`**：`send_frame`/`recv_frame` 是**同步** libc IO（`&self`，阻塞），把 async `DuplexStream` 塞进同步函数不可行。交换缝保持同步、零 IO，且与既有 `test_response` 同款（`Mutex<Option<...>>` + `#[cfg(test)]`）。

```rust
    pub fn send_recv(&self, frame: &[u8], recv_timeout_ms: u64) -> Result<Vec<u8>, Rs485Error> {

                return Ok(injected);
            }
        }
```

```rust
    /// `rs485-plugin` 的交换缝（`Rs485Device::set_test_exchange`）是同步闭包，

/// 解析一帧请求 → 就地求值 → 编码一帧响应（同步；坏帧返回空 Vec，由调用方静默丢弃）。
///
/// ⚠️ **必须 `pub` 而非 `pub(crate)`**（本计划初版写 `pub(crate)`，**错**）：Task 9 的
/// e2e 落在 `mupc-southd/tests/pcs_e2e.rs`（**外部集成测试 crate**），`pub(crate)` 对它
/// 不可见。这与 Task 2 的"缝必须用 feature 而非 `cfg(test)`"是同一条道理。
pub fn handle_frame_sync(svc: &PcsSlaveService, frame: &[u8]) -> Vec<u8> {
    if frame.len() < 4 {
        return Vec::new();
    }
    let slave = frame[0];
    let fc = frame[1];
    let req = parse_request(fc, &frame[2..frame.len() - 2]);
    let rsp = match req {
        PcsRequest::ReadHoldingRegisters(addr, cnt) => {
            let map = svc.state.hold.lock().unwrap_or_else(|e| e.into_inner());
            let out: Vec<u16> = (0..cnt)
                .map(|i| to_pcs_reg(map.get(&addr.wrapping_add(i)).copied().unwrap_or(0.0)))
                .collect();
            Ok(PcsResponse::ReadHoldingRegisters(out))
        }
        PcsRequest::ReadInputRegisters(addr, cnt) => {
            let map = svc.state.hold.lock().unwrap_or_else(|e| e.into_inner());
            let out: Vec<u16> = (0..cnt)
                .map(|i| match addr.wrapping_add(i) {
                    REG_SOC => to_pcs_reg(SIM_SOC),
                    REG_RUN_STATE => to_pcs_reg(PcsSimState::run_state(&map)),
                    r @ REG_ALARM_BASE..=REG_ALARM_LAST => svc.state.alarm_wire(r),
                    _ => to_pcs_reg(0.0),
                })
                .collect();
            Ok(PcsResponse::ReadInputRegisters(out))
        }
        PcsRequest::WriteSingleRegister(addr, value) => {
            svc.state.write_hold(addr, value);
            Ok(PcsResponse::WriteSingleRegister(addr, value))
        }
        PcsRequest::WriteMultipleRegisters(addr, words) => {
            for (i, w) in words.iter().copied().enumerate() {
                svc.state.write_hold(addr.wrapping_add(i as u16), w);
            }
            let n = words.len() as u16;
            Ok(PcsResponse::WriteMultipleRegisters(addr, n))
        }
        PcsRequest::Custom(..) => Err(PcsException::IllegalFunction),
    };
    encode_adu(slave, fc, rsp)
}
```

```rust
fn parse_request(fc: u8, data: &[u8]) -> PcsRequest {
    match fc {
        0x03 if data.len() >= 4 => PcsRequest::ReadHoldingRegisters(
            u16::from_be_bytes([data[0], data[1]]),
            u16::from_be_bytes([data[2], data[3]]),
        ),
        0x04 if data.len() >= 4 => PcsRequest::ReadInputRegisters(
            u16::from_be_bytes([data[0], data[1]]),
            u16::from_be_bytes([data[2], data[3]]),
        ),
        0x06 if data.len() >= 4 => PcsRequest::WriteSingleRegister(
            u16::from_be_bytes([data[0], data[1]]),
            u16::from_be_bytes([data[2], data[3]]),
        ),
        0x10 if data.len() >= 5 => {
            let addr = u16::from_be_bytes([data[0], data[1]]);
            let cnt = u16::from_be_bytes([data[2], data[3]]) as usize;
            let byte_cnt = data[4] as usize;
            let body = &data[5..];
            if byte_cnt != cnt * 2 || body.len() < byte_cnt {
                return PcsRequest::Custom(fc, data.to_vec());
            }
            let words = (0..cnt)
                .map(|i| u16::from_be_bytes([body[i * 2], body[i * 2 + 1]]))
                .collect();
            PcsRequest::WriteMultipleRegisters(addr, words)
        }
        _ => PcsRequest::Custom(fc, data.to_vec()),
    }
}
```

```rust
/// PCS（两级式 PCS = 实时控制模块）配置段（设计 §13.7，ADR-016）。
///
/// **独立顶层段**而非并入 `south_stations`：`StationConf` 是纯采集语义（`regs` 只有读数），
/// 无处安放控制面参数（响应超时 / 采集兼心跳周期）；且 PCS 由 `PcsHandle` **独占该口**
/// （校验规则 P-2），与站级调度器的"一口多站"模型不同。
///
/// 缺省 `enabled: false` ⇒ 既有部署 yaml **零改动即零行为变化**。
#[derive(Debug, Clone, Deserialize, Serialize)]
pub struct SouthPcsConfig {
    /// 是否启用 PCS 通道。`false` ⇒ 不构造 `PcsHandle`、不开该口。
    #[serde(default)]
    pub enabled: bool,
    /// 串口设备（**须独占**，不得与任何 `south_stations` 站同口 —— 校验规则 P-2）。
    #[serde(default = "default_serial_port_pcs")]
    pub port: String,
    /// 协议处理器名（与站级同源，缺省 `modbus`）。
    #[serde(default = "default_protocol")]
    pub protocol: String,
    /// PCS 从站地址（拨码，默认 1；有效 1..=247）。
    #[serde(default = "default_slave_addr_pcs")]
    pub slave: u8,
    /// 波特率（PCS 线格式 V1.3：19200 N-8-1）。
    #[serde(default = "default_pcs_baud_rate")]
    pub baud_rate: u32,
    /// 数据位。
    #[serde(default = "default_data_bits_pcs")]
    pub data_bits: u8,
    /// 停止位。
    #[serde(default = "default_stop_bits_pcs")]
    pub stop_bits: u8,
    /// 校验位（缺省 none）。
    #[serde(default)]
    pub parity: StationParity,
    /// **采集周期（兼心跳职能）**：每拍 FC04 读一次 3 区块，同时产出 SOC / 运行态 / 三相 /
    /// 全部点（设计 §13.4 —— 三条读路径合并为一条）。下界 `PCS_MIN_INTERVAL_MS`。
    #[serde(default = "default_interval_ms")]
    pub interval_ms: u64,
    /// 单次读写响应超时（毫秒）。缺省 200（原 `intercore.modbus_rtu.response_timeout_ms` 默认值）。
    #[serde(default = "default_pcs_response_timeout_ms")]
    pub response_timeout_ms: u64,
    /// 3 区只读点表（`pcs_3zone` 等）—— 与站级 `regs` **同一类型、同一校验函数**（规则 P-4）。
    #[serde(default)]
    pub regs: Vec<RegBlockConf>,
}

    /// 段内校验（跨段规则 P-1/P-2/P-3 在 core-bin —— 需同时看 `south_stations` 与 `intercore`）。
    pub fn validate(&self) -> Result<(), String> {
        if !self.enabled {
            return Ok(());
        }
        if self.port.trim().is_empty() {
            return Err("south_pcs: port 为空".into());
        }
        if !(1..=247).contains(&self.slave) {
            return Err(format!("south_pcs: slave 越界: {}", self.slave));
        }
        if self.interval_ms < PCS_MIN_INTERVAL_MS {
            return Err(format!(
                "south_pcs: interval_ms={} 须 ≥ {}ms（防超短周期打满总线）",
                self.interval_ms, PCS_MIN_INTERVAL_MS
            ));
        }
        if self.response_timeout_ms == 0 {
            return Err("south_pcs: response_timeout_ms 须 > 0".into());
        }
        if self.regs.is_empty() {
            return Err("south_pcs: regs 为空（必填点表 —— 空点表 = 采集恒空转的静默死配）".into());
        }
        // 规则 P-4：块级校验**显式调用**站级同一批函数（**不是只调 expand**）。
        //
        // ⚠️ **勘误（2026-09-26，落地评审查出后回写）**：本计划初版此处只写
        // `crate::points::expand(blk)?`，**严重不足** —— `expand` 只覆盖**点级**
        // （`count/at ≥ 1`、`name` 与 `count>1` 并存）与**块内**规则 7/8/9，
        // **不含**空洞（规则 11）、**不含** `scale == 0`（规则 5）。
        // 而规则 5 恰是最尖的一条：YAML 漏写 `scale` ⇒ serde 缺省 `0.0`
        // ⇒ 整块 `raw × 0` **静默全 0**，无任何配置期提示。
        // 设计 §13.8 的 P-4 行亦同步订正（原写"`points::expand` 同一函数、空洞 ≤ 4、
        // 单块 ≤ 120 寄存器…"，其中"单块 ≤ 120"在全仓**根本不是任何一条独立规则**）。
        //
        // **最终形态**（提交 `90695dc`+`db7a2e7`）：逐块调
        // `expand` → `validate_scale`(5) → `validate_count_and_discrete_bits`(12)
        // → `validate_width_multiple`(19) → `validate_anchoring`(11, 吃 expand 结果)，
        // 循环后 `validate_block_spans`(14) 吃整段切片，
        // 最后 `check_metric_uniqueness`(10) 汇聚查重。
        // 其中 12/19 原**内联**在 `validate_station_regs`，已抽成函数两处共用；
        // 10 的判据与 `role` 无关（纯 metrics 去重）故同样可复用。
        // **明确不复用并如实登记**：规则 15（`validate_maximality` 需 `&[StationConf]`）、
        // 规则 6/13（依赖 `role`，而本段无 `role` 字段）。
        // 另：本段**拒绝** `regs[].interval_ms`（块级周期覆盖在本段无意义 ⇒ fail-closed）。
        for blk in &self.regs {
            let pts = crate::points::expand(blk)?;
            validate_scale("south_pcs: ", blk)?;
            validate_count_and_discrete_bits("south_pcs: ", blk)?;
            validate_width_multiple("south_pcs: ", blk)?;
            validate_anchoring("south_pcs: ", blk, &pts)?;
        }
        validate_block_spans("south_pcs: ", &self.regs)?;
        Ok(())
    }
}

    8
}
fn default_stop_bits_pcs() -> u8 {
    1

}
```

```rust
pub struct PcsInner {
    cfg: SouthPcsConfig,
    bus: Arc<dyn StationBus>,
    /// **采集与控制共用的唯一一把锁**（设计 §13.3/§13.4）。入口持锁使整条控制序列
    /// （切模式 → 启停 → 写功率）在物理线路上原子，同时把采集读挡在序列之外 ——
    /// 这是 §11.8② "写必须与读共用同一总线仲裁"的更强形式（两者同属一个所有者）。
    lock: Mutex<()>,
    /// 链路在线态（由采集循环维护；连续 3 拍失败判离线 —— 对齐既有心跳口径，设计 Δ-16）
    connected: RwLock<bool>,
    /// 已下发的有功模式字（0=恒功率 / 2=分相）。初值 0xFF 哨兵 ⇒ 首条指令必写 `REG_MODE`
    /// （PCS 上电默认模式未知，不能省首次写）。
    mode: AtomicU8,
    /// 是否已下发运行指令（`REG_START_STOP=1`）。初值 false ⇒ 首条指令必写启停。
    started: RwLock<bool>,

    /// **只由 `restore_interlock_latched` 置/清**；`stop()`/`ensure_started` 均不改。
    stopped_latched: RwLock<bool>,
    /// 人工授权重启位（M1，**单次**）：授权后放行 `ensure_started` 的 S-4 守卫一次，

    snapshot: StdRwLock<PcsSnapshot>,

    sink: Arc<dyn StationSink>,

    bad: AtomicU32,

    /// 本拍采集时刻（`latest_soc` 以它作时间戳 —— 设计 Δ-18）

    pub soc: Option<f64>,
    pub run_state: Option<u16>,
    pub i_phase: Option<[f64; 3]>,
    pub p_phase: Option<[f64; 3]>,
    pub p_total: Option<f64>,

/// PCS 门面（PCS 的完整所有者）。各消费方持 `Arc<PcsHandle>`。
pub struct PcsHandle {
    inner: Arc<PcsInner>,
}

impl PcsHandle {
    pub fn new(
        cfg: SouthPcsConfig,
        bus: Arc<dyn StationBus>,
        sink: Arc<dyn StationSink>,
    ) -> Arc<Self> {
        Arc::new(Self {
            inner: Arc::new(PcsInner {
                cfg,
                bus,
                lock: Mutex::new(()),
                connected: RwLock::new(false),
                mode: AtomicU8::new(0xFF),
                started: RwLock::new(false),
                stopped_latched: RwLock::new(false),
                restart_authorized: AtomicBool::new(false),
                snapshot: StdRwLock::new(PcsSnapshot::default()),
                sink,
                bad: AtomicU32::new(0),
            }),
        })
    }

    fn slave(&self) -> u8 {
        self.inner.cfg.slave
    }

    // ── 测试观测点（仅测试构建；生产零痕迹）──────────────────────────
    #[cfg(test)]
    pub(crate) async fn debug_started(&self) -> bool {
        *self.inner.started.read().await
    }
    #[cfg(test)]
    pub(crate) fn debug_mode(&self) -> u8 {
        self.inner.mode.load(Ordering::Relaxed)
    }
    #[cfg(test)]
    pub(crate) fn debug_restart_authorized(&self) -> bool {
        self.inner.restart_authorized.load(Ordering::Relaxed)
    }

    // ── 联锁面（供 `InterlockPort` 适配）────────────────────────────
    /// 停机原语：写 `REG_START_STOP=0`。**不设/不清 latch**（C-1：置位由触发沿经
    /// `restore_interlock_latched(true)` 完成）。成功后复位 `started=false` + `mode=0xFF`
    /// （否则 release 后 `ensure_started`/`ensure_mode` 见缓存命中而跳过重写 → 静默失效）。
    /// 写 500=0 在 latch 期间**仍允许**（供联锁周期重试停机）。
    pub async fn stop(&self) -> Result<(), String> {
        let _g = self.inner.lock.lock().await;
        match self
            .inner
            .bus
            .write_single(self.slave(), regs::REG_START_STOP, regs::to_pcs_reg(0.0))
            .await
        {
            Ok(()) => {
                *self.inner.started.write().await = false;
                self.inner.mode.store(0xFF, Ordering::Relaxed);
                Ok(())
            }
            Err(e) => Err(format!("PCS 停机写 500=0 失败: {e}")),
        }
    }

    /// 置/清联锁 latch（C-1 **唯一**入口：触发沿 `true`；release / DB 读回 `false`）。
    /// 不取总线锁（纯内存状态，不涉及物理线路）。
    ///
    /// ⚠️ **勘误（2026-09-26，落地评审查出后回写）**：本计划初版**漏抄**了原文的
    /// 「`if latched { restart_authorized = false }`」（`intercore/src/transport/modbus.rs:762-773` 的 Minor-2）。
    /// 漏掉即 **fail-open**：「`authorize_restart` → 新一次联锁触发 → release」后，
    /// `ensure_started` 会凭**触发前**的陈旧授权在 `RUN_STATE=0` 下自动重启，
    /// **绕过 M1 人工确认**（人工确认的是**上一次**事件，却授权了**这一次**）。
    /// **注意条件性**：只在 `latched == true`（新触发沿）时清；`restore(false)`（release）
    /// **不得**清，否则会误杀合法授权。
    pub async fn restore_interlock_latched(&self, latched: bool) -> Result<(), String> {
        *self.inner.stopped_latched.write().await = latched;
        // 新触发沿作废任何**未消费**的人工重启授权（M1：人工确认针对的是**最新**一次事件）。
        if latched {
            self.inner.restart_authorized.store(false, Ordering::Relaxed);
        }
        Ok(())
    }

    /// latch 查询。
    pub async fn is_interlock_stopped(&self) -> bool {
        *self.inner.stopped_latched.read().await
    }

    /// M1 保护跳闸/停机**人工授权重启**（单次）：`!latch` 时复位 `started` **并置授权**，
    /// 放行下次 `ensure_started` 在 `RUN_STATE=0` 停机稳态下重写 500=1 一次。
    /// latch 期间 `Err`（须先 release）。
    pub async fn authorize_restart(&self) -> Result<(), String> {
        if *self.inner.stopped_latched.read().await {
            return Err("联锁锁存中：须先 release 才能授权重启".to_string());
        }
        *self.inner.started.write().await = false;
        self.inner.restart_authorized.store(true, Ordering::Relaxed);
        Ok(())
    }

    /// 最新 `RUN_STATE(1013)`（**同步** getter，读采集快照）。
    pub fn last_run_state(&self) -> Option<u16> {
        let s = self.inner.snapshot.read().unwrap_or_else(|e| e.into_inner());
        if s.valid {
            s.run_state
        } else {
            None
        }
    }
}
```

```rust
impl PcsHandle {
    /// 下发 AI 双参数（恒功率）：写 `REG_MODE=0` → `ensure_started` → 写 1001/1002。
    pub async fn send_dual_param(&self, cmd: &PcsDualParam) -> Result<(), PcsError> {
        // ⚠️ 勘误（2026-09-26，落地评审查出）：**latch 检查须在取锁之前**（原文
        // `modbus.rs:669-677` 即此序）—— 本计划初版写成"先取锁再查"，虽因两者都在
        // 任何 IO 前拒发而语义等价，但**取锁顺序**对齐原文可避免"latch 期间还去抢总线锁"
        // 这一无谓争用（latch 期间本就该连锁都不取）。
        self.check_latched().await?;
        let _g = self.inner.lock.lock().await;
        self.ensure_mode(regs::MODE_CONST_POWER).await?;
        self.ensure_started().await?;
        self.write_reg(regs::REG_CONST_P_SET, regs::to_pcs_reg(cmd.p_ref))
            .await?;
        self.write_reg(regs::REG_CONST_Q_SET, regs::to_pcs_reg(0.0))
            .await?;

    }

    /// 下发台区储能分相 P/Q：写 `REG_MODE=2` → `ensure_started` → 写 1006-1011
    /// （逐相 `clamp ±25`，与迁移前 `clamp_phase` 同源）。
    pub async fn send_tai_command(
        &self,
        p: [f64; 3],
        q: [f64; 3],
        _strategy_mode: &str,
    ) -> Result<(), PcsError> {
        let _g = self.inner.lock.lock().await;
        self.check_latched().await?;
        self.ensure_mode(regs::MODE_PHASE_SPLIT).await?;
        self.ensure_started().await?;
        for i in 0..3u16 {
            self.write_reg(
                regs::REG_PHASE_P_A + i,
                regs::to_pcs_reg(regs::clamp_phase(p[i as usize])),
            )
            .await?;
            self.write_reg(
                regs::REG_PHASE_Q_A + i,
                regs::to_pcs_reg(regs::clamp_phase(q[i as usize])),
            )
            .await?;
        }
        Ok(())
    }

    // ── 内部原语（**不取锁**，由入口持锁；与迁移前纪律一致，防嵌套死锁）──
    /// ⚠️ 勘误（2026-09-26）：本计划初版**漏了原文的 `tracing::warn!`**（原文
    /// `modbus.rs:639` 与 `:670` 两处同文："interlock stopped：拒绝下行（含启动/功率写）"）。
    /// 漏掉属**可观测性净减少**（latch 期间拒发在现网无任何日志线索）⇒ 必须补回。
    async fn check_latched(&self) -> Result<(), PcsError> {
        if *self.inner.stopped_latched.read().await {
            tracing::warn!("interlock stopped：拒绝下行（含启动/功率写）");
            return Err(PcsError::Latched("联锁锁存禁止下发".into()));
        }
        Ok(())
    }

    /// FC06 写单寄存器。**不动在线态**（在线/离线统一由采集循环判定 —— 设计 Δ-16）。
    async fn write_reg(&self, addr: u16, value: u16) -> Result<(), PcsError> {
        self.inner
            .bus
            .write_single(self.slave(), addr, value)
            .await?;
        Ok(())
    }

    /// FC04 读输入寄存器。**不含在线态副作用**（同 `write_reg` 的理由）。
    async fn read_input(&self, addr: u16, len: u16) -> Result<Vec<u16>, PcsError> {
        Ok(self.inner.bus.read_input(self.slave(), addr, len).await?)
    }

    /// 确保处于指定有功模式（缓存命中则跳过；否则写 `REG_MODE` 并更新缓存）。
    async fn ensure_mode(&self, mode: u16) -> Result<(), PcsError> {
        if self.inner.mode.load(Ordering::Relaxed) as u16 == mode {
            return Ok(());
        }
        self.write_reg(regs::REG_MODE, regs::to_pcs_reg(mode as f64))
            .await?;
        self.inner.mode.store(mode as u8, Ordering::Relaxed);
        Ok(())
    }

    /// 确保 PCS 已运行（`REG_START_STOP=1`）。
    ///
    /// ① `stopped_latched` ⇒ `Err`（联锁禁启，底层兜底）；
    /// ② `started==true` 缓存命中 ⇒ `Ok`（跳过总线往返）；
    /// ③ 否则 **S-4 前置读**：先 FC04 读 `REG_RUN_STATE(1013)` 校验 PCS 非停机 ——
    ///    堵住「离线窗口内保护跳闸 → 链路恢复自动重启跳闸机」。读到 0（停机）时：
    ///    已 `restart_authorized` ⇒ **消费授权**（清位）并放行重写 500=1（M1 单次旁路）；
    ///    否则 `Err` 交上层（运维走 `authorize_restart`）。非 0 或读数无效 ⇒ 清授权并正常写 500=1。
    /// ④ **I-2 复查**：读后、写 500=1 前再查一次 latch（`restore` 不取总线锁，可随时置位）。
    async fn ensure_started(&self) -> Result<(), PcsError> {
        if *self.inner.stopped_latched.read().await {
            return Err(PcsError::Latched("联锁锁存禁止自动启动".into()));
        }
        if *self.inner.started.read().await {
            return Ok(());
        }
        // S-4：首个写启动前先读一次 RUN_STATE 校验非停机（M1 守卫升级）
        let words = self.read_input(regs::REG_RUN_STATE, 1).await?;
        let run = decode_run_state(words.first().copied().unwrap_or(u16::MAX));
        if run == Some(0) {
            if !self.inner.restart_authorized.load(Ordering::Relaxed) {
                tracing::warn!("M1 前置校验：RUN_STATE=0（停机/保护跳闸），不自动启动，交上层");
                return Err(PcsError::StoppedGuard(
                    "RUN_STATE=0 不允许自动启动（M1 守卫）".into(),
                ));
            }
            // 决策点即清位：即使随后写失败 / I-2 复查放弃，授权已消耗（须重授权），
            // 杜绝过期授权在下次停机后凭陈旧位自动重启（M1 单次语义）。
            self.inner.restart_authorized.store(false, Ordering::Relaxed);
            tracing::info!("M1 授权重启：RUN_STATE=0 且已授权，放行重发 500=1（单次，授权已消费）");
        } else {
            self.inner.restart_authorized.store(false, Ordering::Relaxed);
        }
        // I-2：读后、写 500=1 前再查一次 latch
        if *self.inner.stopped_latched.read().await {
            tracing::warn!("S-4 写前复查：联锁 latch 已在此窗口置位，放弃启动");
            return Err(PcsError::Latched("S-4 写前 latch 置位，放弃启动".into()));
        }
        self.write_reg(regs::REG_START_STOP, regs::to_pcs_reg(1.0))
            .await?;
        *self.inner.started.write().await = true;
        Ok(())
    }
}
```

```rust
/// 连续失败上限（判离线）—— 对齐迁移前心跳的 `BAD_LIMIT = 3`（`modbus.rs:553`）。
const BAD_LIMIT: u32 = 3;
/// 采集循环最小 tick（防 `interval(0)` panic）。
const MIN_PCS_TICK_MS: u64 = 100;

impl PcsHandle {
    /// 链路在线态（由采集循环维护；设计 §13.4 的"累积 3 拍"口径）。
    pub async fn is_connected(&self) -> bool {
        *self.inner.connected.read().await
    }

    /// SOC（%）。**读采集快照**（非现读）—— 时间戳为本拍采集时刻（设计 Δ-18）。
    pub async fn latest_soc(&self) -> Option<(f64, std::time::Instant)> {
        let s = *self.inner.snapshot.read().unwrap_or_else(|e| e.into_inner());
        if !s.valid {
            return None;
        }
        s.soc.zip(s.ts)
    }

    /// 三相展示读数（读采集快照；设计 Δ-17：粒度为**单块**，块读失败即整体 `None`）。
    pub async fn read_three_phase(&self) -> Option<ThreePhaseRead> {
        let s = *self.inner.snapshot.read().unwrap_or_else(|e| e.into_inner());
        if !s.valid {
            return None;
        }
        Some(ThreePhaseRead {
            i_phase: s.i_phase,
            p_phase: s.p_phase,
            p_total: s.p_total,
        })
    }

    /// **一拍采集**（测试可直接驱动，不含 sleep）：FC04 读一次 3 区块 → 解码 →
    /// 更新快照 → 投 sink → 记账。
    ///
    /// 持**与采集/控制共用的同一把锁**：本函数运行期间控制序列无法插进物理线路（设计 §13.3）。
    pub async fn tick_once(&self) {
        let _g = self.inner.lock.lock().await;
        let blk = match self.inner.cfg.regs.first() {
            Some(b) => b.clone(),
            None => return,
        };
        let res = self
            .inner
            .bus
            .read_input(self.slave(), blk.addr, blk.count)
            .await;

        match res {
            Ok(words) => {
                let ts = std::time::Instant::now();
                // ① 快照（SOC / 运行态 / 三相）
                let snap = build_snapshot(&words, blk.addr, ts);
                *self.inner.snapshot.write().unwrap_or_else(|e| e.into_inner()) = snap;
                // ② 记账：清零 + 置在线
                self.inner.bad.store(0, Ordering::Relaxed);
                {
                    let mut c = self.inner.connected.write().await;
                    if !*c {
                        tracing::info!(station = "pcs", "PCS 链路恢复在线");
                    }
                    *c = true;
                }
                // ③ 停机观测（M1 告警**去抖**）：条件与迁移前逐字相同（run_state=0 且已下发运行
                //    且非 latch）；latch 期间不告警（S-1 豁免：自命令软停/联锁停机非异常）。
                //
                // ⚠️ **勘误（2026-09-26，落地评审查出）**：本计划初版写「本拍只判一次 ⇒ 天然去抖
                //    （迁移前靠 `stopped_warned` 位，口径等价）」—— **该结论是错的**。
                //    原文的 `stopped_warned` 是**跨拍持久状态**，去抖完全靠那个 flag，**不在"判几次"**。
                //    而 M1 语义下 `started` 是**刻意不复位**的（`modbus.rs:574-577`："不动 started
                //    缓存、不自动重发 500=1"）⇒ 该条件一旦成立就**长期为真** ⇒ 逐拍 `warn!` 会以
                //    `interval_ms` 周期**无限刷屏**（≈86400 条/日），正是原文注释点名要防的
                //    "避免停机期间每秒刷屏"。**必须补回跨拍 flag**（`PcsInner.stopped_warned`）。
                //
                //    对照：同一函数里 offline 事件**有**跃迁去抖（`was_online` 守卫），M1 warn
                //    若不去抖则两者自相矛盾。
                if snap.run_state == Some(0)
                    && *self.inner.started.read().await
                    && !*self.inner.stopped_latched.read().await
                {
                    // 仅在"非停机 → 停机"跃迁时告警一次（跨拍记忆）
                    if !self.inner.stopped_warned.swap(true, Ordering::Relaxed) {
                        tracing::warn!(
                            "PCS 运行状态=0(停机)但 MUPC 此前已下发启动——疑似保护跳闸/人工停机；\
                             链路在线，MUPC 不自动重启，请上层/运维确认后处理"
                        );
                    }
                } else {
                    self.inner.stopped_warned.store(false, Ordering::Relaxed);
                }
                // ④ 遥测点上送（块级：成功即全量，与站级调度器"标量每轮全量"口径一致）
                let reads: crate::mapper::BlockReads =
                    vec![(blk.clone(), Ok(crate::mapper::BlockData::Regs(words)))];
                let pts: Vec<(String, f64, bool)> = crate::mapper::telemetry_points(Role::Pcs, &reads)
                    .into_iter()
                    .map(|s| (s.metric, s.value, false))
                    .collect();
                if !pts.is_empty() {
                    self.inner
                        .sink
                        .on_station_telemetry("pcs", Role::Pcs, pts)
                        .await;
                }
            }
            Err(e) => {
                // 快照**立即失效**（单拍语义）—— 与迁移前"读失败即 None"逐字等价（设计 §13.4）
                *self.inner.snapshot.write().unwrap_or_else(|x| x.into_inner()) =
                    PcsSnapshot::default();
                let bad = self.inner.bad.fetch_add(1, Ordering::Relaxed) + 1;
                tracing::debug!(error = %e, bad, "PCS 3 区采集失败");
                if bad >= BAD_LIMIT {
                    let was_online = {
                        let mut c = self.inner.connected.write().await;
                        let prev = *c;
                        *c = false;
                        prev
                    };
                    // ★★ 判离线时**必须同时复位控制侧缓存**（= 迁移前 `mark_offline` 的语义，
                    //    设计 Δ-16 的落地评审查出项，见该行末尾的补记）★★
                    // 理由（W1，`intercore/src/transport/modbus.rs:361-370`）：断线期间 PCS **可能
                    // 掉电/复位** ⇒ `started`/`mode` 缓存**不可信**；不复位则恢复后
                    // ① `ensure_mode` 见缓存命中 ⇒ **跳过 `REG_MODE` 重写**；
                    // ② `ensure_started` 见 `started==true` ⇒ **命中缓存直接 Ok**（连 S-4 的
                    //    1013 读都不发生）⇒ 在**未知实际模式**下直接写 1006-1011 功率寄存器。
                    // **这是 fail-open，必须复位**（`last_run_state` 由快照失效承担，已在上方）。
                    *self.inner.started.write().await = false;
                    self.inner.mode.store(0xFF, Ordering::Relaxed);
                    if was_online {
                        self.inner
                            .sink
                            .on_station_offline("pcs", Role::Pcs, &e.to_string())
                            .await;
                    }
                }
            }
        }
    }

    /// 启动采集循环（每 `interval_ms` 一拍；**不做退避** —— 与迁移前心跳的固定周期一致）。
    /// 返回的 `JoinHandle` **调用方必须持有并观测**（同站级调度器 `spawn` 的约定）。
    pub fn spawn_collection_loop(self: &Arc<Self>) -> tokio::task::JoinHandle<()> {
        let me = Arc::clone(self);
        let period = me.inner.cfg.interval_ms.max(MIN_PCS_TICK_MS);
        tokio::spawn(async move {
            let mut ticker = tokio::time::interval(std::time::Duration::from_millis(period));
            loop {
                ticker.tick().await;
                me.tick_once().await;
            }
        })
    }
}

/// 由 3 区块读数构造快照（纯函数，便于单测）。
///
/// `base` = 块起始地址（`pcs_3zone` 为 1000）；寄存器按 `addr - base` 索引。
/// 各段**独立** `Option`：域外读数为 `None`（保留迁移前的域校验 —— SOC ∈ [0,100]、
/// `RUN_STATE` ∈ 0..=3，M9a 口径）。
fn build_snapshot(words: &[u16], base: u16, ts: std::time::Instant) -> PcsSnapshot {
    let at = |addr: u16| -> Option<u16> {
        if addr < base {
            return None;
        }
        words.get((addr - base) as usize).copied()
    };
    let arr3 = |addr: u16| -> Option<[f64; 3]> {
        Some([
            regs::from_pcs_reg(at(addr)?) * regs::SCALE_3PH,
            regs::from_pcs_reg(at(addr + 1)?) * regs::SCALE_3PH,
            regs::from_pcs_reg(at(addr + 2)?) * regs::SCALE_3PH,
        ])
    };
    PcsSnapshot {
        valid: true,
        ts: Some(ts),
        soc: at(regs::REG_SOC).and_then(decode_soc),
        run_state: at(regs::REG_RUN_STATE).and_then(decode_run_state),
        i_phase: arr3(regs::REG_I_A),
        p_phase: arr3(regs::REG_P_A),
        p_total: at(regs::REG_P_TOTAL).map(|w| regs::from_pcs_reg(w) * regs::SCALE_3PH),
    }
}
```
