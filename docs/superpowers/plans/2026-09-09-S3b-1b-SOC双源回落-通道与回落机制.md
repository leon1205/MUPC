# S3b-1b · SOC 双源回落 — battery SOC 源通道 + AiIntegrator 双源裁决实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 打通 southd battery 站（role=battery）SOC → AiIntegrator 的**源通道**，并实现 **BMS 站 SOC 优先、掉线/超期回落核间 `latest_soc`** 的双源裁决（04 策略 §2.11.1）。BECG 站级 BMS soc 现被 scheduler 丢弃只落库（southd→AiIntegrator 无通道）。

**Architecture:** 三处接线——① southd `StationSink` 加 `on_battery_soc`（scheduler 在 battery 站 `poll_to_result` 成功且 pkg.battery.soc 有值时并调，soc 值已由 mapper 解码，scheduler 已确认本轮新鲜）；② core-bin `SouthSink` 实现它，转发 `ai_integrator.set_battery_soc(soc)`；③ AiIntegrator 加 `bms_soc: RwLock<Option<(f64, Instant)>>` 缓存 + `set_battery_soc` 注入 + evaluate 前 SOC 源裁决（BMS fresh → 覆盖；否则回落核间）。**回落天然复用既有 N3 路径**：BMS 不 fresh → 不强写 → 若 latest_data.battery.soc 为 None 则走既有 N3 核间补；裁决只动 evaluate 前，不动 `merge_battery_missing`（保留 U-26 P1-3 语义，避免破既有 soc 保留测试）。

**Tech Stack:** Rust、tokio RwLock、southd scheduler/StationSink、core-bin startup SouthSink、strategy-engine AiIntegrator/tai_storage。

**设计合同：** 04 策略 §2.11.1 `[DESIGN_APPROVED: 2026-09-08]`（SOC 源优先级 + N3 回落 + 逐源 ts）+ 02 §10.5（C-2 闸门：last_data_ts 仅 grid 推进——BMS soc 只影响 battery 字段不影响闸门）。范围：**通道 + 回落机制**（用户已确认，不含完整滞回状态机/多 BMS 站 map/SOC 融合进 TaiStorage 优先级选择）。

**关键设计（实现决议）**：
- `bms_soc: RwLock<Option<(f64, std::time::Instant)>>` 字段（SOC 源 ts 放 AiIntegrator，不改 DataPackage——BatteryData 无 ts 且改全仓 ~33 构造点太贵）。
- `pub async fn set_battery_soc(&self, soc: f64)`：写 `bms_soc = Some((soc, Instant::now()))`（southd 侧本轮采集刚成功即新鲜；超期判定在 evaluate 裁决时用自身 Instant elapsed）。
- 裁决放 `run_fallback_strategies` 读 latest_data 后、`tai.evaluate` 前：私有 `async fn apply_soc_source(&self, data: &mut DataPackage)`：
  - 若 `bms_soc` fresh（`elapsed <= DATA_STALE_AFTER`）→ `data.battery.soc = Some(bms)`（BMS 优先覆盖，含南向/核间旧值）。
  - 否则（BMS 超期/无）→ 不改 data.battery.soc（回落：若其为 None → 后续 evaluate 读 None → tai unwrap_or(50)。但既有 N3 已在 set_latest_data 每次 soc None 时补核间写进 latest_data，故 data.battery.soc 通常已有核间值 → 回落用核间自然成立）。**若需在 BMS 超期且 data 无 soc 时主动读核间**：可在此处加与 N3 相同的核间补逻辑（fresh latest_soc → 写），使回落不依赖 set_latest_data 时序。**决议**：裁决处也补核间（对称 N3），保证 evaluate 前 soc 有确定源。
- last_data_ts 闸门（C-2）不动——BMS soc 只影响 battery 字段，不影响 grid phase 闸门。

```rust
    /// SOC 双源裁决（04 §2.11.1）：evaluate 前把 latest_data.battery.soc 解析为确定源。
    /// BMS 站（southd on_battery_soc 通道写入）fresh → 优先覆盖；否则回落核间 latest_soc
    /// （对称 N3：fresh 才写）。tai_storage.evaluate 以 data.battery.soc 为准（unwrap_or(50)）。
    async fn apply_soc_source(&self, data: &mut DataPackage) {
        let bms_fresh = {
            let b = self.bms_soc.read().await;
            match *b {
                Some((soc, ts)) if ts.elapsed() <= Self::DATA_STALE_AFTER => Some(soc),
                _ => None,
            }
        };
        if let Some(soc) = bms_fresh {
            data.battery.soc = Some(soc);
            return;
        }
        // BMS 超期/无 → 回落核间（fresh 才写；与 set_latest_data 的 N3 补同语义）
        if data.battery.soc.is_none() {
            if let Some(client) = &self.intercore_client {
                if let Some((soc, ts)) = client.latest_soc().await {
                    if ts.elapsed() <= Self::DATA_STALE_AFTER {
                        data.battery.soc = Some(soc);
                    }
                }
            }
        }
    }
```
