## 1. 总体架构设计

### 1.1 架构定位

故障录波模块归属于 `data-processing` crate，作为该 crate 的 `waveform` 子模块存在。其数据来源为 intercore 核间通信模块提供的10ms周期高频采样数据帧，输出到本地文件系统（波形文件）和 SQLite（元数据），并通过 gateway 的 IEC 104 和 MQTT 通道上报北向。

### 1.3 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 波形子模块位置 | data-processing crate 内独立 `waveform` 子模块 | 避免新建 crate 的跨 crate 复杂接口定义，直接复用 data-processing 的 SQLite 连接和数据通道 |
| 环形缓冲区实现 | 双缓冲 Vec 预分配 | 避免 VecDeque 的运行时开销，固定大小预分配可达到 O(1) 写入且无内存分配 |
| 波形存储格式 | 自定义二进制 .wave 格式 | 比 COMTRADE 更紧凑（少 50% 体积），写入速度更快，适合嵌入式场景 |
| COMTRADE 生成方式 | 按需导出（not real-time） | 避免录波时的高 CPU 开销，导出时异步生成 |
| 并发控制 | parking_lot::RwLock 保护缓冲区 | 读多写少的场景下 RwLock 优于 Mutex，且 parking_lot 比 std 更轻量 |

## 3. 波形采样架构

### 3.1 环形缓冲区设计

#### 3.1.1 数据结构

环形缓冲区是波形采样的核心数据结构，采用**固定大小预分配 Vec + 写入游标**实现，避免运行时动态内存分配。

```rust
// waveform/ring_buffer.rs

/// 环形缓冲区：预分配固定大小的连续内存，支持 O(1) 写入和批量读取
pub struct RingBuffer {
    /// 存储矩阵: [channel_count][capacity]，列优先存储（通道连续）
    data: Vec<f64>,
    /// 通道数 (≤ 10)
    channel_count: usize,
    /// 缓冲区容量（每个通道的样本数）
    capacity: usize,
    /// 写入游标（下一个写入位置，0..capacity 循环）
    // 使用普通类型而非 Atomic*：外层 SafeRingBuffer 的 RwLock 已保证线程安全
    write_cursor: usize,
    /// 总写入计数（用于计算触发偏移量，单调递增）
    // 使用普通类型而非 Atomic*：外层 SafeRingBuffer 的 RwLock 已保证线程安全
    total_written: u64,
    /// 时间戳缓冲区（每个采样点的时间戳，与 data 中所有通道的同一列对应）
    timestamps: Vec<i64>,
}
```

**缓冲区容量计算：**

```
// 原本容量 = sample_rate × pre_trigger_duration_ms / 1000
// 修订后：容量需要容纳完整录波（pre + post），因双缓冲架构下
// post-trigger 数据在活动缓冲区中持续收集，缓冲区必须足够大以
// 容纳完整的 post_trigger 时长。max() 保证容量能覆盖 pre 和 post 中较大者。
capacity = sample_rate × max(pre_trigger_duration_ms, post_trigger_duration_ms) / 1000
```

默认：4000 Hz × max(200 ms, 1000 ms) = 4000 采样点/通道
总内存：10 通道 × 4000 点 × 8 字节 (f64) + 4000 × 8 字节 (时间戳) ≈ 352 KB

#### 3.1.2 关键操作

```rust
impl RingBuffer {
    /// 创建指定容量和通道数的环形缓冲区
    pub fn new(channel_count: usize, capacity: usize) -> Self;

    /// 写入一个采样点（所有通道在 t 时刻的值）
    /// samples: 长度 = channel_count 的切片
    /// timestamp: 该采样点的时刻（微秒级 unix 时间戳）
    pub fn push(&self, samples: &[f64], timestamp: i64);

    /// 读取指定偏移量开始的 N 个采样点
    /// offset: 相对于触发点的偏移（负值=触发前，0=触发点）
    /// count: 需要读取的样本数
    /// returns: Vec<Vec<f64>> — [channel][sample] 矩阵
    pub fn read_range(&self, trigger_offset: usize, pre_samples: usize, post_samples: usize) -> Vec<Vec<f64>>;

    /// 获取当前写入位置（触发点定位用）
    pub fn current_position(&self) -> (usize, u64);

    /// 获取每个通道的容量
    pub fn capacity(&self) -> usize;

    /// 重置缓冲区（清空所有数据）
    pub fn reset(&self);
}
```

**`push()` 操作细节：**

```
写入流程（RwLock 写锁已持有，直接访问字段）：
1. cursor = self.write_cursor
2. 计算 base = cursor * channel_count
3. 将 samples[i] 写入 data[base + i]（i = 0..channel_count）
4. timestamps[cursor] = timestamp
5. self.write_cursor = (cursor + 1) % capacity
6. self.total_written += 1
```

**`read_range()` 操作细节：**

```
读取流程（触发点位置为 trigger_pos）：
1. 起点位置 start = (trigger_pos + offset + capacity) % capacity
   （其中 offset = trigger_offset - pre_samples，可能是负值）
2. 需要读取的数量 count = pre_samples + post_samples
3. 从 start 开始连续读取 count 个样本
4. 处理可能的换行（当 start + count > capacity 时需分两段读）
```

#### 3.1.3 线程安全设计

```rust
// 使用 parking_lot::RwLock 包裹 RingBuffer
// 生产者（高频采样写入）持写锁，极短持有时间（仅 memcpy）
// 消费者（触发表决、波形读取）持读锁

use parking_lot::RwLock;

pub struct SafeRingBuffer {
    inner: Arc<RwLock<RingBuffer>>,
}
```

### 3.2 双缓冲区机制

#### 3.2.1 设计原理

两个环形缓冲区交替工作，确保连续故障不丢失数据。

```
                    ┌─────────────────────┐
 稳态采样 ─────────▶│  RingBuffer A (活动)  │──▶ 新数据覆盖旧数据
                    └─────────────────────┘

    故障触发
        │
        ▼
                    ┌─────────────────────┐
                    │  RingBuffer A (冻结)  │──▶ 等待读取 + 写入文件
                    └─────────────────────┘
                    ┌─────────────────────┐
                    │  RingBuffer B (活动)  │──▶ 继续采样
                    └─────────────────────┘

    录制完成
        │
        ▼
                    ┌─────────────────────┐
                    │  RingBuffer A (重置)  │──▶ 恢复就绪状态
                    └─────────────────────┘
```

#### 3.2.2 数据结构

```rust
// waveform/sampling.rs

/// 双缓冲区管理器
///
/// post-trigger 数据收集策略：
/// 缓冲区容量被设计为可容纳 max(pre_samples, post_samples)，因此
/// 触发后，备用缓冲区（B）可以持续收集全部 post_samples 而不会被覆盖。
/// pre-data 从冻结缓冲区（A）读取，post-data 从活动缓冲区（B）读取。
pub struct DualBufferManager {
    /// 两个环形缓冲区
    buffers: [SafeRingBuffer; 2],
    /// 当前活动的缓冲区索引 (0 或 1)
    active_index: AtomicUsize,
    /// 上一次故障使用的缓冲区索引（用于判断双缓冲切换）
    last_used_index: AtomicUsize,
    /// 录波状态
    state: AtomicU8,  // 0=IDLE, 1=CAPTURING (录制故障后数据), 2=SAVING (正在写入文件)
    /// 触发时活动缓冲区的写入位置，用于后续定位 post-trigger 数据起点
    post_trigger_start: AtomicUsize,
}

impl DualBufferManager {
    /// 写入采样点（写入当前活动的缓冲区）
    pub fn push_samples(&self, samples: &[f64], timestamp: i64);

    /// 触发录波：冻结当前缓冲区，切换到备用缓冲区，记录 post-trigger 起点
    /// returns: (冻结缓冲区索引[pre], 触发时刻样本位置, 活动缓冲区索引[post], post-trigger起始位置)
    pub fn trigger(&self) -> Result<(usize, usize, usize, usize), WaveformError>;

    /// 获取录波数据
    /// pre_samples 从 pre_buffer_idx（冻结缓冲区）读取，
    /// post_samples 从 post_buffer_idx（活动缓冲区，从 post_trigger_start 开始）读取。
    pub fn capture_waveform(&self, pre_buffer_idx: usize, post_buffer_idx: usize,
                            trigger_offset: usize, post_trigger_start: usize,
                            pre_samples: usize, post_samples: usize) -> WaveformData;

    /// 释放缓冲区（录波数据已保存完毕）
    pub fn release_buffer(&self, buffer_idx: usize);
}
```

#### 3.2.3 连续故障处理流程

```
场景：500ms 内发生两次故障

时间线：
t=0    t=200ms      t=500ms      t=1200ms      t=1700ms
 │         │            │             │            │
 │ 故障A   │            │   故障B     │            │
 ▼         ▼            ▼             ▼            ▼
┌──────────────────────────────────────────────────────────┐
│ BufferA: 正常采样 ──▶ 冻结(故障前) ──▶ 继续录故障后      │
│                      (from t-200)     (直到 t+1000)      │
│                                                          │
│ BufferB:              新的活动缓冲区   冻结(故障前)        │
│                                      (from t+300~500)    │
│                                      继续录故障后         │
│                                      (直到 t+1500)       │
│                                                          │
│ 第三个故障(双缓冲皆满):                                   │
│ 丢弃 BufferA(已完成保存)，释放给 BufferC 使用              │
└──────────────────────────────────────────────────────────┘
```

### 3.3 多通道同步采样设计

#### 3.3.1 通道定义

```rust
/// 录波通道定义
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum WaveformChannel {
    Ua = 0,  // A相电压 (V)
    Ub = 1,  // B相电压 (V)
    Uc = 2,  // C相电压 (V)
    Ia = 3,  // A相电流 (A)
    Ib = 4,  // B相电流 (B)
    Ic = 5,  // C相电流 (C)
    U0 = 6,  // 零序电压 (V)
    I0 = 7,  // 零序电流 (A)
    P  = 8,  // 有功功率 (kW)
    Q  = 9,  // 无功功率 (kVar)
    // 注：第10通道保留给频率(f)，但触发条件不再依赖它做录制
    // 频率作为采集数据的一部分存入每个采样点的metadata
}

pub const WAVEFORM_CHANNEL_COUNT: usize = 10;

/// 通道组掩码
#[derive(Debug, Clone)]
pub struct ChannelMask(u16);

impl ChannelMask {
    pub const VOLTAGE_3PHASE: u16 = 0b0000_0000_0111;  // Ua, Ub, Uc
    pub const CURRENT_3PHASE: u16 = 0b0000_0011_1000;  // Ia, Ib, Ic
    pub const ZERO_SEQUENCE: u16 = 0b0000_1100_0000;   // U0, I0
    pub const POWER: u16        = 0b0011_0000_0000;     // P, Q
    pub const ALL: u16          = 0b0011_1111_1111;     // 所有10通道

    pub fn new(mask: u16) -> Self;
    pub fn is_channel_enabled(&self, ch: WaveformChannel) -> bool;
    pub fn enabled_count(&self) -> u32;
}
```

#### 3.3.2 同步策略

```rust
/// 通道同步保证策略：
///
/// 1. intercore 数据帧中所有通道数值使用同一个时钟边沿采集
///    （由实时控制模块的 ADC 触发信号保证硬件级同步）
///
/// 2. 软件层面，push_samples() 的 samples 切片所有元素对应同一时间戳
///    timestamp 精度要求 ≤ 100μs
///
/// 3. 周期性同步校验（每秒一次）：
///    - 向所有电压/电流通道注入 50Hz 已知正弦波
///    - 计算各通道间相位差，确认 ≤ 1°
///    - 若超过阈值，记录告警日志并标记数据质量
```

```rust
    fn default() -> Self { /* 所有默认值按照 PRD 3.1.2 和 3.2.2 */ }
}

impl TriggerConfig {
    /// 验证配置合法性
    /// - 故障前记录时长不能 > 故障后记录时长 × 3
    /// - 采样率必须是指定档位

    pub fn validate(&self) -> Result<(), TriggerConfigError>;
```

#### 3.4.2 触发状态机

```rust
// waveform/trigger.rs

/// 触发判定器
///
/// 使用状态机管理每个触发条件的激活/解除状态，实现回差防抖。
pub struct TriggerEngine {
    config: Arc<RwLock<TriggerConfig>>,
    /// 每个触发条件的当前状态
    states: [TriggerState; 6],  // 索引对应 FaultTriggerType 枚举
    /// 防抖计数器（各条件独立）
    debounce_counters: [u32; 6],
    /// 触发后冷却时间（防止短时间内同条件反复触发）
    cooldown_until: AtomicI64,
}

/// 触发条件枚举
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum FaultTriggerType {
    OverVoltage = 0,
    UnderVoltage = 1,
    OverCurrent = 2,
    ShortCircuit = 3,
    FrequencyAbnormal = 4,
    ZeroSeqOverCurrent = 5,
}

/// 单个触发条件的状态
#[derive(Debug, Clone, Copy, PartialEq)]
enum TriggerState {
    /// 正常（未触发）
    Normal,
    /// 已触发（正在录波过程中）
    Triggered,
    /// 回差等待：信号已离开触发区但未回到完整回差区间
    HysteresisWaiting,
}
```

#### 3.4.3 触发判定流程

```
每个采样点到达时执行：

1. 冷却检查
   ├── 当前时间 < cooldown_until → 跳过本采样点，返回 NO_TRIGGER
   └── 当前时间 >= cooldown_until → 继续

2. 对每个启用的触发条件（FaultTriggerType）执行：
   ├── 获取当前采样值
   ├── 根据当前 state 执行判定：
   │   ├── Normal → 检查是否满足触发阈值
   │   │   ├── 满足 → debounce_counter[i]++
   │   │   │   └── debounce_counter[i] >= debounce_samples → 触发! → state=Triggered
   │   │   └── 不满足 → debounce_counter[i] = 0
   │   ├── Triggered → 检查是否退出回差区
   │   │   ├── 完全回到正常范围 → state=Normal, 记录解除时间
   │   │   ├── 在回差区内 → state=HysteresisWaiting
   │   │   └── 仍在触发区 → 保持 Triggered
   │   └── HysteresisWaiting → 检查是否退出回差区
   │       ├── 完全回到正常范围 → state=Normal
   │       └── 在回差区内 → 保持
   │
3. 如果有至少一个条件触发，返回 TRIGGERED(触发条件列表)
   否则返回 NO_TRIGGER
```

### 4.3 二进制波形文件格式 (.wave)

#### 4.3.1 文件头部 (Header) — 64 字节

| 偏移 | 长度 | 字段 | 类型 | 说明 |
|------|------|------|------|------|
| 0 | 4B | magic | u32 | 魔数 `WAVE` (0x57415645) |
| 4 | 2B | version | u16 | 文件格式版本号 (v1 = 0x0001) |
| 6 | 2B | channel_count | u16 | 录波通道数 (≤10) |
| 8 | 4B | channel_mask | u32 | 通道启用位掩码 |
| 12 | 4B | reserved1 | u32 | 保留 |
| 16 | 8B | sample_count | u64 | 每通道样本数 |
| 24 | 8B | sample_rate | u64 | 采样率 (Hz) |
| 32 | 8B | trigger_timestamp | i64 | 触发时刻的 unix 时间戳 (ms) |
| 40 | 8B | trigger_offset | u64 | 触发点在样本序列中的偏移量（第几个样本） |
| 48 | 4B | pre_trigger_nsamples | u32 | 故障前样本数 |
| 52 | 4B | post_trigger_nsamples | u32 | 故障后样本数 |
| 56 | 4B | event_id | u32 | 关联的 fault_records.id |
| 60 | 1B | data_quality | u8 | 0=good, 1=gap_detected, 2=major_gap |
| 61 | 1B | time_quality | u8 | 0=synchronized, 1=unsynchronized |
| 62 | 2B | reserved2 | u16 | 保留 |

#### 4.3.2 数据体 (Body)

```
┌──────────────────────────────┐
│ Header (64 bytes)            │
├──────────────────────────────┤
│ Channel 0 samples (N × f64)  │  ← 第一个通道所有样本
│ Channel 1 samples (N × f64)  │  ← 第二个通道所有样本
│ ...                          │
│ Channel M-1 samples (N × f64)│  ← 第 M 个通道所有样本
├──────────────────────────────┤
│ Timestamps (N × i64)         │  ← 每个采样点的微秒时间戳
├──────────────────────────────┤
│ Footer: checksum (8 bytes)   │
└──────────────────────────────┘
```

**数据布局特点**：

- 通道连续存储：同一个通道的所有样本在内存中连续（有利于统计计算）
- 时间戳单独存储：N 个 i64 时间戳，精度微秒
- 校验和：CRC64 (ECMA-182)

#### 4.4.2 循环覆盖策略流程

```

1. 更新磁盘使用统计

2. 检查 1：单日录波次数
   ├── if today_count >= daily_limit → 停止录波（但保留故障事件元数据记录）
   └── else → 继续

3. 检查 2：磁盘空余空间
   ├── if free_space < 200MB → 紧急停止所有录波，紧急告警
   ├── if free_space < 500MB → 执行步骤 5（紧急清理）
   └── else → 继续

4. 检查 3：总存储占用
   ├── if total_usage < total_capacity → OK，无需清理
   └── if total_usage >= total_capacity → 执行步骤 5

5. 执行清理：
   a. 扫描 waveforms/recordings 目录下所有 .wave 文件
   b. 删除超过 retention_days 的文件（按文件修改时间判断）
   c. 若仍超出上限，按修改时间升序排序，从最旧开始删除
     直到 total_usage < total_capacity × 0.8（80% 水位线）
   d. 删除文件后，同时将该文件对应 SQLite 记录的 has_waveform 置为 0
     但保留事件元数据记录
```

### 4.5 单次录波大小上限控制

当配置导致单次录波超过 10MB 时，自动截断：

```rust
/// 计算实际录波的样本数（受上限约束）
fn calculate_actual_samples(config: &TriggerConfig) -> (u32, u32) {
    let max_bytes_per_record: u64 = 10 * 1024 * 1024; // 10 MB

    let channel_count = config.channel_mask.enabled_count();
    let total_samples = config.sample_rate * (config.pre_trigger_ms + config.post_trigger_ms) / 1000;
    let estimated_size = 64  // header
        + (total_samples as u64) * (channel_count as u64) * 8  // 通道数据
        + (total_samples as u64) * 8  // 时间戳
        + 8; // footer checksum

    if estimated_size <= max_bytes_per_record {
        (config.pre_trigger_ms, config.post_trigger_ms)
    } else {
        // 等比缩小（从触发点前后各保留同等比例）
        let ratio = max_bytes_per_record as f64 / estimated_size as f64;
        let new_pre = (config.pre_trigger_ms as f64 * ratio.sqrt()) as u32;
        let new_post = (config.post_trigger_ms as f64 * ratio.sqrt()) as u32;
        (new_pre.max(40), new_post.max(40))  // 保证至少 40ms
    }
}
```

```rust
fn generate_cfg(waveform: &WaveformData, meta: &WaveformMetadata) -> String {
    let mut cfg = String::new();

    // 第1行: 变电站名称, 设备标识, 版本年份 (IEEE C37.111-1999 Section 4.1)
    // 标准格式: StationName, StationID, RevisionYear
    cfg.push_str(&format!("StationName, MUPC_{}, 1999\n", device_id));

    // 第2行: COMTRADE 版本年份
    cfg.push_str("1999\n");

    // 第3行: 通道数
    let analog_count = meta.channel_count;
    cfg.push_str(&format!("{}, {}A\n", analog_count, 0)); // 0 数字通道

    // 第4~N行: 通道定义
    let channels = get_channel_definitions(meta.channel_mask);
    for (i, ch) in channels.iter().enumerate() {
        cfg.push_str(&format!(
            "{}, {}, , , {}, {:.6}, {:.6}, 0, -32768, 32767, {:.6}, {:.6}, S\n",
            i + 1,
            ch.name,
            ch.unit,
            ch.a,       // 转换系数: 数字量→物理量
            ch.b,       // 偏移量
            ch.a,       // 主站端转换系数（同前）
            ch.b,       // 主站端偏移量
        ));
    }

    // 采样率行
    cfg.push_str(&format!("{}\n", meta.sample_rate));

    // 采样率系数行
    cfg.push_str("1\n");

    // 起始时间
    let trigger_time = Utc.timestamp_millis(meta.trigger_timestamp);
    let pre_duration_ms = (meta.pre_trigger_nsamples as f64 / meta.sample_rate as f64 * 1000.0) as i64;
    let start_time = trigger_time - chrono::Duration::milliseconds(pre_duration_ms);
    let end_time = trigger_time + chrono::Duration::milliseconds(
        (meta.post_trigger_nsamples as f64 / meta.sample_rate as f64 * 1000.0) as i64
    );
    cfg.push_str(&format!("{}\n", start_time.format("%Y/%m/%d,%H:%M:%S.%6f")));
    cfg.push_str(&format!("{}\n", end_time.format("%Y/%m/%d,%H:%M:%S.%6f")));

    // 数据类型
    cfg.push_str("BINARY\n");

    // 时标倍率
    cfg.push_str("1\n");

    // 最后一行: 备注
    cfg.push_str(&format!(
        "MUPC Fault Recorder v1.0, EventID:{}, SampleRate:{}Hz, Duration:{}ms\n",
        meta.event_id, meta.sample_rate,
        meta.pre_trigger_nsamples + meta.post_trigger_nsamples
    ));

    cfg
}
```

```rust
fn generate_dat_binary(channels: &[Vec<f64>], trigger_offset: usize) -> Vec<u8> {
    let sample_count = channels[0].len();
    let channel_count = channels.len();
    let mut dat = Vec::with_capacity(sample_count * (4 + channel_count * 2));

    for i in 0..sample_count {
        // 采样点编号 (4字节): 1-based
        dat.extend_from_slice(&(i as u32 + 1).to_le_bytes());

        // 每个通道的 16-bit 整数值
        for ch in channels {
            let normalized = *ch / max_abs_value(ch);  // 归一化到 [-1, 1]
            let int_val = (normalized * 32767.0) as i16;
            dat.extend_from_slice(&int_val.to_le_bytes());
        }
    }

    dat
}
```

### 7.2 高频采样数据帧结构

**波形采样数据帧格式（FrameType = 0x0040）：**

```
┌───────────────────────────────────────────────┐
│ Frame Header (8 bytes)                        │
│   magic(0xAA55) + length + type(0x0040) + seq │
├───────────────────────────────────────────────┤
│ Payload (48 bytes):                           │
│   timestamp: i64 (8 bytes)   微秒级时间戳      │
│   ua: f32 (4 bytes)         A相电压瞬时值(V)   │
│   ub: f32 (4 bytes)         B相电压瞬时值(V)   │
│   uc: f32 (4 bytes)         C相电压瞬时值(V)   │
│   ia: f32 (4 bytes)         A相电流瞬时值(A)   │
│   ib: f32 (4 bytes)         B相电流瞬时值(A)   │
│   ic: f32 (4 bytes)         C相电流瞬时值(A)   │
│   u0: f32 (4 bytes)         零序电压瞬时值(V)   │
│   i0: f32 (4 bytes)         零序电流瞬时值(A)   │
│   p: f32 (4 bytes)          有功功率瞬时值(kW)  │
│   q: f32 (4 bytes)          无功功率瞬时值(kVar)│
│   freq: f32 (4 bytes)       频率(Hz)           │
├───────────────────────────────────────────────┤
│ CRC16 (2 bytes)                                │
│ Padding (6 bytes)                               │
├───────────────────────────────────────────────┤
│ Total: 64 bytes                                 │
└───────────────────────────────────────────────┘
```

**使用 f32 而非 f64 的理由：** 核间通信以太网链路带宽有限（10/100Mbps），f32 可满足 0.1% 精度要求同时减半带宽占用。波形存储时由 data-processing 转换为 f64。

**传输速率计算：**

| 采样率 | 帧间隔 | 每秒帧数 | 带宽需求 |
|--------|--------|----------|----------|
| 1kHz   | 1ms    | 1000     | 64KB/s   |
| 2kHz   | 500μs  | 2000     | 128KB/s  |
| 4kHz   | 250μs  | 4000     | 256KB/s  |
| 8kHz   | 125μs  | 8000     | 512KB/s  |
| 16kHz  | 62.5μs | 16000    | 1MB/s    |

即使在 16kHz 最高采样率下，1MB/s 的带宽需求对 100Mbps 以太网（~11.9MB/s 有效带宽）完全可行。

### 7.4 data-processing 数据接收

```rust
// data-processing 中负责从 intercore 接收波形采样数据的适配器

/// intercore 数据源适配器
pub struct IntercoreSampleSource {
    /// 从 intercore 接收帧的 channel
    rx: mpsc::Receiver<IntercoreFrame>,
    /// 波形采样管理器引用
    sampler: Arc<DualBufferManager>,
    /// 触发引擎引用
    trigger_engine: Arc<TriggerEngine>,
}

impl IntercoreSampleSource {
    /// 启动采样数据接收循环
    pub async fn run(mut self) {
        while let Some(frame) = self.rx.recv().await {
            if frame.header.frame_type != FrameType::WaveformSample {
                continue;
            }

            // 解析波形采样帧
            let sample_data = frame.parse_waveform_sample().unwrap();

            // 构建采样包
            let packet = SamplePacket {
                channels: [
                    sample_data.ua as f64,
                    sample_data.ub as f64,
                    sample_data.uc as f64,
                    sample_data.ia as f64,
                    sample_data.ib as f64,
                    sample_data.ic as f64,
                    sample_data.u0 as f64,
                    sample_data.i0 as f64,
                    sample_data.p as f64,
                    sample_data.q as f64,
                    // 注：freq 作为 metadata 但不作为第10通道
                ],
                timestamp: sample_data.timestamp,
                quality: SampleQuality::Good,
            };

            // 写入环形缓冲区
            self.sampler.push_samples(&packet.channels, packet.timestamp);

            // 触发判定
            if let Some(trigger_result) = self.trigger_engine.evaluate(&packet) {
                if trigger_result.triggered {
                    // 异步触发录波流程（不阻塞采样）
                    let sampler = self.sampler.clone();
                    let trigger = trigger_result.clone();
                    tokio::spawn(async move {
                        Self::handle_trigger(sampler, trigger).await;
                    });
                }
            }
        }
    }

    async fn handle_trigger(sampler: Arc<DualBufferManager>, result: TriggerResult) {
        // 1. 触发：冻结当前缓冲区（含 pre-trigger 数据），切换到备用缓冲区，
        //    记录 post_trigger_start 位置用于后续读取 post-trigger 数据
        //    trigger() 返回: (pre_buffer_idx, trigger_pos, post_buffer_idx, post_trigger_start)
        let (pre_buf, trigger_offset, post_buf, post_start) = sampler.trigger().unwrap();

        // 2. 等待故障后记录时长（实际做法：tokio::time::sleep + CancellationToken）
        //    等待期间采样数据继续写入 post_buf（活动缓冲区），缓冲区容量 = max(pre, post)，
        //    因此可容纳全部 post_samples 不会被覆盖。
        let pre_samples = config.pre_trigger_ms * config.sample_rate / 1000;
        let post_samples = config.post_trigger_ms * config.sample_rate / 1000;
        tokio::time::sleep(Duration::from_millis(config.post_trigger_ms as u64)).await;

        // 3. 捕获波形数据：pre 从冻结缓冲区（pre_buf），post 从活动缓冲区（post_buf）
        let waveform = sampler.capture_waveform(
            pre_buf, post_buf,
            trigger_offset, post_start,
            pre_samples, post_samples,
        );

        // 4. 写入文件 + SQLite
        // 5. 触发上报
        // 6. 释放缓冲区
        // 释放 pre_buffer（冻结缓冲区已读取完毕）
        sampler.release_buffer(pre_buf);
    }
}
```

### 7.5 实时性保证

为满足"录波启动延迟 ≤ 1 采样周期"的要求，触发判定必须在采样数据到达时同步完成，不能经过异步队列：

```
采样帧到达 (intercore TCP recv)
    │
    ├──▶ 写入环形缓冲区（O(1) 操作）
    │
    ├──▶ 触发判定（纯内存计算，无锁或极短锁持有时间）
    │    └── 若触发 → 设置原子标志位，唤醒后台录波任务
    │
    └──▶ 继续接收下一帧（不等待录波完成）
```

```rust
// waveform/report.rs 或 mqtt-bridge 中的实现

pub struct MqttWaveformReporter {
    mqtt_client: Arc<NorthMqttClient>,
    device_id: String,
    retry_count: u32,      // 默认 3
    retry_interval: Duration, // 默认 30s
}

#[async_trait]
impl WaveformReporter for MqttWaveformReporter {
    async fn report_event(&self, event: &FaultEventWithWaveform,
                          summary: &WaveformSummary) -> Result<(), ReportError> {
        let payload = serde_json::to_string(&self.build_event_payload(event, summary))
            .map_err(|e| ReportError::ProtocolError(e.to_string()))?;

        // 带重试的上报
        let mut last_error = None;
        for attempt in 0..=self.retry_count {
            match self.mqtt_client.publish(NORTH_FAULT_EVENT, &payload).await {
                Ok(_) => return Ok(()),
                Err(e) => {
                    last_error = Some(e);
                    if attempt < self.retry_count {
                        tokio::time::sleep(self.retry_interval).await;
                    }
                }
            }
        }

        Err(ReportError::RetryExhausted(
            format!("Failed after {} retries: {:?}", self.retry_count, last_error)
        ))
    }

    async fn report_file(&self, event_id: i64, file_path: &Path) -> Result<(), ReportError> {
        let file_content = tokio::fs::read(file_path).await
            .map_err(|e| ReportError::FileNotFound(e.to_string()))?;

        let chunk_size = 2048;
        let total_chunks = (file_content.len() + chunk_size - 1) / chunk_size;
        let file_name = file_path.file_name()
            .and_then(|n| n.to_str())
            .unwrap_or("unknown");

        for (i, chunk) in file_content.chunks(chunk_size).enumerate() {
            let payload = serde_json::json!({
                "event_id": event_id,
                "file_name": file_name,
                "total_chunks": total_chunks,
                "chunk_index": i,
                "data": BASE64_STANDARD.encode(chunk),
                "chunk_size": chunk.len(),
                "checksum_sha256": sha256::digest(chunk),
                "final": i == total_chunks - 1,
            });

            self.mqtt_client.publish(NORTH_FAULT_FILE_CHUNK, &payload.to_string()).await
                .map_err(|e| ReportError::NetworkError(e.to_string()))?;
        }

        Ok(())
    }
}
```

```rust
/// 上报幂等性保证：
/// 每个 event_id 在上报任务启动时被记录到 already_reported 集合中
/// if already_reported.contains(event_id) → 跳过上报
/// 集合定期清理（按保留期限）

pub struct IdempotentReporter {
    inner: Arc<dyn WaveformReporter>,
    reported: Arc<Mutex<HashSet<i64>>>,
}

#[async_trait]
impl WaveformReporter for IdempotentReporter {
    async fn report_event(&self, event: &FaultEventWithWaveform,
                          summary: &WaveformSummary) -> Result<(), ReportError> {
        let mut reported = self.reported.lock().unwrap();
        if reported.contains(&event.event.id) {
            return Ok(());  // 已上报，跳过
        }
        let result = self.inner.report_event(event, summary).await;
        if result.is_ok() {
            reported.insert(event.event.id);
        }
        result
    }
}
```

## 9. 性能设计

### 9.1 录波启动延迟 ≤ 1 采样周期

**目标：** 从故障条件满足到第一个采样点写入波形记录的时间差 ≤ 1/采样率。

**实现策略：**

```
采样帧到达
    │
    ├── 1. 写入环形缓冲区 (当前帧)     ← 时间: T0
    │
    ├── 2. 触发判定 (纯内存)           ← T0 + 1μs
    │    └── 比较 + 状态机切换
    │
    ├── 3. 触发成立
    │    ├── a. 设置原子标志 frozen=true  ← T0 + 2μs
    │    │    （后续采样仍然写入，但标记为"录波中"）
    │    └── b. 记录触发位置            ← T0 + 3μs
    │
    ├── 4. 唤醒后台录波任务 (tokio::spawn)  ← T0 + 5μs
    │    不阻塞当前采样接收线程
    │
    └── 总延迟 ≈ 5μs << 250μs (4kHz 的 1 采样周期)
```

**关键实现细节：**

- 触发判定在采样接收函数内**同步执行**，不经过 tokio 队列
- 环形缓冲区写入和触发判定使用 `parking_lot::RwLock`，写锁持有时间仅约 1μs
- 波形文件写入在独立 tokio task 中执行，不阻塞采样流程
- 使用 `AtomicUsize` 和 `AtomicU64` 减少锁竞争

### 9.2 CPU 占用控制（录波峰值 ≤ 15%）

**基线分析：**

| 操作 | 预估耗时 | 频率 | CPU 占用 |
|------|---------|------|----------|
| 环形缓冲区写入 | 1μs | 4000次/s (4kHz) | 0.4% |
| 触发判定 | 2μs | 4000次/s | 0.8% |
| 波形文件写入(峰值) | 30ms | ~1次/录波 | 3% (1200ms内) |
| 校验和计算 | 5ms | ~1次/录波 | 0.5% |
| COMTRADE 导出 | 200ms | 按需 | 非实时 |
| 存储容量检查 | 10ms | 每30秒 | <0.1% |
| 总计(稳态) | - | - | <2% |
| 总计(录波峰值) | - | - | <15% |

**优化措施：**

1. **零拷贝写入：** 环形缓冲区使用预分配 Vec，写入无内存分配
2. **批量校验和：** 写入完成后一次性计算 CRC64，而非边写边算
3. **延迟导出：** COMTRADE/CSV 导出不作为录波流程的一部分，按需异步执行
4. **I/O 分离：** 使用 `tokio::fs` 异步文件写入
5. **存储检查定时任务：** 每 30 秒执行一次容量检查，而非每次录波前检查

### 9.3 内存占用控制

**稳态内存：**

| 组件 | 占用 | 说明 |
|------|------|------|
| 环形缓冲区 A | 352KB | 10ch × 4000 点 × 8B + 4000 × 8B 时间戳 |
| 环形缓冲区 B | 352KB | 备用缓冲区（同容量，保证 post-trigger 完整收集） |
| 触发配置 | 1KB | Arc<RwLock<>> |
| 存储管理器 | 1KB | 路径、计数器 |
| 总计(稳态) | ~706KB | << 上限 2MB |

**录波峰值内存：**

| 组件 | 占用 | 说明 |
|------|------|------|
| 稳态部分 | 706KB | |

```rust
/// 录波数据保存异步任务
async fn save_waveform_task(
    waveform: WaveformData,
    storage: Arc<StorageManager>,
    db: Arc<Mutex<Connection>>,
    reporter: Option<Arc<dyn WaveformReporter>>,
) -> Result<(), DataProcessingError> {
    // 1. 写入 .wave 文件（通过 tokio::fs，不阻塞主线程）
    let file_path = storage.generate_file_path(&waveform);
    let file_info = tokio::task::spawn_blocking(move || {
        // 阻塞操作在 blocking 线程池执行
        let mut writer = WaveformWriter::create(&file_path, &waveform.metadata())?;
        for ch in &waveform.channels {
            writer.write_channel(ch)?;
        }
        writer.write_timestamps(&waveform.timestamps)?;
        writer.finalize()
    }).await??;

    // 2. 写入 SQLite 元数据
    let file_info_clone = file_info.clone();
    tokio::task::spawn_blocking(move || {
        let conn = db.lock().unwrap();
        update_sqlite_waveform_info(&conn, waveform.event_id, &file_info_clone)
    }).await??;

    // 3. 触发北向上报（异步，不阻塞）
    if let Some(reporter) = reporter {
        tokio::spawn(async move {
            if let Err(e) = reporter.report_event(...).await {
                tracing::error!("上报故障事件失败: {}", e);
            }
        });
    }

    Ok(())
}
```

## 11. 错误处理与边界条件

### 11.1 采样数据丢失

```rust
impl IntercoreSampleSource {
    async fn run(mut self) {
        let mut expected_seq: Option<u16> = None;
        let mut gap_count: u32 = 0;

        while let Some(frame) = self.rx.recv().await {
            let current_seq = frame.header.seq_no;

            // 检测序列号跳变 → 数据丢失
            if let Some(expected) = expected_seq {
                let actual_gap = current_seq.wrapping_sub(expected);
                if actual_gap > 1 {
                    gap_count += actual_gap - 1;
                    // 在环形缓冲区中插入 NaN 填充
                    for _ in 0..(actual_gap - 1) {
                        let null_packet = SamplePacket::null(current_timestamp);
                        self.sampler.push_samples(&null_packet.channels, null_packet.timestamp);
                        self.trigger_engine.evaluate(&null_packet);
                    }
                }
            }

            // 判断丢失严重程度
            if gap_count >= 10 {
                // 连续 10+ 点丢失 → 标记 major_gap，中断当前录波
                tracing::warn!("采样数据严重丢失: {} 点", gap_count);
                self.sampler.mark_major_gap();
                gap_count = 0;
            }

            expected_seq = Some(current_seq.wrapping_add(1));
        }
    }
}
```

### 11.2 配置异常处理

```rust
impl TriggerConfig {
    pub fn validate(&self) -> Result<(), TriggerConfigError> {
        // 1. 采样率必须是可用档位
        if ![1000, 2000, 4000, 8000, 16000].contains(&self.sample_rate) {
            return Err(TriggerConfigError::new(
                format!("不支持的采样率: {}Hz，可用: 1k/2k/4k/8k/16k", self.sample_rate)
            ));
        }

        // 2. 故障前 ≤ 故障后 × 3
        if self.pre_trigger_ms as u64 > self.post_trigger_ms as u64 * 3 {
            return Err(TriggerConfigError::new(
                format!("故障前时长({}ms) 不能超过故障后时长({}ms) 的 3 倍",
                    self.pre_trigger_ms, self.post_trigger_ms)
            ));
        }

        // 3. 至少启用一个通道组
        if self.channel_mask.0 & ChannelMask::ALL == 0 {
            return Err(TriggerConfigError::new("至少需要启用一个通道组"));
        }

        // 4. 总记录时长 ≥ 80ms
        if self.pre_trigger_ms + self.post_trigger_ms < 80 {
            return Err(TriggerConfigError::new(
                format!("总记录时长({}ms) 不能小于 80ms",
                    self.pre_trigger_ms + self.post_trigger_ms)
            ));
        }

        Ok(())
    }

    /// 不支持的采样率自动四舍五入到最近档位
    pub fn auto_fix_sample_rate(&mut self) {
        let valid_rates = [1000u32, 2000, 4000, 8000, 16000];
        let nearest = valid_rates.iter()
            .min_by_key(|&&r| (r as i32 - self.sample_rate as i32).abs())
            .copied()
            .unwrap_or(4000);
        if nearest != self.sample_rate {
            tracing::warn!("采样率 {}Hz 不可用，自动调整为 {}Hz", self.sample_rate, nearest);
            self.sample_rate = nearest;
        }
    }
}
```

```rust
impl StorageManager {
    pub fn can_record(&self) -> Result<bool, WaveformError> {
        // 1. 检查单日录波次数
        self.check_daily_limit()?;

        // 2. 检查磁盘空余空间
        let free_space = self.get_free_space()?;
        if free_space < 200 * 1024 * 1024 {
            // < 200MB: 紧急告警，停止录波
            tracing::error!("磁盘空余空间不足 200MB (当前: {}MB)，紧急停止录波", free_space / 1024 / 1024);
            return Err(WaveformError::StorageFull(
                format!("紧急: 磁盘空余仅 {}MB", free_space / 1024 / 1024)
            ));
        }
        if free_space < self.free_space_threshold {
            // < 500MB: 执行清理
            self.cleanup()?;
        }

        // 3. 检查总存储占用
        let total_usage = self.calculate_total_usage()?;
        if total_usage >= self.total_capacity {
            self.cleanup()?;
        }

        Ok(true)
    }

    fn check_daily_limit(&self) -> Result<(), WaveformError> {
        let today = self.today_ymd();
        let last_date = self.last_reset_date.load(Ordering::Relaxed);

        if today != last_date {
            // 新的一天，重置计数
            self.today_count.store(0, Ordering::Relaxed);
            self.last_reset_date.store(today, Ordering::Relaxed);
        }

        let count = self.today_count.load(Ordering::Relaxed);
        if count >= self.daily_limit {
            return Err(WaveformError::StorageFull(
                format!("今日录波次数已达上限 ({}次)", self.daily_limit)
            ));
        }

        Ok(())
    }
}
```

```rust
/// 文件写入带重试
async fn write_with_retry(
    file_path: &Path,
    data: &[u8],
    max_retries: u32,
) -> Result<(), WaveformError> {
    for attempt in 0..=max_retries {
        match tokio::fs::write(file_path, data).await {
            Ok(_) => return Ok(()),
            Err(e) => {
                if attempt < max_retries {
                    tracing::warn!("写入文件失败(尝试{}/{}): {}，30秒后重试",
                        attempt + 1, max_retries, e);
                    tokio::time::sleep(Duration::from_secs(30)).await;
                } else {
                    return Err(WaveformError::IoError(format!(
                        "写入文件失败(已重试{}次): {}", max_retries, e
                    )));
                }
            }
        }
    }
```
