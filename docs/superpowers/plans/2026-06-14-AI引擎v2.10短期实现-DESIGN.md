#### 2.1.4 渐进式切换时序

```
safe_update(new_weights)
  │
  ├─→ load_weights(new_weights) → shadow_model
  │
  ├─→ safety_checker.check(shadow_model) → score
  │     └→ score < threshold? → Err(SafetyViolation)
  │
  ├─→ performance_monitor.evaluate(current_model) → current_score
  ├─→ performance_monitor.evaluate(shadow_model) → shadow_score
  │     └→ shadow_score < current_score * 0.95? → Err(PerformanceDegradation)
  │
  └─→ gradual_switch(target_weights)
        │
        ├─ 启动异步任务（tokio::spawn）
        ├─ 每步间隔 step_interval_secs
        │     blend_ratio += 1.0 / steps
        │     发布混合权重事件
        └─ 完成后通知 ModelManager
```

在 `ModelManager` 中新增字段：

#### 2.2.4 折扣因子数学定义

折扣累积奖励（Discounted Cumulative Reward）：

```
D_t = Σ_{i=0}^{T} γ^i * r_{T-i}
    = r_t + γ * r_{t-1} + γ² * r_{t-2} + ... + γ^T * r_0
```

- `γ = 0.99`：每步向后追溯，100 步前奖励权重约为 `0.99^100 ≈ 0.366`
- `γ = 0.9`：短期记忆，100 步前奖励权重约为 `0.9^100 ≈ 0.000027`

缓冲区大小 `buffer_size = 1000`，超出时移除最旧奖励。

#### 2.2.5 与现有奖励函数正交性

即时奖励计算不受影响：

```rust
pub fn calculate(&self, mode: RunningMode, action: &ActionOutput, state: &FusedSystemState) -> f64 {
    let immediate = match mode { /* ... */ }; // 现有逻辑不变
    immediate // 返回即时奖励
}

pub fn calculate_discounted(&self, current_reward: f32) -> f32 {
    self.discounted_accumulator.discounted_sum()
}
```

两个方法独立调用，返回值用途不同：
- `calculate()`：用于在线微调的梯度更新
- `calculate_discounted()`：用于 Web UI 展示长期累积效果

#### 2.3.4 线性插值数学定义

```
alpha = step_counter / transition_steps
weight_i = (1 - alpha) * current_weight_i + alpha * target_weight_i
```

- `step = 0` 时：`weight = current_weights`
- `step = steps` 时：`weight = target_weights`
- 线性插值确保过渡平滑，避免权重突变

## 三、数据流设计

### 3.1 R1 数据流

```
决策周期 (full_decision_cycle)
  │
  │ 1. 当前模型决策 → action
  │
  │ 2. 在线微调样本收集 → DataPoint
  │     └→ OnlineUpdater.add_sample(data)
  │
  │ 3. 周期性微调触发 → safe_update(new_weights)
  │     │
  │     ├─→ 克隆权重到影子模型
  │     │
  │     ├─→ SafetyConstraintChecker.check(shadow)
  │     │     └→ 调用 RobustnessManager 异常检测
  │     │         └→ 异常类型 → 安全评分
  │     │
  │     ├─→ PerformanceMonitor.evaluate(current vs shadow)
  │     │     └→ 对比评估分数
  │     │
  │     └─→ GradualSwitcher.gradual_switch()
  │           └→ 后台异步执行
  │               └→ tokio::spawn
  │                   └→ 每步发布 BlendWeightsEvent
  │
  │ 4. ModelManager 订阅混合权重事件
  │     └→ 更新当前使用的模型权重
  │
  └→ 5. 下一步决策使用混合权重
```

### 3.2 R2 数据流

```
每决策周期
  │
  │ 1. 即时奖励计算 → calculate()
  │     └→ 返回 f64，用于在线微调梯度更新
  │
  │ 2. 折扣累积奖励更新 → calculate_discounted()
  │     └→ push(即时奖励) 到 buffer
  │     └→ 返回折扣累积奖励 D_t
  │
  │ 3. Web UI 查询 → cumulative_discounted_reward()
  │     └→ 用于展示长期累积效果（与即时奖励并列显示）
```

### 3.3 R3 数据流

```
场景切换触发 (ModeSelector::switch)
  │
  │ 1. 获取旧场景权重 current_weights
  │ 2. 获取新场景权重 target_weights
  │ 3. 初始化 step_counter = 0, state = InProgress
  │
  └→ 后续每决策周期（ModeSelector 持有 &mut self）
        │
        └→ ModeSelector::current_weights()
              └→ SmoothSceneTransition::get_interpolated_weights(&mut self)
                    └→ 返回线性插值权重
                    └→ step_counter += 1
                    └→ 若 step_counter >= transition_steps → state = Completed
```

## 四、错误处理

### 4.1 R1 错误处理

| 错误类型 | 触发条件 | 处理策略 | 日志级别 |
|----------|----------|----------|----------|
| `SafetyViolation` | 影子模型安全评分 < 阈值 | 拒绝更新，保留当前权重 | WARN |
| `PerformanceDegradation` | 影子模型性能 < 当前 * 0.95 | 拒绝更新，保留当前权重 | WARN |
| `SwitchInProgress` | 切换进行中再次调用 safe_update | 拒绝，返回 Ok(false) | INFO |
| `ModelNotReady` | 影子模型未初始化 | 返回错误 | ERROR |

### 4.2 R2 错误处理

| 错误类型 | 触发条件 | 处理策略 |
|----------|----------|----------|
| `GammaOutOfRange` | gamma 不在 [0.9, 0.999] | 构造函数 panic 或返回错误 |
| `BufferOverflow` | buffer_size = 0 | 构造函数拒绝 |

### 4.3 R3 错误处理

| 错误类型 | 触发条件 | 处理策略 |
|----------|----------|----------|
| `WeightsNotAvailable` | 场景切换前调用 current_weights | 返回默认权重或错误 |
| `TransitionNotStarted` | 切换已完成后继续调用 | 直接返回目标权重 |

## 七、关键设计决策

### 7.1 R1 设计决策

**Q：为何复用 RobustnessManager 而非新建 SafetyConstraintChecker？**

A：`RobustnessManager` 已实现 `detect_anomaly()` 方法，可将异常类型映射为安全评分（100 - 异常惩罚分）。复用避免重复逻辑，且与异常工况管理保持一致。

**Q：渐进式切换的背景任务如何与 ModelManager 同步？**

A：使用 `broadcast::Sender<BlendWeightsEvent>` 通道，ModelManager 订阅该通道接收混合权重更新事件。切换完成事件也通过同一通道发布。

### 7.2 R2 设计决策

**Q：折扣累积奖励如何与现有即时奖励分离？**

A：新增独立方法 `calculate_discounted()`，返回值类型为 `f32`（区别于即时奖励的 `f64`）。Web API 同时返回两个值，用途明确区分。

**Q：gamma 上限为何是 0.999 而非 1.0？**

A：gamma = 1.0 会导致无限视距奖励，缓冲区溢出时数学上无法正确归一化。0.999 确保长期权重有界。

### 7.3 R3 设计决策

**Q：平滑过渡期间 ModeSelector::current_weights() 如何工作？**

A：`ModeSelector` 持有 `smooth_transition: Option<SmoothSceneTransition>`。`current_weights()` 方法代理到过渡器，过渡完成后返回 `SceneWeights::lookup(current_mode)`。

**Q：为何在 ModeSelector 而非 ModelManager 实现平滑过渡？**

A：场景切换触发源可能是调度主站（IEC 104）或本地 Web UI，由 `ModeSelector` 统一管理。权重插值逻辑与场景耦合，在 `ModeSelector` 内实现保持内聚。
