## 1. 术语与缩略语

| 术语 | 说明 |
|------|------|
| BootROM | RK3588 芯片内固化的一级引导程序，不可修改，上电后最先执行 |
| OTP / eFuse | 一次性可编程熔丝，Rockchip RK3588 中用于存储根公钥哈希等不可篡改信息 |
| SPL (Secondary Program Loader) | 二级引导程序（通常是 U-Boot SPL），由 BootROM 加载，负责初始化 DDR 并加载 U-Boot |
| U-Boot | 开源引导加载程序，RK3588 平台标准 bootloader |
| FIT (Flattened Image Tree) | U-Boot 使用的镜像打包格式，支持包含内核、DTB、initramfs 及签名 |
| dm-verity | Linux 内核 device-mapper 目标，提供块设备级别的只读完整性验证 |
| Verified Boot | U-Boot 安全启动机制，通过公钥验签确保镜像完整性 |
| Anti-Rollback Counter | 单调递增计数器，防止设备运行旧版本固件 |
| TPL (Tertiary Program Loader) | 三级引导程序（某些平台需要），RK3588 中不使用 |
| BL31 (Boot Loader stage 3-1) | ARM Trusted Firmware 的 EL3 安全监控器，RK3588 中由 U-Boot SPL 加载 |
| OTP Secure World | Rockchip OTP 中仅 TrustZone 安全世界可访问的区域 |
| HSM (Hardware Security Module) | 硬件安全模块，用于安全存储私钥和执行密码学操作 |

## 2. 技术选型

### 2.1 启动链方案对比

针对 RK3588 / ARM64 平台，有三种主流安全启动方案：

| 方案 | 描述 | RK3588 兼容性 | 成熟度 | 维护成本 | 生态支持 | 评分 |
|------|------|:---:|:---:|:---:|:---:|:---:|
| **A: U-Boot Verified Boot (FIT 签名)** | U-Boot 原生 verified boot 机制，使用 FIT 镜像格式，嵌入公钥验签 | **原生支持** | 高 | 低 | Rockchip BSP 标配 | **推荐** |
| B: GRUB + shim | x86 主流方案，依赖 UEFI Secure Boot | 不适用 | — | — | ARM64 无 UEFI ROM | 淘汰 |
| C: 自定义 EFI Stub + 签名工具 | 绕过 U-Boot，内核自验签或自定义 bootloader | 可行但冗余 | 低 | 极高 | 无社区支持 | 淘汰 |

**决策结论：采用方案 A，U-Boot Verified Boot（FIT 签名）是唯一成熟且被 RK3588 原生支持的方案。**

理由：
1. **Rockchip BSP 原生支持**：RK3588 的 U-Boot 2023.07+ 已内置 verified boot 机制和 FIT 签名验签支持
2. **RSA/SM2 双算法支持**：U-Boot 同时支持 RSA 和 SM2（需开启 CONFIG_FIT_SIGNATURE + CONFIG_SM2）
3. **无需额外 bootloader**：不增加启动链复杂度
4. **社区成熟度高**：被大量 ARM64 设备（树莓派、NXP i.MX、TI AM6x）验证

### 2.2 BootROM 级安全启动

RK3588 BootROM 原生支持 **Secure Boot**，通过在 OTP fuses 中烧录 SHA-256 公钥哈希值，BootROM 在加载 U-Boot SPL 前自动验签。

配置方式：在 Rockchip BSP 中使能 `CONFIG_ROCKCHIP_SECURE_BOOT`，并使用 Rockchip 提供的签名工具对 SPL 镜像签名。

### 2.3 密码算法选择策略

| 场景 | 推荐算法 | 备选方案 | 决策依据 |
|------|----------|----------|----------|
| BootROM 签名 | RSA-4096 SHA-256 | SM2 (需 Rockchip 支持) | BootROM 固件算法固定于芯片 ROM |
| U-Boot FIT 签名 | RSA-4096 SHA-256 或 SM2 | — | 由安全策略配置，U-Boot 编译时决定 |
| dm-verity 哈希树 | SHA-256 | SM3 (需内核支持) | openEuler 默认使能 SHA-256 |
| 运行时校验 | SM3（国密模式）或 SHA-256 | — | 由 mupc-security crate 在 Rust 层实现 |
| 私钥加密存储 | SM4-CBC / AES-256-GCM | — | 开发测试环境使用 SM4（复用 security crate） |

### 2.4 密钥强度要求

| 算法 | 密钥长度 | 安全强度 | 等效 RSA 长度 |
|------|----------|----------|---------------|
| RSA | 4096 bit | 128 位 | — |
| SM2 | 256 bit (曲线) | 128 位 | 3072 |
| SHA-256 | 256 bit | 128 位 | — |
| SM3 | 256 bit | 128 位 | — |

### 2.5 工具链语言选型

| 组件 | 语言 | 理由 |
|------|------|------|
| 签名工具 (signing-cli) | **Rust** | 与项目栈一致，复用 security crate 的 SM2/SM3/SM4 实现 |
| 密钥生成工具 (keygen-cli) | Rust | 同上 |
| OTP 烧录工具 (otp-burn-tool) | Rust + Rockchip 库绑定 | 直接操作 `/dev/mem` 或 Rockchip 内核接口 |
| 运行时安全启动状态服务 | Rust (mupc-security crate 扩展) | 集成到现有 security crate |
| U-Boot 内验签逻辑 | C (U-Boot 原生) | 无法更改，U-Boot 编译时配置 |

## 3. 启动链架构设计

### 3.1 完整启动链流程

```
+---------+     +------------+     +--------+     +------------------+     +-----------+
| BootROM | --> | U-Boot SPL | --> | U-Boot | --> | Linux Kernel     | --> | RootFS    |
| (芯片内) |     | (DDR init) |     | (主引导) |     | + FIT (DTB/init) |     | (dm-verity)|
+---------+     +------------+     +--------+     +------------------+     +-----------+
    |                 |                |                     |                     |
    | 验签SPL         | 加载+验签UBoot | 验签FIT镜像         | 挂载rootfs          | 块级实时验签
    | (OTP公钥哈希)   | (嵌在SPL的公钥) | (嵌在U-Boot的公钥)  | (dm-verity根哈希    |
    |                 |                |                     |  由FIT签名保护)     |
    v                 v                v                     v                     v
  安全状态           安全状态          安全状态              安全状态               安全状态
  [SEC_ROM_OK]      [SEC_SPL_OK]     [SEC_UBOOT_OK]        [SEC_KERNEL_OK]       [SEC_ROOTFS_OK]
```

### 3.2 信任链传递

```

                   │

│ Step 2: U-Boot SPL                                      │
│  - 初始化 DDR、时钟等硬件                                │
│  - 加载完整 U-Boot (从 eMMC 的 boot 分区)                │
│  - 验签 U-Boot 镜像 (使用 SPL 内置的公钥)                │
│  - 验证通过 → 释放 U-Boot 执行权                         │

│  - 验签 FIT 镜像内各组件哈希 (RSA-4096/SM2)             │
│  - 检查防回滚计数器 (固件版本 >= OTP 记录值)                │
│  - 检查吊销清单 (验证签名公钥未被吊销)                      │
│  - 验证通过 → 启动内核并传递 dm-verity 根哈希             │

└─────────────────────────────────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────────────┐
│ Step 4: Linux Kernel                                    │
│  - 验证 initramfs 完整性 (若适用)                        │
│  - 使用内核 cmdline 中的 dm-verity 根哈希挂载 rootfs    │
│  - dm-verity 在 I/O 路径实时校验数据块                   │
│  - 检测到篡改 → 按策略处理 (panic/restart)               │
└─────────────────────────────────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────────────┐
│ Step 5: 用户空间初始化 (init/systemd)                    │
│  - systemd 读取安全启动状态设备节点                        │
│  - mupc-security::secure_boot_status 初始化               │
│  - 读取 /sys/class/misc/secure_boot/status 获取各级状态  │
│  - 记录安全启动日志                                      │
│  - 向北向通道上报安全启动结果                             │
└─────────────────────────────────────────────────────────┘
```

### 3.3 RK3588 启动媒体与分区表

RK3588 从 eMMC 启动时的分区布局：

```
eMMC 分区布局:
┌──────────────────────────────────────────────────┐
│ 0x000000 - 0x003FFF: 一级引导区域 (BootROM 保留)  │
│ 0x004000 - 0x00BFFF: U-Boot SPL (含签名附件)     │
│ 0x00C000 - 0x00CFFF: U-Boot TPL (RK3588 不使用)  │
│ 0x00D000 - 0x00EFFF: U-Boot 环境变量             │
│ 0x00F000 - 0x01EFFF: 保留区域                    │
├──────────────────────────────────────────────────┤
│ 分区名    | 起始     | 大小      | 类型          │
│ boot      |   4MB    |  64MB    | U-Boot 主镜像  │
│ recovery  |  68MB    |  128MB   | 恢复分区       │
│ vendor    |  196MB   |  64MB    | 厂商配置       │
│ dtb       |  260MB   |  16MB    | 设备树         │
│ boot      |  276MB   |  256MB   | FIT 镜像       │
│           |          |          | (kernel+DTB)   │
│ rootfs_a  |  532MB   |  2GB     | 根文件系统 A   │
│ rootfs_b  |  2580MB  |  2GB     | 根文件系统 B   │
│ user_data |  4628MB  | 剩余     | 用户数据/日志  │
│ boot_log  | 末尾-32MB|  32MB    | 启动日志分区   │
└──────────────────────────────────────────────────┘
```

**说明**：
- A/B 根文件系统分区（rootfs_a / rootfs_b）支持 OTA 更新时的无缝切换
- 当前激活分区由 U-Boot 环境变量 `rootfs_slot` 指定
- 每个根文件系统分区均有独立的 dm-verity 哈希树（存储在分区末尾的元数据区）

### 3.4 各阶段验签详情

| 阶段 | 验签对象 | 签名算法 | 验签密钥位置 | 预期耗时 |
|------|----------|----------|-------------|---------|
| BootROM | U-Boot SPL 镜像 | RSA-4096 PKCS#1 v1.5 | OTP fuses (sha256 哈希) | ≤ 500ms |
| U-Boot SPL | U-Boot 主镜像 | RSA-4096/SM2 | SPL 内置公钥 | ≤ 500ms |
| U-Boot | FIT (kernel+DTB) | RSA-4096/SM2 | U-Boot 内置公钥 | ≤ 2s |
| Kernel | rootfs (dm-verity) | SHA-256/SM3 (哈希树) | 内核 cmdline 传根哈希 | 启动时校验元数据 |
| 运行时 | 关键文件周期性校验 | SM3/SHA-256 | mupc-security 存储 | 每 60s (≤2% CPU) |

**关键说明**：
- BootROM 验签不支持 SM2（Rockchip BootROM 固件算法固定），因此 SPL 签名必须使用 RSA-4096
- U-Boot SPL 和 U-Boot 主镜像可以同时支持 RSA-4096 和 SM2，由安全策略配置
- dm-verity 根哈希必须以明文形式传递给内核 cmdline，其本身由 FIT 镜像签名保护

## 4. 密钥管理方案

### 4.1 密钥层次结构

```
密钥层次 (四层密钥体系):

┌─────────────────────────────────────────────────────────────────────┐
│ Layer 0: 根密钥 (Root Key)                                          │
│  - 算法: RSA-4096 或 SM2                                            │
│  - 存储: 离线 HSM / 硬件加密离线存储                                 │
│  - 用途: 签发出厂 U-Boot SPL 镜像                                    │
│  - OTP 存储: sha256(root_pubkey_der) → 32 字节                      │
│  - 生命周期: 设备整个生命周期（物理销毁前不变更）                        │
│  - 轮换: 仅能通过返厂更换硬件                                        │
└─────────────────────────────────────────────────────────────────────┘
                       │ 签发
                       ▼
┌─────────────────────────────────────────────────────────────────────┐
│ Layer 1: SPL 签名密钥 (SPL Signing Key)                             │
│  - 算法: RSA-4096                                                   │
│  - 存储: 离线 HSM / 硬件加密离线存储                                 │
│  - 用途: 签名 U-Boot SPL 镜像                                       │
│  - 受根密钥保护: SPL 的公钥由根密钥签名                              │
│  - 生命周期: 可按需轮换 (需通过根密钥重新签发)                        │
└─────────────────────────────────────────────────────────────────────┘
                       │ 签发
                       ▼
┌─────────────────────────────────────────────────────────────────────┐
│ Layer 2: U-Boot 签名密钥 (U-Boot Signing Key)                       │
│  - 算法: RSA-4096 或 SM2 (由安全策略决定)                            │
│  - 存储: 离线 HSM / 硬件加密离线存储                                 │
│  - 用途: 签名 FIT 镜像 (kernel + DTB)                               │
│  - 嵌入 U-Boot 二进制文件: 验签时使用内置公钥                         │
│  - 生命周期: 可按需轮换 (建议每年至少轮换一次)                        │
│  - 多重: 支持同时嵌入新旧两个公钥（无缝轮换）                          │
└─────────────────────────────────────────────────────────────────────┘
                       │ 签发
                       ▼
┌─────────────────────────────────────────────────────────────────────┐
│ Layer 3: dm-verity 根哈希 (Root Hash)                               │
│  - 不是密钥，是 dm-verity 哈希树的根节点值                           │
│  - 由 U-Boot 签名密钥间接保护（根哈希内嵌于已签名的 FIT 镜像中）     │
│  - 每次系统构建（rootfs 变更）时更新                                 │
└─────────────────────────────────────────────────────────────────────┘

恢复密钥 (独立于主密钥链):
┌─────────────────────────────────────────────────────────────────────┐
│ Layer R: 恢复分区签名密钥 (Recovery Key)                            │
│  - 算法: RSA-4096 (与主密钥链独立)                                   │
│  - 存储: 离线 HSM，与主密钥物理隔离                                  │
│  - 用途: 签名恢复分区镜像                                           │
│  - 公钥: 内嵌于 U-Boot 恢复模式代码中                               │
│  - 生命周期: 仅在设备需要返厂时可能变更                              │
│  - 泄露风险: 低（仅在工厂恢复场景使用）                               │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.2 OTP 存储布局

RK3588 OTP（eFuse）存储规划（按 32-bit word 寻址，总容量 64 words = 2048 bits）：

| 偏移 (word) | 名称 | 大小 (bits) | 写入时机 | 描述 |
|:---:|------|:---:|------|------|
| 0-7 | **root_key_hash** | 256 | 出厂前 | sha256(根公钥 DER 编码)，高 256 bits |
| 8 | **secure_boot_enable** | 1 | 出厂前 | 设置为 1 使能安全启动 |
| 8 | **recovery_key_hash** | 1 | 出厂前 | (预留) 恢复密钥启用位 |
| 9-15 | **anti_rollback_counter** | 224 | 每次固件升级 | 单调递增计数器 (7 × 32-bit, 支持 224 次更新) |
| 16-23 | **reserved_1** | 256 | — | 预留 |
| 24-31 | **reserved_2** | 256 | — | 预留 |
| 32-39 | **device_identity** | 256 | 出厂前 | 设备唯一标识 (可选) |
| 40-63 | **factory_reserved** | 768 | 出厂前 | Rockchip 保留 |

**OTP 资源约束**：
- 总容量：2048 bits (64 × 32-bit)
- 根密钥哈希占用：256 bits（32 字节 SHA-256）
- 防回滚计数器占用：224 bits（7 个 32-bit word，支持最多 224 次单调递增）
- 剩余可规划：约 1536 bits

**生成步骤**（以 Rust CLI 工具 `mupc-keygen` 实现）：

```rust
// 伪代码描述 KeygenTool 工作流程

/// 生成安全启动完整密钥集
async fn generate_secure_boot_keys(output_dir: &Path, algorithm: KeyAlgorithm) -> Result<KeySet> {
    // 1. 初始化 RK3588 TRNG (硬件真随机数发生器)
    let mut trng = Trng::open("/dev/hwrng")?;
    
    // 2. 生成根密钥对 (RSA-4096)
    let root_keypair = generate_rsa_keypair(&mut trng, RsaBits::Bit4096)?;
    
    // 3. 生成 SPL 签名密钥对 (RSA-4096)
    let spl_keypair = generate_rsa_keypair(&mut trng, RsaBits::Bit4096)?;
    
    // 4. 生成 U-Boot 签名密钥对 (RSA-4096 或 SM2)
    let uboot_keypair = match algorithm {
        KeyAlgorithm::Rsa4096 => generate_rsa_keypair(&mut trng, RsaBits::Bit4096)?,
        KeyAlgorithm::Sm2 => generate_sm2_keypair(&mut trng)?,
    };
    
    // 5. 生成恢复密钥对 (RSA-4096, 独立于主链)
    let recovery_keypair = generate_rsa_keypair(&mut trng, RsaBits::Bit4096)?;
    
    // 6. 导出密钥文件 (加密存储)
    let key_set = KeySet {
        root: export_encrypted_key(root_keypair, output_dir, "root")?,
        spl: export_encrypted_key(spl_keypair, output_dir, "spl")?,
        uboot: export_encrypted_key(uboot_keypair, output_dir, "uboot")?,
        recovery: export_encrypted_key(recovery_keypair, output_dir, "recovery")?,
    };
    
    // 7. 输出密钥清单文件
    write_manifest(output_dir, &key_set)?;
    
    Ok(key_set)
}

/// 导出密钥文件结构:
///   keys/
///   ├── root/
///   │   ├── root_private.pem       (AES-256-GCM 加密, PEM)
///   │   ├── root_public.pem         (公钥 PEM)
///   │   ├── root_public.der         (公钥 DER, 用于 OTP 烧录)
///   │   └── root_key_hash.bin       (sha256 哈希, 32 字节)
///   ├── spl/
///   │   ├── spl_signing_private.pem (加密)
///   │   └── spl_signing_public.pem
///   ├── uboot/
///   │   ├── uboot_signing_private.pem (加密)
///   │   └── uboot_signing_public.pem
///   ├── recovery/
///   │   ├── recovery_private.pem    (加密)
///   │   └── recovery_public.pem
///   └── manifest.json               (密钥清单)
```

### 4.4 密钥存储安全策略

| 环境 | 根密钥 | SPL 密钥 | U-Boot 密钥 | 恢复密钥 |
|------|:---:|:---:|:---:|:---:|
| **生产** | 离线 HSM | 离线 HSM | 离线 HSM | 离线 HSM |
| **预发布 (Staging)** | 离线 HSM | 离线 HSM | 离线 HSM | 离线存储加密 |
| **开发测试** | 加密文件 | 加密文件 | 加密文件 | 加密文件 |
| **CI/CD 流水线** | 不存储 | 不存储 | 密钥管理服务 | 不存储 |

### 4.5 密钥轮换与吊销

#### 密钥轮换 (模式 B: 代码内多密钥支持)

```
过渡期策略:
                    
时间线:  ──────── 旧密钥有效 ────────┬──── 旧密钥吊销 ──────→
                                     │
                          ┌──────────┴──────────┐
                          │  过渡期: 双密钥有效   │
                          │  新/旧公钥同时嵌入     │
                          │  U-Boot/FIT          │
                          │  新密钥签名的固件部署  │
                          └──────────────────────┘
```

**U-Boot 公钥嵌入配置 (双密钥)**:

```c
// U-Boot 设备树公钥节点配置 (.dts)
// 支持嵌入多个公钥，任一通过即可
&{/signature} {
    key-uboot-2025 {
        required = "conf";
        algo = "sha256,rsa4096";
        key-name-hint = "uboot-2025";
        // 公钥数据...
    };
    key-uboot-2026 {
        required = "conf";
        algo = "sha256,rsa4096";
        key-name-hint = "uboot-2026";
        // 公钥数据...
    };
};
```

#### 密钥吊销清单

吊销清单格式（嵌入 FIT 镜像的独立配置节点）：

```
FIT 镜像结构:
/ {
    images {
        kernel {...};
        fdt {...};
    };
    configurations {
        config-1 {
            kernel = "kernel";
            fdt = "fdt";
            signature {...};           // FIT 签名
        };
    };
    revocation {                       // 吊销清单节点
        revoked-keys = [
            "sha256-<fingerprint1>",   // 吊销的公钥指纹
            "sha256-<fingerprint2>",
        ];
        revocation-sig {...};          // 吊销清单自身签名
    };
};
```

### 5.2 签名工具链 crate：`mupc-signing-tool`

这是一组独立的命令行工具，**不**加入 workspace 编译（因为它们运行在开发机/CI/CD 上，而非目标设备），但复用 security crate 的密码学实现。

**工具清单**：

| 工具 | 功能 | 命令行示例 |
|------|------|-----------|
| `mupc-keygen` | 生成安全启动密钥集 | `mupc-keygen --algo rsa4096 --output ./keys/` |
| `mupc-sign` | 签名各级镜像 | `mupc-sign --key ./key.pem --type fit --input Image --output Image.sig` |
| `mupc-otp` | 生成 OTP 烧录文件 / 模拟烧录 | `mupc-otp prepare --key-hash root_key_hash.bin --output otp.bin` |
| `mupc-verity` | 生成 dm-verity 哈希树 | `mupc-verity setup --rootfs rootfs.img --hash rootfs.hash` |
| `mupc-rollback-ctl` | 管理防回滚计数器 | `mupc-rollback-ctl read` / `mupc-rollback-ctl write --value 5` |

```rust
/// 安全启动整体状态
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SecureBootStatus {
    /// 安全启动是否已启用
    pub enabled: bool,
    /// 各级验签结果
    pub chain_status: BootChainStatus,
    /// 当前根密钥指纹 (SHA-256 hex)
    pub root_key_fingerprint: String,
    /// 防回滚计数器值
    pub anti_rollback_counter: u32,
    /// 上次启动验签时间戳
    pub last_boot_verification: DateTime<Utc>,
    /// 整体状态
    pub overall_status: OverallBootStatus,
}

/// 启动链各级状态
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct BootChainStatus {
    pub bootrom: StageStatus,   // BootROM 验签结果
    pub spl: StageStatus,       // SPL 验签结果
    pub uboot: StageStatus,     // U-Boot FIT 验签结果
    pub dm_verity: StageStatus, // dm-verity 状态
}

/// 单阶段验签结果
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum StageStatus {
    Pass,
    Fail,
    NotVerified,
    Degraded,
}

/// 整体状态
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum OverallBootStatus {
    Pass,
    Fail,
    Degraded,
    Recovery,
}

/// 安全启动服务 - 运行时主接口
#[derive(Debug, Clone)]
pub struct SecureBootService {
    status_path: PathBuf,
    audit_log_path: PathBuf,
}

impl SecureBootService {
    /// 创建安全启动服务
    pub fn new(config: SecureBootConfig) -> Result<Self, SecureBootError>;

    /// 初始化：读取内核安全启动状态
    pub async fn initialize(&self) -> Result<SecureBootStatus, SecureBootError>;

    /// 获取当前安全启动状态
    pub async fn get_status(&self) -> Result<SecureBootStatus, SecureBootError>;

    /// 获取防回滚计数器值
    pub async fn get_anti_rollback_counter(&self) -> Result<u32, SecureBootError>;

    /// 记录安全启动事件日志
    pub async fn log_event(&self, event: BootEvent) -> Result<(), SecureBootError>;

    /// 查询安全启动日志
    pub async fn query_logs(&self, filter: LogFilter) -> Result<Vec<BootEvent>, SecureBootError>;

    /// 执行运行时完整性检查
    pub async fn run_integrity_check(&self) -> Result<IntegrityReport, SecureBootError>;

    pub async fn run_health_check(&self) -> Result<HealthReport, SecureBootError>;
}

pub struct BootEvent {

    pub stage: BootStage,

    Uboot,
    Fit,
    DmVerity,
```

## 6. 签名与验签流程

### 6.1 镜像签名流程

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 签名流程 (以 FIT 镜像为例)                                               │
│                                                                          │
│  1. 准备镜像内容                                                         │
│     kernel = vmlinuz-6.1.0               # Linux 内核二进制              │
│     fdt    = rk3588-mupc.dtb             # 设备树                        │
│                                                                          │
│  2. 构建 FIT 镜像源 (its) 描述文件                                         │
│     ┌──────────────────────────────────┐                                │
│     │ /dts-v1/;                        │                                │
│     │ / {                              │                                │
│     │     description = "MUPC FIT";    │                                │
│     │     #address-cells = <1>;        │                                │
│     │     images {                     │                                │
│     │         kernel {                 │                                │
│     │             data = /incbin/("./vmlinuz");                         │
│     │             type = "kernel";     │                                │
│     │             arch = "arm64";      │                                │
│     │             os = "linux";        │                                │
│     │             compression = "none";│                                │
│     │             hash {               │                                │
│     │                 algo = "sha256"; │                                │
│     │             };                   │                                │
│     │         };                       │                                │
│     │         fdt { ... };             │                                │
│     │     };                           │                                │
│     │     configurations {             │                                │
│     │         default = "conf-1";      │                                │
│     │         conf-1 {                 │                                │
│     │             kernel = "kernel";   │                                │
│     │             fdt = "fdt";         │                                │
│     │             signature {          │                                │
│     │                 algo = "sha256,rsa4096";                          │
│     │                 key-name-hint = "uboot-sign-key";                │
│     │             };                   │                                │
│     │         };                       │                                │
│     │     };                           │                                │
│     │ };                               │                                │
│     └──────────────────────────────────┘                                │
│                                                                          │
│  3. 执行签名 (使用 mupc-sign 或 mkimage)                                  │
│     $ mupc-sign --key uboot_signing_private.pem \                       │
│                 --fit kernel.itb \                                       │

│     # 或使用 U-Boot 原生工具:                                            │
│     $ mkimage -f kernel.its kernel.itb                                   │
│     $ mkimage -F kernel.itb -k keys/ -r -K u-boot.dtb \                 │
│               -k uboot_signing_key.key                                   │
│                                                                          │
│  4. 验签验证                                                             │
│     $ mupc-sign --verify --fit kernel.itb --pubkey uboot_signing_public.pem│
```

### 6.2 验签流程时序图

```
芯片上电 (POR)
    │
    ▼
┌──────────────────┐
│  BootROM         │
│  读 OTP fuse     │──── 获取 sha256(root_pubkey)
│  验证 SPL 签名    │
│  (RSA-4096)      │
└──────┬───────────┘
       │
       ├── 验证通过 ────→ 跳转到 SPL 入口
       │
       └── 验证失败 ────→ SECURE_BOOT_FAIL
                          错误码: ERR_BOOTROM_SIG_FAIL
                          指示灯: 1Hz 双闪
    │
    ▼
┌──────────────────┐
│  U-Boot SPL      │
│  初始化 DDR       │
│  加载 U-Boot      │──── 从 eMMC boot 分区加载
│  验签 U-Boot      │
│  (RSA-4096/SM2)  │
└──────┬───────────┘
       │
       ├── 验证通过 ────→ 跳转到 U-Boot 入口
       │
       └── 验证失败 ────→ SECURE_BOOT_FAIL
                          错误码: ERR_SPL_SIG_FAIL
    │
    ▼
┌──────────────────┐
│  U-Boot          │
│  加载环境变量     │
│  读取防回滚计数器  │──── 从 OTP 读取
│  检查吊销清单      │
│  加载 FIT 镜像    │──── 从 boot 分区加载
│  验签 FIT 各组件  │
│  (RSA-4096/SM2)  │
└──────┬───────────┘
       │
       ├── 全部通过 ────→ 设置内核 cmdline
       │                  root=/dev/dm-0
       │                  root_hash=0xabcd...
       │                  → 跳转到内核入口
       │
       ├── 计数器过低 ──→ SECURE_BOOT_FAIL
       │                  ERR_ROLLBACK_DETECTED
       │
       └── 验签失败 ────→ SECURE_BOOT_FAIL
                          ERR_UBOOT_FIT_SIG_FAIL
    │
    ▼
┌──────────────────┐
│  Linux Kernel    │
│  创建设备映射器   │──── dm-verity 加载
│  挂载 rootfs     │
│  (dm-verity)     │
│  读取校验         │──── 块级实时验证
│  Systemd 启动    │
│  SecureBootSvc   │──── 读取 /sys 状态
└──────┬───────────┘
       │
       ├── dm-verity OK → 正常启动
       │
       └── dm-verity 检测到篡改
           → panic / restart_on_corruption
    │
    ▼
┌──────────────────┐
```

### 6.3 内核安全启动状态读取接口

U-Boot 通过设备树（chosen 节点）或内核特定的驱动程序传递验签状态：

```
/sys/class/misc/secure_boot/
├── status             # 整体状态: "pass" | "fail" | "degraded"
├── bootrom            # BootROM 结果: "pass" | "fail" | "unknown"
├── spl                # SPL 结果: "pass" | "fail" | "unknown"
├── uboot              # U-Boot 结果: "pass" | "fail" | "unknown"
├── fit_kernel         # FIT kernel 签名结果: "pass" | "fail"
├── fit_dtb            # FIT DTB 签名结果: "pass" | "fail"
├── anti_rollback      # 防回滚计数器值 (十进制字符串)
├── root_key_hash      # 根密钥哈希 (hex)
├── revocation_count   # 吊销清单中的条目数
└── last_error         # 最近启动错误码 (若无错误则为 "none")
```

这些状态由 U-Boot 在启动时写入特定的内存区域，内核驱动程序在初始化时读取并导出到 sysfs。

### 7.3 OTA 更新流程（含安全启动检查）

```rust
// ota-update 中与安全启动集成的关键逻辑

/// OTA 管理器扩展方法
impl OtaManager {
    /// 更新前验证固件包
    async fn verify_firmware_package(
        &self,
        package_path: &Path,
    ) -> Result<FirmwarePackage, OtaError> {
        // 1. 读取并验证包元数据签名
        let metadata = self.extract_metadata(package_path)?;
        self.verifier
            .verify_signature(&metadata_bytes, &metadata.signature)
            .await?;
        
        // 2. 检查防回滚计数器
        let current_counter = self
            .secure_boot_service
            .get_anti_rollback_counter()
            .await?;
        
        if metadata.anti_rollback_counter <= current_counter {
            return Err(OtaError::AntiRollbackViolation {
                current: current_counter,
                required: metadata.anti_rollback_counter,
            });
        }
        
        // 3. 验证各组件哈希
        for component in &metadata.components {
            self.verifier
                .verify_integrity(&component.path, &component.hash)
                .await?;
        }
        
        // 4. 验证各组件自身签名（SPL/U-Boot/FIT 已有内嵌签名）
        //    此步骤确保即使 OTA 元数据被篡改，各组件签名本身也是有效的
        
        Ok(FirmwarePackage { metadata, components })
    }
    
    /// 应用固件更新
    async fn apply_firmware(
        &self,
        package: FirmwarePackage,
    ) -> Result<(), OtaError> {
        // 1. 写入备用分区 (rootfs_b 或 rootfs_a)
        self.write_inactive_slot(&package).await?;
        
        // 2. 更新防回滚计数器 (在写入成功之后, 重启之前)
        self.secure_boot_service
            .increment_anti_rollback_counter(
                package.metadata.anti_rollback_counter
            )
            .await?;
        
        // 3. 更新 U-Boot 环境变量 (设置下次启动至新分区)
        self.update_boot_env(&package).await?;
        
        // 4. 触发重启
        //    重启后自动执行完整安全启动链验签
        //    若验签失败，回滚至原分区
        info!("固件更新完成，准备重启...");
        // (重启后，U-Boot 会自动验签新分区，dm-verity 校验 rootfs)
        
        Ok(())
    }
}
```

### 7.4 防回滚计数器详细设计

```
防回滚计数器操作流程:

┌─────────────────────────────────────────────────────────────┐
│ 防回滚计数器 (Anti-Rollback Counter)                       │
│                                                             │
│ 存储位置: OTP fuses (words 9-15, 共 224 bits)              │
│ 编码方式: 7 × 32-bit word, 每位代表一次递增                 │
│           (一次烧录一个 word, 单 word 中位从 LSB 开始)      │
│ 最大值: 224 (受 OTP 可用 fuse 数量限制)                    │
│                                                             │
│ 操作:                                                       │
│  - 读取: 读出所有 7 words, 统计 set bits 总数               │
│  - 递增: 将下一个未使用的 bit 置 1                          │
│  - 写入指定值: 从 LSB 开始一次性置位到目标值                │
│                                                             │
│ OTP 写入保护:                                               │
│  - 仅在 U-Boot 阶段可写 (通过 Rockchip 密钥使能)           │
│  - 用户空间不可直接写入 (仅通过安全启动服务接口)            │
│                                                             │
│ 阈值告警:                                                   │
│  - >= 180 (80%): WARNING 告警 (防回滚计数器接近上限)       │
│  - >= 224 (100%): CRITICAL 告警 (需返厂更换硬件)           │
└─────────────────────────────────────────────────────────────┘
```

```rust
use clap::Parser;

#[derive(Parser)]
struct Args {

    #[arg(short, long)]
    input: PathBuf,

    #[arg(short, long)]

    #[arg(long, default_value = "rsa4096")]
    algorithm: String,
}

async fn run() -> Result<(), Box<dyn std::error::Error>> {
    let args = Args::parse();
    
    // 读取镜像数据
    let image_data = std::fs::read(&args.input)?;
    
    match args.algorithm.as_str() {
        "rsa4096" => {
            // RSA-4096 签名 (使用 rsa crate)
            // ...
        }
        "sm2" => {
            // SM2 签名 (复用 mupc-security)
            let key_pem = std::fs::read_to_string(&args.key)?;
            let keypair = Sm2KeyPair::from_pem(&key_pem)?;

    }
```

```
dm-verity 哈希树位置策略:

      (而非独立分区，以避免分区表复杂性)
```

## 10. 失败处理与恢复机制

### 10.1 安全启动错误码定义

| 错误码 | 阶段 | 含义 | 恢复方式 |
|--------|:---:|------|----------|
| `ERR_BOOTROM_SIG_FAIL` | BootROM | SPL 签名验证失败 | 仅恢复模式可修复 |
| `ERR_SPL_SIG_FAIL` | SPL | U-Boot 签名验证失败 | 恢复模式可修复 |
| `ERR_UBOOT_FIT_SIG_FAIL` | U-Boot | FIT (kernel/DTB) 签名失败 | 恢复模式可修复 |
| `ERR_ROLLBACK_DETECTED` | U-Boot | 防回滚计数器检测到降级 | 需刷写新版固件 |
| `ERR_REVOCATION_LIST_INVALID` | U-Boot | 吊销清单签名无效或加载失败 | 恢复模式可修复 |
| `ERR_KEY_REVOKED` | U-Boot | 签名公钥在吊销清单中 | 需刷写有效密钥签名的固件 |
| `ERR_ROOTFS_HASH_MISMATCH` | Kernel | dm-verity 根哈希不匹配 | 恢复模式可修复 |
| `ERR_DM_VERITY_CORRUPTION` | Runtime | dm-verity 检测到数据块篡改 | 自动重启（restart_on_corruption） |
| `ERR_RECOVERY_MODE` | Recovery | 恢复模式被触发（非错误，状态通知） | — |

### 10.2 恢复模式流程

```

  1. 物理按下恢复按钮 + 检测到安全启动失败
  2. 或: 系统连续 3 次启动失败后自动进入

流程:
┌─────────────────────────────────────────────────────────────────────┐
│ 1. 触发条件:                                                        │
│    - 用户按下 GPIO 恢复按钮 (需持续按住 ≥3 秒)                      │
│    - U-Boot 检测到安全启动失败 + 按钮 GPIOS 状态                     │

│    - 初始化网络 (Ethernet)                                           │
│    - 连接 OTA 更新服务器                                             │
│    - 下载带签名的修复固件                                            │
│    - 验证修复固件签名完整性                                          │
│    - 将修复固件写入主固件分区                                        │
│    - 重启系统                                                        │
│                                                                      │
│ 4. 重启后:                                                           │
│    - 全链重新验签                                                    │
│    - 若验签通过 → 正常启动                                           │
│    - 若验签再次失败 → 重新进入恢复模式                               │
│    - 连续 3 次恢复失败 → 安全错误状态 (需返厂)                       │
│                                                                      │
│ 安全限制:                                                            │
│    - 恢复模式不提供 shell 访问                                       │

│    - 串口输出仅限于状态信息 (无交互式命令行)                         │
```

### 11.3 健康检查

```rust
// security/src/secure_boot/health.rs

/// 健康检查实现
impl SecureBootService {
    /// 执行每日健康检查
    pub async fn run_health_check(&self) -> Result<HealthReport, SecureBootError> {
        let mut report = HealthReport::default();
        report.timestamp = Utc::now();
        
        // 1. 验证 dm-verity 哈希树完整性
        report.dm_verity_integrity = self.check_dm_verity_hash_tree().await?;
        
        // 2. 确认 OTP 熔丝状态
        report.otp_status = self.read_otp_status().await?;
        
        // 3. 检查防回滚计数器存储区域可写性
        report.anti_rollback_writable = self.check_counter_writability().await?;
        
        // 4. 确认安全启动状态文件未被篡改
        report.boot_status_file_integrity = self
            .verify_status_file_integrity()
            .await?;
        
        // 如果发现异常，触发告警
        if !report.is_healthy() {
            self.alert_manager
                .send_alert(Alert::HealthCheckFailed(report.clone()))
                .await?;
        }
        
        Ok(report)
    }
}
```

### 13.1 启动时间预算

### 13.2 性能优化建议

1. **FIT 签名仅签哈希**：U-Boot FIT 签名模式建议使用 `algo = "sha256,rsa4096"`，只对配置中各组件的哈希值签名，而非对整个大镜像签名，显著降低签名/验签数据量
2. **启用 dm-verity 哈希预取**：内核配置 `CONFIG_DM_VERITY_HASH_PREFETCH=y`，减少启动时的 I/O 等待
3. **使用 A76 大核验签**：确保 U-Boot 阶段运行在 A76 大核而非 A55 小核上，发挥 RSA-4096 的最佳性能
4. **并行哈希计算**：U-Boot 验签多组件（kernel + DTB）时，若可能，并行计算各组件的哈希值

## 14. 安全分析

### 14.1 威胁模型

| 攻击向量 | 攻击描述 | 被防御的启动阶段 | 防护机制 |
|----------|----------|:---:|----------|
| 固件篡改 | 直接修改 eMMC 中的 SPL/U-Boot/内核镜像 | BootROM → Kernel | 逐级签名验签 |
| 回滚攻击 | 刷写包含已知漏洞的旧版本固件 | U-Boot | 防回滚计数器 (OTP) |
| 密钥泄露 | 攻击者获取签名私钥 | — | 吊销清单机制 |
| OTP 篡改 | 尝试修改 OTP 中的公钥哈希 | BootROM | OTP 一次性编程, 不可回写 |
| dm-verity 绕过 | 替换根文件系统同时替换哈希树 | Kernel | 哈希树根由 FIT 签名保护 |
| 物理调试接口 | 通过 JTAG/SWD 绕过安全启动 | 所有阶段 | RK3588 调试接口安全策略 |
| 恢复模式攻击 | 通过恢复模式加载恶意固件 | Recovery | 恢复分区使用独立密钥签名 |

### 14.2 信任根假设

安全启动的有效性基于以下信任根假设：

1. **RK3588 BootROM 不可篡改**：BootROM 固件固化于芯片 ROM，无法通过软件或物理手段修改
2. **OTP 熔丝不可回写**：一旦烧录，OTP 中的位不能从 1 变回 0
3. **签名私钥不泄露**：私钥存储于离线 HSM，严格的物理访问控制

若以上任何假设被打破，本安全启动方案的安全保证将失效。

| # | 风险 | 等级 | 概率 | 影响 | 对策 |
