## 1. 设计目标与原则

### 1.1 设计目标

为 MUPC 微电网特种调控装置通信管理模块提供一套简洁、专业、高效的本地运维 Web UI 界面。

### 1.2 设计原则

- **工业控制风格**：以信息展示为主，避免过度装饰，强调功能性和可读性
- **简洁专业**：界面元素精简，信息层次清晰，降低运维人员认知负担
- **高效操作**：减少操作步骤，支持快速配置和故障排查
- **跨平台兼容**：支持 Chrome 90+、Firefox 88+、Edge 90+，页面响应时间 ≤ 2 秒

## 7. 交互说明

### 7.1 页面导航

- 侧边栏固定显示，点击菜单项跳转对应页面
- 当前页面菜单项高亮显示（左侧边框 3px 主色）
- 页面跳转后，滚动条回到顶部

### 7.2 表单交互

**保存配置**：
1. 用户填写/修改表单
2. 点击「保存配置」按钮
3. 按钮显示 loading 状态（文字变为「保存中...」）
4. 保存成功后显示成功提示（绿色 toast，3秒后自动消失）
5. 配置自动生效，无需重启

**表单验证**：
- 实时验证：失去焦点时验证格式
- 提交验证：点击保存时全面验证
- 错误提示：输入框下方红色文字说明错误原因
- 错误示例：「心跳间隔必须在 1-60 秒之间」

### 7.3 确认对话框

**敏感操作二次确认**：
- 弹窗标题：「确认操作」
- 弹窗内容：「此操作将修改系统配置，是否继续？」
- 按钮：「取消」（次按钮）、「确认」（主按钮）

### 7.4 异常提示

| 场景 | 提示方式 | 样式 |
|------|----------|------|
| 操作成功 | Toast 提示 | 绿色背景，顶部居中，3秒自动消失 |
| 操作失败 | Toast 提示 | 红色背景，顶部居中，需手动关闭 |
| 认证失败 | 登录页提示 | 红色文字，居中于表单下方 |
| 连接断开 | 状态栏提示 | 红色背景，白色文字，固定底部 |

### 7.5 实时日志

- WebSocket 连接状态显示在日志查看页面顶部
- 连接成功：绿色文字「实时日志已连接」
- 连接断开：红色文字「实时日志已断开，正在重连...」
- 日志自动滚动到最新（除非用户手动滚动到上方查看历史）
- 手动滚动到上方时，停止自动滚动，显示「滚动到最新」按钮

### 7.6 页面刷新

- 状态监控页面：自动刷新周期 5 秒
- 页面刷新时，显示刷新指示器（右上角旋转图标）
- 用户手动刷新时，整个页面显示半透明遮罩 + loading 动画

## 8. 用户认证流程

### 8.1 未登录状态

- 访问任意页面（除 `/login`）均跳转至登录页面
- 登录成功后跳转到原始请求页面或首页

### 8.2 登录流程

1. 用户输入用户名、密码
2. 点击登录按钮
3. 显示 loading 状态
4. 认证成功 → 跳转首页
5. 认证失败 → 显示错误提示「用户名或密码错误」

### 8.3 登出流程

1. 点击「退出登录」
2. 清除本地会话
3. 跳转登录页面

### 8.4 会话管理

- 会话有效期内（浏览器关闭前）保持登录状态
- 使用 Session 登录模式（`POST /api/auth/login`）

## 10. 技术实现建议

### 10.1 前端框架

- 建议使用 **纯 HTML + CSS + JavaScript** 或 **Vue 3**（轻量级）
- 不引入重型框架，保证页面加载速度 ≤ 2 秒

### 10.2 HTTP 服务

- 使用 Axum 或纯 HTTP 服务实现
- 默认端口：8080
- WebSocket 端点：`/ws/logs`（实时日志推送）

### 10.3 认证机制

- Session 登录模式（`POST /api/auth/login`）
- 敏感操作（配置修改）需额外确认对话框

### 10.4 API 设计建议

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/auth/login` | POST | 登录认证 |
| `/api/status` | GET | 获取系统状态 |
| `/api/config` | GET | 获取配置 |
| `/api/config` | PUT | 保存配置 |
| `/api/logs` | GET | 获取日志列表（支持分页、筛选） |
| `/ws/logs` | WebSocket | 实时日志推送 |
