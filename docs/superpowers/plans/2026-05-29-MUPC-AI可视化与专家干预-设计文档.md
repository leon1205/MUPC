## 1. 总体架构

### 1.1 架构定位

本设计基于 PRD (v1.0-reviewed)，在现有 Phase 3C AI 优化引擎和 Web API 基础上扩展。核心思路是 **"三明治"分层**：Web UI (前端) -> web-api (路由/权限/聚合) -> strategy-engine/ai-engine (数据/控制)。

```
┌──────────────────────────────────────────────────────────────────────┐
│  Web UI 层                                                           │
│  AI 决策面板 | 专家干预 | A/B 测试 | 微调监控 | 审计日志             │
└──────────────────────────┬───────────────────────────────────────────┘
                           │ SSE (实时推送) + REST (请求/响应)
                           ▼
┌──────────────────────────────────────────────────────────────────────┐
│  web-api 层 (本设计核心新增)                                         │
│                                                                      │
│  ┌────────────────┐ ┌────────────────┐ ┌─────────────────────────┐   │
│  │ ai_visualization│ │expert_ │       │ ab_testing               │   │
│  │ (5 GET 只读)   │ │intervention    │ │ (模型管理 + A/B 测试)   │   │
│  └───────┬────────┘ │(4 写操作+审计)  │ └──────────┬──────────────┘   │
│          │          └────────┬───────┘            │                   │
│          │                   │                     │                   │
│  ┌───────┴───────────────────┴─────────────────────┴──────────────┐  │
│  │  SsePushService (新增 SSE 推送)                                 │  │
│  │  AuthMiddleware (扩展：角色权限)                                │  │
│  │  AuditLogger (新增：审计日志写入)                               │  │
│  └─────────────────────────────────────────────────────────────────┘  │
└──────────────────────────┬───────────────────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────────────────┐
│  后端模块 (扩展)                                                     │
│                                                                      │
│  strategy-engine::AiIntegrator  ←→  ai-engine::ModelManager          │
│       ├── get_prediction()               ├── get_current_reward()    │
│       ├── get_reward_history()           ├── get_scene_mode()        │
│       ├── apply_weight_changes()         ├── set_weights()           │
│       ├── apply_mode_switch()            ├── set_mode()              │
│       ├── get_model_versions()           ├── create_ab_test()        │
│       ├── get_ab_test_result()           ├── rollback_model()        │
│       └── get_finetune_status()          └── get_finetune_status()   │
└──────────────────────────────────────────────────────────────────────┘
```

### 1.2 设计原则

1. **web-api 作为安全边界**：所有权限校验、输入验证、审计日志记录在 web-api 层完成，后端模块不重复校验。
2. **AiIntegrator 作为服务门面**：web-api 不直接调用 ai-engine，统一通过 strategy-engine 的 AiIntegrator 编排。
3. **只读/写操作分离**：可视化查询（GET）可以适当放宽延迟要求；干预操作（PUT/POST/DELETE）严格要求一致性和审计。
4. **SSE 优先于 WebSocket**：数据流为单向（服务端→前端），SSE 更轻量且与 Axum 集成良好。

#### 2.2.2 各接口详细定义

##### (1) GET /api/ai/predictions — 获取预测曲线数据

**功能说明**：返回 LSTM 模型的最新预测结果，包含光伏出力和负荷的预测曲线、历史基线、置信度区间。

**请求参数（Query）**：
```
type: Option<String>  // 可选过滤："pv" | "load"，不传则返回全部
```

**成功响应 200**：
```json
{
  "timestamp": "2026-05-29T10:00:00Z",
  "predictions": {
    "pv": {
      "history": [
        {"time": "2026-05-29T09:00:00Z", "value": 12.5},
        {"time": "2026-05-29T09:01:00Z", "value": 13.2}
      ],
      "forecast": [
        {"time": "2026-05-29T10:00:00Z", "value": 15.1, "confidence_lower": 14.2, "confidence_upper": 16.0},
        {"time": "2026-05-29T10:01:00Z", "value": 15.3, "confidence_lower": 14.3, "confidence_upper": 16.3}
      ],
      "confidence": 0.873,
      "horizon_secs": 1800
    },
    "load": {
      "history": [
        {"time": "2026-05-29T09:00:00Z", "value": 8.0},
        {"time": "2026-05-29T09:01:00Z", "value": 7.8}
      ],
      "forecast": [
        {"time": "2026-05-29T10:00:00Z", "value": 6.5, "confidence_lower": 5.8, "confidence_upper": 7.2}
      ],
      "confidence": 0.912,
      "horizon_secs": 1800
    }
  },
  "model_loaded": true
}
```

**错误响应**：
- 503 Service Unavailable：AI 引擎未启用时（`model_loaded: false`，前端据此显示提示）

**数据源**：调用 `AiIntegrator::get_prediction()` -> `ModelManager::predict()`

##### (2) GET /api/ai/decision — 获取当前决策状态

**功能说明**：返回 AI 引擎最新一次决策的完整状态，包括系统状态快照、决策动作、决策依据。

**成功响应 200**：
```json
{
  "timestamp": "2026-05-29T10:00:05Z",
  "system_state": {
    "battery_soc": 0.65,
    "pv_power_kw": 15.1,
    "load_power_kw": 8.2,
    "grid_power_kw": 3.5,
    "transformer_load_kw": 22.0
  },
  "action": {
    "p_batt_set_kw": 5.0,
    "load_shedding_kw": 0.0,
    "pv_limit_ratio": 1.0,
    "confidence": 0.873
  },
  "scene": {
    "current_mode": "commercial_arbitrage",
    "confidence": 0.94,
    "source": "auto_detected",
    "switched_at": "2026-05-29T08:00:00Z"
  },
  "reward_breakdown": [
    {"name": "price_arbitrage", "value": 12.5, "weight": 1.0, "percentage": 45.2},
    {"name": "battery_degradation", "value": -3.2, "weight": 1.0, "percentage": -11.6},
    {"name": "pv_consumption", "value": 8.1, "weight": 1.0, "percentage": 29.3},
    {"name": "transformer_overload", "value": -4.0, "weight": 1.0, "percentage": -14.5}
```

**数据源**：调用 `AiIntegrator::get_decision()` 获取最新决策，结合 `get_scene_mode()` 获取场景信息。web-api 层缓存最后一次决策结果，避免每次请求都触发推理。

##### (3) GET /api/ai/rewards — 获取奖励值

**功能说明**：返回当前总奖励值和指定时间范围内的奖励历史趋势。

**请求参数（Query）**：
```

```

```json
{
  "current": {
    "total": 22.5,
    "components": [
      {"name": "price_arbitrage", "value": 12.5, "weight": 1.0},
      {"name": "pv_consumption", "value": 8.1, "weight": 1.0},
      {"name": "battery_degradation", "value": -3.2, "weight": 1.0},

    {
      "timestamp": "2026-05-29T09:00:00Z",
      "total_reward": 20.1,
      "components": [
```

**数据源**：

##### (6) PUT /api/ai/weights — 更新优化目标权重

**功能说明**：手动调整优化目标权重，实时生效。

**请求体**：
```json
{
  "weights": [
    {"name": "pv_consumption", "value": 1.5},
    {"name": "battery_degradation", "value": 2.0}
  ]
}
```

**命名约束**：
- `name` 可选值：`pv_consumption`, `voltage_regulation`, `battery_degradation`, `transformer_overload`, `price_arbitrage`, `demand_penalty`, `green_energy_ratio`
- `value` 范围：0.0 ~ 5.0，超出返回 400

**请求头**：
```
X-Session-Id: <session-id>
```

**成功响应 200**：
```json
{
  "status": "ok",
  "applied_at": "2026-05-29T10:01:00Z",
  "effective_weights": [
    {"name": "pv_consumption", "old_value": 1.0, "new_value": 1.5},
    {"name": "battery_degradation", "old_value": 1.0, "new_value": 2.0}
  ]
}
```

**错误响应**：
- 400 Bad Request：权重值越界或名称无效
- 403 Forbidden：调度人员角色
- 503 Service Unavailable：AI 引擎未启用

**处理流程**：
1. web-api 层校验 Session 和角色权限
2. 校验权重值和名称合法性
3. 记录审计日志（操作前快照）
4. 调用 `AiIntegrator::apply_weight_changes()`
5. 持久化到 `/etc/mupc/weights.toml`
6. 返回成功响应

##### (11) POST /api/ai/abtest — 创建 A/B 测试

**功能说明**：启动一个新的 A/B 测试。

**请求体**：
```json
{
  "model_type": "lstm",
  "experiment_version": "lstm_v1.3.0-rc1",
  "traffic_percent": 20,
  "duration_hours": 48,
  "metrics": ["avg_reward", "pv_consumption_rate", "voltage_qualification_rate"]
}
```

**校验规则**：
- `experiment_version` 必须为 `standby` 状态
- `traffic_percent` 必须在 1-50 之间
- 同一 `model_type` 不能有运行中的 A/B 测试
- 实验组与对照组模型类型一致

**成功响应 201**：
```json
{
  "test_id": "test-20260529-001",
  "status": "running",
  "control_version": "lstm_v1.2.0",
  "experiment_version": "lstm_v1.3.0-rc1",
  "traffic_percent": 20,
  "started_at": "2026-05-29T10:00:00Z",
  "estimated_end_at": "2026-05-31T10:00:00Z"
}
```

### 2.3 SSE 实时推送

#### 2.3.1 方案选择：SSE (Server-Sent Events)

| 维度 | SSE | WebSocket | 轮询 |
|------|-----|-----------|------|
| 通信方向 | 单向（服务端→客户端） | 双向 | 请求→响应 |
| 连接开销 | 1 个 HTTP 连接 | 1 个 HTTP 升级连接 | 每次请求新连接 |
| 自动重连 | 浏览器原生支持 | 需自行实现 | 需自行实现 |
| Axum 支持 | `axum::response::sse::Sse` | `axum::extract::ws::WebSocket` | 原生 HTTP |
| 适用场景 | 服务端频率推送（最适合） | 双向交互 | 低频查询 |
| 资源占用 | 低（keep-alive） | 中（需管理状态） | 高（频繁 TCP 握手） |

**结论：采用 SSE**。理由：
- 本需求的所有推送都是服务端→浏览器单向
- SSE 在 Axum 0.7 中原生支持 `axum::response::sse::Sse`
- 浏览器自动重连，减少前端复杂度
- 比 WebSocket 更轻量，无需处理复杂协议

#### 2.3.2 SSE 端点设计

```
GET /api/ai/stream
```

**功能**：建立 SSE 连接，订阅 AI 决策面板的实时数据推送。

**连接参数（Query）**：
```
session_id: string (必填)    // 用于认证
types: string (可选)         // 订阅类型，逗号分隔：status,decision,predictions,rewards,finetuning
                             // 默认全部订阅
```

**事件格式**：
```
event: decision
data: { "timestamp": "...", "action": {...}, "system_state": {...} }

event: predictions
data: { "timestamp": "...", "pv": {...}, "load": {...} }

event: rewards
data: { "total": 22.5, "components": [...], "timestamp": "..." }

event: status
data: { "engine_status": "ready", "scene_mode": {...} }

event: finetuning
data: { "state": "collecting", "buffer_size": 128, ... }

event: heartbeat
data: { "time": "2026-05-29T10:00:00Z" }
```

#### 2.3.3 推送频率

| 事件类型 | 推送频率 | 触发方式 |
|---------|---------|---------|
| `status` | 每 5 秒 | 定时器 |
| `decision` | 每决策周期（约 1-5 秒） | AI 引擎决策完成事件 |
| `predictions` | 每 60 秒 | 定时器 |
| `rewards_current` | 每决策周期 | 随决策事件 |
| `finetuning` | 每 5 秒（微调中）/ 状态变化时 | 定时器+事件 |
| `heartbeat` | 每 30 秒 | 定时器 |

#### 2.3.4 SSE 后台架构

```
web-api 进程内：
┌──────────────────────────────────────────────┐
│  SsePushService                              │
│                                              │
│  tokio::sync::broadcast::Sender<SseEvent>    │
│       │                                      │
│       ├── 定时任务1: 每5秒推送 status          │
│       ├── 定时任务2: 每60秒推送 predictions     │
│       ├── 事件通道: 从 AiIntegrator 接收       │
│       │   decision/rewards/finetuning 事件    │
│       │                                      │
│       └── 多个 SSE 消费者 (每个 Web UI 标签页) │
│           └── broadcast::Receiver             │
│               └── Sse::new(receiver)          │
└──────────────────────────────────────────────┘
```

```rust
// 伪代码示意
pub struct SsePushService {
    tx: broadcast::Sender<SseEvent>,
    ai_integrator: Arc<AiIntegrator>,
}

impl SsePushService {
    /// 启动后台推送任务
    pub async fn start(&self) {
        let tx = self.tx.clone();
        let integrator = self.ai_integrator.clone();

        // 定时推送 status (每5秒)
        tokio::spawn(async move {
            let mut interval = tokio::time::interval(Duration::from_secs(5));
            loop {
                interval.tick().await;
                let status = integrator.status().await;
                let _ = tx.send(SseEvent::Status(status));
            }
        });

        // 定时推送 predictions (每60秒)
        tokio::spawn(async move {
            let mut interval = tokio::time::interval(Duration::from_secs(60));
            loop {
                interval.tick().await;
                let pred = integrator.get_prediction().await;
                let _ = tx.send(SseEvent::Predictions(pred));
            }
        });
    }
}
```

## 3. A/B 测试流量路由方案

### 3.1 确定性 Hash 路由

基于 `device_id` 进行一致性哈希分流，确保同一设备在测试期间始终分配到同一模型版本。

```rust
/// A/B 测试流量分配器
pub struct AbTestRouter {
    /// 运行中的 A/B 测试表
    active_tests: Arc<RwLock<HashMap<ModelType, ActiveAbTest>>>,
}

impl AbTestRouter {
    /// 确定设备应路由到哪个模型版本
    pub fn route_device(
        &self,
        device_id: &str,
        model_type: ModelType,
    ) -> RoutingDecision {
        let tests = self.active_tests.read().unwrap();
        match tests.get(&model_type) {
            None => RoutingDecision::UseControl(model_type.default_version()),
            Some(test) => {
                // 确定性 hash: device_id 的 hash 值取模 100
                let hash = self::hash_device_id(device_id);
                if hash < test.traffic_percent {
                    RoutingDecision::UseExperiment(test.experiment_version.clone())
                } else {
                    RoutingDecision::UseControl(test.control_version.clone())
                }
            }
        }
    }
}

/// 基于 device_id 的确定性 hash
/// 使用 DJB2 算法保证分布均匀
fn hash_device_id(device_id: &str) -> u8 {
    let mut hash: u32 = 5381;
    for b in device_id.bytes() {
        hash = hash.wrapping_mul(33).wrapping_add(b as u32);
    }
    (hash % 100) as u8  // 0-99
}
```

### 3.2 路由集成到 AiIntegrator

```
AiIntegrator::decide()
  ↓
  AbTestRouter::route_device(device_id, model_type)
  ↓
  ┌─ UseControl → ModelManager (当前 active 模型)
  └─ UseExperiment → ModelManager (实验组 standby 模型)
  ↓
  返回 ActionOutput
```

### 3.3 流量分配生命周期

```
启动测试:
  AiIntegrator::create_ab_test(config)
    → 校验 config
    → 设置 AbTestRouter.active_tests[model_type] = test_config
    → 5 秒内所有新决策请求按 hash 路由
    → 返回 test_id

运行中:
  每个 decide() 请求 → route_device() → 按 hash 分配

停止测试:
  DELETE /api/ai/abtest/{id}
    → 从 AbTestRouter 移除 test_config
    → 5 秒内所有流量恢复至对照组
    → 生成最终报告

超时停止:
  后台 tokio 定时任务检查 duration_hours
    → 到期自动停止
    → 生成最终报告
```

## 8. 边界条件处理

### 8.1 AI 引擎未启用

所有 `/api/ai/*` 路由在处理器中先检查 `AiIntegrator::is_ready()`，未就绪时返回统一的 503 响应：

```json
{
  "error": "ai_engine_not_ready",
  "message": "AI 引擎当前未启用，系统运行于本地策略模式",
  "engine_status": "unloaded"
}
```

### 8.2 模型未加载

预测和决策接口分别检查 LSTM/RL 模型状态，在响应中通过字段指示：
```json
{
  "predictions": {"pv": null, "load": null},
  "model_loaded": false,
  "message": "预测模型未加载"
}
```

### 8.3 权限不足

统一返回 HTTP 403：
```json
{
  "error": "permission_denied",
  "message": "当前角色无权执行此操作",
  "required_role": "operator",
  "current_role": "viewer"
}
```

### 8.4 操作冲突

- 权重修改正在应用时收到新的权重修改：最后一个生效，旧的被覆盖（无队列）
- 模式切换时 AI 引擎正在推理：返回 202 Accepted，操作排队，前端 SSE 等待生效通知
- 创建 A/B 测试时同类型已有运行中测试：返回 409 Conflict

## 10. 附录：数据流全景

### 10.1 决策面板页面加载数据流

```
Web UI 打开 /ai/dashboard
  │
  ├── HTTP GET /api/ai/status          → 展示场景模式 + AI 引擎状态
  ├── HTTP GET /api/ai/decision        → 展示系统状态 + 决策动作 + 奖励细分
  ├── HTTP GET /api/ai/predictions     → 展示预测曲线
  ├── HTTP GET /api/ai/rewards?range=24h → 展示奖励趋势图
  │
  └── SSE 连接 /api/ai/stream          → 实时推送更新
       ├── event: status (5s)
       ├── event: decision (决策周期)
       ├── event: predictions (60s)
       └── event: heartbeat (30s)
```

### 10.2 权重调整操作数据流

```
Web UI → 二次确认对话框 → PUT /api/ai/weights
  │
  ├── auth.rs: Session 验证 + 角色检查 (Operator/AiExpert)
  ├── routes/ai/weights.rs: 校验权重值范围 0.0-5.0
  ├── audit/storage.rs: 写入审计日志 (操作前快照)
  ├── strategy-engine AiIntegrator::apply_weight_changes()
  │     └── ai-engine ModelManager::set_weights()
  ├── 持久化到 /etc/mupc/weights.toml
  │
  └── 响应 → Web UI 显示"权重已更新"
       └── SSE 推送最新 status (含权重值)
```
