# S3a · 站级南向统一调度 — 框架 + 总表收敛实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建站级南向统一调度器框架 `mupc-southd`（配置驱动的多端口多从站采集调度，BECG-3568 每 RS485 口独立 master），并完成**关口/台区总表收敛**：硬编码 `master_meter` task → `role: meter_grid` 站，策略 phase 输入链路回归等价（总表回归为收敛闸门），southd mapper 成为 `AiIntegrator.set_latest_data` 唯一写方。BMS/空调/储能表/消防 role 在 S3a 仅框架 + 通用 telemetry 占位（语义点表待厂方 → S3b）。

**Architecture:** 新 crate `mupc-southd`（core-bin 依赖）静态依赖 rs485-plugin/data-processing/storage；每口一条采集 task（`PortRuntime` 持单 `Rs485Device` + 请求级 slave 参数化读，阻塞 IO 走 `spawn_blocking`），口内多从站按 `interval_ms`/`next_due` 串行轮询；站超时隔离（该站 offline，同口其它站照常）。`StationBus` trait 抽象串口 → 调度器纯逻辑可 mock 测。`mapper` role→DataPackage：`meter_grid` 完整分相（移植 startup `read_master_meter`），其它 role 通用 decode→telemetry 占位。收敛期 `master_meter` 段与 `south_stations.meter_grid` **二选一启用**（validate 互斥 R-H），`AiIntegrator.set_latest_data` 单写守卫断言。

**Tech Stack:** Rust、tokio（spawn_blocking）、serde/serde_yaml、rs485-plugin（Rs485Device/ModbusHandler/meter_regs）、data-processing（RegFormat/DataPackage/PhaseElectricalData）、storage（WriteBuffer.buffer_telemetry）、web-api SsePushService。

fn build_read_frame(slave: u8, func: u8, addr: u16, count: u16) -> Vec<u8> {
    let mut cmd = vec![slave, func, (addr >> 8) as u8, addr as u8, (count >> 8) as u8, count as u8];

}

- [ ] **Step 1: StationBus trait + 错误**

```rust
//! 口级总线抽象：每 port 一个 master，请求级 slave 读。真实=Rs485Device(spawn_blocking)；测试=mock。
use async_trait::async_trait;

#[derive(Debug, Clone, PartialEq, Eq, thiserror::Error)]
pub enum BusError {
    #[error("口 {0} 打开失败: {1}")] Open(String, String),
    #[error("站 slave={0} 读 {addr:#06x}x{count} 失败: {1}")] Read { slave: u8, addr: u16, count: u16, reason: String },
}

#[async_trait]
pub trait StationBus: Send + Sync {
    /// 读一段保持寄存器（口内串行；调用方按站 slave 传参）
    async fn read_holding(&self, slave: u8, addr: u16, count: u16) -> Result<Vec<u16>, BusError>;
}

/// 真机：每 port 单 Rs485Device。构造 open 失败 → Err（该口全站 offline，不阻断启动，§10.7）。
pub struct Rs485PortBus { port: String }
impl Rs485PortBus {
    pub fn open(conf: &crate::config::StationConf) -> Result<Self, BusError> { /* 用第一个站配置建 device；open；持 Arc */ }
}
#[async_trait]
impl StationBus for Rs485PortBus {
    async fn read_holding(&self, slave: u8, addr: u16, count: u16) -> Result<Vec<u16>, BusError> {
        // spawn_blocking 承载阻塞 libc 读；Rs485Device 内部 tx_lock 串行化同口请求
        let dev = self.device.clone();
        tokio::task::spawn_blocking(move || dev.read_holding_registers_from(slave, addr, count).map_err(|e| BusError::Read { slave, addr, count, reason: e.to_string() }))
            .await.map_err(|e| BusError::Read { slave, addr, count, reason: e.to_string() })?
    }
}
```

（Rs485Device 现 `read_holding_registers` 是 `&self` 同步——`Arc<Rs485Device>` 可 spawn_blocking。若 open 内部要 config：Rs485Device::new + open 需 Config/device_id/handler——`ProtocolHandlerRegistry::get("modbus", &config)` 见 startup.rs:162。）

/// 读一块（三相相量=count 6→[f64;3]；标量 2→单值）。返回 None=读失败（沿用旧数据）。
pub fn decode_block(regs: &[u16], b: &RegBlockConf) -> Vec<f64> {
    let mut out = Vec::new();
    let mut i = 0;
    while i + 1 < regs.len() {
        out.push(decode_regs(&regs[i..(i+2).min(regs.len())], b.format, b.scale));
        i += 2;
    }
    out
}
