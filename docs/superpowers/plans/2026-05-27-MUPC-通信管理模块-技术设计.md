## 1. 技术选型明细

### 1.1 核心依赖

| 组件 | 选型 | 理由 |
|------|------|------|
| **语言** | Rust 1.75+ | 内存安全、高性能、trait 生态成熟 |
| **异步运行时** | Tokio 1.x | 与 tokio-net 强绑定，生态最完整 |
| **网络框架** | Tower 0.5 + tokio-net | 解耦传输层，支持自定义协议 |
| **设备抽象** | trait + Box<dyn> | 运行时多态，支持动态插件 |
| **插件加载** | libloading 0.8 | 跨平台 POSIX 支持，Phase 2 动态插件 |
| **进程内消息总线** | tokio::sync::mpsc | Tokio 原生，无额外依赖 |
| **进程间消息总线** | AMQP (Phase 2) / MQTT (Phase 2) | 工业协议兼容 |
| **Web 框架** | Axum 0.7+ | 轻量、tower 集成好、async-graphql 友好 |
| **日志框架** | tracing 0.1 + tracing-subscriber | 结构化日志，与 Tokio 生态一致 |
| **配置管理** | toml + serde | 简单清晰，Phase 2 考虑 config权威 |

### 1.2 技术约束

- **目标平台**: Linux (openEuler) on RK3588
- **内存限制**: 嵌入式环境，内存占用需控制在 50MB 以内
- **启动时间**: 冷启动 < 3s
- **可靠性**: 单核故障不能导致整系统重启

## 3. 关键 API 定义

### 3.1 设备抽象 (core/device.rs)

```rust
/// 设备抽象 trait，所有南向设备必须实现
pub trait Device: Send + Sync {
    /// 设备类型标识
    fn device_type(&self) -> &'static str;

    /// 读取设备数据
    async fn read(&self, req: &ReadRequest) -> Result<ReadResponse, DeviceError>;

    /// 写入设备数据
    async fn write(&self, req: &WriteRequest) -> Result<WriteResponse, DeviceError>;

    /// 下发控制指令
    async fn control(&self, cmd: &ControlCommand) -> Result<ControlResponse, DeviceError>;

    /// 设备健康检查
    async fn health_check(&self) -> Result<HealthStatus, DeviceError>;
}

/// 读请求
pub struct ReadRequest {
    pub point_id: String,       // 数据点标识
    pub timeout_ms: u64,
}

/// 读响应
pub struct ReadResponse {
    pub value: Value,          // Value = f64 | bool | String
    pub timestamp: u64,
    pub quality: DataQuality,   // Good | Uncertain | Bad
}

/// 设备错误
#[derive(Debug)]
pub enum DeviceError {
    Timeout,
    DeviceOffline,
    InvalidPoint,
    ProtocolError(String),
    Other(Box<dyn std::error::Error>),
}

impl std::error::Error for DeviceError {}
```

### 3.2 核间通信帧格式 (intercore/frame.rs)

**TCP 帧结构（定长 64 字节）:**

```
┌──────────────────────────────────────────────────────────┐
│  0-1   │  2-3   │  4-7   │  8-15  │  16-23  │  24-63   │
├────────┼────────┼────────┼────────┼─────────┼──────────┤
│ Type   │ Length │ SeqNo  │ ai_    │ strategy│ Reserved │
│ (u16)  │ (u16)  │ (u32)  │ ready  │ _mode   │          │
│        │        │        │ (u8)   │ (u8)    │          │
└──────────────────────────────────────────────────────────┘
```

| 字段 | 偏移 | 类型 | 说明 |
|------|------|------|------|
| `type` | 0-1 | u16 | 帧类型（见下表） |
| `length` | 2-3 | u16 | 帧长度（固定 64） |
| `seq_no` | 4-7 | u32 | 序列号 |
| `ai_ready` | 8 | u8 | AI 引擎可用状态（0=不可用，1=可用） |
| `strategy_mode` | 9 | u8 | 策略模式（0=基础，1=智能，2=兜底） |
| `reserved` | 10-63 | [u8; 54] | 保留扩展 |

**帧类型定义:**

| Type | 值 | 帧名称 | 方向 |
|------|----|--------|------|
| `HEARTBEAT_REQ` | 0x0001 | 心跳请求 | 主控→实时控制 |
| `HEARTBEAT_RSP` | 0x0002 | 心跳响应 | 实时控制→主控 |
| `CONTROL_CMD` | 0x0010 | 控制指令 | 主控→实时控制 |
| `CONTROL_RSP` | 0x0011 | 控制响应 | 实时控制→主控 |
| `STATUS_REPORT` | 0x0020 | 状态上报 | 实时控制→主控 |
| `DATA_UPLOAD` | 0x0030 | 数据上传 | 实时控制→主控 |

**控制指令帧 (CONTROL_CMD):**

```
┌──────────────────────────────────────────────────────────┐
│  0-15   │  16-23   │  24-31   │  32-63                   │
├─────────┼──────────┼──────────┼───────────────────────────┤
│ cmd_id  │ cmd_type│ priority │ cmd_params (JSON)         │
│ (u16)   │ (u8)    │ (u8)    │                           │
└──────────────────────────────────────────────────────────┘
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `cmd_id` | u16 | 指令 ID |
| `cmd_type` | u8 | 0=开关控制, 1=功率调节, 2=充放电控制 |
| `priority` | u8 | 0=基础, 1=智能, 2=紧急 |
| `cmd_params` | JSON | 参数 JSON 字符串 |

### 3.3 IEC 104 数据类型 (gateway/asdu.rs)

```rust
/// 信息对象地址 (IOA) 3字节
#[derive(Debug, Clone, Copy)]
pub struct IOA(pub [u8; 3]);

/// 类型标识 (Type ID)
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum TypeId {
    M_SP_NA_1 = 1,   // 单点信息
    M_DP_NA_1 = 3,   // 双点信息
    M_ME_NA_1 = 9,   // 测量值，归一化值
    M_ME_NC_1 = 13,  // 测量值，短浮点数
    M_SP_TB_1 = 30,  // 单点信息带时标
    M_DP_TB_1 = 31,  // 双点信息带时标
    M_ME_TD_1 = 34,  // 测量值带时标
    C_SC_NA_1 = 45,  // 单点命令
    C_DC_NA_1 = 46,  // 双点命令
    C_SE_NA_1 = 48,  // 调节命令
}

/// 传输原因 (Cause of Transmission)
#[derive(Debug, Clone, Copy)]
pub struct Cot(pub u8);

impl Cot {
    pub const PERIODIC: u8 = 1;      // 周期/循环
    pub const BACKGROUND: u8 = 2;    // 后台扫描
    pub const SPONTANEOUS: u8 = 3;   // 突发
    pub const COMMAND: u8 = 6;       // 命令
    pub const ACTIVATION: u8 = 7;    // 激活
    pub const ACTIVATION_CON: u8 = 8;// 激活确认
}

/// ASDU (应用服务数据单元)
#[derive(Debug)]
pub struct ASDU {
    pub type_id: TypeId,          // 类型标识
    pub sq_num: u8,               // 平方号
    pub cot: Cot,                 // 传输原因
    pub orig_addr: u16,           // 源站地址
    pub ioas: Vec<IOA>,           // 信息对象地址列表
    pub values: Vec<Value>,       // 数据值列表
}

/// 数据值
#[derive(Debug, Clone)]
pub enum Value {
    SinglePoint(bool),            // 单点 (开/关)
    DoublePoint(u8),             // 双点 (00=中间,01=开,10=关,11=无效)
    Normalized(f64),             // 归一化值 (-1.0 ~ 1.0)
    Scaled(f64),                 // 标度化值
    Float(f64),                  // 短浮点数
}

/// 带时标的数据
#[derive(Debug)]
pub struct TimedValue {
    pub value: Value,
    pub timestamp: u64,           // Unix 时间戳 (秒)
    pub quality: Quality,
}
```

### 6.2 关键设计约束

1. **插件隔离**: 插件运行在同一进程，通过 trait 边界隔离
2. **故障恢复**: 单个模块 panic 不导致进程退出，由 supervisor 恢复
3. **资源限制**: 每个设备连接池最大 100 连接，全局内存 50MB

## 7. 错误处理策略

### 7.1 错误层次

```
┌─────────────────────────────────────────────┐
│            应用层错误 (AppError)             │
│  - 业务逻辑错误、策略执行失败                │
├─────────────────────────────────────────────┤
│            协议层错误 (ProtocolError)        │
│  - IEC 104 帧错误、MQTT 协议错误            │
├─────────────────────────────────────────────┤
│            通信层错误 (IoError)              │
│  - TCP 连接断开、超时                        │
├─────────────────────────────────────────────┤
│            设备层错误 (DeviceError)          │
│  - 设备离线、无响应                          │
└─────────────────────────────────────────────┘
```

### 7.2 统一错误类型 (common/error.rs)

**PRD 要求**:
- 错误码（u16）、错误描述、错误来源模块
- 支持错误链（`error.source()`）
- 所有模块返回的错误统一封装为 `MupcError` 枚举

```rust
/// 错误码定义
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum ErrorCode {
    // 通用错误 (0x0000-0x00FF)
    Ok = 0x0000,
    Unknown = 0x0001,
    InvalidParam = 0x0002,
    NotFound = 0x0003,
    Timeout = 0x0004,
    ConnectionFailed = 0x0005,

    // 网关错误 (0x0100-0x01FF)
    ModuleNotFound = 0x0100,
    FrameParseError = 0x0101,
    AsduTypeMismatch = 0x0102,

    // 核间通信错误 (0x0200-0x02FF)
    IntercoreTimeout = 0x0200,
    HeartbeatMissed = 0x0201,
    FrameChecksumError = 0x0202,

    // 设备错误 (0x0300-0x03FF)
    DeviceOffline = 0x0300,
    DeviceBusy = 0x0301,
    WriteFailure = 0x0302,
}

/// 统一错误类型 MupcError
#[derive(Debug)]
pub struct MupcError {
    /// 错误码
    pub code: ErrorCode,
    /// 错误描述
    pub message: String,
    /// 错误来源模块
    pub module: &'static str,
    /// 错误来源（支持错误链）
    pub source: Option<Box<dyn std::error::Error + Send + Sync>>,
}

impl MupcError {
    pub fn new(code: ErrorCode, message: impl Into<String>, module: &'static str) -> Self {
        Self {
            code,
            message: message.into(),
            module,
            source: None,
        }
    }

    pub fn with_source<E>(mut self, source: E) -> Self
    where
        E: std::error::Error + Send + Sync + 'static,
    {
        self.source = Some(Box::new(source));
        self
    }
}

impl std::error::Error for MupcError {
    fn source(&self) -> Option<&(dyn std::error::Error + 'static)> {
        self.source.as_ref().map(|e| e.as_ref() as _)
    }
}

impl std::fmt::Display for MupcError {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "[{:?}] {} (module: {})", self.code, self.message, self.module)
    }
}

// 便捷错误构造宏
#[macro_export]
macro_rules! define_error {
    ($name:ident, $code:expr, $module:expr) => {
        pub fn $name(msg: impl Into<String>) -> MupcError {
            MupcError::new($code, msg, $module)
        }
    };
}
```
