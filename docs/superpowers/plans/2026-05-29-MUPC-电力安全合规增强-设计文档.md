## 1. 设计总览

### 1.1 设计目标

在现有的 `security` crate（SM2/SM4/SM3 算法实现 + TLS 连接器）基础上，扩展六项安全合规能力：

1. 纵向加密认证装置对接（IPSec IKEv2 VPN 客户端）
2. SM2 证书 TLS 集成（rustls 自定义 CryptoProvider）
3. 控制指令全链路加密审计（gateway -> strategy-engine -> intercore）
4. 证书生命周期管理（导入、存储、热更新、吊销）
5. MQTT over TLS + 国密集成
6. 安全事件告警与合规自检

## 2. 模块划分决策

### 2.1 方案选择：在 security crate 中扩展

**决策结果**：不新建 crate，在现有 `security` crate 中扩展新的模块。

**理由**：

| 因素 | 在 security 中扩展 | 新建 crate |
|------|-------------------|-----------|
| 代码耦合度 | 新模块直接调用 SM2/SM4/SM3 内部接口，无需跨 crate 抽象 | 需要在新 crate 中重新暴露安全原语接口，重复封装 |
| 内部状态共享 | 证书存储、审计日志、加密策略都可以共享 security crate 内部状态 | 需要跨 crate 传递 Arc/RwLock 状态，增加复杂度 |
| 编译依赖 | 不增加 workspace 编译单元数 | 增加一个编译单元，略微增加编译时间 |
| 职责清晰度 | 安全合规 = 安全机制 + 合规策略，同一领域 | 安全原语 vs 合规管理，各有侧重 |
| 维护性 | 单一 crate，修改时同步更新 | 跨 crate 修改时需同步 PR |

**扩展策略**：维持现有模块结构（`sm2.rs`、`sm4.rs`、`sm3.rs`、`cert.rs`、`tls.rs`、`errors.rs`）不变，新增 6 个模块：

| 模块文件 | 新增依赖 | 说明 |
|----------|---------|------|
| `lea.rs` | `strongswan` 进程调用 | 纵向加密认证，IPSec VPN 客户端 |
| `audit.rs` | `serde_json`、`chrono` | 加密审计日志，不可篡改日志链 |
| `cert_mgr.rs` | `x509-parser`、`notify` | 证书生命周期管理，热更新 |
| `policy.rs` | `serde` | 加密策略配置，通道级策略 |
| `alarm.rs` | `tracing` | 安全事件告警生成与推送 |
| `compliance.rs` | - | 合规自检引擎，法规映射 |

**影响范围**：
- `lib.rs`：增加 6 个 `pub mod` 声明和对应的 re-export
- `Cargo.toml`：新增 `notify`、`chrono`（已在 workspace）、`sha2` 等依赖
- 无 API 破坏性变更，原有 pub 接口保持兼容

## 3. 纵向加密认证装置对接方案

### 3.1 架构策略：strongSwan VICI 协议集成

**决策**：由于 Rust 生态尚无成熟的 IPSec IKEv2 原生实现，采用通过 Unix Socket 调用 strongSwan VICI 协议的方式集成。

**VICI 协议**：strongSwan 提供的 Unix Socket 管理接口，支持用 JSON 格式发送 IKE 配置和隧道管理命令。

```
┌─────────────────────────────┐

│  ┌───────────────────────┐  │
│  │ LeaManager            │  │
│  │  - init_conn()        │  │
│  │  - create_tunnel()    │  │
│  │  - close_tunnel()     │  │
│  │  - get_tunnel_status()│  │
│  └─────────┬─────────────┘  │
│            │ Unix Socket     │
│            │ /var/run/       │
│            │ charon.vici     │
└────────────┼─────────────────┘
             ▼
┌─────────────────────────────┐
│  strongSwan charon daemon   │
│  ┌───────────────────────┐  │
│  │ IKEv2 + SM2 + SM4/SM3 │  │
```

### 3.3 VICI 协议通信

VICI 协议使用 JSON-RPC 风格的请求/响应消息，通过 Unix Socket (`/var/run/charon.vici`) 传输。

**关键操作映射**：

| 操作 | VICI 命令 | 参数 |
|------|-----------|------|
| 加载证书 | `load-cert` | `{type: "x509", cert: "<PEM>"}` |
| 加载私钥 | `load-key` | `{type: "private", key: "<PEM>"}` |
| 创建 IKE 连接 | `load-conn` | `{<IKE配置JSON>}` |
| 初始化隧道 | `initiate` | `{child: "<conn_name>"}` |
| 查询状态 | `list-sas` | `{ike: "<conn_name>"}` |
| 关闭隧道 | `unload-conn` | `{name: "<conn_name>"}` |

### 3.5 隧道管理关键流程

**创建隧道**：
1. 检查 strongSwan charon 守护进程是否运行
2. 通过 VICI 加载 SM2 证书和私钥
3. 通过 VICI 加载连接配置
4. 发起 IKEv2 握手（SM2 证书双向认证）
5. 协商 SM4-GCM + HMAC-SM3 算法
6. 建立 IPSec SA，开始数据加密传输

**自动重连**：
```
指数退避序列：1s, 2s, 4s, 8s, 16s, 32s, 60s(cap)
在每次重连失败后翻倍，达到上限后保持 60s 间隔
重连成功或管理员手动重置后恢复初始值
```

**多隧道支持**：

### 3.7 VICI 报文编码

VICI 协议报文格式为节段化编码（segment-based encoding）：

```
[长度: 4字节大端][名称: 长度字节][类型: 1字节][值...]
```

VICI 支持 5 种类型：
- 0x00: 节段开始（section start）
- 0x01: 节段结束（section end）
- 0x02: 键值对（key-value, 字符串值）
- 0x03: 列表项（list item）
- 0x04: 键值对（key-value, 原始字节值）

## 4. SM2 证书 TLS 集成方案

### 4.1 核心挑战

rustls 0.22/0.23 **不原生支持** SM2 签名算法和 SM4 密码套件。需要实现：

1. 自定义 `rustls::crypto::CryptoProvider` — 接管签名验证 + 密钥交换 + 记录加密
2. 自定义 `rustls::client::danger::ServerCertVerifier` — 验证 SM2 证书
3. SM4-GCM AEAD 实现 — 用于 TLS 记录层加密（RFC 8998 要求）

### 4.2 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                      rustls                              │
│  ┌───────────────────────────────────────────────────┐  │
│  │            CryptoProvider (自定义)                  │  │
│  │  ┌────────────────┐  ┌────────────────────────┐   │  │
│  │  │ Sm2SigningKey  │  │ Sm4GcmCipherSuite     │   │  │
│  │  │ - SM2签名/验签  │  │ - SM4-GCM 加密/解密   │   │  │
│  │  │ - RFC 8998     │  │ - 12B nonce / 16B tag │   │  │
│  │  │   sig_scheme   │  └────────────────────────┘   │  │
│  │  └────────────────┘                                │  │
│  │  ┌────────────────┐  ┌────────────────────────┐   │  │
│  │  │ Sm2KeyExchange │  │ Sm2ServerCertVerifier  │   │  │
│  │  │ - ECDHE with   │  │ - SM2证书链验证         │   │  │
│  │  │   sm2p256v1    │  │ - 有效期/CRL检查        │   │  │
│  │  └────────────────┘  └────────────────────────┘   │  │
```

### 4.3 自定义 CryptoProvider 设计

```rust
pub struct SmCryptoProvider;

impl CryptoProvider for SmCryptoProvider {
    fn cipher_suites(&self) -> Vec<CipherSuite> {
```

### 4.4 SM4-GCM TLS 记录加密

RFC 8998 定义 SM4-GCM 用于 TLS 1.3 记录层加密：

```rust
/// SM4-GCM TLS 记录保护器
pub struct Sm4GcmCipher {
    key: [u8; 16],  // SM4 128-bit key
    fixed_iv: [u8; 12],  // 4B fixed + 8B implicit nonce
    sequence_number: u64,
}

impl Sm4GcmCipher {
    /// 加密 TLS 记录
    pub fn encrypt(&mut self, plaintext: &[u8], content_type: u8) -> Result<Vec<u8>> {
        // 1. 构造 nonce: fixed_iv XOR sequence_number
        let nonce = self.build_nonce();
        
        // 2. SM4-GCM 加密
        let ciphertext = sm4_gcm_encrypt(plaintext, &self.key, &nonce)?;
        
        // 3. 自增序列号
        self.sequence_number += 1;
        
        Ok(ciphertext)  // ciphertext + tag(16B)
    }
    
    pub fn decrypt(&mut self, ciphertext: &[u8], content_type: u8) -> Result<Vec<u8>> {
        let nonce = self.build_nonce();
        let plaintext = sm4_gcm_decrypt(ciphertext, &self.key, &nonce)?;
        self.sequence_number += 1;
        Ok(plaintext)
    }
}
```

### 4.5 SM2 证书验证器

```rust
/// SM2 服务器证书验证器
pub struct Sm2ServerCertVerifier;

impl rustls::client::danger::ServerCertVerifier for Sm2ServerCertVerifier {
    fn verify_server_cert(
        &self,
        end_entity: &rustls::pki_types::CertificateDer,
        intermediate_certs: &[rustls::pki_types::CertificateDer],
        server_name: &rustls::pki_types::ServerName,
        ocsp_response: &[u8],
        now: rustls::pki_types::UnixTime,
    ) -> Result<ServerCertVerified, rustls::Error> {
        // 1. 解析证书
        let cert = X509Certificate::from_der(end_entity)
            .map_err(|_| rustls::Error::InvalidCertificate(...))?;
        
        // 2. 验证签名算法 OID = SM2-with-SM3 (1.2.156.10197.1.501)
        let sig_oid = cert.signature_algorithm().oid();
        if sig_oid != OID_SM2_SM3 {
            return Err(rustls::Error::InvalidCertificate(...));
        }
        
        // 3. 验证公钥曲线 = sm2p256v1 (1.2.156.10197.1.301)
        let curve_oid = cert.public_key().curve_oid();
        if curve_oid != OID_SM2_CURVE {
            return Err(rustls::Error::InvalidCertificate(...));
        }
        
        // 4. 验证有效期
        cert.validity().check(now)?;
        
        // 5. 验证证书链
        self.verify_cert_chain(&cert, intermediate_certs, now)?;
        
        // 6. CRL 检查
        self.check_crl(&cert)?;
        
        Ok(ServerCertVerified::assertion())
    }
}
```

### 4.6 SM2 客户端证书支持

```rust
/// SM2 签名密钥（用于客户端证书认证）
pub struct Sm2SigningKey {
    private_key: gmsm::Sm2KeyPair,
}

impl rustls::sign::SigningKey for Sm2SigningKey {
    fn choose_scheme(&self, offered: &[SignatureScheme]) -> Option<Box<dyn rustls::sign::Signer>> {
        if offered.contains(&SignatureScheme::SM2_SIG_SM3) {
            Some(Box::new(Sm2Signer { key: self.private_key.clone() }))
        } else {
            None  // 不支持非 SM2 方案
        }
    }
}

struct Sm2Signer {
    key: gmsm::Sm2KeyPair,
}

impl rustls::sign::Signer for Sm2Signer {
    fn sign(&self, message: &[u8]) -> Result<rustls::Signature, rustls::Error> {
        let sig_bytes = sm2_sign(message, ...)?;
        Ok(rustls::Signature::new(SignatureScheme::SM2_SIG_SM3, sig_bytes))
    }
    
    fn scheme(&self) -> SignatureScheme {
        SignatureScheme::SM2_SIG_SM3
    }
}
```

### 4.7 TLS 配置入口

```rust
/// 构建国密 TLS 客户端配置
pub fn build_sm2_tls_client_config(
    ca_cert_path: &str,
    client_cert_path: Option<&str>,
    client_key_path: Option<&str>,
) -> Result<rustls::ClientConfig> {
    let mut config = rustls::ClientConfig::builder_with_provider(
        Arc::new(SmCryptoProvider)
    )
    .with_protocol_versions(&[&rustls::version::TLS13])
    .map_err(|e| GmError::TlsConfigError(e.to_string()))?
    .dangerous()
    .with_custom_certificate_verifier(Arc::new(Sm2ServerCertVerifier))
    .with_no_client_auth();
    
    // 设置客户端证书（双向认证）
    if let (Some(cert_path), Some(key_path)) = (client_cert_path, client_key_path) {
        let certs = load_sm2_certificates(cert_path)?;
        let key = load_sm2_signing_key(key_path)?;
        config.set_single_cert(certs, key)?;
    }
    
    Ok(config)
}
```

### 4.8 rustls `SignatureScheme` 扩展

rustls 0.23 的 `SignatureScheme` 枚举定义在 `rustls::SignatureScheme` 中。查看其源码，目前包含的标准方案中**没有** `SM2_SIG_SM3`。

**两种方案**：

| 方案 | 说明 | 推荐 |
|------|------|------|
| A. Fork rustls 添加 SM2 枚举值 | 修改 rustls 源码，添加 `SM2_SIG_SM3 = 0x0708` | 不推荐（维护负担重） |
| B. 使用自定义 provider + raw bytes | 在自定义 provider 中用字节数组表示签名方案 ID | **推荐** |

**方案 B 实现**：

```rust
// RFC 8998 Section 2.2: sm2sig_sm3 的 TLS 算法 ID
const SM2_SIG_SM3_TLS_ID: u16 = 0x0708;  // 非标准，需与实现协商

// 由于 rustls::SignatureScheme 不包含 SM2_SIG_SM3，
// 我们在自定义 provider 中通过底层 TLS 字节直接处理签名方案协商
```

**实际方案**：鉴于 rustls 不支持直接扩展签名方案的枚举值，推荐**混合架构**：

```
Phase 1: 使用 Tongsuo/GmSSL 动态库 + rustls 备选
  - 运行时 fork GmSSL 子进程进行握手（开发成本最低）
  - 或通过 FFI 调用 Tongsuo 的 SSL 函数

Phase 2: 自定义 rustls fork 或提交 PR 到 rustls
  - 提交 RFC 8998 SM2 签名方案支持到 rustls 上游
  - 若不被采纳，维护轻量 fork

Phase 3: 纯 Rust 实现
  - 使用 sm4-gcm 实现 TLS 记录加密
  - 使用 gmsm 实现 SM2 签名验证
  - 围绕 rustls CryptoProvider 接口包装
```

**近期实现策略**：使用 `rustls::crypto::CryptoProvider` 的自定义实现，将 SM4-GCM 作为 AEAD 算法，通过底层 `tls13` 拓展性接口接入。对于签名方案，在 `CertificateVerifier` 中自行处理 SM2 证书的验证逻辑，绕过 rustls 的签名方案枚举限制。

```rust
pub struct SecureStrategyEngine {

impl SecureStrategyEngine {
    async fn process_encrypted_command(
        &self,
        encrypted: EncryptedControlCommand,
    ) -> Result<ControlCommand> {
        // 1. 重放防护检查
        self.replay_protector.check(
            encrypted.context.seq_no,
            encrypted.context.timestamp_ms,
        )?;
        
        // 2. SM2 验签（验证 gateway 的签名）
        let payload_to_verify = [
            encrypted.context.serialize(),
            &encrypted.encrypted_payload,
        ].concat();
        self.security.sm2_verify(
            &payload_to_verify,
            &encrypted.signature,
            &encrypted.signer_fingerprint,
        )?;
        
        // 3. SM4-GCM 解密
        let plaintext = self.security.sm4_gcm_decrypt(
            &encrypted.encrypted_payload,
            &encrypted.context.key_id(),
            &encrypted.iv,
        )?;
        
        // 4. 策略校验（业务逻辑）
        let command: ControlCommand = serde_json::from_slice(&plaintext)?;
        self.validate_strategy(&command).await?;
        
        // 5. 重新加密（用 intercore 密钥）
        let new_context = EncryptionContext::new(
            "strategy-engine", "intercore",
            &self.security.next_seq_no(),
        );
        let new_iv = generate_iv_12();
        let new_ciphertext = self.security.sm4_gcm_encrypt(
            &plaintext, &new_context.key_id(), &new_iv,
        )?;
        
        // 6. 新签名
        let new_payload_to_sign = [new_context.serialize(), &new_ciphertext].concat();
        let new_signature = self.security.sm2_sign(&new_payload_to_sign)?;
        
        let re_encrypted = EncryptedControlCommand {
            context: new_context,
            encrypted_payload: new_ciphertext,
            iv: new_iv,
            signature: new_signature,
            signer_fingerprint: self.security.local_fingerprint(),
        };
        
        self.bus.send(re_encrypted).await?;
        Ok(command)
    }
```

```rust
// intercore 新增 TCP 会话加密

pub struct SecureIntercoreFrame {
    inner: IntercoreFrame,
    /// TCP 会话级的 SM4-GCM 加密层
    encryptor: Sm4GcmSessionEncryptor,
}

impl SecureIntercoreFrame {
    /// 发送加密指令到实时控制模块
    async fn send_encrypted_command(
        &self,
        encrypted: EncryptedControlCommand,
    ) -> Result<()> {
        // 1. SM4-GCM 解密（intercore 密钥）
        let plaintext = self.security.sm4_gcm_decrypt(
            &encrypted.encrypted_payload,
            &encrypted.context.key_id(),
            &encrypted.iv,
        )?;
        
        // 2. SM2 验签（验证 strategy-engine 的签名）
        let payload_to_verify = [
            encrypted.context.serialize(),
            &encrypted.encrypted_payload,
        ].concat();
        self.security.sm2_verify(
            &payload_to_verify,
            &encrypted.signature,
            &encrypted.signer_fingerprint,
        )?;
        
        // 3. 组装 TCP 帧
        let frame = IntercoreFrame::new(
            FrameType::ControlCmd,
            encrypted.context.seq_no as u16,
            plaintext,
        );
        
        // 4. TCP 会话级 SM4-GCM 加密
        let encrypted_bytes = self.encryptor.encrypt_frame(&frame.to_bytes()?)?;
        
        // 5. 通过 RJ45 发送
        self.tcp_stream.write_all(&encrypted_bytes).await?;
    }
}

/// TCP 会话级 SM4-GCM 加密器
pub struct Sm4GcmSessionEncryptor {
    /// 共享密钥（SM2 密钥交换派生）
    session_key: [u8; 16],
    /// 发送端序列号 (GCM nonce)
    send_counter: u64,
    /// 接收端序列号
    recv_counter: u64,
}

impl Sm4GcmSessionEncryptor {
    /// 使用 SM2 密钥交换派生会话密钥
    pub fn from_key_exchange(
        local_key: &Sm2KeyPair,
        peer_public_key: &[u8],
    ) -> Result<Self> {
        let shared_secret = sm2_derive_shared_key(local_key, peer_public_key)?;
        // HKDF-SM3 派生 16 字节会话密钥
        let session_key = sm3_derive_key(
            &shared_secret,
            b"MUPC_INTERCORE_SESSION",
            b"tcp-encrypt-v1",
            16,
        )?;
        Ok(Self {
            session_key: session_key.try_into().unwrap(),
            send_counter: 0,
            recv_counter: 0,
        })
    }
    
    /// 加密帧
    pub fn encrypt_frame(&mut self, frame: &[u8]) -> Result<Vec<u8>> {
        let nonce = self.build_nonce(self.send_counter);
        self.send_counter += 1;
        sm4_gcm_encrypt(frame, &self.session_key, &nonce)
    }
    
    /// 解密帧
    pub fn decrypt_frame(&mut self, encrypted: &[u8]) -> Result<Vec<u8>> {
        let nonce = self.build_nonce(self.recv_counter);
        self.recv_counter += 1;
        sm4_gcm_decrypt(encrypted, &self.session_key, &nonce)
    }
    
    fn build_nonce(&self, counter: u64) -> Vec<u8> {
        let mut nonce = vec![0u8; 12];
        // 前 4 字节固定，后 8 字节为序列号
        nonce[4..].copy_from_slice(&counter.to_be_bytes());
        nonce
    }
}
```

```rust
/// 重放防护器
pub struct ReplayProtector {
    /// 已处理的序列号窗口 (滑动窗口, 5分钟)
    window: ReplayWindow,
    /// 上次清理时间
    last_cleanup: Instant,
}

impl ReplayProtector {
    /// 检查序列号是否有效
    pub fn check(&mut self, seq_no: u64, timestamp_ms: u64) -> Result<()> {
        let now = SystemTime::now()
            .duration_since(UNIX_EPOCH)
            .unwrap()
            .as_millis() as u64;
        
        // 1. 时间窗口检查
        if now.saturating_sub(timestamp_ms) > 300_000 {
            return Err(GmError::ReplayDetected(
                "指令时间戳超出 5 分钟窗口".into()
            ));
        }
        
        // 2. 序列号重复检查
        if self.window.contains(seq_no) {
            return Err(GmError::ReplayDetected(
                format!("序列号 {} 已处理过", seq_no)
            ));
        }
        
        // 3. 记录序列号
        self.window.insert(seq_no);
        
        Ok(())
    }
}
```

### 6.3 证书热更新设计

**热更新场景**：证书文件被替换后，正在使用的旧连接继续使用旧证书，新建连接使用新证书。

```rust
/// 证书热更新处理器
pub struct HotReloadHandler {
    current: Arc<RwLock<CertStore>>,
    pending: Arc<RwLock<Option<CertStore>>>,
}

impl HotReloadHandler {
    /// 启动文件监控（notify crate）
    pub fn start_watching(&self, cert_dir: &Path) -> Result<()> {
        let mut watcher = notify::RecommendedWatcher::new(
            move |event: notify::Result<notify::Event>| {
                // 文件变更后标记 pending
                if let Ok(event) = event {
                    if matches!(event.kind,
                        notify::EventKind::Modify(_) |
                        notify::EventKind::Create(_)
                    ) {
                        self.mark_pending();
                    }
                }
            },
            notify::Config::default(),
        )?;
        
        watcher.watch(cert_dir, notify::RecursiveMode::NonRecursive)?;
        Ok(())
    }
    
    /// 尝试切换 pending 证书
    pub fn try_switch(&mut self) -> Result<bool> {
        if let Some(pending) = self.pending.read().unwrap().take() {
            // 验证新证书
            pending.verify_all()?;
            
            // 原子切换
            let mut current = self.current.write().unwrap();
            *current = pending;
            
            // 通知各模块重新加载 TLS 配置
            self.notify_consumers();
            
            Ok(true)
        } else {
            Ok(false)
        }
    }
}

/// 证书使用模式
pub enum CertUsageStrategy {
    /// 旧连接保持旧证书，新连接用新证书（推荐）
    GracefulSwitch,
    /// 立即停止所有旧证书使用
    ImmediateSwitch,
}
```

```rust
        interval.tick().await;
        if let Err(e) = manager.reload() {
            tracing::warn!("证书自动重载失败: {}", e);
        }
    }
}
```

### 6.4 证书导入验证流程

```
用户上传 PEM
    │
    ▼
Step 1: 格式检查
  ├── PEM 解码 → 通过/失败
  ├── DER 解码 → X.509 证书
  └── 签名算法 OID = SM2-with-SM3 (1.2.156.10197.1.501)
  
Step 2: 公钥算法检查
  ├── 公钥算法 = id-ecPublicKey (1.2.840.10045.2.1)
  └── 曲线 = sm2p256v1 (1.2.156.10197.1.301)
  
Step 3: 有效期检查
  ├── notBefore ≤ now ≤ notAfter
  └── 若剩余有效期 < 30 天 → WARNING 告警
  
Step 4: 证书链验证
  ├── 查找签发者证书（按 Issuer 匹配）
  ├── 验证签名（签发者对当前证书的签名）
  └── 递归直到自签名 CA
  
Step 5: CRL 检查（如 CRL 存在）
  └── 检查证书序列号不在 CRL 列表中
  
Step 6: 私钥匹配验证（如提供私钥）
  ├── 使用公钥加密随机数
  └── 使用私钥解密，验证结果一致
  
Step 7: 保存到 /etc/mupc/certs/
  ├── 证书: [role]-[id].pem  (权限 644)
  ├── 私钥: [role]-[id]-key.pem  (权限 600, owner root)
  └── 更新 certs.json 索引
```

### 6.5 CRL 验证

```rust
/// CRL 管理器
pub struct CrlManager {
    crls: HashMap<String, CertificateRevocationList>,
    check_enabled: bool,
    update_interval: Duration,
}

impl CrlManager {
    /// 解析 CRL (X.509 v2 CRL 格式)
    pub fn parse_crl(&mut self, crl_der: &[u8]) -> Result<()> {
        let crl = x509_parser::revocation_list::CertificateRevocationList::from_der(crl_der)
            .map_err(|e| GmError::CertVerifyFailed(format!("CRL 解析失败: {}", e)))?;
        
        // 验证 CRL 签发者签名
        self.verify_crl_signature(&crl)?;
        
        // 存储 CRL
        let issuer = crl.tbs_certificate.issuer.to_string();
        self.crls.insert(issuer, crl);
        
        Ok(())
    }
    
    /// 检查证书是否被吊销
    pub fn check_revoked(&self, cert_serial: &[u8]) -> Result<bool> {
        if !self.check_enabled {
            return Ok(false);
        }
        
        for crl in self.crls.values() {
            for revoked in &crl.tbs_certificate.revoked_certificates {
                if revoked.serial_number == cert_serial {
                    return Ok(true);  // 被吊销
                }
            }
        }
        
        Ok(false)
    }
}
```

### 7.3 SM4 应用层加密/解密

```rust
/// SM4 应用层加密器
pub struct Sm4PayloadCipher {
    /// SM4 会话密钥（SM2 密钥交换派生）
    session_key: Sm4Key,
    /// 密钥 ID（用于标识加解密使用的密钥）
    key_id: String,
}

impl Sm4PayloadCipher {
    /// 通过 SM2 密钥交换初始化
    pub fn from_key_exchange(
        local_key_path: &str,
        peer_public_key_path: &str,
    ) -> Result<Self> {
        let local_key = load_sm2_keypair(local_key_path)?;
        let peer_key = load_sm2_public_key(peer_public_key_path)?;
        
        let shared_secret = sm2_derive_shared_key(&local_key, &peer_key)?;
        let key_bytes = sm3_derive_key(
            &shared_secret,
            b"MUPC_MQTT_PAYLOAD",
            b"sm4-payload-v1",
            16,
        )?;
        
        Ok(Self {
            session_key: Sm4Key::from_bytes(&key_bytes)?,
            key_id: Self::derive_key_id(&key_bytes),
        })
    }
    
    /// 加密 MQTT Payload
    /// 返回格式: [key_id(8)][iv(12)][ciphertext][tag(16)]
    pub fn encrypt_payload(&self, payload: &[u8]) -> Result<Vec<u8>> {
        let iv = generate_iv_12();
        let ciphertext = sm4_gcm_encrypt(
            payload, self.session_key.as_bytes(), &iv,
        )?;
        // SM4-GCM 输出 = 密文 + 16字节认证标签
        
        let mut result = Vec::new();
        result.extend_from_slice(self.key_id.as_bytes());  // 8 字节密钥 ID
        result.extend_from_slice(&iv);                      // 12 字节 IV
        result.extend_from_slice(&ciphertext);              // 密文 + tag
        Ok(result)
    }
    
    /// 解密 MQTT Payload
    pub fn decrypt_payload(&self, data: &[u8]) -> Result<Vec<u8>> {
        let iv = &data[8..20];                    // 12 字节 IV
        let ciphertext = &data[20..];              // 密文 + 16 字节 tag
        
        sm4_gcm_decrypt(ciphertext, self.session_key.as_bytes(), iv)
    }
    
    fn derive_key_id(key: &[u8]) -> String {
        // 取 SM3 哈希前 8 字节作为密钥 ID
        let hash = sm3_hash(key).unwrap();
        hex::encode(&hash[..8])
    }
}
```

## 10. 外部依赖与风险评估

### 10.1 依赖评估

| 依赖 | 用途 | 风险等级 | 备用方案 |
|------|------|----------|---------|
| `notify` (v6) | 证书目录文件监控 | 低 | `tokio::fs::watch` 轮询 |
| `serde_yaml` | 策略配置 YAML | 低 | TOML/JSON 格式替代 |
| strongSwan VICI | IPSec 隧道管理 | **高** | 直接使用 `libipsec` (C FFI) |
| `rustls` CryptoProvider | SM2 TLS 握手 | 中 | 调用 GmSSL FFI |
| `x509-parser` | CRL/证书解析 | 低 | `rasn` 手动解析 DER |

### 10.2 关键风险应对

**风险 1：rustls 不支持 SM2 签名方案枚举**

当前 rustls 0.23 的 `SignatureScheme` 枚举不包含 `SM2_SIG_SM3`。解决路径：

1. 提交 RFC 8998 支持 PR 到 rustls 上游（首选）
2. 在自定义 `CryptoProvider` 中通过 `Tls13CipherSuite` 自定义签名方案
3. 若 1/2 不可行，使用 `rustls::crypto::CryptoProvider` + 自定义 `ServerCertVerifier`，在验证器内部处理 SM2 证书验证，绕过签名方案枚举限制

**风险 2：strongSwan VICI 协议复杂度**

VICI 使用自定义 segment-based 编码（非 JSON），处理稍复杂。解决方案：

1. 封装 `ViciClient` 模块，屏蔽编码细节
2. 单元测试覆盖所有 VICI 报文类型
3. 可先实现 JSON 格式 (strongSwan 5.9+ 支持 JSON 模式)

**风险 3：MQTT 国密互通性**

不同 MQTT Broker 对 SM2 TLS 的支持程度不一。解决方案：

1. 先以 EMQX 5.x（支持国密 TLS）为主要互操作目标
2. MQTT 5.0 User Properties 携带加密参数，Broker 不解密 Payload
3. Broker 至少需支持 SM2 TLS 传输层加密

## 12. 开放问题

1. **rustls 自定义 CryptoProvider 的稳定性**：rustls 0.23 的 CryptoProvider trait 仍在演化中，SM2 支持可能需要维护自定义 fork 或在每个 rustls 版本升级时适配。

2. **strongSwan 进程管理**：需确定 MUPC 是否负责启动/停止 strongSwan charon 守护进程，还是假设系统已预装并运行 strongSwan。

3. **SNMP Trap 依赖**：Rust SNMP 生态尚不成熟（`snmp` crate 年久失修），SNMP Trap 推送可降级为 syslog + Webhook。

4. **硬件安全模块 (HSM) 对接**：当前设计为软件密钥存储，若需对接 PKCS#11 HSM 需额外集成 `cryptoki` crate。

5. **证书自动续期**：当前设计依赖管理员手动导入新证书或通过 SCP 复制。若需自动化（ACME 协议），需额外支持。
