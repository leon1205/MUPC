## 1. 产品概述与核心价值

### 1.1 项目背景

MUPC 通信管理模块 Phase 3A 已实现 `FaultRecorder` 接口和 `FaultRecorderImpl` 的SQLite故障事件记录功能，但该实现仅记录故障事件的**元数据**（故障类型、触发条件阈值），未记录故障前后的**波形数据**（高频率采样的电气量时序数据）。

当前现状：
- `FaultRecorder` trait 中 `get_waveform()` 方法存在，但返回空数据结构（`channels: vec![]`, `sample_rate: 0`, `trigger_timestamp: 0`, `duration_ms: 0`）
- 无波形数据采样逻辑
- 无波形数据存储逻辑
- 无波形数据查询回放功能
- 无波形数据导出功能
- 无波形数据北向上报功能

### 1.2 解决的核心问题

| 问题 | 影响 | 本PRD的解决方案 |
|------|------|-----------------|
| 故障时仅有事件记录，无波形数据可分析 | 运维人员无法定位故障根因 | 实现故障前后波形采样与存储 |
| 波形数据离线存储，不支持远程获取 | 故障分析依赖现场取数 | 实现波形数据北向上报（IEC 104 / MQTT） |
| 录波参数不可配置 | 无法适应不同工况场景 | 实现可配置的触发条件和采样参数 |
| 波形数据格式封闭 | 无法导入第三方分析工具 | 支持 COMTRADE / CSV 格式导出 |

### 1.3 适用范围

| 项目 | 说明 |
|------|------|
| 设备 | MUPC 微电网特种调控装置 |
| 平台 | Linux (openEuler)、RK3588 |
| 数据源 | 实时控制模块（通过 intercore 获取高频采样数据） |
| 通信 | 北向 IEC 104 / MQTT / IEC 61850 上报告警和分析数据 |

### 1.4 核心价值

- **故障根因分析**：通过故障前后的波形数据，准确定位过压、欠压、谐波畸变、短路等故障的起止时刻和演变过程
- **电能质量追溯**：为电压暂降、暂升、中断等电能质量事件提供波形证据
- **设备状态评估**：通过波形趋势分析断路器、变压器等设备的运行健康状况
- **事故调查取证**：满足电力系统事故调查对录波数据的合规性要求（保存期限≥30天）

## 2. 目标用户角色

### 2.1 运维人员

**职责**：负责 MUPC 设备的日常巡检、参数配置和故障初步排查。

**使用场景**：
- 配置故障录波的触发条件和参数（采样率、时长、通道选择）
- 在设备本地或远程查看最近的故障事件列表
- 将波形数据导出，提交给故障分析工程师

### 2.2 故障分析工程师

**职责**：负责对故障事件进行深入分析，定位故障根因，出具分析报告。

**使用场景**：
- 查询故障事件关联的波形数据
- 回放波形数据，观察故障前后各电气量的变化趋势
- 导出 COMTRADE 格式波形数据，导入专业分析软件（如 ETAP、DIgSILENT）
- 分析多通道同步录波数据，判断故障类型和相别

### 2.3 调度人员

**职责**：负责调度主站侧对 MUPC 设备的监控和管理。

**使用场景**：
- 接收 MUPC 上报的故障事件和录波文件
- 在主站系统上查看故障波形概览
- 远程调取指定故障事件的录波数据

## 3. 核心功能列表

### 3.1 故障触发条件配置

#### 3.1.1 用户故事

**运维人员**需要在设备投运前或运行中，根据台区电气特性配置故障录波的触发条件，避免误触发或漏触发。

#### 3.1.2 功能描述

支持以下触发条件的独立配置，每个条件包含启用开关、阈值和回差（滞回区间）。

| 触发条件 | 参数 | 默认值 | 单位 | 说明 |
|----------|------|--------|------|------|
| 过压触发 | 电压越上限阈值 | 420.0 | V | 相电压有效值超过阈值触发 |
| 过压触发 | 回差 | 10.0 | V | 电压回落到 阈值-回差 以下才解除触发 |
| 欠压触发 | 电压越下限阈值 | 200.0 | V | 相电压有效值低于阈值触发 |
| 欠压触发 | 回差 | 10.0 | V | 电压回升到 阈值+回差 以上才解除触发 |
| 过流触发 | 电流越上限阈值 | 150.0 | A | 相电流有效值超过阈值触发 |
| 过流触发 | 回差 | 5.0 | A | 电流回落到 阈值-回差 以下才解除触发 |
| 短路触发 | 电流突变量阈值 | 500.0 | A | 电流瞬时值超过阈值触发（不判有效值） |
| 频率越限触发 | 频率上限 | 50.5 | Hz | 频率超过上限触发 |
| 频率越限触发 | 频率下限 | 49.5 | Hz | 频率低于下限触发 |
| 频率越限触发 | 回差 | 0.1 | Hz | 频率回到范围内才解除触发 |
| 零序过流触发 | 零序电流阈值 | 20.0 | A | 零序电流超过阈值触发（接地检测） |

#### 3.1.3 验收标准

| ID | 验收条件 | 验证方法 |
|----|----------|----------|
| TRG-01 | 所有 6 种触发条件可独立启用/禁用 | 单元测试：逐个设置启用/禁用状态，确认触发逻辑生效/失效 |
| TRG-02 | 所有阈值参数可配置，配置即时生效 | 单元测试：修改阈值后，输入低于新阈值的信号不应触发，输入高于新阈值的信号应触发 |
| TRG-03 | 回差机制正确：触发后需信号回到 阈值±回差 范围内才解除 | 单元测试：设置回差后，触发信号短暂回落到阈值和阈值±回差之间，确认不解除触发 |
| TRG-04 | 多个触发条件同时满足时，每个故障事件记录所有触发条件 | 集成测试：输入同时触发过压和过频的信号，故障记录中两个条件均有标记 |

### 3.2 故障前后波形采样

#### 3.2.1 用户故事

**故障分析工程师**需要获取故障时刻前后完整的波形数据，以分析故障的演变过程。

#### 3.2.2 功能描述

故障触发时，录制触发点前后特定时间窗口内的高频采样数据。

**采样参数配置**：

| 参数 | 取值范围 | 默认值 | 说明 |
|------|----------|--------|------|
| 采样率 | 1kHz, 2kHz, 4kHz, 8kHz, 16kHz | 4kHz | 每通道每秒采样点数 |
| 故障前记录时长 | 40ms ~ 1000ms | 200ms | 触发时刻之前的采样记录长度 |
| 故障后记录时长 | 40ms ~ 5000ms | 1000ms | 触发时刻之后的采样记录长度 |
| 总记录时长 | 故障前 + 故障后 | 1200ms | 一次录波的总时长 |

**采样通道**：

| 通道组 | 通道数 | 内容 |
|--------|--------|------|
| 三相电压 | 3 | Ua, Ub, Uc 瞬时值 (V) |
| 三相电流 | 3 | Ia, Ib, Ic 瞬时值 (A) |
| 零序电压 | 1 | U0 瞬时值 (V) |
| 零序电流 | 1 | I0 瞬时值 (A) |
| 有功功率 | 1 | P 瞬时值 (kW) |
| 无功功率 | 1 | Q 瞬时值 (kVar) |
| 频率 | 1 | f 瞬时值 (Hz) |

**可配置通道选择**：用户可选择启用/禁用一个或多个通道组，节省存储空间。

**循环录波缓冲**：
- 设备启动后持续将高频采样数据写入环形缓冲区
- 缓冲区长度 = 故障前记录时长对应的采样点数（如 4kHz × 200ms = 800 点）
- 故障触发时，将缓冲区数据 + 持续写入的故障后数据打包为一次完整的波形记录

**双缓冲区机制**：
- 一次录波完成后立即切换到第二个缓冲区，保证连续故障不丢失波形数据
- 第一个缓冲区的数据在保存完成前不被覆盖

#### 3.2.3 验收标准

| ID | 验收条件 | 验证方法 |
|----|----------|----------|
| SMP-01 | 采样率可在 1kHz ~ 16kHz 范围内按指定档位配置 | 单元测试：设置不同采样率，确认采集的波形数据点间隔符合设定值 |
| SMP-02 | 故障前记录时长可在 40ms ~ 1000ms 范围内配置 | 单元测试：设置故障前时长，触发后确认缓冲区数据点数 = 采样率 × 时长 |
| SMP-03 | 故障后记录时长可在 40ms ~ 5000ms 范围内配置 | 单元测试：设置故障后时长，触发后确认录波数据总点数 = 采样率 × (前+后时长) |
| SMP-04 | 所有 10 个通道的数据同步录波 | 集成测试：输入已知波形信号，触发后确认 10 个通道各有完整数据 |
| SMP-05 | 环形缓冲区在稳态时不间断更新，不阻塞采数流程 | 集成测试：连续运行 24 小时，录波触发时数据完整无缺口 |
| SMP-06 | 双缓冲区机制在连续触发故障时，两次录波数据均完整保存 | 集成测试：在 500ms 内连续触发两次故障，确认两次录波数据均正确 |
| SMP-07 | 录波启动延迟 ≤ 1 个采样周期 | 单元测试：从故障条件满足到第一个采样点写入波形记录的时间差 ≤ 1/采样率 |

### 3.3 波形数据存储

#### 3.3.1 用户故事

**运维人员**需要确保波形数据可靠存储于本地，并在设备长期运行中自动管理存储空间。

#### 3.3.2 功能描述

**存储结构**：

波形数据与故障事件元数据分开存储：

| 存储类型 | 存储内容 | 存储引擎 | 说明 |
|----------|----------|----------|------|
| 元数据 | 故障事件记录（类型、时间、触发条件值） | SQLite | 已有 Phase 3A 实现，需扩展字段 |
| 波形数据 | 二进制格式的采样数据 | 文件系统 | 新增，按故障事件 ID 命名文件 |

**SQLite 扩展字段**（在现有 `fault_records` 表基础上增加）：

| 字段 | 类型 | 说明 |
|------|------|------|
| waveform_path | TEXT | 波形数据文件的路径（相对路径，相对于录波数据目录） |
| sample_rate | INTEGER | 本次录波的采样率（Hz） |
| pre_trigger_ms | INTEGER | 故障前记录时长（ms） |
| post_trigger_ms | INTEGER | 故障后记录时长（ms） |
| channel_mask | INTEGER | 录波通道的位掩码，标识启用的通道 |
| waveform_size | INTEGER | 波形数据文件大小（字节） |

**波形文件格式**（二进制紧凑格式）：

```
┌──────────────────────────────┐
│  Header (64 bytes)           │
├──────────────────────────────┤
│  Channel 0 samples (N × f64) │
│  Channel 1 samples (N × f64) │
│  ...                         │
│  Channel M samples (N × f64) │
├──────────────────────────────┤
│  Footer (8 bytes): checksum  │
└──────────────────────────────┘
```

Header 格式：

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0 | 4B | magic | 魔数 `WAVE` (0x57415645) |
| 4 | 2B | version | 文件格式版本号 (v1 = 0x0001) |
| 6 | 2B | channel_count | 录波通道数 (≤10) |
| 8 | 8B | sample_count | 每通道样本数 |
| 16 | 8B | sample_rate | 采样率 (Hz) |
| 24 | 8B | trigger_timestamp | 触发时刻的 unix 时间戳 (ms) |
| 32 | 8B | trigger_offset | 触发点在样本序列中的偏移量（第几个样本） |
| 40 | 8B | pre_trigger_nsamples | 故障前样本数 |
| 48 | 8B | post_trigger_nsamples | 故障后样本数 |
| 56 | 4B | channel_mask | 通道启用位掩码 |
| 60 | 4B | reserved | 保留 |

**数据目录布局**：

```
/data/mupc/waveforms/
├── index/                    # SQLite 数据库文件（已有 fault_records 表）
│   └── fault_records.db
└── recordings/               # 波形数据文件
    ├── 2026/
    │   ├── 05/
    │   │   ├── 20260529_143022_001.wave    # 文件名格式: YYYYMMDD_HHMMSS_seq.wave
    │   │   └── 20260529_143022_002.wave
    │   └── ...
    └── ...
```

#### 3.3.3 存储容量管理

**循环覆盖策略**：

| 策略参数 | 默认值 | 说明 |
|----------|--------|------|
| 单次录波存储上限 | 10 MB | 单个波形文件大小上限。超过上限时截断（从触发点向前后各保留同等比例样本） |
| 总存储空间上限 | 2 GB | 波形数据目录占用磁盘空间上限 |
| 保留期限 | 30 天 | 超过此期限的波形文件可被自动删除 |
| 空余空间阈值 | 500 MB | 磁盘空余空间低于此值时，优先删除最旧的波形文件（无视保留期限） |
| 单日录波次数上限 | 1000 次 | 每自然日录波次数超过此值时停止录波，恢复后第二天自动解除 |

**覆盖执行顺序**：
1. 先删除超过 30 天保留期限的波形文件
2. 若仍超出总存储空间上限，继续删除最旧的波形文件（无论是否过期）
3. 若磁盘空余空间仍低于 500MB，继续删除最旧波形文件
4. 每次覆盖操作删除的波形文件同时删除对应的故障事件记录中的 `waveform_path` 引用

#### 3.3.4 验收标准

| ID | 验收条件 | 验证方法 |
|----|----------|----------|
| STO-01 | 故障事件元数据写入 SQLite，波形数据写入文件系统 | 集成测试：触发故障后确认 SQLite 有记录且文件存在 |
| STO-02 | 波形文件格式符合上述二进制格式定义 | 单元测试：读取写入的波形文件，解析 header 各字段与写入值一致 |
| STO-03 | 波形文件校验和验证：读取时校验 footer checksum | 单元测试：手动修改波形文件一个字节，读取时报告校验失败 |
| STO-04 | 单次录波超过 10MB 时自动截断 | 集成测试：配置长时间录波（5000ms + 16kHz），确认文件 ≤ 10MB |
| STO-05 | 超过保留期限（30天）的波形文件被自动清理 | 集成测试：创建过期的录波文件，触发清理后确认被删除 |
| STO-06 | 磁盘空余空间低于 500MB 时触发紧急清理 | 集成测试：模拟低磁盘空间，确认不再新建录波文件并清理旧文件 |
| STO-07 | 单日录波达到 1000 次后停止录波，次日恢复 | 集成测试：触发 1001 次录波，确认第 1001 次不生成波形文件但记录告警日志 |

### 3.4 波形数据查询与回放

#### 3.4.1 用户故事

**故障分析工程师**需要在设备本地或远程查询指定时间范围或故障类型的事件列表，并回放对应的波形数据。

#### 3.4.2 功能描述

**查询维度**：

| 查询维度 | 查询参数 | 说明 |
|----------|----------|------|
| 时间范围 | 起始时间、结束时间 | 支持按触发时间范围查询 |
| 故障类型 | fault_type | 过滤指定故障类型的事件 |
| 故障ID | id | 精确查询单条故障事件 |
| 分页 | page, page_size | 分页返回，默认每页 20 条，最大 100 条 |

**波形回放 API**：

```rust
/// 查询故障事件列表
async fn query_events(filter: &FaultEventFilter) -> Result<PaginatedEvents, FaultRecorderError>;

/// 获取指定故障事件的波形数据（加载波形文件到内存）
async fn get_waveform(event_id: i64) -> Result<WaveformData, FaultRecorderError>;

/// 获取波形数据的概要信息（触发点前后统计量）
async fn get_waveform_summary(event_id: i64) -> Result<WaveformSummary, FaultRecorderError>;
```

**波形概要信息**：

```rust
pub struct WaveformSummary {
    pub event_id: i64,
    pub pre_trigger_stats: ChannelStats,    // 故障前各通道统计
    pub post_trigger_stats: ChannelStats,   // 故障后各通道统计
    pub trigger_point: TriggerInfo,         // 触发点信息
}

pub struct ChannelStats {
    pub channel_name: String,               // 通道名称
    pub max: f64,                           // 最大值
    pub min: f64,                           // 最小值
    pub avg: f64,                           // 平均值
    pub rms: f64,                           // 有效值
    pub thd: Option<f64>,                   // 谐波畸变率（电压通道特有）
}
```

#### 3.4.3 验收标准

| ID | 验收条件 | 验证方法 |
|----|----------|----------|
| QRY-01 | 按时间范围查询，返回该时间窗口内的所有故障事件 | 单元测试：创建 3 个时间不同的事件，按时间窗口查询返回正确的子集 |
| QRY-02 | 按故障类型过滤，返回匹配类型的事件 | 单元测试：创建不同类型事件，按类型过滤返回正确子集 |
| QRY-03 | 分页查询正确，页码和页大小参数生效 | 单元测试：创建 50 条记录，page_size=20 查询第 1 页返回 20 条，第 2 页返回 20 条，第 3 页返回 10 条 |
| QRY-04 | 按事件 ID 精确查询返回单条事件及其波形文件路径 | 单元测试：查询存在的 ID 返回正确数据，查询不存在的 ID 返回空 |
| QRY-05 | 波形数据加载：从文件加载完整的 WaveformData 结构 | 集成测试：触发录波后调用 get_waveform()，返回的数据与原始采样数据一致 |
| QRY-06 | 波形概要统计：触发点前后的最大值、最小值、平均值、有效值计算正确 | 单元测试：输入已知正弦波数据，校验统计值与理论值误差＜1% |

### 3.5 波形数据导出

#### 3.5.1 用户故事

**故障分析工程师**需要将波形数据导出为标准格式（COMTRADE 或 CSV），以导入专业电力分析软件进行深入分析。

#### 3.5.2 功能描述

**导出格式支持**：

| 格式 | 版本/规范 | 说明 |
|------|-----------|------|
| COMTRADE | IEEE Std C37.111-1999 | 电力系统瞬态数据交换通用格式，支持 .cfg + .dat 文件对 |
| CSV | UTF-8 with BOM | 通用表格格式，首行为通道名称，每行一个采样点 |

**COMTRADE 格式说明**：

导出为 3 个文件：

| 文件 | 扩展名 | 内容 |
|------|--------|------|
| 配置文件 | .cfg | 通道定义、采样率、变电站信息、时间戳 |

### 3.6 波形数据北向上报

#### 3.6.1 用户故事

#### 3.6.2 功能描述

### 3.7 多通道同步录波

#### 3.7.1 用户故事

**故障分析工程师**需要同时观察电压、电流、功率等多个电气量在同一时间点的波形，以判断故障类型和相别。

#### 3.7.2 功能描述

- 所有采样通道使用同一个采样时钟，确保各通道数据在时间上严格对齐
- 单次录波的数据结构中，所有通道的采样点数量相同（均为 `sample_count`）
- 第 i 个采样时刻的数据在内存中表示为 `[ch0[i], ch1[i], ..., chN[i]]`

**通道间同步要求**：

| 要求 | 指标 |
|------|------|
| 通道间时延 | ≤ 1 个采样周期（如 4kHz 下 ≤ 250μs） |
| 时间戳标定 | 每个采样点的时间戳精度 ≤ 100μs |
| 各通道采样点数 | 严格相等，偏差 = 0 |

**周期性同步校验**：
- 每秒执行一次通道同步性校验
- 校验方法：向所有通道注入同一已知信号（如 50Hz 正弦波），确认各通道数据的相位差 ≤ 1°

#### 3.7.3 验收标准

| ID | 验收条件 | 验证方法 |
|----|----------|----------|
| CHN-01 | 所有通道的采样点数严格相同 | 单元测试：触发录波后，检查 WaveformData 中各 channel 的 Vec 长度一致 |
| CHN-02 | 通道间相位差 ≤ 1°（在 50Hz 信号下） | 集成测试：输入相同的 50Hz 正弦波到所有通道，计算各通道间相位差 |
| CHN-03 | 可选择启用/禁用一个或多个通道组 | 单元测试：设置 channel_mask 只包含三相电压，确认波形数据只包含 3 个通道 |
| CHN-04 | 通道间时延 ≤ 1 个采样周期 | 单元测试：同一时刻采集所有通道的值，记录时间戳偏差 |

### 3.8 故障事件与波形关联

#### 3.8.1 用户故事

**运维人员**查看故障列表时，应能直观地看到每个事件是否关联了波形数据，并能一键跳转到波形详情。

#### 3.8.2 功能描述

- 故障事件记录（SQLite）与波形文件通过 `event_id` 关联
- 波形文件 header 中存储对应的 `event_id`
- 双向关联：通过事件 ID 找波形文件，通过波形文件头反查事件元数据
- 事件列表中增加 `has_waveform` 字段，标识是否存在关联的波形数据文件
- 波形数据文件被覆盖删除后，对应的事件的 `has_waveform` 更新为 false，但事件元数据保留

**关联数据结构**：

```rust
pub struct FaultEventWithWaveform {
    pub event: FaultRecord,
    pub has_waveform: bool,             // 是否有波形数据文件
    pub waveform_info: Option<WaveformFileInfo>,  // 波形文件信息
}

pub struct WaveformFileInfo {
    pub file_path: String,              // 波形文件路径
    pub file_size: u64,                 // 文件大小
    pub sample_rate: u64,               // 采样率
    pub channel_count: u32,             // 通道数
    pub record_duration_ms: u64,        // 记录时长
}
```

#### 3.8.2 验收标准

| ID | 验收条件 | 验证方法 |
|----|----------|----------|
| ASO-01 | 触发录波后，故障事件记录与波形文件通过 event_id 双向关联 | 集成测试：从事件查询波形文件存在于预期路径，从波形文件 header 读取 event_id 匹配 |
| ASO-02 | 事件列表中 `has_waveform` 字段与波形文件存在状态一致 | 集成测试：创建事件后确认 has_waveform=true，删除波形文件后确认 has_waveform=false |
| ASO-03 | 波形文件被覆盖删除后，事件元数据保留不变 | 集成测试：删除波形文件后查询事件，确认元数据完整 |

## 4. 非功能性需求

### 4.1 采样精度

| 指标 | 要求 | 说明 |
|------|------|------|
| 采样值分辨率 | ≥ 16 bit | ADC 采样位深 |
| 采样值精度 | ±0.5% of reading | 采样值与真实值的偏差 |
| 时间戳精度 | ±100μs | 每个采样点的时间戳误差 |
| 通道间同步 | ±1 个采样周期 | 所有通道采样时刻偏差 |

### 4.2 存储容量

| 指标 | 值 | 计算依据 |
|------|----|----------|
| 单次录波典型大小 | ~640KB | 10 通道 × 4800 采样点 × 8 字节 (f64) + 64B header |
| 总存储空间上限 | 2 GB | 支持约 3200 次录波 |
| 每日典型录波次数 | ≤ 50 次（典型电网） | 在 2GB 上限下可存储约 64 天 |
| 存储上限覆盖周期 | 7 ~ 64 天（取决于故障频率） | 超过上限时按 3.3.3 节策略循环覆盖 |

### 4.3 录波启动延迟

| 指标 | 要求 |
|------|------|
| 触发检测延迟 | ≤ 1ms（从信号变化到触发条件判定完成） |
| 录波启动延迟 | ≤ 1 个采样周期（从触发判定完成到开始记录） |
| 录波完成延迟 | 故障后记录时长 + 文件写入时间 ≤ 5 秒 |

### 4.4 系统资源占用

| 资源 | 占用上限 | 说明 |
|------|----------|------|
| CPU | 录波期间峰值 ≤ 15% (RK3588 @1.8GHz) | 文件写入时的峰值占用 |
| 内存 | 稳态：≤ 2MB，录波期间峰值：≤ 10MB | 环形缓冲区 + 录波工作缓冲区 |
| 磁盘 I/O | 单次录波写入 ≤ 100ms | 文件写入不阻塞采样流程 |

### 4.5 时间同步

| 指标 | 要求 |
|------|------|
| 时间源 | NTP 或 PTP | 与调度主站时间同步 |
| 时间精度 | 与主站偏差 ≤ 1ms | 确保录波时间戳与调度主站一致 |
| 未同步时 | 使用系统本地时间，标记 `time_quality=unsynchronized` | 告警记录中体现时间可信度 |

## 5. 边界条件与异常处理

### 5.1 存储空间不足

| 场景 | 行为 | 告警级别 |
|------|------|----------|
| 磁盘空余空间 < 500MB | 删除最旧的波形文件直到空余空间 > 500MB，停止新录波 | 重要告警 |
| 磁盘空余空间 < 200MB | 紧急停止所有录波功能，保留核心功能运行 | 紧急告警 |
| 单次录波写入失败 | 将波形数据保留在内存缓冲区，30 秒后重试，重试 3 次放弃 | 告警 |
| 元数据写入失败（SQLite） | 当前录波整体失败，记录日志，不影响下一次录波 | 告警 |

### 5.2 多故障并发

| 场景 | 行为 |
|------|------|
| 录波进行中（故障后时段）发生第二个故障 | 不中断当前录波，在第二个缓冲区启动第二次录波 |
| 两个缓冲器均满时发生第三个故障 | 丢弃当前录波中最旧的一次，释放一个缓冲区用于新的录波 |
| 同一秒内触发多次同类型故障 | 合并为一次故障事件，记录首次触发时间，后续触发更新事件状态 |
| 不同类型的故障在 100ms 内先后发生 | 作为独立事件分别录波，共享故障前重叠时段的波形数据 |

### 5.3 采样数据丢失

| 场景 | 行为 |
|------|------|
| 单个采样点丢失 | 数据文件中用 `NaN` 填充缺失位置，在波形文件中标记 `data_quality=gap_detected` |
| 连续 10 个以上采样点丢失 | 中断当前录波，已录数据保留，标记 `data_quality=major_gap` |
| 所有通道同时数据丢失 | 可能为 intercore 通信中断，停止录波，发起通信重连 |
| 单个通道数据丢失 | 其他通道继续录波，缺失通道用 `NaN` 填充 |

### 5.4 触发抖动

| 场景 | 行为 |
|------|------|
| 触发条件在临界值附近震荡 | 使用 3.1.2 节的回差机制防止反复触发 |
| 同一故障条件在 1 秒内反复满足/解除 | 合并为一次故障事件，记录首次触发和最终解除时间 |
| 瞬态尖峰（< 1ms）误触发 | 触发条件判定引入 3 个连续采样点的确认窗口（防抖滤波） |

### 5.5 配置异常

| 场景 | 行为 |
|------|------|
| 故障前记录时长 > 故障后记录时长 3 倍 | 拒绝配置，返回配置错误 |
| 采样率设置为不支持的值 | 四舍五入到最近的可用档位，记录日志提示 |
| 所有通道均禁用 | 拒绝配置，要求至少启用一个通道组 |
| 总记录时长 < 80ms | 拒绝配置（至少 40ms 前 + 40ms 后） |

| 环形缓冲区 | 固定大小的内存缓冲区，新数据覆盖旧数据 |
| COMTRADE | IEEE 标准 C37.111 定义的电力系统瞬态数据交换格式 |
| 通道同步 | 多通道数据在时间上严格对齐 |
