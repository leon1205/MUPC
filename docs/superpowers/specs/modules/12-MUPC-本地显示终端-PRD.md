## 1. 产品概述

### 1.1 背景（Why）

MUPC 设备为台区储能治理装置的非实时处理核心，长期 **headless 部署**（无本地面板）。现场运维/调试人员在设备柜前只能通过远端（web-api / 上位机）查看状态，就地缺乏可视化手段，故障排查、充放确认必须依赖外部工具，效率低且存在「现场无网 / 远端不可达时黑盒」的空窗。

平台目标调整已落地：AI 引擎停用，本地策略引擎 TaiStorage 为唯一默认下发源（经核间 modbus 向 PCS 下发分相 P/Q）；SOC 由 BMS 站与核间读 PCS（REG 1010）双源裁决。设备经 HDMI 外接一块 8 寸屏（1024x768）即可在柜面就地呈现上述关键运行状态。

### 1.2 产品价值

- **就地可视**：在设备现场直接读屏，无需笔记本 / 远端即可确认储能 SOC、PCS 充放状态与三相功率/电流。
- **降低误判**：以实时 PCS 状态（模块运行状态寄存器 + SOC 裁决值）为判据，避免「看功率猜充放」的主观误判。
- **可靠性兜底展示**：数据不可得时**明示不可得（不造假值）**，避免把「离线/未取数」误读为「真 0 功率」。

### 1.3 目标平台与形态（由 PM 已裁定，作为本 PRD 边界）

- **技术形态**：**独立原生渲染进程**——新显示的独立进程，帧缓冲/轻量图形栈，**不依赖任何浏览器内核**。
- **不得直连核间 modbus 总线**：显示数据由 mupcd（主进程运行时）经**跨进程数据通道**供给。通道具体形态（IPC 类型 / 协议 / 生命周期）属**设计合同阶段**裁决，本 PRD 只约束其非功能边界（新鲜度、断连、可靠性）。
- 数据只在 mupcd 内「读点表 → 域值化/裁决 → 推送」，渲染进程只做**展示与降级**，不做取数、不做策略、不写控制。
- 显示进程**只读**：任何情况下不向 PCS / 核间 / mupcd 下发指令。

## 3. 核心功能列表

> 每个功能给出「用户故事 + 可量化验收标准」。验收标准按平台现状给定阈值，若评审调整须回写本文件（禁止另建独立文件）。

### F1 储能 SOC 展示

**用户故事**：作为现场运维，我在柜前扫一眼屏，就能看到当前电池 SOC 数值与其健康区间，判断是否接近上下限，无需连远端。

**数据来源（本 PRD 约束）**：展示值为 **mupcd 运行时 SOC 双源裁决后的域值**（BMS 站 SOC 与核间读 PCS REG 1010 经 `resolve_soc_source` 裁决后的输出），而非某一原始源。本 PRD 不定义裁决算法（属既有平台逻辑），仅要求「展示裁决值 + 展示所用源」。

**验收标准（可量化）**：
1. 屏上常显 SOC 数值，单位 %，精度整数位即可，量程显示 0–100%。
2. SOC 旁以可视手段标注当前**数据源**：`BMS` / `PCS(REG1010)` / `双源一致`，源信息随展示值同帧更新。
3. 数值区间着色提示：`≤15%（下限邻近）` 与 `≥85%（上限邻近）` 使用警示色块/边框（阈值对齐平台安全配置 soc_min/soc_max，默认 0.10/0.90，可由评审确认是否放宽至 15%/85%）。
4. SOC 源全部失效时（双源皆失，见 §6.2），按 §6 降级规则显示，**禁止补 0 或沿用陈旧值冒充实时值**（可冻结并打「源失效」标，见 §6.2）。

---

### F2 PCS 运行状态（充 / 放 / 停机 / 待机）展示

**用户故事**：作为现场运维，我要在屏上直接读出 PCS「此刻是在充还是在放」，且该结论应来自设备状态机而非我肉眼猜功率正负。

**数据来源 / 判定依据（本 PRD 约束）**：以 PCS **模块运行状态**寄存器（REG 1013，UInt16）定义为准：`0=停机、1=待机、2=充电、3=放电`。充放语义判定以该状态机**为主判据**；SOC 裁决值与三相有功功率**仅作一致性佐证**（异常时提示，不覆盖主判据）。

**验收标准（可量化）**：
1. 屏上至少一屏内显式给出四态之一：**停机 / 待机 / 充电 / 放电**，文字 + 语义色（充=绿、放=橙/蓝、停机=灰、待机=黄，色板可由设计微调但必须四态可区分）。
2. 判据为 REG 1013 值；当 1013 读失败（PCS 离线）时进入降级（§6.1），**不得**由功率正负反推充放（因读回功率极性语义待追认，见 §8 / 数据源字段表）。
3. 佐证一致性：当 1013=2（充电）而三相有功和（Σ1029-1031）显著为负、或 1013=3（放电）而 Σ 显著为正（反向显著 = 超过量程 5% 阈值，见 §6 表）时，屏上显示「状态与功率方向不一致」提示角标，供调试定位；**主状态仍以 1013 为准**。

---

### F3 三相有功功率展示（A/B/C）

**用户故事**：作为调试工程师，我要在屏上看到 PCS 交流输出 A/B/C 三相各有功功率（kW），确认下发分相 P 目标与实读一致。

**数据来源**：PCS 3 区只读表 **输出有功功率 A/B/C 相**：REG 1029/1030/1031（Int16，量纲 `*0.1 kW`，即读值 × 0.1 = kW）；可加显 **设备总有功** REG 1032（Int16，`*0.1 kW`）。

**验收标准（可量化）**：
1. 三相互相 + 总计常显，单位 kW，显示保留 1 位小数；显示值 = 寄存器读值 × 0.1（由 mupcd 完成，渲染端不重算量纲）。
2. 刷新跟随 F5 帧节奏（帧到即更新，≤500 ms 生效）。
3. 每相数值按**当前充放语义**（来自 F2 主判据 REG 1013）着色区分方向性呈现；是否直接以「功率负号=充电」展示，**依赖厂方点表追认**（见 §8、数据源字段表符号缺口）——在追认前，方向标签一律取自 F2 状态机，**不**以功率符号自判（避免方向反置造假）。
4. 读失败 / 未取数：该相显示 `--` 并附「源离线/未取数」标，**禁止显 0.0**（防被误读为真实 0 功率）。

> **依赖点表追认声明**：F3 数值（绝对值）展示不阻塞；唯「用三相功率正负号直接表达充/放」这一呈现方式依赖「读回测量值极性与设定侧一致（正=放/负=充）」的厂方追认，追认前一律以 F2 状态机标注方向。

---

### F4 三相电流展示（A/B/C）

**用户故事**：作为现场运维，我要在屏上看到 PCS 交流输出 A/B/C 三相电流（A），配合功率确认设备出力。

**数据来源**：PCS 3 区只读表 **输出电流 A/B/C 相**：REG 1022/1023/1024（Int16，量纲 `*0.1 A`，读值 × 0.1 = A）。

**验收标准（可量化）**：
1. 三相电流常显，单位 A，保留 1 位小数；显示值 = 寄存器读值 × 0.1。
2. 刷新跟随 F5 帧节奏（帧到即更新，≤500 ms 生效）。
3. 读失败 / 未取数：该相显示 `--` + 「源离线/未取数」标，**禁止显 0.0**。
4. 方向性标注策略同 F3：追认前以 F2 状态机标注充/放方向，不依赖电流符号自判。

> **依赖点表追认声明**：同 F3，绝对值展示不阻塞；符号极性用途依赖厂方追认。

---

### F5 数据刷新与新鲜度策略

**用户故事**：作为运维，我希望屏上数字是「够新」的，并且当数据不新鲜 / 掉线时屏上会**明确告诉我**，而不是默默停更让我误以为现场稳定。

**验收标准（可量化）**：
1. mupcd 数据推送周期（帧率）≥ **1 Hz**（帧间隔标称 1 s，可容抖 ±30%）。
2. 渲染端收到新帧到屏上更新生效 ≤ **500 ms**（不含帧率本身）；数值变动即时反映，无闪屏/残影（见 §4 刷新 NFR）。
3. 数据新鲜度判定：以帧内时间戳计，**当前时间 − 帧时间戳 > 2 s** 即判「过期」；过期后渲染端对该字段显示「数据过期」角标，**保留最近有效帧数值但不冒充实时**。
4. 每帧携带**时间戳**与**每个字段的有效标志（valid/invalid）**，由 mupcd 在域值化后打标；渲染端仅按标志展示或降级。
5. 各字段独立降级：单点读失败不影响其余字段刷新（点级 valid 标志）。

## 4. 非功能性需求

### 4.1 刷新与渲染性能（对渲染进程的约束）

1. 屏面整体视觉刷新 ≥ 1 Hz；单帧渲染提交耗时均值 ≤ **30 ms**（@1024x768），避免数值区闪烁/撕裂。
2. 渲染进程 **CPU 预算 ≤ 15% 单核均值（1 s 窗口）**；**常驻内存 ≤ 64 MB**。此为边界上限，若设计所选轻量栈实测更优可下调；若某栈超限，设计合同阶段须另行说明并获评审同意（不得静默放水）。
3. 渲染进程内不得有忙等/自旋等待数据通道；空闲帧间隙应让出 CPU（阻塞读或事件驱动），满载（通道断）时 CPU 亦须 ≤ 5% 单核均值。

### 4.2 布局与可读性（1024x768）

1. 全部核心字段（SOC、运行状态、A/B/C 三相功率、A/B/C 三相电流）在 **1024×768 单屏一屏放下**，无滚动、无分页、无隐藏到交互层。
2. 关键数值采用大字号；**状态语义用「文字 + 语义色 + 图标」三重冗余**表达，不依赖颜色单一信道（满足可读性/色弱）。
3. 布局固定分区，字段位置稳定不跳变（值变化不改布局，仅数值变化），便于现场记忆「哪块看什么」。
4. 屏幕长期静态显示同一内容时避免烧屏：允许对静态装饰做低影响处理（如整体周期微移或反色节拍），但核心数值区不得因防烧屏而抖动可读性。

### 4.3 进程稳定性与崩溃自恢复

1. 渲染进程**异常退出后 ≤ 3 s 自动重启**并恢复显示（由 mupcd/系统看门狗拉起；具体拉起归属在系统集成侧）。
2. 渲染进程崩溃/重启**不得影响 mupcd 主进程、策略引擎、核间/南向通信**（进程隔离）。
3. mupcd 主进程异常重启时，数据通道断开，渲染端进入 §6.3 通道断开态；mupcd 恢复并重建通道后，渲染端 **≤ 1 s** 回到实时显示。
4. 上电启动顺序：显示进程先于/并行于数据通道就绪时可显示「初始化中」占位画面；数据通道就绪后 ≤ 1 s 内切到实时画面。显示进程不得阻塞 mupcd 启动关键路径。

### 4.4 跨进程数据通道可靠性边界（通道形态留给设计）

本 PRD 不裁定通道具体技术形态，但要求其对上层表现满足：
1. 数据投递语义：允许丢帧，但**不允许**静默传输损坏数值（须有校验/序列号/版本一致性手段，或丢帧重传最新帧）。
2. 断连检测：渲染端须在通道中断 ≤ **3 s** 内感知并进入 §6.3 降级画面；恢复 ≤ 1 s 回实时。
3. 渲染端不得因通道对端（mupcd）行为异常而崩溃或内存失控（对不可信/畸形帧须有防护，畸形帧丢弃并告警计数）。
4. 通道只承载「读展示」数据与心跳/健康信息，**禁止**承载任何下行写指令通道。

## 5. 边界与异常（不造假值原则）

> 总原则：**源不可得 → 显式「不可得」**；可展示冻结帧但必须打标，**任何情况下不得用 0 / 陈旧值 / 臆测值冒充实时真值**。

| # | 异常场景 | 展示行为（渲染端） | 数据侧职责（mupcd） |
|---|---------|---------------------|----------------------|
| 6.1 | PCS 离线（核间 modbus 读失败，REG 1013/SOC 源失效） | F2 状态显示「PCS 离线」；F3/F4 各相显示 `--`+「源离线」；F1 若有另一源则显示另一源值并标注，双源皆失见 6.2 | 帧中对应字段 valid=false；整体标「PCS 离线」 |
| 6.2 | SOC 双源皆失（BMS 站 + PCS REG1010 均无效） | SOC 区显 `--`+「SOC 源失效」警示色；**不补 0、不沿用旧值** | valid=false，不下发疑似值 |
| 6.3 | 跨进程数据通道断（mupcd 侧 / IPC 侧异常） | ≤3 s 内切换「与主进程数据通道断开」画面；可保留最近有效帧并打「冻结/过期」标；通道恢复 ≤1 s 回实时 | 通道健康状态随连接生命周期维护 |
| 6.4 | 点表未覆盖 / mupcd 尚未实现某点读取（如 1022-1024/1029-1031 未接入采集） | 该字段显 `--`+「未取数」；不显示 0 | 该字段 valid=false，注释原因 |
| 6.5 | 字段数值域异常（读值越界/非有限，如功率读值超物理量程） | 显 `--`+「数据异常」；不做插值 | 域值化时做量程/有限性校验，异常置 invalid |
| 6.6 | 1013 状态与功率方向显著相反（佐证不一致） | 主状态以 1013 展示，另加「方向不一致」角标（F2 验收 3） | 在 mupcd 侧聚合比对后随帧给一致性标志 |
| 6.7 | 渲染进程自身异常/启动失败 | 黑屏或「显示进程异常」占位；由拉起机制 ≤3 s 重启 | 不阻塞主进程 |

**量程/语义越界阈值口径**（供 §6.5 与 F2 佐证）：以「读值 × 量纲」后偏离物理合理区（如单相有功 / 电流绝对值超出该机型额定区显著比例，或 1013 状态枚举外值）判定；具体阈值在数据源字段表符号缺口追认时一并由厂方/设计确认，评审前采用「读值非有限或越 Int16 工程界」即判异常。

## 6. 范围外（本期不做）

1. **交互操作**：触摸/按键输入、翻页、菜单、设置——渲染进程为**只读展示**。
2. **历史趋势/曲线**：功率/SOC 历史曲线、录波、统计不在本期。
3. **告警/事件屏**：独立告警列表屏、声光告警不在本期（1014/1015 故障/降额可作状态旁辅助角标，但不做告警屏）。
4. **远程/网络访问**：屏面 Web 化、投屏、截图上传不在本期。
5. **向 PCS 下发 / 控制**：渲染端与数据通道均不承载下行写。
6. 与本屏无关的 DCDC/光伏/负载（STS 侧）专屏数据不在本期展示（见 §8 说明，避免误用 STS 负载区当 PCS 输出）。

## 8. 可行性结论段（供设计/开发判断）

**真源可得性结论：F3/F4 三相功率与电流为「真源可得」**。

- PCS 3 区只读表（FC04）明确给出 **输出有功功率 A/B/C 相 = REG 1029/1030/1031（Int16，×0.1 = kW）**、**设备总有功 = REG 1032**、**输出电流 A/B/C 相 = REG 1022/1023/1024（Int16，×0.1 = A）**。
- 该区与**现有已工作的 SOC=1010、运行状态=1013 同属一个只读点表/同一 FC04 读通道**，mupcd 仅需在同一核间 modbus 事务上扩展读取连续区间（1022–1032 一带）即可获得全部展示真源，**无新增协议/新设备**。
- 因此 F1/F2/F3/F4 的「真实数值展示」均可落地，不阻塞。

**唯一符号语义缺口（影响面：仅「用功率/电流正负号直接表达充放方向」这种呈现，不影响数值绝对值展示）**：
- 文档设定侧（4 区写表 + 文末功能说明）明示 **交流分相/恒功率/恒流模式：设为正则放电，设为负则充电**；但 **3 区只读区 1022–1024/1029–1032 的定义列只给量纲（Int16 可负），未以文字明示读回测量值的极性与设定侧一致**。
- 处置建议（本 PRD 已按此写验收）：**F2 充放主判据用 REG 1013 状态机（0停机/1待机/2充电/3放电），不依赖功率符号**；F3/F4 方向标注随 F2。功率/电流正负仅作佐证且带「方向不一致」提示。
- 若产品要求屏上把功率本身画成「正放负充」，则该呈现项标 **「依赖厂方点表追认：读回 1022-1024/1029-1031 极性与设定侧一致（正=放/负=充）」**；追认前降级为 F2 状态机标注方向（见数据源字段表「待追认」）。

**功能依赖点表追认汇总**：F1（无）、F2（无，状态机判据）、F3（数值无 / 负号呈现有）、F4（数值无 / 负号呈现有）。F3/F4 核心展示不阻塞，方向性呈现待追认。
