## 0. PM 已裁定边界（不得违背，本 PRD 的硬边界）

| # | 裁定 | 对本 PRD 的约束 |
|---|------|------------------|
| B1 | 设备屏**有触摸屏** | 本地屏为可交互 HMI，不再是只读屏 |
| B2 | 原 08 的**操作类功能也由本地屏承载**（配置管理、日志等），用户以触摸操作 | 配置/日志/联锁等写操作入口全部迁入本地屏 |
| B3 | 08 的 AI 相关页面（§6 AI 可视化 / §7 专家干预 / §8 A/B 测试）**保留需求设计但标暂停**（AI 引擎已停用，无数据源），本期不实现 | 见 §3.8 暂停范围 |
| B4 | **移除 `web-api`**，取消通过 Web 页面访问的机制 | 系统需展示/操作的内容统一由本模块在本地屏承载；原 web-api 出口功能须做需求级迁移声明（§3.7） |
| B5（T-3 固化） | **本机权限模型 = 无登录 + 审计 + 二次确认** | 物理在场即授权，**无登录 / 会话 / PIN / RBAC**；写操作（**配置保存、联锁释放、M1 授权、任何下发**）须二次确认 + 记审计（§2.1 / §3.7 PL-1）。**模式切换为暂停项、本期无界面入口**（§3.8），不产生该类写操作 |
| B6（T-1 固化） | **日志检索 = 仅选项式筛选** | 仅「级别多选 + 模块筛选 + 预设时间区间」；**不做自由文本搜索**，本期**不引入虚拟键盘 / 文本输入**（§3.3 F10 / §3.6 F12） |
| B7（T-2 固化） | **日志导出本期不支持** | 本地屏无文件 / 下载通道，不提供任何导出入口；现场取日志诉求另立需求（§3.3 F10） |

## 1. 产品概述

### 1.1 背景（Why）

MUPC 设备为台区储能治理装置的非实时处理核心，长期 **headless 部署**（无本地面板）。原有两个并行的人机面：

1. **12 号本地显示终端（v1.0）**：HDMI 外接 8 寸 1024×768 屏，**只读**呈现 SOC / PCS 充放 / 三相功率电流。
2. **08 号 Web 管理与 AI 可视化**：`web-api` crate 提供的浏览器访问面（8080），承载系统状态监控、配置管理、日志查看，以及 AI 可视化/专家干预/A/B 测试。

平台现状已变化：

- **AI 引擎已停用**，本地策略引擎为唯一默认下发源；08 号中占比最大的 AI 类页面（§6/§7/§8）已无数据源，实际处于空转状态。
- `web-api` 的浏览器访问面在**现场无网 / 远端不可达**时完全不可用；而现场运维与调试恰恰发生在柜前。
- 同一份信息被两套机制重复承载（12 号屏 + 08 号 Web），维护面与一致性成本双份。

**结论（B4）**：取消 Web 访问机制，**把本地屏从「只读状态屏」升级为「触摸式本地人机界面（HMI）」**，统一承载原 08 的本地展示与操作。

### 1.2 产品定位（v2.0 升级）

> 12-MUPC 本地显示终端 = **台区储能装置的柜面触摸式本地人机界面**。

- **唯一本地人机面**：设备需向现场人员呈现与操作的内容，统一经本模块在本地屏呈现，不再有第二套 Web 面。
- **就地可视 + 就地可操作**：既读得到（SOC / PCS 充放 / 三相量 / 装置与连接状态 / 告警 / 版本），也操作得了（运行参数配置、日志查询、联锁人工释放与授权）。
- **可靠性兜底展示**：数据不可得时**明示不可得（不造假值）**，避免把「离线 / 未取数」误读为「真 0 功率」（沿用 v1.0 铁律，见 §5）。

### 1.3 产品价值

| 价值 | 说明 |
|------|------|
| 就地可视 | 柜前直接读屏，无需笔记本 / 远端即可确认储能 SOC、PCS 充放状态、三相功率电流 |
| 就地可操作 | 现场即可改运行参数、查日志、释放联锁，消除「必须开电脑」的运维瓶颈 |
| 降低误判 | 以 PCS 运行状态寄存器（REG 1013）为主判据，不靠「看功率符号猜充放」 |
| 单一维护面 | 取消 Web 面，消除两套人机面的实现与一致性成本 |
| 可靠性兜底 | 数据不可得时明示「不可得」，不造假值 |

### 1.4 目标平台与形态边界

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux（openEuler 22.03+ / Ubuntu 20.04+，aarch64） |
| 硬件 | BECG-3568（RK3568/RK3588），HDMI 外接 8 寸 **1024×768** 触摸屏 |
| 技术形态 | **独立原生渲染进程**（本机进程，不依赖浏览器内核、不依赖 Web UI） |
| 数据获取 | 显示数据由 mupcd（主进程运行时）经数据通道供给；显示进程**不直连核间 modbus 总线** |
| 写操作通道 | 运维写操作（配置 / 联锁释放 / 授权）经 mupcd 提供的**受控接口**完成（见 §3.7）；**禁止**显示进程直连 PCS / 核间总线下发 |
| 交互能力 | 单点触摸（是否需多点触控：**待设计确认**，本期按单点触摸设计） |
| 通道形态 | 跨进程通道 / 写操作接口的具体形态属**设计合同阶段**裁决，本 PRD 只约束能力与非功能边界 |

## 2. 用户角色

现场触屏场景下，用户面收窄（无远程角色）：

| 角色 | 说明 | 关注 | 典型操作 |
|------|------|------|----------|
| **现场运维工程师** | 例行巡检、状态确认、故障初步处置 | SOC、充放状态、功率量级、告警、装置整体状态 | 读主状态页；查告警；查日志；人工释放联锁 |
| **调试 / 试验工程师** | 台区联调、策略验证、参数下发核对 | 三相功率/电流与下发目标是否一致、SOC 裁决值是否可信、参数配置 | 读三相量；改运行参数；按模块/级别筛日志 |
| **（间接）远程支持人员** | 电话指导现场人员操作 | 屏上字段与编号稳定可复述，便于远程对拍 | 不直接操作设备 |

### 2.1 身份与权限模型（本机触摸，PM 已裁定 T-3）

**现场语义判定**：本地屏物理安装在设备柜面，**能触到屏幕即已在物理安全边界内**。原 08 的 Session 登录 / 密码 / 角色（RBAC）体系是为**网络可达面**设计的；Web 面取消后，其登录面失去存在理由。

**PM 裁定结论（T-3，本 PRD 基线，不再有备选项）**：

1. **无登录、无会话、无 PIN、无 RBAC**——**物理在场即授权**。本模块**不提供**任何账号 / 密码 / 登录 / 登出 / 角色分级 / 会话管理界面与需求；原 08 §2.3 的认证授权机制**不再适用**，随 Web 面一并废止。
2. **写操作必须记审计**：所有写操作（**配置保存、联锁释放、M1 授权、任何下发**）写入审计记录，操作者标识为本地控制台（固定标识，如 `local-console`），记录时间、操作类型、操作前后值、结果与失败原因（见 §3.7 PL-1）。**模式切换属暂停项、本期无界面入口（§3.8），不在本期写操作集合内**——避免与「已暂停」自相矛盾。
3. **写操作必须二次确认**：所有生效性 / 破坏性写操作须经二次确认对话框（展示「将执行的操作 + 影响范围 + 前后值摘要」），默认焦点在「取消」（见 §3.6 F14）。
4. **防误触补偿**：因无身份把关，须以「二次确认 + 防抖 / 幂等 + 控件尺寸与间距」共同兜底（见 §3.6 F14），写接口须具备防重放能力（见 §4.4 第 5 条）。

### 页面结构（信息架构，需求级）

**本期信息架构 = 6 个页面**：主状态页 P1 / 配置页 P2 / 日志页 P3 / 安全 · 联锁页 P4 / 审计页 P5 / 系统 · 关于页 P6。
其中 **P2、P4 含写操作**（必须二次确认 + 记审计）；**P1、P3、P5、P6 为读取 / 展示页**（P3、P5 含选项式筛选，无文本输入）。逐页给出功能落点，**不留「二选一」未决归属**：

| # | 页面 | 定位 | 承载功能（落点） | 状态 |
|---|------|------|------------------|------|
| P1 | **主状态页** | 默认页（开机 / 无操作超时回归页） | F1 SOC、F2 PCS 运行状态、F3 三相有功、F4 三相电流、F5 刷新与新鲜度、F6 装置整体状态、F7 告警列表 | 本期实现 |
| P2 | **配置页** | 运行参数触摸读写 | F9 运行参数触摸读写与保存生效 | 本期实现 |
| P3 | **日志页** | 日志查看 / 选项式筛选 / 实时推送 | F10 日志查看与选项式筛选 | 本期实现 |
| P4 | **安全 / 联锁页** | 联锁状态展示与人工处置（原 web-api 联锁出口的需求级落点，§3.7 映射 #1–#3） | F16 联锁状态展示、F17 人工释放联锁、F18 M1 人工授权重启（PL-04 / PL-05 / PL-06） | 本期实现 |
| P5 | **审计页** | 写操作审计记录查询（只读） | F19 审计记录查询（PL-2 / PL-03） | 本期实现 |

**信息架构裁决（消除原「二选一」未决）**：

1. **联锁相关功能统一归入独立「安全 / 联锁」页（P4）**——**不并入**主状态页的 F6 装置状态区。理由：联锁状态展示 + 人工释放 + M1 授权构成一组「安全处置」闭环，且释放 / 授权为**破坏性写操作**，与只读的主状态页混排会拉高误触风险（§3.6 F14 要求破坏性操作与返回控件间距 ≥ 48 px）。
2. **审计查询归入独立「审计」页（P5）**——**不并入**日志页。理由：审计筛选维度（时间范围 / 操作类型）与日志筛选维度（级别 / 模块 / 时间）不同；且审计为**不可删改的合规凭据**，与诊断日志混排易造成语义混淆（违反 §5「语义不同不得混淆」原则）。
3. 导航栏常驻上述 6 页入口（含 P4 / P5），任意页到任意页触摸 ≤ 2 次（F11 / TT-01，**TT-01 须覆盖新增的 P4 / P5**）。

### 3.1 F-状态展示类

> 合并来源：原 12 号 F1–F5（保留并沿用验收阈值）+ 原 08 §3 系统状态监控。

#### F1 储能 SOC 展示

**用户故事**：作为现场运维，我在柜前扫一眼屏就能看到当前电池 SOC 与其健康区间，判断是否接近上下限，无需连远端。

**数据来源**：mupcd 运行时 SOC 双源裁决后的域值（BMS 站 SOC 与核间读 PCS REG 1010 经 `resolve_soc_source` / `apply_soc_source` 裁决后的输出），非单一原始源。本 PRD 不定裁决算法，只要求「展示裁决值 + 展示所用源」。

**验收标准（可量化）**：
1. 屏上常显 SOC 数值，单位 %，量程 0–100%，显示精度整数位。
2. SOC 旁以可视手段标注**数据源**：`BMS` / `PCS(REG1010)` / `双源一致`；源信息与展示值同帧更新。
3. 区间着色：`≤15%`（下限邻近）与 `≥85%`（上限邻近）使用警示色块/边框（阈值对齐平台安全配置 soc_min/soc_max，默认 0.10/0.90）。
4. SOC 双源皆失效时按 §5 降级，**禁止补 0 或沿用陈旧值冒充实时值**。

#### F2 PCS 运行状态展示（充 / 放 / 停机 / 待机）

**用户故事**：作为现场运维，我要在屏上直接读出 PCS 此刻是充还是放，且该结论来自设备状态机而非我肉眼猜功率正负。

**判定依据**：PCS **模块运行状态**寄存器 REG 1013（UInt16）：`0=停机、1=待机、2=充电、3=放电`。该状态机为主判据；SOC 裁决值与三相有功**仅作一致性佐证**（异常时提示，不覆盖主判据）。

**验收标准（可量化）**：
1. 显式给出四态之一：**停机 / 待机 / 充电 / 放电**；文字 + 语义色 + 图标三重冗余（不依赖颜色单一信道）。
2. 判据为 REG 1013；1013 读失败（PCS 离线）时进入降级（§5），**不得**由功率正负反推充放。
3. 一致性佐证：1013=2（充电）而三相有功和（Σ1029–1031）显著为负、或 1013=3（放电）而 Σ 显著为正（反向显著 = 超量程 5% 阈值）时，显示「状态与功率方向不一致」角标；**主状态仍以 1013 为准**。

#### F3 三相有功功率展示（A/B/C）

**用户故事**：作为调试工程师，我要在屏上看到 PCS 交流输出 A/B/C 三相各有功功率（kW），确认下发分相 P 目标与实读一致。

**数据来源**：REG 1029/1030/1031（Int16，量纲 `*0.1 kW`）；可加显设备总有功 REG 1032（Int16，`*0.1 kW`）。

**验收标准（可量化）**：
1. 三相互相 + 总计常显，单位 kW，保留 1 位小数；显示值 = 寄存器读值 × 0.1（由 mupcd 完成量纲化，渲染端不重算）。
2. 刷新跟随 F5 帧节奏（帧到即更新，≤ 500 ms 生效）。
3. 每相数值按当前充放语义（来自 F2 主判据 REG 1013）着色区分方向性；**方向标签一律取自 F2 状态机，不以功率符号自判**（避免方向反置造假）。
4. 读失败 / 未取数：该相显示 `--` + 「源离线 / 未取数」标，**禁止显 0.0**。

> **依赖点表追认声明**：F3 数值（绝对值）展示不阻塞；唯「用三相功率正负号直接表达充/放」这一呈现方式依赖「读回测量值极性与设定侧一致（正 = 放 / 负 = 充）」的厂方追认。追认前一律以 F2 状态机标注方向。

#### F4 三相电流展示（A/B/C）

**用户故事**：作为现场运维，我要在屏上看到 PCS 交流输出 A/B/C 三相电流（A），配合功率确认设备出力。

**数据来源**：REG 1022/1023/1024（Int16，量纲 `*0.1 A`）。

**验收标准（可量化）**：
1. 三相电流常显，单位 A，保留 1 位小数；显示值 = 寄存器读值 × 0.1。
2. 刷新跟随 F5 帧节奏（帧到即更新，≤ 500 ms 生效）。
3. 读失败 / 未取数：该相显示 `--` + 「源离线 / 未取数」标，**禁止显 0.0**。
4. 方向性标注策略同 F3。

#### F5 数据刷新与新鲜度策略

**用户故事**：作为运维，我希望屏上数字是「够新」的，并且当数据不新鲜 / 掉线时屏上会**明确告诉我**，而不是默默停更让我误以为现场稳定。

**验收标准（可量化）**：
1. mupcd 数据推送周期（帧率）≥ **1 Hz**（帧间隔标称 1 s，容抖 ±30%）。
2. 渲染端收到新帧到屏上更新生效 ≤ **500 ms**（不含帧率本身）；数值变动即时反映，无闪屏 / 残影。
3. 新鲜度判定：`当前时间 − 帧时间戳 > 2 s` 即判「过期」；过期后对该字段显示「数据过期」角标，**保留最近有效帧数值但不冒充实时**。
4. 每帧携带**时间戳**与**每字段的有效标志（valid / invalid）**，由 mupcd 在域值化后打标；渲染端仅按标志展示或降级。
5. 各字段独立降级：单点读失败不影响其余字段刷新（点级 valid 标志）。

#### F6 装置整体状态展示（原 08 §3 并入）

**用户故事**：作为现场运维，我要在一块「装置状态」区看清设备整体是否正常——固件版本、运行时长、CPU 温度、内存占用、各连接状态、当前控制源。

**展示内容与更新频率**：

| 数据项 | 说明 | 更新频率 |
|--------|------|----------|
| 固件版本号 | 当前运行固件版本 | 页面加载时 |
| 编译时间 | 固件编译时间戳 | 页面加载时 |
| 运行时间（uptime） | 系统持续运行时长 | 5 秒 |
| CPU 温度 | RK 处理器温度 | 5 秒 |
| 内存使用率 | 系统内存占用百分比 | 5 秒 |
| IEC 104 连接状态 | 已连接 / 连接中 / 断开 / 未配置 | 5 秒 |
| 核间（intercore）连接状态 | 实时控制模块连接状态 | 5 秒 |
| 跨进程数据通道状态 | 本地屏与 mupcd 的数据通道连接状态 | 5 秒 |
| 当前控制源 | 本地策略引擎（AI 停用期唯一默认下发源） | 5 秒 |

> **AI 引擎状态项处置**：原 08 §3 的「AI 引擎状态」在 AI 停用期为固定值，**并入 §3.8 暂停范围**（本期不设该状态项；若需保留，仅作只读固定文案「AI 引擎已停用，本地策略引擎为默认下发源」）。

**状态指示灯规范**（沿用 08 §3.3）：

|------|------|------|

**验收标准（可量化）**：
1. 装置整体状态以状态卡网格展示，每卡含图标、标签、动态数值。
2. 各连接状态以状态指示灯展示，且**同时给出文字**（不依赖颜色单一信道）。
3. uptime / CPU 温度 / 内存使用率刷新周期 ≤ 5 s。
4. 版本号与编译时间在页面加载时一次性读取并展示，不随刷新跳动。
5. 连接状态不可得时显示「未配置 / 未知」，**不显示为「正常」**。

#### F7 告警列表展示（原 08 §3 并入）

**用户故事**：作为现场运维，我要在屏上看到最近的告警，按时间倒序，知晓设备最近出过什么事。

**验收标准（可量化）**：
1. 告警列表最多展示 **10 条**最新记录，按时间**倒序**排列。
2. 每条含时间戳、级别、消息文本；级别以颜色 + 文字双通道区分（ERROR = `#DC3545` / WARN = `#FFC107` / INFO = `#17A2B8`）。

#### F8 版本与装置信息展示（原 08 §3 并入）

**用户故事**：作为调试工程师，我要在现场屏上直接查看并修改装置运行参数，保存后立即生效，不必回办公室开电脑。

**可配置项与取值域**（沿用 08 §4.2）：

| 配置分组 | 参数 | 默认值 | 范围 / 选项 | 触摸输入方式（需求级） |
|----------|------|--------|-------------|------------------------|
| IEC 104 连接参数 | 对端 IP 地址 | — | 合法 IPv4 地址 | **四段数字步进**（无键盘，见 §3.6 F12） |
| IEC 104 连接参数 | 端口 | 2404 | 1–65535 | 数字步进（受约束） |

**交互规范（触摸化重写，替代表单规范）**：
1. 配置按分组分区展示（IEC 104 / 核间 / 遥测与日志），组内字段纵向排列，一屏可见组内全部字段（超出时允许整页滚动，滚动规范见 §3.6）。
2. 仅提供**受约束输入控件**（枚举选择 / 数字步进）；控件本身限制非法值，使绝大多数越界在输入阶段即不可达。**全程不出现虚拟键盘 / 文本输入**（见 §3.6 F12）。
3. 值变更即时本地校验；非法值时该字段错误态（红色边框 + 文字原因），且保存按钮置灰。
4. **保存需二次确认**（确认弹层展示「将修改的字段：旧值 → 新值」摘要）。
5. 保存成功：屏上 Toast 提示（3 秒自动消失）；保存失败：错误提示 + **保留用户已输入值**，并给出失败原因。
6. 保存过程中按钮显示「保存中…」且禁止重复触发。
7. 配置**自动生效，无需重启装置**（生效语义要求见验收 4）。

**验收标准（可量化）**：
1. 所有配置项通过本地屏**可读、可写**；只读查看不触发任何确认流程。
2. 心跳间隔范围 1–60 秒，越界时显示具体错误提示（非泛化提示）。
3. 配置保存需二次确认；确认弹层展示修改前后值摘要。
4. 保存成功后**自动生效，无需重启**；生效判定：保存返回成功后 ≤ 5 s 内，新参数在对应模块的运行行为中可见（验证方式由设计阶段给出，见 §6 「配置生效链路」）。
5. 保存失败（校验失败 / 写入失败 / 目标模块拒绝）时显示失败原因，且**装置保持原配置运行**（不得半生效）。
6. 修改值在**保存成功后**持久化，装置重启后恢复为最后一次保存值。
7. 「恢复默认值」为独立控件，与「保存」控件的触摸目标间距 ≥ 48 px（防误触，见 §3.6）。

### 3.4 F-安全与联锁类

> 本节为 v2.0 本次修订新增，承载原 `web-api` 联锁出口的需求级迁移（§3.7 映射 #1 / #2 / #3）。
> **页面落点已裁决：统一归入「安全 / 联锁」页（P4）**，不并入主状态页 F6 装置状态区（理由见 §3 信息架构裁决）。三个功能构成「看状态 → 释放 → 授权」的安全处置闭环。

#### F16 联锁状态展示

**用户故事**：作为现场运维，我要在柜前看清装置当前是否处于联锁态、由哪个触发源引起、故障灯 / 运行灯状态如何，判断能否恢复运行。

**展示内容**：联锁触发源明细（DI 触发源）、latch（自锁 / 保持）态、停机失败标志、指示灯 DO1 / DO2（故障灯 / 运行灯）状态。

**验收标准（可量化）**：
1. 「安全 / 联锁」页常显联锁总态：**已联锁 / 未联锁**，以「文字 + 语义色 + 图标」三重冗余表达，不依赖颜色单一信道。
2. 逐条列出触发源明细（含数量）；无触发源时显示明确空态（「当前无联锁触发源」），**不显示空白区**（§5 / EDGE-08 同口径）。
3. latch 态独立可见（已保持 / 未保持）；停机失败标志独立可见。
4. DO1 / DO2 指示灯以「指示灯 + 文字」双通道展示（故障灯亮 / 运行灯亮 / 灭），不可得时显示「未知」，**不得默认显示为「正常」**。
5. 联锁状态变化后 ≤ **2 s** 反映到屏上（无需人工刷新，通道能力见 PL-3）。
6. 状态源不可用时整区显示「联锁状态不可用」，**不得显示为「未联锁」**（二者语义不同，禁止混淆，同 EDGE-09 / EDGE-12 口径）。

#### F17 人工释放联锁

**用户故事**：作为现场运维，触发源已复位后，我要在柜前直接人工释放联锁让装置恢复运行，不必回办公室。

**验收标准（可量化）**：
1. 释放入口位于「安全 / 联锁」页；触摸目标 ≥ **64×64 px**（关键操作，§3.6 F14）。
2. 释放须**二次确认**：弹层展示「将执行的操作 + 影响范围 + 当前触发源与 latch 状态」，默认焦点在「取消」（§3.6 F14）。
3. 释放须**记审计**（PL-1）：含时间戳、操作者固定标识（`local-console`）、操作类型、操作前后状态、结果；成功与失败均留痕。
4. 释放条件不满足时（触发源未复位 / latch 保持时间不足 `release_hold_secs` 等）**必须明示具体拒绝原因**，**不得静默失败**（EDGE-12）。
5. 释放请求不得重复生效：≥ 500 ms 内重复点击不重复提交（防抖 / 幂等，§3.6 F14 / EDGE-14）。
6. 释放成功 ≤ **2 s** 内页面联锁态更新为「未联锁」（若条件仍不满足，保持「已联锁」并显示原因）。

#### F18 M1 保护跳闸 / 停机人工授权重启

**用户故事**：作为现场运维，M1 保护动作导致停机后，我要在柜前完成人工授权重启。

**验收标准（可量化）**：
1. 授权入口位于「安全 / 联锁」页；触摸目标 ≥ **64×64 px**（关键操作）。
2. 授权须**二次确认**（弹层展示操作 + 影响范围），默认焦点在「取消」。
3. 授权须**记审计**（PL-1），成功与失败均留痕。
4. **仅非 latch 态可授权**：处于 latch 态时入口不可用并**明示原因**（「处于 latch 态，须先释放联锁」），**不得静默失败**（EDGE-12）。
5. 失败（含条件不满足）须明示具体拒绝原因；≥ 500 ms 内重复点击不重复生效。

### 3.5 F-审计类

> 本节为 v2.0 本次修订新增，承载 PL-2「审计查询」能力的**页面落点裁决**：**独立「审计」页（P5）**，不并入日志页（理由见 §3 信息架构裁决）。
> 审计**写入**能力（PL-1）为跨功能通用要求，约束所有写操作，定义见 §3.7。

#### F19 审计记录查询（PL-2）

**用户故事**：作为现场运维 / 技术支持，本机无登录，我要在柜前查到「谁在什么时候改了什么、成功还是失败」，审计就是唯一凭据。

**验收标准（可量化）**：
1. 「审计」页按时间**倒序**展示审计记录，每页 **20 条**，支持滚动加载。
2. 每条含：时间戳、操作者标识（`local-console`）、操作类型、操作前后值摘要、结果（成功 / 失败）、失败原因。
3. 提供**选项式**筛选：时间范围（最近 1 h / 最近 24 h / 自定义起止，日期 + 时间**选项式步进**）、操作类型（**选项列表多选**）；**全程无文本输入**（同 §3.6 F12 口径）。
4. 筛选结果更新 ≤ **1 s**；查询响应 ≤ **2 s**。
5. 审计页为**只读**：不提供任何编辑 / 删除 / 清空入口（PL-1「仅可追加」在界面上的体现）。
6. **无导出入口**（同 T-2 口径，PL-2）。
7. 审计为空（或被筛选排除）时显示明确空态（「当前筛选条件下无审计记录」），**不显示空白区**，**不得显示为「未加载」**；审计**数据源不可用**时显示「审计记录不可用」，**不得显示为「无审计记录」**（EDGE-17）。
8. 首页展示最近一条审计的时间戳（便于判断审计链路是否在持续写入）。

### 3.6 F-触摸交互通用需求

> 本节为 v2.0 新增（v1.0 主体为只读屏，明确排除交互）。以下为**交互需求**，不含渲染栈 / 输入栈选型（属设计）。

#### F11 页面导航与切页

**验收标准（可量化）**：
1. 提供常驻导航入口（导航栏 / 标签），可到达全部 **6 个页面**：主状态页、配置页、日志页、**安全 / 联锁页**、**审计页**、系统页（与 §3 信息架构表 P1–P6 一一对应）。
2. 从任意页面到达任一目标页面（**含新增的安全 / 联锁页与审计页**）**点击次数 ≤ 2**。
3. 子页面提供**返回**控件（固定位置，同一应用内位置一致）。
4. 当前所在页面在导航中有明确选中态（视觉 + 文字）。
5. 导航**不提供**任何 AI 类页面入口（见 §3.8），亦不做置灰占位。

#### F12 表单输入范式（PM 已裁定 T-1）

**需求口径（裁定结论，全程无文本输入）**：

1. **基线范式：全程无需虚拟键盘 / 文本输入——仅「选项列表 + 数字步进 + 确认 / 取消」**：
   - 枚举类（日志级别、时间预设区间、模块筛选、**审计操作类型**）→ **选项列表**（单选 / 多选）；
   - 数值类（端口、心跳、周期、IPv4 每段）→ **数字步进**（受最小值 / 最大值硬约束）；
   - IPv4 地址 → **四段数字步进**（每段 0–255）；
   - 确认 / 取消 → 弹层按钮（含联锁释放 / M1 授权的二次确认弹层）。
2. **日志检索仅选项式**（T-1 裁定）：检索维度为「级别多选 + 模块筛选 + 预设时间区间」，**不提供自由文本搜索**，因此**不存在**需要虚拟键盘的场景（见 §3.3 F10）。**审计检索同口径**（时间范围 + 操作类型，见 §3.5 F19）。
3. **本期不引入虚拟键盘**（含中文 / 字母 / 数字软键盘均不引入）；交互全程仅由选项列表、数字步进、确认 / 取消构成。

**验收标准（可量化）**：
1. **全部 6 个页面**（含配置页、日志页、**审计页**、**安全 / 联锁页**）的**全部交互**可在**全程不出现任何键盘 / 文本输入控件**的前提下完成（验收项为「零键盘 / 零文本输入」）。
2. 配置页全部字段可在**无键盘**前提下完成编辑与保存；审计页筛选（时间范围 / 操作类型）同样零文本输入。
3. 数值输入控件具备「最小值 / 最大值」硬约束，越界值无法被输入（而非仅事后报错）。
4. 日志筛选经 **≤ 3 次触摸**完成（同 §3.3 F10 验收 5）；审计筛选同口径（§3.5 F19）。

#### F13 触摸响应时延与反馈

**验收标准（可量化）**：
1. 触摸按下到**视觉反馈**（按下态/高亮）≤ **100 ms**（P95 ≤ 200 ms）。
2. 页面切换（主状态页 ↔ 配置页 ↔ 日志页）≤ **300 ms**。
3. 列表滚动帧率 ≥ **30 fps**（单帧 ≤ 33 ms），滚动中无卡顿白屏。
4. 触摸响应不得阻塞主状态页的数据刷新（F5 指标在任何页面下均须满足）。

#### F14 误触防护

**验收标准（可量化）**：
1. 全部可点控件的触摸目标 ≥ **48×48 px**（8 寸 1024×768 下约 7.6 mm，满足人机工程学最小触摸尺寸）；关键操作（保存、联锁释放、M1 授权）触摸目标 ≥ **64×64 px**（约 10 mm）。
2. 相邻可点控件触摸目标间距 ≥ **16 px**；「破坏性/生效性操作」与「取消/返回」控件间距 ≥ **48 px**。
3. 生效性 / 破坏性操作需**二次确认**：确认弹层明确写出「将执行的操作 + 影响范围」，默认焦点在「取消」。
4. 连续快速重复点击同一生效性控件不得重复生效（生效操作具备幂等 / 防抖，≥ 500 ms 内不重复触发）。
5. 滑动与点击不得互相误触发（列表滑动过程中不触发列表项的点击动作）。

#### F15 屏幕无操作超时回归主状态页

**用户故事**：作为现场运维，我希望屏幕长期停在我离开时的配置页时不会误导后来的人，而是自动回到状态总览。

**验收标准（可量化）**：
1. 无触摸操作达到超时时间（默认 **60 s**，可配置）后，自动返回**主状态页**。
2. 超时返回**不得**丢失正在编辑但未保存的输入：若有未保存修改，超时前须给出提示或保留草稿状态（语义由设计确认，但**不得静默丢弃用户输入**）。
3. 超时计时在触摸事件时重置；超时返回动作本身不产生审计记录。
4. 存在未关闭的确认弹层时不触发超时返回（避免与进行中的操作冲突）。

## 4. 非功能性需求

### 4.1 资源预算

> ⚠️ **形态变更导致预算重定档**：v1.0 为「只读渲染」，本 v2.0 为「交互式 HMI」（含触摸控件、确认弹层、滚动列表、**6 个页面**），资源占用显著高于只读渲染。以下为**重新定档**后的边界上限，**不是放水**：超出即须评审。
>
> **预算口径（本次修订订正）**：本预算基于**「选项式触摸 + 只读文本渲染」**，**不含虚拟键盘 / 输入法（IME）栈、不含可编辑文本框**——T-1 已裁定全程无文本输入（§3.6 F12），交互仅由选项列表 / 数字步进 / 确认取消构成（§3.3 F10、§3.4 F16–F18、§3.5 F19 均遵循）。**原文「可能的软键盘」为裁决残留，已删除**；字体预算仅为**只读文本渲染**所需（中文字形集 + 数值字形），不含键盘 / 编辑态字形与候选词资源。

| 指标 | v1.0（只读，历史参照） | **v2.0 交互式 HMI（本期要求）** | 说明 |
|------|------------------------|--------------------------------|------|
| 常驻内存 | ≤ 64 MB | **≤ 256 MB** | 含触摸控件树、选项式控件状态、6 页页面状态、日志 / 审计列表缓存、字体资源（**只读文本渲染用；不含键盘 / IME 栈**） |
| CPU（稳态均值，1 s 窗口） | ≤ 15% 单核 | **≤ 40% 单核** | 稳态 = 停在主状态页或静态页面 |
| CPU（交互瞬时，页切换/列表刷新） | — | **≤ 60% 单核（瞬时）** | 瞬时峰值，不得持续 |
| CPU（数据通道断开满载） | ≤ 5% 单核 | **≤ 10% 单核** | 断连不得引起忙等/自旋 |
| 磁盘占用（可执行 + 资源） | 未约束 | **≤ 100 MB** | 含字体资源（**无 IME / 键盘资源**）；日志/审计属既有数据，不计入 |

**硬性要求**：
1. 渲染/交互进程内**不得有忙等 / 自旋等待**数据通道；空闲时应让出 CPU（阻塞读或事件驱动）。
2. 上述为**边界上限**；若设计所选轻量栈实测更优，须**下调**并写明实测值。
3. 若某栈超限，**必须**在设计阶段另行说明并获评审同意（不得静默放水）。
4. 内存不得随运行时间单调增长（长期运行无泄漏；日志列表须有上限与淘汰策略）。

### 4.2 布局与可读性（1024×768）

1. **主状态页：主读数区不横向滚动，允许整页纵向滚动（PM 裁定 T-6）**：SOC、PCS 运行状态、A/B/C 三相功率、A/B/C 三相电流、装置整体状态摘要、告警摘要（10 条中的可见部分）在 **1024×768** 下**不得横向滚动**。当信息量超出单屏时，**允许整页纵向滚动**或**分区切换**；纵向滚动**不得**导致主读数区横向滚动或数值跳位（v1.0「无滚动」约束仅在纵向方向放松，横向仍为硬约束）。
2. 目标阅读距离 **0.5–1.5 m**；主读数（SOC、PCS 状态词）字号 **≥ 64 px**，过程量（三相 P/I）字号 **≥ 32 px**，标注/辅助信息字号 **≥ 24 px**。
3. 状态语义用**「文字 + 语义色 + 图标」三重冗余**，不依赖颜色单一信道（满足色弱 / 单色可读）。
4. 布局固定分区，字段位置稳定不跳变（值变化不改布局，仅数值变化），便于现场记忆。
5. 屏幕长期静态显示时防烧屏：允许对静态装饰做低影响处理（周期微移 / 反色节拍），但**核心数值区不得因防烧屏措施而抖动可读性**。
6. 触摸目标尺寸与间距要求见 §3.6 F14（人机工程学：≥ 48×48 px ≈ 7.6 mm；关键操作 ≥ 64×64 px ≈ 10 mm）。

### 4.3 可靠性与自恢复

| 指标 | 要求 |
|------|------|
| 渲染进程异常退出后自恢复 | ≤ **3 s** 自动重启并恢复显示（由拉起机制保证，归属在系统集成侧） |
| 进程隔离 | 显示进程崩溃 / 重启**不得影响** mupcd 主进程、策略引擎、核间 / 南向通信 |
| 数据通道断开感知 | ≤ **3 s** 感知并进入断连降级画面 |
| 数据通道恢复 | mupcd 恢复并重建通道后，≤ **1 s** 回到实时显示 |
| 上电启动顺序 | 显示进程先于 / 并行于通道就绪时可显示「初始化中」占位；通道就绪后 ≤ 1 s 切到实时画面；显示进程**不得阻塞** mupcd 启动关键路径 |
| 触摸失效 | 触摸无响应时**不得**影响数据刷新与其他既有画面（见 §5） |
| 界面可用性 | 主状态页在装置运行期间可用性 ≥ **99.9%** |
| 配置写入送达率 | ≥ 99.99%（本地总线异常时保持原配置并明示失败，见 §5） |

### 4.4 跨进程数据通道可靠性边界（通道形态留给设计）

本 PRD 不裁定通道具体技术形态，但要求其对上层表现满足：

1. **数据投递语义**：允许丢帧，但**不允许静默传输损坏数值**（须有校验 / 序列号 / 版本一致性手段，或丢帧重传最新帧）。
2. **断连检测**：渲染端须在通道中断 ≤ 3 s 内感知并进入降级画面；恢复 ≤ 1 s 回实时。
3. **畸形帧防护**：渲染端不得因通道对端行为异常而崩溃或内存失控（畸形帧丢弃并计数告警）。
4. **单向展示通道**：展示数据通道只承载「读展示 + 心跳/健康」信息，**禁止**承载下行写指令。
5. **写操作独立通道（v2.0 新增）**：运维写操作（配置 / 联锁释放 / M1 授权）走**独立的受控接口**，与展示通道解耦；该接口须具备：参数校验、鉴权（若 §2.1 定为无身份则至少须有防重放/防误触）、审计留痕、失败原因回传。
6. **禁止直连**：显示进程**任何情况下**不得直连核间 modbus / PCS 总线。

### 4.5 数据刷新频率

| 数据项 | 刷新频率 | 方式 |
|--------|----------|------|
| SOC / PCS 状态 / 三相 P / 三相 I | ≥ 1 Hz（帧到即更新） | 数据通道推送 / 拉取 |
| 装置整体状态（uptime / 温度 / 内存） | 5 s | 数据通道 |
| 连接状态指示灯 | 5 s | 数据通道 |
| 告警列表 | 新增 ≤ 2 s | 数据通道推送 |
| 实时日志 | ≤ 2 s | 实时通道推送 |
| 联锁状态 / latch / DO 灯（F16） | 变化后 ≤ 2 s | 数据通道 |
| 版本信息 | 页面加载时一次性读取 | 数据通道 |
| 配置项当前值 | 进入配置页时读取 | 受控接口 |
| 审计记录（F19） | 进入审计页时查询（筛选变更即时重查） | 受控接口 |

## 5. 边界与异常（不造假值原则）

> **总原则**：**源不可得 → 显式「不可得」**；可展示冻结帧但必须打标。**任何情况下不得用 0 / 陈旧值 / 臆测值冒充实时真值。**
> 「不可得」与「值为 0 / 无告警」是**语义不同**的两件事，界面不得混淆（见 EDGE-05 / EDGE-08）。

| ID | 异常场景 | 展示行为（渲染端） | 数据侧职责（mupcd） |
|----|----------|---------------------|----------------------|
| EDGE-01 | PCS 离线（核间 modbus 读失败，REG 1013 / SOC 源失效） | F2 显示「PCS 离线」；F3/F4 各相显示 `--` + 「源离线」；F1 若有另一源则显示该源并标注 | 帧中对应字段 valid=false；整体标「PCS 离线」 |
| EDGE-02 | SOC 双源皆失（BMS 站 + PCS REG1010 均无效） | SOC 区显 `--` + 「SOC 源失效」警示色；**不补 0、不沿用旧值** | valid=false，不下发疑似值 |
| EDGE-03 | 跨进程数据通道断（mupcd 侧 / 通道侧异常） | ≤ 3 s 切换「与主进程数据通道断开」画面；可保留最近有效帧并打「冻结 / 过期」标 | 通道健康状态随连接生命周期维护 |
| EDGE-04 | 点表未覆盖 / mupcd 尚未实现某点读取 | 该字段显 `--` + 「未取数」；不显示 0 | 该字段 valid=false，注明原因 |
| EDGE-05 | 字段数值域异常（读值越界 / 非有限 / 超物理量程） | 显 `--` + 「数据异常」；不做插值 | 域值化时做量程 / 有限性校验，异常置 invalid |
| EDGE-06 | REG 1013 与功率方向显著相反 | 主状态以 1013 展示，另加「方向不一致」角标 | 聚合比对后随帧给一致性标志 |
| EDGE-07 | 渲染进程自身异常 / 启动失败 | 黑屏或「显示进程异常」占位；由拉起机制 ≤ 3 s 重启 | 不阻塞主进程 |
| EDGE-08 | **日志为空 / 筛选无结果** | 显示明确空态（「当前筛选条件下无日志」），**不得显示为"未加载"或空白** | 返回 `total=0` 与筛选条件回显 |
| EDGE-09 | **告警源不可用**（区别于「无告警」） | 告警区显示「告警源不可用」，**不得显示为「无告警」** | 提供告警源可用性标志 |
| EDGE-10 | **配置写入失败**（校验失败 / 落盘失败 / 目标模块拒绝） | 显示失败原因；**保留用户已输入值**；装置保持原配置运行 | 返回结构化失败原因；保证不半生效 |
| EDGE-11 | **配置保存过程中被超时回归 / 页面切换打断** | 不得静默丢弃；须提示「有未保存修改」或保留草稿 | — |
| EDGE-12 | **联锁释放 / M1 授权被拒绝** | 明示拒绝原因（如「触发源未复位」「保持时间不足」「处于 latch 态」），**不得静默失败** | 返回具体拒绝原因 |
| EDGE-13 | **触摸无效 / 触摸设备异常** | 数据刷新与其他显示**不受影响**（触摸是独立输入路径）；可选：显示「触摸不可用」提示 | — |
| EDGE-14 | **触摸抖动 / 重复点击** | 生效性操作具备防抖，500 ms 内不重复触发 | 写接口幂等 |
| EDGE-15 | **日志检索范围超限**（自定义起止区间跨度过大，超出设计阶段评估的上限） | 提示「检索范围超限，请缩小时间范围」，**不执行全库检索** | 拒绝越界查询请求 |
| EDGE-16 | **版本 / 序列号字段缺失** | 显示「未提供」，**不臆造** | 字段为空即如实返回空 |
| EDGE-17 | **审计数据源不可用 / 审计查询失败** | 显示「审计记录不可用」，**不得显示为「无审计记录」**（同 EDGE-09 口径，二者语义不同） | 提供审计存储可用性标志；查询失败返回结构化错误 |

**量程 / 语义越界阈值口径**（供 EDGE-05 与 EDGE-06）：以「读值 × 量纲」后偏离物理合理区（如单相有功 / 电流绝对值超出该机型额定区显著比例，或 1013 状态枚举外值）判定；具体阈值在数据源字段表符号缺口追认时一并由厂方 / 设计确认。评审前采用「读值非有限或越 Int16 工程界」即判异常。
