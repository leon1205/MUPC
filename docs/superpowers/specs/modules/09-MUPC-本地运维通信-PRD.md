## 1. 产品概述

### 1.1 产品定位

MUPC 微电网特种调控装置当前已支持 Web UI 浏览器访问和北向远程通信两种运维通道，但缺少**现场本地无线运维通道**。本 PRD 定义面向运维人员现场操作的本地无线通信能力，作为 Web UI 和北向通信之外的**第三条运维通道**。

**核心价值：**

- 现场运维人员无需携带笔记本电脑连接有线接口，通过手机/平板即可完成本地配置、日志导出和固件升级
- 在装置网络中断或北向通信失效的极端情况下，本地无线通道作为**唯一的现场救急通道**确保装置可运维
- 星闪（NearLink）作为国产自主无线技术，满足电力行业自主可控要求

### 1.2 应用场景

| 场景 | 触发条件 | 选用通道 |
|------|----------|----------|
| 现场工程师首次部署配置 | 装置上电但未接入调度网络 | 星闪/NearLink（推荐）或 Wi-Fi AP 模式 |
| 运维人员定期巡检日志导出 | 到场后快速获取运行日志 | 蓝牙（轻量需求）或 Wi-Fi（大量日志） |
| 固件版本紧急升级 | 现场发现固件 bug 需要立即修复 | 星闪/NearLink 或 Wi-Fi（大文件传输） |
| 装置网络中断后故障排查 | 北向通信全部中断，Web UI 不可达 | 任意可用无线通道（优先级：星闪 > Wi-Fi > 蓝牙） |
| 批量设备现场配置 | 多个 MUPC 装置集中部署 | 星闪/NearLink（低干扰、高并发） |

### 1.3 目标平台

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux (openEuler 22.03+，内核 >= 5.10) |
| 硬件 | RK3585（需确认无线模组型号及接口类型） |
| 编程语言 | Rust |
| 异步运行时 | Tokio |
| 无线模组接口 | USB / SDIO / UART（取决于选型） |
| NearLink 协议 | 支持星闪 SLE（SparkLink Low Energy）基础通信 Profile |
| Wi-Fi 协议 | IEEE 802.11 b/g/n/ac（2.4 GHz + 5 GHz 双频） |
| 蓝牙协议 | BLE 4.2+，兼容 5.0 |
| 客户端兼容 | Android 10+ / iOS 15+ 手机或平板，支持 BLE GATT 和 Wi-Fi Direct |

### 1.4 用户角色

| 角色 | 描述 | 权限范围 | 优先级 |
|------|------|----------|--------|
| **现场运维工程师** | 携带手机/平板到 MUPC 装置现场，执行日常巡检、故障排查、参数调整 | 配置读取、日志导出、参数调整（非关键参数）、固件升级触发 | **高（最高优先）** |
| **系统管理员** | 远程指导现场操作，审批关键配置变更和固件升级 | 审批关键操作、查看审计日志 | 高 |
| **部署工程师** | 新装 MUPC 装置的首次配置和网络接入调试 | 首次配置、网络参数设置、装置注册 | 高 |
| **第三方巡检人员** | 按计划到现场执行巡检，仅需查看运行状态和导出标准日志 | 只读查看、标准日志导出 | 低 |

**无线通道与有线的权限一致性：**

- 无线通道登录成功后与 Web UI 共享同一套权限体系
- 关键操作（固件升级、配置覆盖）需要二次确认
- 所有无线通道的操作记录必须记入审计日志

## 2. 星闪（NearLink）通信

### 2.1 NearLink 连接建立与管理

**User Story：**
> 作为现场运维工程师，我需要通过星闪（NearLink）连接 MUPC 装置，以便在无 Wi-Fi/蓝牙现场环境下执行运维操作。

**验收标准：**

- 装置上电后 NearLink 服务自动启动
- 支持 NearLink 广播模式，设备名称显示为 `MUPC-{序列号后6位}`
- 连接建立时间：从发起连接到通信可用 <= 5 秒
- 支持至少 4 个并发客户端同时连接
- NearLink 通信覆盖半径 >= 100 米（视距无遮挡）
- 数据传输速率 >= 10 Mbps（实际应用层吞吐）
- 连接空闲超时：300 秒无数据交互后自动断开
- 支持自动重连：断连后 10 秒内自动尝试重连，最多重试 3 次

### 2.2 NearLink 本地配置读写

**User Story：**
> 作为现场运维工程师，我需要通过 NearLink 连接读写 MUPC 装置配置参数，以便在现场快速调整装置运行参数。

**验收标准：**

- 通过 NearLink 通道读取所有 Web UI 可读的配置项
- 通过 NearLink 通道写入以下配置项：
  - IEC 104 连接参数（IP、端口、心跳间隔）
  - intercore 通信参数（本地端口、对端端口）
  - 遥测上报周期
  - 日志级别
  - 南向通信设备参数（RS485 波特率、Modbus 地址）
- 配置写入后立即生效，无需重启装置
- 配置读取响应时间 <= 1 秒
- 配置写入响应时间 <= 2 秒
- 每次配置写入记录审计日志

### 2.3 NearLink 日志导出

**User Story：**
> 作为现场运维工程师，我需要通过 NearLink 连接导出系统日志，以便在现场快速获取故障分析数据。

**验收标准：**

- 支持按时间范围过滤后导出日志（默认最近 24 小时）
- 支持按日志级别过滤（ERROR / WARN / INFO）
- 日志导出格式：纯文本 `.log` 文件
- 单次导出最大条数：50000 条
- 导出速度：每 10000 条日志导出时间 <= 30 秒
- 导出过程中实时显示进度百分比
- 支持导出中断和取消

### 2.4 NearLink 固件升级

**User Story：**
> 作为现场运维工程师，我需要通过 NearLink 连接将固件升级包传输到 MUPC 装置并触发升级，以便在现场完成固件更新。

**验收标准：**

- 上传固件包到装置临时存储区（`/tmp/mupc_update/`）
- 固件包格式：`.tar.gz` 压缩包，包含固件镜像和签名文件
- 上传完成后自动触发完整性校验（SHA-256）
- 校验通过后触发固件升级流程
- 支持传输中断后断点续传
- 固件包大小上限：500 MB
- 传输速率 >= 5 Mbps（实际有效吞吐）
- 升级过程中保持稳定的无线连接
- 固件包必须经过签名验证（与 OTA 模块共用验证流程）

## 3. Wi-Fi 本地运维

### 3.1 Wi-Fi AP 模式

**User Story：**
> 作为现场运维工程师，我需要 MUPC 装置作为 Wi-Fi 热点（AP 模式）供我连接，以便在没有现成 Wi-Fi 网络覆盖的现场开展运维。

**验收标准：**

- 装置支持 Wi-Fi AP 模式，默认 SSID 为 `MUPC-AP-{序列号后6位}`
- 默认 AP 密码印刷在装置外壳标签上
- 支持 Wi-Fi 802.11 b/g/n/ac（2.4 GHz + 5 GHz 双频）
- AP 模式最大接入客户端数：8 个
- AP 信号覆盖半径 >= 30 米（视距无遮挡）
- 客户端连接后自动分配 IP 地址（DHCP 地址池：`192.168.4.2/24` ~ `192.168.4.254/24`）
- 装置 AP 模式 IP 地址：`192.168.4.1`
- AP 模式下不影响其他模块运行（北向通信、策略引擎正常运行）
- AP 模式空闲超时：600 秒无客户端连接后自动关闭
- 支持通过 Web UI 或 NearLink 配置 AP 参数（SSID、密码、频段）

### 3.2 Wi-Fi Station 模式

**User Story：**
> 作为现场运维工程师，我需要将 MUPC 装置连接到现场已有的 Wi-Fi 网络，以便通过本地网络远程访问 Web UI 执行运维操作。

**验收标准：**

- 支持 Wi-Fi Station 模式，连接外部 AP
- 支持 WPA2-PSK 和 WPA3-SAE 认证
- 支持 DHCP 自动获取 IP
- 支持手动配置静态 IP（通过 NearLink 或 Web UI 预配置）
- Station 模式下装置通过 Wi-Fi IP 提供 Web UI 访问
- Station 模式连接成功后通过 Web UI 显示已分配的 IP 地址
- 支持保存多个 Wi-Fi 网络配置（最多 5 个），自动按优先级连接
- 周期性扫描可用 Wi-Fi 网络（扫描间隔：60 秒），列表通过 Web UI 展示

### 3.3 Wi-Fi 模式下配置读写

**User Story：**
> 作为现场运维工程师，我需要通过 Wi-Fi 连接（AP 或 Station 模式）读取和修改 MUPC 装置配置。

**验收标准：**

- Wi-Fi 连接的客户端通过 HTTP/HTTPS 访问 Web UI 执行配置操作
- 配置能力与 Web UI 本地配置管理功能完全一致
- 通过 REST API 直接读写配置（无需浏览器），API 路径：`/api/v1/config/*`
- API 请求认证方式：Bearer Token（通过 Web UI 登录获取）
- 配置 API 响应时间 <= 1 秒（读取），<= 2 秒（写入）

### 3.4 Wi-Fi 模式下日志导出

**User Story：**
> 作为现场运维工程师，我需要通过 Wi-Fi 连接导出大量系统日志，以便离线分析故障。

**验收标准：**

- 日志导出 API：`GET /api/v1/logs/export?start=...&end=...&level=...`
- 支持时间范围过滤（开始时间、结束时间，UTC 格式）
- 支持日志级别过滤（ERROR / WARN / INFO / DEBUG）
- 支持全文关键词搜索
- 导出格式：`.log` 文本文件
- 单次导出最大条数：100000 条
- 大日志导出支持分页下载（每页最多 10000 条）
- 压缩导出选项：支持 `.tar.gz` 压缩格式

### 3.5 Wi-Fi 模式下固件升级

**User Story：**
> 作为现场运维工程师，我需要通过 Wi-Fi 连接将固件升级包快速传输到 MUPC 装置并完成升级。

**验收标准：**

- 固件上传 API：`POST /api/v1/ota/upload`
- 支持分块上传（每块大小：4 MB），支持断点续传
- 固件包校验方式：上传完成后自动计算 SHA-256 并与上传时提供的校验值比对
- 校验通过后触发升级流程
- 升级进度实时反馈：`GET /api/v1/ota/progress` 返回当前进度百分比
- 与 OTA 模块的升级状态机集成，共用升级流程
- **Wi-Fi 固件升级与 OTA 远程升级的关系：**
  - Wi-Fi 上传的固件包使用与 OTA 远程升级相同的验证流程（签名验证 + 哈希校验）
  - Wi-Fi 上传的固件包通过本地 OTA 管理器执行安装
  - 两种通道共用同一套固件版本管理和回滚机制

## 4. 蓝牙 BLE 通信

### 4.1 BLE GATT 服务

**User Story：**
> 作为现场运维工程师，我需要通过手机蓝牙连接 MUPC 装置，以便在不依赖 Wi-Fi 或星闪的条件下快速查看装置状态和导出小量数据。

**验收标准：**

- 装置作为 BLE 外设（Peripheral）广播 GATT 服务
- 广播名称：`MUPC-BLE-{序列号后6位}`
- 广播间隔：100 ms
- 支持 BLE 4.2 / 5.0
- 覆盖半径 >= 10 米（视距无遮挡）
- 最多同时连接 1 个 BLE 客户端
- 定义标准 GATT 服务 UUID：`0000MUPC-0000-1000-8000-00805F9B34FB`
- 定义多个 Characteristic：

| Characteristic | 属性 | UUID | 内容 |
|---------------|------|------|------|
| 设备状态特征 | 只读 | `0000STAT-0001-1000-8000-00805F9B34FB` | 序列号、固件版本、运行状态 |
| 配置读写特征 | 读写 | `0000CONF-0001-1000-8000-00805F9B34FB` | 配置参数读写 |
| 日志传输特征 | 只读通知 | `0000LOG-0001-1000-8000-00805F9B34FB` | 日志块传输 |
| 固件传输特征 | 写入 | `0000FWUP-0001-1000-8000-00805F9B34FB` | 固件升级触发 |
| 控制命令特征 | 写入 | `0000CTRL-0001-1000-8000-00805F9B34FB` | 控制命令 |

### 4.2 蓝牙设备状态读取

**User Story：**
> 作为现场运维工程师，我需要通过蓝牙快速读取 MUPC 装置的基本状态信息，以便远程巡检时快速确认装置运行状况。

**验收标准：**

- 通过 BLE 设备状态特征读取以下信息：
  - 装置序列号
  - 固件版本号（主版本号 + 次版本号 + 补丁号）
  - 运行时间（uptime，秒）
  - CPU 温度（摄氏度）
  - 内存使用率（百分比）
  - 主要模块连接状态（IEC 104、intercore）—— 在线/离线
  - 当前告警数量
- 读取响应时间 <= 500 ms
- 数据格式：JSON 字符串，UTF-8 编码

### 4.3 蓝牙配置读写

**User Story：**
> 作为现场运维工程师，我需要通过蓝牙读取和修改 MUPC 装置的少量关键配置参数，以便在无法连接 Wi-Fi 或星闪时快速调整。

**验收标准：**

- 通过 BLE 配置读写特征支持以下参数的读取和写入：
  - IEC 104 心跳间隔（秒）
  - 日志级别（ERROR / WARN / INFO / DEBUG）
  - 遥测上报周期（秒）
  - RS485 波特率
- 配置写入需通过 BLE 配对绑定验证
- 写入操作需要客户端先发送包含认证凭据的控制帧
- 配置写入响应时间 <= 3 秒
- 配置读取响应时间 <= 1 秒
- 配置写入后立即生效

### 4.4 蓝牙日志导出

**User Story：**
> 作为现场运维工程师，我需要通过蓝牙连接导出最近一段时间的运行日志，以便在紧急情况下快速获取故障线索。

**验收标准：**

- 通过 BLE 日志传输特征按块传输日志数据
- 每块最大 512 字节
- 默认导出最近 1 小时 ERROR 和 WARN 级别日志
- 支持通过控制命令特征指定导出条件：
  - 时间范围（最近 N 分钟，N 可配置为 10/30/60/120/480）
  - 日志级别（ERROR / WARN / INFO）
  - 最大条目数（默认 500 条）
- 日志数据以 UTF-8 纯文本格式传输
- 单次导出最大条目数：2000 条
- 全部日志传输完成时有明确的结束标记
- 传输过程中支持客户端发起取消

### 4.5 蓝牙固件升级触发

**User Story：**
> 作为现场运维工程师，我需要通过蓝牙触发 MUPC 装置的固件升级流程，以便在最受限的网络条件下也能启动固件更新。

**验收标准：**

- 蓝牙通道**不传输完整的固件包**（蓝牙传输速率不足）
- 通过蓝牙控制命令特征触发以下操作：
  - 触发 OTA 检查：命令装置通过北向通道检查并下载更新
  - 触发 Wi-Fi 固件传输：若已在 Wi-Fi 网络中，触发预下载的固件升级
  - 查询当前升级状态
  - 触发回滚到上一版本
- 控制命令响应时间 <= 2 秒
- 命令执行结果通过状态通知实时反馈

## 5. 无线通信安全

### 5.1 接入认证

**User Story：**
> 作为系统管理员，我需要所有无线通道具备接入认证机制，防止未经授权的设备连接到 MUPC 装置。

**验收标准 —— NearLink 接入认证：**

- 首次连接需要 PIN 码配对（PIN 码印刷在装置外壳标签上）
- 配对成功后自动建立信任关系
- 支持信任设备列表管理（最多 20 个信任设备）
- 不受信任的设备无法建立数据通信连接

**验收标准 —— Wi-Fi 接入认证：**

- AP 模式：WPA2-PSK 或 WPA3-SAE 加密
- Station 模式：支持 WPA2-PSK / WPA3-SAE
- 默认密码印刷在装置外壳标签上
- 密码支持通过 Web UI 或 NearLink 修改

**验收标准 —— 蓝牙接入认证：**

- 使用 BLE 配对绑定机制（Just Works 或 Passkey Entry）
- 传输配置写入命令时需额外验证 Token
- Token 有效期：30 分钟

**验收标准 —— 统一接入策略：**

- 连续 5 次认证失败后锁定该无线通道 5 分钟
- 锁定事件写入审计日志，触发告警
- 支持管理员远程或通过 Web UI 解锁

### 5.2 数据传输加密

**User Story：**
> 作为系统管理员，我需要确保所有无线通道传输的数据经过加密，防止数据被窃听或篡改。

**验收标准：**

- NearLink 通信：使用 NearLink 原生链路层加密（AES-128/256）
- Wi-Fi 通信：使用 WPA2/WPA3 加密（链路层）+ HTTPS 通信（应用层）
- 蓝牙通信：使用 BLE 加密配对后的链路加密
- 日志导出数据：传输过程中加密，落地后不强制加密（日志文件本身不含敏感信息）
- 配置数据传输：端到端应用层加密（AES-256-GCM），密钥协商使用 ECDH
- 固件包传输：固件包本身已签名加密（复用 OTA 模块的加密方案）
- 禁止明文传输任何凭据（密码、Token）

### 5.3 审计日志

**User Story：**
> 作为系统管理员，我需要所有无线通道的操作行为被完整记录，以便进行安全审计和事故追溯。

**验收标准：**

- 所有通过无线通道的操作必须记录审计日志
- 审计日志包含以下字段：

| 字段 | 说明 |
|------|------|
| 操作时间 | UTC 时间戳 |
| 操作类型 | 连接/断开/配置写入/日志导出/固件升级/回滚 |
| 操作者身份 | 设备 MAC / BLE MAC / Token ID |
| 操作对象 | 配置项路径、文件名、固件版本号 |
| 操作结果 | 成功/失败 + 失败原因 |
| 连接通道类型 | NearLink / Wi-Fi / Bluetooth |

- 审计日志存储于独立文件：`/var/log/mupc/audit.log`
- 审计日志不可篡改（日志文件只可追加，不可修改或删除）
- 审计日志保留周期 >= 180 天

## 6. 通道管理与省电策略

### 6.1 多通道共存与优先级

**User Story：**
> 作为系统，我需要同时开启多个无线通道并按优先级提供服务，以便在不同场景下提供最优的运维通道。

**验收标准：**

- 三种无线通道可同时开启，互不干扰
- 通道优先级规则（由高到低）：

| 优先级 | 通道 | 说明 |
|--------|------|------|
| 1（最高） | NearLink | 最优先，安全且高速 |
| 2 | Wi-Fi Station 模式 | 已有网络连接 |
| 3 | Wi-Fi AP 模式 | 临时热点 |
| 4（最低） | Bluetooth | 低带宽，仅轻量操作 |

- 当一个通道正在进行数据传输时，另一通道的连接请求不被拒绝
- 配置写入操作通过任何通道发起效果相同（最终一致性）
- 固件升级操作仅允许同时通过单一通道进行

### 6.2 无线通道状态监控

**User Story：**
> 作为现场运维工程师，我需要查看所有无线通道的实时状态，以便了解当前可用的运维途径。

**验收标准：**

- 通过 Web UI 无线状态页面展示以下信息：
  - 各通道开关状态（开启/关闭）
  - 各通道连接状态（已连接/等待连接/未启用）
  - 已连接客户端数量
  - 当前数据传输速率（Mbps）
  - 累计传输数据量（MB）
  - 信号强度（dBm，仅对已连接的客户端）
- 状态刷新周期：5 秒
- 通过 BLE 设备状态特征也可读取各通道状态

### 6.3 无线通道手动控制

**User Story：**
> 作为现场运维工程师，我需要手动开启或关闭各无线通道，以便在特定场景下控制无线发射（如在防爆区域关闭所有无线）。

**验收标准：**

- 通过 Web UI 可独立开启/关闭 NearLink、Wi-Fi AP、Wi-Fi Station、蓝牙
- 关闭操作立即生效（无线模块停止广播/扫描）
- 开启操作后 10 秒内服务恢复
- 支持定时开关（例如：工作日 09:00-18:00 开启，其余时间关闭）
- 支持一键关闭所有无线通道（"飞行模式"）
- 通道状态变更记录审计日志
- 装置重启后各通道恢复为断电前的状态

### 6.4 无线省电策略

**User Story：**
> 作为系统管理员，我需要无线模块在非工作时间自动进入低功耗模式，以降低装置整体功耗。

**验收标准：**

- 配置无线通道空闲超时时间（默认 300 秒无客户端连接自动关闭）
- 支持配置定时开关计划
- 低功耗模式下，NearLink 和 Wi-Fi AP 停止广播，蓝牙保持可发现模式
- 低功耗模式下功耗降低 >= 80%（相对全功率状态）
- 有连接请求时（如客户端扫描/配对）自动唤醒

## 7. 边界条件与异常处理

### 7.1 无线模组不可用

```
装置检测不到无线模组（硬件缺失 / 驱动未加载）
    ↓
记录系统告警并写入日志
    ↓
Web UI 显示无线通道全部不可用并标明原因
    ↓
装置正常运行不受影响（仅运维通道缺失）
```

### 7.2 多通道并发冲突

```
Wi-Fi AP 模式和 Station 模式配置了相同频段导致互相干扰
    ↓
系统自动限制：AP 模式和 Station 模式不可同时使用同一频段
    ↓
用户配置 AP + Station 在同频段时给出警告
    ↓
推荐配置：AP 使用 5 GHz，Station 使用 2.4 GHz，或反之
```

### 7.3 固件升级中断

```
固件传输过程中无线连接断开
    ↓
若已传输部分固件包：
    ↓
  方案 A（支持断点续传的通道）：标记断点，连接恢复后继续传输
  方案 B（不支持断点续传的通道）：下载任务标记为失败，清理临时文件
    ↓
固件包不完整的情况下不触发升级
    ↓
记录升级失败事件到审计日志
```

### 7.4 同时接入多个运维通道

```
运维人员通过 NearLink 连接的同时，另一运维人员通过 Wi-Fi 连接
    ↓
两通道均可正常使用
    ↓
配置写入操作：后写入的覆盖先写入的（以操作时间戳为准）
    ↓
固件升级操作：仅允许单一通道触发，第二通道触发时返回"升级进行中"错误
    ↓
所有操作记录审计日志
```

### 7.5 无线通道安全攻击

```
检测到连续认证失败（连续 5 次失败）
    ↓
锁定目标通道 5 分钟
    ↓
记录攻击事件到安全审计日志
    ↓
Web UI 显示安全告警信息
    ↓
管理员可通过 Web UI 手动解锁或永久拉黑攻击源 MAC 地址
```

### 7.6 蓝牙连接频繁断开

```
蓝牙连接在短时间内（30 秒内）断开重连超过 3 次
    ↓
主动延长蓝牙扫描间隔（从 100 ms → 500 ms）
    ↓
若持续不稳定，建议用户切换至 NearLink 或 Wi-Fi
    ↓
记录不稳定事件到日志
```
