## 1. 产品概述

### 1.1 产品定位

MUPC 微电网特种调控装置通信管理模块是"异构双核心模块主控架构"中的**非实时处理核心**（大脑），与"实时控制核心模块"（小脑）协同工作。

数据处理与存储模块（data-processing）作为"大脑"的核心数据处理组件，**承担以下职责**：

- **数据采集**：从 intercore 模块接收实时控制模块的高频采样数据，汇聚为统一数据源
- **遥测上送**：以 >= 1Hz 频率将遥测数据通过消息总线分发给消费者（gateway、strategy-engine 等）
- **故障录波**：检测故障条件时录制故障前后波形，支持波形数据的存储、查询、导出和北向上报
- **历史数据存储**：持久化存储周期性电气量数据、电池运行数据、告警日志和系统事件记录
- **设备台账管理**：管理管辖范围内所有设备的资产信息、铭牌参数、维护记录，支持北向上送
- **数据生命周期管理**：按配置策略自动清理过期数据，保障存储空间合理使用

### 1.2 目标平台

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux (openEuler 22.03+) |
| 硬件 | RK3588，存储介质：eMMC（默认 64GB）+ TF 卡扩展槽 |
| 编程语言 | Rust 1.75+ |
| 异步运行时 | Tokio 1.x |
| 数据库 | SQLite (rusqlite) |
| 消息总线 | tokio::sync::mpsc |

### 1.3 与上下游模块的关系

```
实时控制模块
     │
     ▼ (TCP/RJ45 高频数据帧)
intercore
     │
     ▼ (DataCollector 接收)
data-processing
     ├── HighFrequencyTelemetry ──→ 消息总线(telemetry.high_freq) ──→ gateway(北向上送)
     │                                                               └── strategy-engine(策略决策)
     ├── FaultRecorder ──→ 消息总线(telemetry.fault) ──→ gateway(北向上送)
     │                    ├── 波形文件(.wave) → 文件系统
     │                    └── 故障元数据 → SQLite
     ├── 历史数据存储 ──→ SQLite（电气量、电池数据、告警日志、事件记录）
     └── 设备台账管理 ──→ SQLite（资产信息、铭牌参数、维护记录）
```

| 上游模块 | 数据流向 | 说明 |
|----------|----------|------|
| intercore | → data-processing | TCP/RJ45 高频采样数据（10ms 间隔瞬时值帧） |

| 下游模块 | 数据流向 | 说明 |
|----------|----------|------|

## 2. 遥测数据采集与上送（≥1Hz）

### 2.1 DataCollector — 数据采集

**职责**：从 intercore 模块接收实时控制模块的数据，汇聚为统一数据源。

**接口定义**：

```rust
pub trait DataCollector {
    async fn start(&mut self) -> Result<(), DataProcessingError>;
    async fn stop(&mut self) -> Result<(), DataProcessingError>;
    fn get_latest_data(&self) -> Option<TelemetryData>;
}
```

**数据来源**：intercore 模块（TCP/RJ45）

**采集数据类型**：

| 数据类型 | 说明 | 单位 |
|----------|------|------|
| battery_soc | 电池荷电状态 | % |
| battery_power | 电池充放电功率 | kW |
| pv_output | 光伏出力 | kW |
| load_power | 负荷功率 | kW |
| grid_power | 电网功率（有功） | kW |
| transformer_load | 变压器负载率 | % |

**数据包内容**：电气量、电池数据、设备状态、UTC 时间戳

**验收标准 [DP-DC]**：

| ID | 验收条件 | 验证方法 |
|----|----------|----------|
| DP-DC-01 | DataCollector 能从 intercore 接收数据 | 单元测试 |

### 2.2 HighFrequencyTelemetry — 高频遥测

**职责**：以 >= 1Hz 频率上报遥测数据到消息总线。

**接口定义**：

```rust
pub trait HighFrequencyTelemetry {
    async fn start(&mut self) -> Result<(), DataProcessingError>;
    async fn stop(&mut self) -> Result<(), DataProcessingError>;
    fn get_current_value(&self, point: &str) -> Option<f64>;

```

**上报频率**：1Hz（可配置，动态调整采集周期）

**内存缓冲**：保留最近 1 分钟数据（60 条记录）

**消息主题**：

| 主题 | 内容 |
|------|------|
| `telemetry.high_freq` | 高频遥测数据 |
| `strategy.decision` | 策略决策结果 |

**验收标准 [DP-HF]**：

| ID | 验收条件 | 验证方法 |

| DP-HF-03 | 支持动态调整采集周期 | 单元测试 |

## 3. 故障录波（波形采样、触发条件、COMTRADE导出、上报）

### 3.1 产品背景与核心价值

MUPC Phase 3A 已实现 `FaultRecorder` 接口和 `FaultRecorderImpl` 的 SQLite 故障事件记录功能，但该实现仅记录故障事件的**元数据**（故障类型、触发条件阈值），未记录故障前后的**波形数据**（高频率采样的电气量时序数据）。

**解决的核心问题**：

| 问题 | 影响 | 解决方案 |
|------|------|----------|
| 故障时仅有事件记录，无波形数据可分析 | 运维人员无法定位故障根因 | 实现故障前后波形采样与存储 |
| 波形数据离线存储，不支持远程获取 | 故障分析依赖现场取数 | 实现波形数据北向上报（IEC 104 / MQTT） |
| 录波参数不可配置 | 无法适应不同工况场景 | 实现可配置的触发条件和采样参数 |
| 波形数据格式封闭 | 无法导入第三方分析工具 | 支持 COMTRADE / CSV 格式导出 |

**核心价值**：

- **故障根因分析**：通过故障前后的波形数据，准确定位过压、欠压、谐波畸变、短路等故障的起止时刻和演变过程
- **电能质量追溯**：为电压暂降、暂升、中断等电能质量事件提供波形证据
- **设备状态评估**：通过波形趋势分析断路器、变压器等设备的运行健康状况
- **事故调查取证**：满足电力系统事故调查对录波数据的合规性要求（保存期限 >= 30 天）

### 3.2 故障触发条件配置

#### 3.2.1 功能描述

支持以下触发条件的独立配置，每个条件包含启用开关、阈值和回差（滞回区间）。

| 触发条件 | 参数 | 默认值 | 单位 | 说明 |
|----------|------|--------|------|------|
| 过压触发 | 电压越上限阈值 | 420.0 | V | 相电压有效值超过阈值触发 |
| 过压触发 | 回差 | 10.0 | V | 电压回落到 阈值-回差 以下才解除触发 |
| 欠压触发 | 电压越下限阈值 | 200.0 | V | 相电压有效值低于阈值触发 |
| 欠压触发 | 回差 | 10.0 | V | 电压回升到 阈值+回差 以上才解除触发 |
| 过流触发 | 电流越上限阈值 | 150.0 | A | 相电流有效值超过阈值触发 |
| 过流触发 | 回差 | 5.0 | A | 电流回落到 阈值-回差 以下才解除触发 |
| 短路触发 | 电流突变量阈值 | 500.0 | A | 电流瞬时值超过阈值触发（不判有效值） |
| 频率越限触发 | 频率上限 | 50.5 | Hz | 频率超过上限触发 |
| 频率越限触发 | 频率下限 | 49.5 | Hz | 频率低于下限触发 |
| 频率越限触发 | 回差 | 0.1 | Hz | 频率回到范围内才解除触发 |
| 零序过流触发 | 零序电流阈值 | 20.0 | A | 零序电流超过阈值触发（接地检测） |

#### 3.2.2 验收标准 [TRG]

| ID | 验收条件 | 验证方法 |
|----|----------|----------|
| TRG-01 | 所有 6 种触发条件可独立启用/禁用 | 单元测试：逐个设置启用/禁用状态，确认触发逻辑生效/失效 |
| TRG-02 | 所有阈值参数可配置，配置即时生效 | 单元测试：修改阈值后，输入低于新阈值的信号不应触发，输入高于新阈值的信号应触发 |
| TRG-03 | 回差机制正确：触发后需信号回到阈值 +/- 回差范围内才解除 | 单元测试：设置回差后，触发信号短暂回落到阈值和阈值 +/- 回差之间，确认不解除触发 |
| TRG-04 | 多个触发条件同时满足时，每个故障事件记录所有触发条件 | 集成测试：输入同时触发过压和过频的信号，故障记录中两个条件均有标记 |

### 3.3 故障前后波形采样

#### 3.3.1 功能描述

故障触发时，录制触发点前后特定时间窗口内的高频采样数据。

**采样参数配置**：

| 参数 | 取值范围 | 默认值 | 说明 |
|------|----------|--------|------|
| 采样率 | 1kHz, 2kHz, 4kHz, 8kHz, 16kHz | 4kHz | 每通道每秒采样点数 |
| 故障前记录时长 | 40ms ~ 1000ms | 200ms | 触发时刻之前的采样记录长度 |
| 故障后记录时长 | 40ms ~ 5000ms | 1000ms | 触发时刻之后的采样记录长度 |
| 总记录时长 | 故障前 + 故障后 | 1200ms | 一次录波的总时长 |

**采样通道**：

| 通道组 | 通道数 | 内容 |
|--------|--------|------|
| 三相电压 | 3 | Ua, Ub, Uc 瞬时值 (V) |
| 三相电流 | 3 | Ia, Ib, Ic 瞬时值 (A) |
| 零序电压 | 1 | U0 瞬时值 (V) |
| 零序电流 | 1 | I0 瞬时值 (A) |
| 有功功率 | 1 | P 瞬时值 (kW) |
| 无功功率 | 1 | Q 瞬时值 (kVar) |
| 频率 | 1 | f 瞬时值 (Hz) |

**可配置通道选择**：用户可选择启用/禁用一个或多个通道组，节省存储空间。

**循环录波缓冲**：
- 设备启动后持续将高频采样数据写入环形缓冲区
- 缓冲区长度 = 故障前记录时长对应的采样点数（如 4kHz x 200ms = 800 点）
- 故障触发时，将缓冲区数据 + 持续写入的故障后数据打包为一次完整的波形记录

**双缓冲区机制**：
- 一次录波完成后立即切换到第二个缓冲区，保证连续故障不丢失波形数据
- 第一个缓冲区的数据在保存完成前不被覆盖

#### 3.3.2 验收标准 [SMP]

| ID | 验收条件 | 验证方法 |
|----|----------|----------|
| SMP-01 | 采样率可在 1kHz ~ 16kHz 范围内按指定档位配置 | 单元测试：设置不同采样率，确认采集的波形数据点间隔符合设定值 |

### 3.4 波形数据存储

#### 3.4.1 功能描述

**存储结构**：

波形数据与故障事件元数据分开存储：

| 存储类型 | 存储内容 | 存储引擎 | 说明 |
|----------|----------|----------|------|
| 元数据 | 故障事件记录（类型、时间、触发条件值） | SQLite | 已有 Phase 3A 实现，需扩展字段 |
| 波形数据 | 二进制格式的采样数据 | 文件系统 | 新增，按故障事件 ID 命名文件 |

**SQLite 扩展字段**（在现有 `fault_records` 表基础上增加）：

| 字段 | 类型 | 说明 |
|------|------|------|
| waveform_path | TEXT | 波形数据文件的路径（相对路径，相对于录波数据目录） |
| sample_rate | INTEGER | 本次录波的采样率（Hz） |
| pre_trigger_ms | INTEGER | 故障前记录时长（ms） |
| post_trigger_ms | INTEGER | 故障后记录时长（ms） |
| channel_mask | INTEGER | 录波通道的位掩码，标识启用的通道 |
| waveform_size | INTEGER | 波形数据文件大小（字节） |

**波形文件格式**（二进制紧凑格式）：

```
+------------------------------+
|  Header (64 bytes)           |
+------------------------------+
|  Channel 0 samples (N x f64) |
|  Channel 1 samples (N x f64) |
|  ...                         |
|  Channel M samples (N x f64) |
+------------------------------+
|  Footer (8 bytes): checksum  |
+------------------------------+
```

Header 格式：

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0 | 4B | magic | 魔数 `WAVE` (0x57415645) |
| 4 | 2B | version | 文件格式版本号 (v1 = 0x0001) |
| 6 | 2B | channel_count | 录波通道数 (<=10) |
| 8 | 8B | sample_count | 每通道样本数 |
| 16 | 8B | sample_rate | 采样率 (Hz) |
| 24 | 8B | trigger_timestamp | 触发时刻的 unix 时间戳 (ms) |
| 32 | 8B | trigger_offset | 触发点在样本序列中的偏移量（第几个样本） |
| 40 | 8B | pre_trigger_nsamples | 故障前样本数 |
| 48 | 8B | post_trigger_nsamples | 故障后样本数 |
| 56 | 4B | channel_mask | 通道启用位掩码 |
| 60 | 4B | reserved | 保留 |

**数据目录布局**：

```
/data/mupc/waveforms/
+-- index/
|   +-- fault_records.db
+-- recordings/
    +-- 2026/
        +-- 05/
            +-- 20260529_143022_001.wave
            +-- 20260529_143022_002.wave
```

文件名格式：`YYYYMMDD_HHMMSS_seq.wave`

#### 3.4.2 存储容量管理

**循环覆盖策略**：

| 策略参数 | 默认值 | 说明 |
|----------|--------|------|
| 单次录波存储上限 | 10 MB | 单个波形文件大小上限。超过上限时截断 |
| 总存储空间上限 | 2 GB | 波形数据目录占用磁盘空间上限 |
| 保留期限 | 30 天 | 超过此期限的波形文件可被自动删除 |
| 空余空间阈值 | 500 MB | 磁盘空余空间低于此值时，优先删除最旧的波形文件 |
| 单日录波次数上限 | 1000 次 | 每自然日录波次数超过此值时停止录波 |

**覆盖执行顺序**：
1. 先删除超过 30 天保留期限的波形文件
2. 若仍超出总存储空间上限，继续删除最旧的波形文件（无论是否过期）
3. 若磁盘空余空间仍低于 500MB，继续删除最旧波形文件
4. 每次覆盖操作删除的波形文件同时删除对应的故障事件记录中的 `waveform_path` 引用

### 3.8 多通道同步录波

#### 3.8.1 功能描述

- 所有采样通道使用同一个采样时钟，确保各通道数据在时间上严格对齐
- 单次录波的数据结构中，所有通道的采样点数量相同（均为 `sample_count`）
- 第 i 个采样时刻的数据在内存中表示为 `[ch0[i], ch1[i], ..., chN[i]]`

**通道间同步要求**：

| 要求 | 指标 |
|------|------|
| 通道间时延 | <= 1 个采样周期（如 4kHz 下 <= 250us） |
| 时间戳标定 | 每个采样点的时间戳精度 <= 100us |
| 各通道采样点数 | 严格相等，偏差 = 0 |

**周期性同步校验**：
- 每秒执行一次通道同步性校验
- 校验方法：向所有通道注入同一已知信号（如 50Hz 正弦波），确认各通道数据的相位差 <= 1 度

#### 3.8.2 验收标准 [CHN]

| ID | 验收条件 | 验证方法 |
|----|----------|----------|
| CHN-01 | 所有通道的采样点数严格相同 | 单元测试：触发录波后，检查 WaveformData 中各 channel 的 Vec 长度一致 |
| CHN-02 | 通道间相位差 <= 1 度（在 50Hz 信号下） | 集成测试：输入相同的 50Hz 正弦波到所有通道，计算各通道间相位差 |
| CHN-03 | 可选择启用/禁用一个或多个通道组 | 单元测试：设置 channel_mask 只包含三相电压，确认波形数据只包含 3 个通道 |
| CHN-04 | 通道间时延 <= 1 个采样周期 | 单元测试：同一时刻采集所有通道的值，记录时间戳偏差 |

### 3.9 故障事件与波形关联

#### 3.9.1 功能描述

- 故障事件记录（SQLite）与波形文件通过 `event_id` 关联

### 3.10 故障录波边界条件与异常处理

#### 3.10.1 存储空间不足

| 场景 | 行为 | 告警级别 |
|------|------|----------|
| 磁盘空余空间 < 500MB | 删除最旧波形文件直到空余空间 > 500MB，停止新录波 | 重要告警 |
| 磁盘空余空间 < 200MB | 紧急停止所有录波功能，保留核心功能运行 | 紧急告警 |
| 单次录波写入失败 | 将波形数据保留在内存缓冲区，30 秒后重试，重试 3 次放弃 | 告警 |
| 元数据写入失败（SQLite） | 当前录波整体失败，记录日志，不影响下一次录波 | 告警 |

#### 3.10.2 多故障并发

| 场景 | 行为 |
|------|------|
| 录波进行中（故障后时段）发生第二个故障 | 不中断当前录波，在第二个缓冲区启动第二次录波 |
| 两个缓冲器均满时发生第三个故障 | 丢弃当前录波中最旧的一次，释放一个缓冲区用于新的录波 |
| 同一秒内触发多次同类型故障 | 合并为一次故障事件，记录首次触发时间，后续触发更新事件状态 |
| 不同类型的故障在 100ms 内先后发生 | 作为独立事件分别录波，共享故障前重叠时段的波形数据 |

#### 3.10.3 采样数据丢失

| 场景 | 行为 |
|------|------|
| 单个采样点丢失 | 数据文件中用 `NaN` 填充缺失位置，在波形文件中标记 `data_quality=gap_detected` |
| 连续 10 个以上采样点丢失 | 中断当前录波，已录数据保留，标记 `data_quality=major_gap` |
| 所有通道同时数据丢失 | 可能为 intercore 通信中断，停止录波，发起通信重连 |
| 单个通道数据丢失 | 其他通道继续录波，缺失通道用 `NaN` 填充 |

#### 3.10.4 触发抖动处理

| 场景 | 行为 |
|------|------|
| 触发条件在临界值附近震荡 | 使用回差机制防止反复触发 |
| 同一故障条件在 1 秒内反复满足/解除 | 合并为一次故障事件，记录首次触发和最终解除时间 |
| 瞬态尖峰（< 1ms）误触发 | 触发条件判定引入 3 个连续采样点的确认窗口（防抖滤波） |

#### 3.10.5 配置异常

| 场景 | 行为 |
|------|------|
| 故障前记录时长 > 故障后记录时长 3 倍 | 拒绝配置，返回配置错误 |
| 采样率设置为不支持的值 | 四舍五入到最近的可用档位，记录日志提示 |
| 所有通道均禁用 | 拒绝配置，要求至少启用一个通道组 |
| 总记录时长 < 80ms | 拒绝配置（至少 40ms 前 + 40ms 后） |

```
  device_id (FK -> DEVICE_ASSET.device_id)
  maintenance_date
  maintenance_type (routine_inspection / fault_repair / firmware_upgrade /
                    part_replacement / calibration / other)
  description
  operator
  result (success / failed / partial)
  next_maintenance_date (nullable)
  created_at
```

**关键约束**：

- 支持按日期范围查询维护记录
- 单设备维护记录查询响应时间不超过 300ms

### 5.5 台账数据北向上送

#### 5.5.1 功能描述

**触发方式**：

| 触发方式 | 说明 | 优先级 |
|----------|------|--------|
| 主动全量上送 | 设备台账发生变更（新增/修改/删除）后 30 秒内自动上送 | 高 |

**关键约束**：

- 上送失败时自动重试，最多重试 3 次，重试间隔分别为 10s、30s、60s
- 上送结果记录日志，包含：上送时间、数据条数、成功/失败状态、失败原因

## 6. 数据生命周期管理

### 6.1 数据保留策略配置

#### 6.1.1 功能描述

系统支持为不同类型数据分别配置保留期限。

| 数据类型 | 默认保留期限 | 配置范围 | 说明 |

### 6.2 自动数据清理

#### 6.2.1 功能描述

系统每日凌晨 2:00（可配置）执行自动数据清理任务。

**清理逻辑**：
- 按数据类型分别执行，删除超出保留期限的数据记录
- 清理任务执行前检查可用存储空间：
  - 存储空间剩余 < 10% 时：触发告警"存储空间不足（critical）"
  - 存储空间剩余 < 5% 时：触发告警"存储空间即将耗尽（critical）"，同时缩短保留期限至默认值的 50%
- 清理过程记录日志：清理数据类型、删除记录数、清理耗时、释放空间大小
- 清理任务执行超时上限为 30 分钟，超时自动终止并记录告警
- 清理任务可手动触发

### 6.3 数据导出

## 8. 边界条件与异常处理

### 8.1 磁盘空间不足（通用）

| 磁盘使用率 | 系统行为 |
|------------|----------|
| >= 85% | 记录 WARN 级别日志 |
| >= 90% | 触发 minor 级别告警"磁盘空间即将不足" |
| >= 95% | 触发 critical 级别告警，立即执行紧急清理，停止历史数据写入 |
| >= 98% | 停止所有数据写入（含告警和事件），仅维持只读查询功能 |

### 8.2 数据写入失败（通用）

| 场景 | 处理方式 |
|------|----------|
| 单次写入超时（> 5 秒） | 放弃本次写入，记录错误日志，继续处理下一条 |
| 连续 10 次写入失败 | 触发告警"数据库写入异常"，每 5 分钟重试一次 |
| 数据库文件损坏 | 切换到降级模式，尝试修复，通知运维人员 |
| 数据库连接断开 | 自动重连，最多重试 5 次（间隔 1s、2s、4s、8s、16s），失败后触发告警 |

### 8.3 系统意外断电

- 数据写入采用事务保证单条写入的原子性
- 断电恢复后，未完成的事务自动回滚，不产生脏数据
- 系统启动时自动检查数据完整性
- 内存缓冲的数据在系统重启后丢失，但系统功能不中断

### 8.4 时间同步异常

- 所有数据记录的时间戳以系统时间为准
- 系统支持 NTP 时间同步
- 时间发生跳变（如 NTP 同步校正）时，不产生重复数据或数据空洞
- 未同步时数据标记 `time_quality=unsynchronized`

### 11.2 总表电气量落库口径（1 分钟聚合）

**R-11.2-A 聚合而非抽样**：落库记录为该聚合周期内的**统计聚合值**；**不得**用周期内的某一瞬时采样值（含"每分钟取 1 个采样点"）替代。

**R-11.2-B 聚合量**：每个聚合周期、每个可落通道产出**均值**；**分钟极值（最大 / 最小）** 按 Q2（§11.8）裁定的通道范围产出。

**R-11.2-C 时间戳口径**：记录时间戳 = 该聚合周期的**起点**，须对齐到 `grid_aggregate_period_ms` 的整数倍（UTC 毫秒），一个周期恰有 N 个通道记录（N = 可落通道数 + 极值通道数 × 2）。

**R-11.2-D 通道清单**（以 §4.1.1 维度为目标集，以点表实有为准）：

| 通道 | 落库 | 极值 | 现状可得性（依据） |
|------|------|------|-------------------|
| 三相电压 `u_a/u_b/u_c` | 均值 | 待定（Q2） | ✅ 点表 `u` 块（`mupc-southd/src/mapper.rs:151`） |
| 三相电流 `i_a/i_b/i_c` | 均值 | 待定（Q2） | ✅ 点表 `i` 块，**带方向符号**（`mapper.rs:152`、方向由分相有功符号承载 `:133-149`） |
| 三相有功 `p_a/p_b/p_c` | 均值 | — | ✅ 点表 `p` 块（`mapper.rs:153`） |
| 三相无功 `q_a/q_b/q_c` | 均值 | — | ✅ 点表 `q` 块（`mapper.rs:154`） |
| 三相功率因数 `pf_a/pf_b/pf_c` | 均值 | — | ✅ 点表 `pf` 块（`mapper.rs:155`） |

**R-11.2-E 缺测不得冒充**：周期内某通道无有效采样时，须以 `quality` 标记（§4.1.1 的 `quality` 字段）表达"无数据"，**不得写入 0** 冒充有效值；周期内**完全无有效采样**时仍须产出该周期记录（以便"断档"可被查询识别，而非静默少行）。

**R-11.2-F 数据量与存储成本量级**（按 §7.3 的 ~200 字节/条估算；按**单个总表站**计，采集周期 1000 ms —— 生效配置 `interval_ms: 1000`，`mupc_core_config.yaml:419`）：

| 落库形态 | 行/天 | 按 200 B/行 | 90 天 | 年 |
|----------|-------|-------------|-------|-----|
| 逐点 · 顶层 6 通道（现状若落库） | 51.8 万 | 104 MB/天 | 9.3 GB | 37.8 GB |
| 逐点 · 顶层 + 分相 21 通道 | 181 万 | 363 MB/天 | 32.7 GB | 132 GB |
| **1 分钟聚合 · 均值（21 通道）** | 3.0 万 | 6.0 MB/天 | 543 MB | 2.2 GB |
| 1 分钟聚合 · 分钟极值（+6 行/周期） | +0.86 万 | +1.7 MB/天 | +156 MB | +0.6 GB |
| **合计（均值 21 + 极值 6）** | **3.9 万** | **7.8 MB/天** | **~700 MB** | **~2.8 GB** |

- **结论**：逐点在 21 通道口径下 90 天即占数据分区（§7.3：44 GB）的 **74%**、1 年 132 GB（**不可行**）；1 分钟聚合 90 天仅 **~1.6%**，与 §6.1「电气量保留 90 天」相容。
- ⚠️ **口径提示（两种口径不可互推，更不可互相证明）**：本表按落库实现的**窄表**形态计（每个通道 1 行，`storage/src/services.rs:397-404`）；§7.3 按"**每设备每周期 1 条**（~200 B/条）"的**逻辑记录**口径计，**不按通道展开**。两者**维度不同**：同一"设备-周期"在窄表下实写 **27 行**（21 均值行 + 6 极值行），而 §7.3 只计 **1 条** ⇒ 同一设备同一天的物理占用**相差约 27×**（单设备：窄表 **7.8 MB/天**；按 §7.3 折算是 **288 KB/天**）。因此：① **不得**用 §7.3 反证本增量"容量一致"；② **不得**把 §7.3 的 28.8 MB/天（100 台设备）当作窄表形态下的预期值 —— 对窄表而言该值是**低估**（差约 27×）；③ 本增量的容量代价**只以本表为准**。§7.3 是否按物理行重算，属**另立需求**（见 §11.9）。

### 11.3 `storage:` 配置段（U-67）

**R-11.3-A 落点与生效**：配置项位于主配置文件 `mupc_core_config.yaml` 的**新增 `storage:` 段**（现状 `mupc-core-bin/src/core_config.rs` **无该段任何字段**；两份部署 YAML 也无该段）。**进 YAML、不进 DB**；**重启生效**（不引入 DB 覆写层，不做运行时热更新）。

> **命名消歧**：本节的 `storage:` **YAML 段**与 §5.6.2 原规划的 `/api/v1/storage`（保留期 / 空间策略的**管理面**路径，§6.1）**不是同一组配置** —— 后者属数据生命周期（保留期），本增量**不涉及**；两者的关系见 Q6。为避免混淆，本 `storage:` 段**只含 §11.3-B 三项**，不含保留期字段。

**R-11.3-B 字段清单**：

| 键 | 含义 | 默认值 | 取值范围 / 合法性 | 依据 |
|----|------|--------|------------------|------|
| `storage.batch_capacity` | 遥测写缓冲**批量提交容量**（条） | **1000** | **2 ~ 100000（须 ≥ 2）** | = 现实现 `startup.rs:661-665` 的 `WriteBuffer::new(1000, …)`。**⚠️ 合法域下限由 `1` 收窄为 `2`**（产品裁定 2026-09-26，见 §11.9 的 R-11.3-F）：`batch_capacity = 1` 时**每次 push 都落容量分支** ⇒ 采集路径**永不 `trim_oldest`** ⇒ **R-11.5-A2 的有界性保证失效**（非退化配置，是保证失效）。实现侧 `validate_storage` 已按此拒 `1` 并给出理由；YAML 注释同步 |
| `storage.flush_interval_ms` | 遥测写缓冲**提交间隔**（ms） | **5000** | 100 ~ 600000（须 ≥ 1，禁 0） | = 现实现的 `5000` |
| `storage.grid_aggregate_period_ms` | **总表电气量聚合落库周期**（ms） | **60000**（1 分钟） | 10000 ~ 3600000，且须为 1000 ms 的整数倍 | §4.1.1 / `:693`「默认 1 分钟」 |

**R-11.3-C 默认值即现状（零行为变化）**：`storage:` 段**整段缺省**时，`batch_capacity` / `flush_interval_ms` 落上述默认值，运行行为与本次变更前**逐条一致**。

**R-11.3-D 概念不得混用**（与 `03 设计文档` §4.4.2「口径对齐 / 概念消歧」同源）：`batch_capacity` 与 `flush_interval_ms` 是**flush 窗口**（缓冲区**提交节拍**，只影响落库延迟与事务粒度）；`grid_aggregate_period_ms` 是**存储周期**（记录**时间粒度**）。**两个量、不可相互推导**，不得合并为一个键，不得用前者解释后者。

**R-11.3-E 配置错误的处置**：**建议 = 拒启动**（fail-fast，报错点名违规键）。理由：① 三项均**仅在启动期读取一次**，静默降级会造成"以为配了其实没配"的失真；② 与 `core_config.rs` 既有惯例一致（`intercore` / `gateway` / `io` / `display` 段均为启动期校验、违规即 `Err`，见 `core_config.rs:464-517`）。**此条为建议，须产品确认（Q1）**；若裁为"告警 + 降级取默认"，则须同时给出降级的可观测要求（启动期一条 WARN + 运行期状态可见）。

**R-11.3-F `batch_capacity` 下限 = 2（产品裁定 2026-09-26）**：合法域为 **`2 ~ 100000`**，**拒绝 `1`**。理由：`batch_capacity = 1` 时**每次 `push` 都落容量触发分支**，而该分支**不裁剪**本批（"先谈提交再谈裁剪"语义的搬移）⇒ 采集路径**永不 `trim_oldest`** ⇒ **R-11.5-A2 的"缓冲区累计条数须有上界"失效**——这不是"退化但可用"的配置，是**保证失效**。实现落点：`mupc-core-bin/src/core_config.rs` 的 `validate_storage`（拒 `1` 并在错误文案里给出理由）；`WriteBuffer` 侧对"上界 = `max_points + 1`"的论证**补足前提「`capacity ≥ 2`」**（`mupc/crates/storage/src/services.rs`）。**注**：默认值 `1000` 不受影响；本裁定使接受域成为**旧字面域的真子集**，原 `1 ~ 100000（须 ≥ 1）` 一并订正为 `2 ~ 100000（须 ≥ 2）`。

### 11.5 落库失败语义（U-68③：最小加固）

**R-11.5-A 不得静默丢弃**：批量提交失败时，**不得**静默整批丢弃（现状 `storage/src/services.rs:279-310`：`flush()` 先 `drain` 再提交，失败即整批丢弃、仅有 error 日志）。要求：

| 编号 | 要求 |
|------|------|
| R-11.5-A1 | **回填**：提交失败的批次须**回填**缓冲区（保持原相对顺序），不丢；下一提交触发时重试 |
| R-11.5-A2 | **有界**：缓冲区累计条数须有上界（默认 = 2 × `batch_capacity`；是否独立成配置键见 Q1 附带项），超限时丢弃**最旧**数据 |
| R-11.5-A3 | **丢弃必告警并计数**：任何丢弃须同时 ①记录 error 日志（含丢弃条数）②产生一条 `major` 级告警/事件 ③丢弃计数累计可观测（§4.3 告警链路） |
| R-11.5-A4 | **告警不得风暴**：持续失败时按提交周期**聚合**告警（同一时段内的连续失败合并为一条并递增计数），不得每个周期各报一条 |
| R-11.5-A5 | **不阻塞采集**：上述机制不得影响采集侧（写入延迟仍满足 HST-ELEC-02 的 p99 ≤ 10 ms）；不得因落库失败退出进程或停止采集 |

**R-11.5-B 边界如实声明**：本要求**不覆盖**断电 / 进程被强杀 / 落盘介质故障等**进程内不可恢复**场景（内存中未提交数据丢失属已知边界）；§7.6「写入失败日志」中原"不上报告警"的口径**仅对单条写入失败**成立，**批量丢失必须告警**（与 R-11.5-A3 一致）。

| 内存最新值（总表电气量、外设遥测） | 北向上送（IEC 104）、策略引擎、上云（U-74） | 采集回调的**内存快照** | **不得**轮询历史表 |
| 内存最新值（外设数值，**若 U-73 立**） | 12 号本地屏外设页 | 采集回调的**内存快照**（§11.6.2 入口） | 同上；屏**现无**外设页（12 PRD 未含外设数值项） |
| 告警 / 事件 | 12 号本地屏 F7 | `storage.events` | 12 PRD §6（非 `telemetry`） |
| 12 屏 F1–F4（SOC / PCS 状态 / 三相有功 / 三相电流） | 12 号本地屏 | **核间 PCS 寄存器**（12 PRD §3.1 F1–F4，`:147-195`；主判据 REG 1013 `:163`） | 与 `telemetry` 表无关 |

**R-11.6-B 已知设计余量**：在历史查询入口落地前，`telemetry` 表**只写不读**属**已知设计余量**；**不得**据此宣称"历史数据查询功能已实现"。

**R-11.6-C 与另两份 PRD 的口径一致**：
- **与 01（通信网关）**：北向上送的取数为**内存最新值**，不查历史库 —— 保持 01 PRD §2.3「周期性发送遥测数据，周期可配置（默认 1 秒）」的语义（历史库只用于事后查询，与上送周期无关）。
- **与 12（本地显示终端）**：屏的 F1–F4 走核间寄存器、F7 走 `storage.events`，**均不轮询本模块历史表**；**屏若需展示外设数值（U-73）或上云若需外设点表（U-74），须走 §11.6.2 的入口，不得改为轮询 `telemetry` 表**。

#### 11.6.2 外设遥测"最新值快照 + 变更通知"入口（本模块为提供方）

**R-11.6-D 数据可用性要求**（消费方为 U-73 屏外设页 / U-74 上云点表）：

| 编号 | 要求 |
|------|------|
| R-11.6-D1 | 本模块须提供"**按设备 / 点的最新值快照**"（内存态），覆盖**全部已采集的外设遥测点**（标量点 + 位点 / 信号点），不得只覆盖总表 |
| R-11.6-D2 | **刷新活性（这是活性要求，不是过期判据）**：快照须随新采集值持续刷新 —— 任一有值点的时标与当前时刻之差**不慢于该站采集周期**（`south_stations.stations[].interval_ms`）。**过期判据以单一真源 `stale_timeout_s = 5 s` 为准**（01 PRD §8.5 LV-3 / §8.7、02 PRD §9.7.1 同源），**本模块不另立门限**；本行**不得**被读作"5 s 内必须判断为新鲜"的第二个阈值 |
| R-11.6-D3 | **陈旧 / 无值须可表达**：站离线或该点从未采集时，快照须能返回"无值 / 陈旧"态，**不得用 0 冒充**；**陈旧判定用 D2 末句的单一真源**（`stale_timeout_s = 5 s`），本模块不复述、不放宽、不加严 |
| R-11.6-D4 | **变更通知**：点值发生变化后，须在 **≤ 1 s** 内发出变更通知（供订阅方增量刷新，避免轮询）—— 与 01 PRD §8.5 LV-4「端到端时延 ≤ 1 s」、12 PRD RQ-9.0-2「≤1 s」**同一口径**，本模块**不另立数值** |
| R-11.6-D5 | 消费方**不得**通过轮询 `telemetry` 历史表获得最新值（与 R-11.6-A / R-11.6-C 同源） |

> **时延口径消歧（防再被读成冲突）**：R-11.6-D2 / D4 均为**本入口自身的时延**（快照刷新节奏 / 变更通知发出），**不含**南向采集耗时。若消费方另有"**采集完成 → 消费方可见**"的**端到端**时延要求，那是**另一个量**、由消费方 PRD 各自定义（12 PRD F25.3：≤ **站周期 + 1 帧节拍（≤1 s）**；01 PRD §8.7：采集完成 → IEC 104 发出 ≤ 周期 + 100 ms、→ MQTT 发出 ≤ 周期 + 1 s），**不得**与本入口时延互相换算、亦不得互相充当判据。
>
> **单一真源声明**：本入口属 12 PRD RQ-9.0-3 所指的**同一份**最新值快照（与 01 号上云、03 号存储查询共用），**不得**各自另建第二份真源，亦**不得**各自另立新鲜度门限。

**R-11.6-E 现状与前置**：该入口**当前不存在** —— 本地屏读 `storage.events`（非遥测），上云两条通道（MQTT / IEC 104）均未定义外设点表。**该入口的立与不立属独立需求**（U-73 / U-74），见 Q8。
