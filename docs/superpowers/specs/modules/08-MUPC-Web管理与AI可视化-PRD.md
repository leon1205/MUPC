## 1. 产品概述

### 1.1 产品定位

MUPC Web 管理与 AI 可视化模块是 MUPC 通信管理模块的本地人机交互层，承载以下核心职责：

1. **本地运维管理**：通过 Web UI 对 MUPC 装置进行状态监控、配置管理、日志查看等日常运维操作。
2. **AI 决策可视化**：将 AI 优化引擎（LSTM 预测、RL 决策）的"黑盒"输出转化为可读的可视化信息，使运维人员理解、信任并验证 AI 决策。
3. **专家干预与可控性**：提供人工干预途径，在 AI 决策不符合现场需求时允许专家修正优化目标或强制切换运行模式。
4. **A/B 测试与模型管理**：支持 AI 模型版本管理、灰度对比验证和安全回滚，降低模型更新风险。
5. **审计可追溯**：所有干预操作和关键变更记录完整审计日志，满足电力系统安全审计要求。

### 1.2 核心价值

| 价值 | 说明 |
|------|------|
| 可解释性 | 将 AI 决策过程转化为可视化信息，解决"黑盒"信任问题 |
| 可控性 | 提供人工干预途径，允许修正优化目标或强制切换运行模式 |
| 可验证性 | 通过 A/B 测试框架在灰度场景中验证模型更新效果 |
| 可追溯性 | 所有干预操作和模型变更均有完整审计日志 |

### 1.3 目标平台与环境

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux (openEuler 22.03+) |
| 硬件 | RK3588 |
| 后端语言 | Rust |
| 异步运行时 | Tokio |
| Web 框架 | Axum（或纯 HTTP 服务） |
| Web 浏览器 | Chrome 90+、Firefox 88+、Edge 90+ |
| HTTP 默认端口 | 8080 |
| WebSocket 端点 | `/ws/logs`（实时日志推送） |

### 1.4 适用范围

| 项目 | 说明 |
|------|------|
| 访问方式 | Web UI 浏览器访问 |
| 后端模块 | web-api、ai-engine、strategy-engine |
| 数据存储 | SQLite（审计日志、奖励历史、A/B 测试数据）、TOML 配置文件（权重、模式）、JSON 清单文件（模型版本） |

## 2. 用户角色

### 2.1 角色定义

| 角色 | 描述 | 核心职责 | 权限等级 |

| **AI 运维专家** | 具备 AI 模型知识和微电网背景的高级运维人员 | 可视化分析 AI 决策、触发 A/B 测试、执行模型回滚、监控在线微调 | 最高级（可操作所有功能） |

### 2.3 认证与授权机制

- **认证方式**：Session 登录模式（`POST /api/auth/login`）
- **默认用户**：admin（密码可配置，从配置文件中读取）
- **会话管理**：会话有效期内保持登录状态，浏览器关闭前有效
- **权限模型**：通过角色（Role）实现，每个用户绑定一个角色
- **角色配置**：角色定义存储在配置文件 `/etc/mupc/auth/roles.toml` 中
- **二级确认**：敏感操作（配置修改、权重调整、模式切换、A/B 测试、模型回滚）需二次确认对话框
- **三级确认 + 密码验证**：模型回滚需要三级确认 + 操作人密码二次身份验证
- **密码策略**：新密码长度 8-20 位，包含字母和数字
- **权限检查**：在 web-api 层执行权限校验，后端模块不重复校验
- **未认证访问**：访问任意受保护页面（除 `/login`）跳转至登录页面

## 3. 系统状态监控

### 3.1 功能描述

提供 MUPC 装置整体运行状态的实时监控看板，作为 Web UI 的默认首页（路由 `/`）。运维人员无需登录即可被重定向至登录页，登录后默认进入该页面。

### 3.2 显示内容

| 数据项 | 说明 | 更新频率 |
|--------|------|----------|
| 固件版本号 | 当前运行固件版本 | 页面加载时 |
| 编译时间 | 固件编译时间戳 | 页面加载时 |
| 运行时间（uptime） | 系统持续运行时长 | 5 秒 |
| CPU 温度 | RK3588 处理器温度 | 5 秒 |
| 内存使用率 | 系统内存占用百分比 | 5 秒 |
| IEC 104 连接状态 | 已连接/连接中/断开/未配置 | 5 秒 |
| intercore 连接状态 | 实时控制模块连接状态 | 5 秒 |
| AI 引擎状态 | 就绪/加载中/异常/未启用 | 5 秒 |
| 策略模式 | 当前运行策略模式 | 5 秒 |
| 最近告警 | 最近 10 条告警记录 | WebSocket 实时推送 |

### 3.3 状态指示灯

| 状态 | 颜色 | 样式 |
|------|------|------|
| 已连接/正常 | `#28A745` | 实心圆 |
| 连接中/等待 | `#FFC107` | 闪烁动画（1s 间隔） |
| 断开/错误 | `#DC3545` | 实心圆 |
| 未配置 | `#5F6368` | 空心圆 |

### 3.4 验收标准

- [ ] 状态监控页面作为默认首页（路由 `/`），页面自动刷新周期 5 秒
- [ ] 状态卡片以网格布局展示，每个卡片包含图标、标签和动态数值
- [ ] IEC 104 和 intercore 连接状态使用状态指示灯直观展示
- [ ] 告警列表最多展示 10 条最新记录，按时间倒序排列
- [ ] 页面底部状态栏展示系统状态、各模块连接状态和版本信息
- [ ] WebSocket 实时推送连接断开时，状态栏显示红色背景提示

## 4. 配置管理

### 4.1 功能描述

提供 MUPC 装置运行参数的 Web 配置界面（路由 `/config`），配置保存后自动生效，无需重启装置。

### 4.2 可配置项

| 配置分组 | 参数 | 默认值 | 范围/选项 |
|----------|------|--------|-----------|
| IEC 104 连接参数 | 对端 IP 地址 | — | 合法 IPv4 地址 |
| IEC 104 连接参数 | 端口 | 2404 | 1-65535 |
| IEC 104 连接参数 | 心跳间隔 | 10 秒 | 1 秒 ~ 60 秒 |
| intercore 通信参数 | 本地端口 | 2500 | 1-65535 |
| intercore 通信参数 | 对端端口 | 2501 | 1-65535 |
| 遥测与日志 | 遥测上报周期 | 1 秒 | ≥ 1 秒 |
| 遥测与日志 | 日志级别 | INFO | ERROR / WARN / INFO / DEBUG |

### 4.3 交互规范

- 配置按区域分区展示：IEC 104 连接参数、intercore 通信参数、遥测与日志
- 输入框焦点丢失时实时校验格式，提交保存时全面验证
- 验证失败时，输入框下方显示红色错误文字说明原因
- 保存操作需二次确认对话框确认
- 保存成功后显示绿色 Toast 提示（3 秒自动消失）
- 配置自动生效，无需重启装置
- 保存过程中按钮显示 loading 状态（文字变为"保存中..."）

### 4.4 验收标准

- [ ] 所有配置项通过 Web UI 可读、可写
- [ ] 心跳间隔配置范围限制 1~60 秒，越界时显示具体错误提示
- [ ] 配置保存后自动生效，无需重启
- [ ] 配置修改操作需要二次确认对话框
- [ ] 保存成功后显示成功提示，失败时显示错误提示
- [ ] 权限不足的用户无法看到保存按钮，仅看到只读的当前值

## 5. 日志管理

### 5.1 功能描述

提供系统日志的 Web 查看、搜索、筛选和导出功能（路由 `/logs`），支持 WebSocket 实时日志推送。

### 5.2 功能要求

| 功能 | 说明 |
|------|------|
| 实时日志查看 | WebSocket 推送，支持 ERROR / WARN / INFO / DEBUG 级别过滤 |
| 时间范围筛选 | 按起始时间和结束时间筛选日志 |
| 关键字搜索 | 支持按关键字搜索日志消息内容 |
| 日志导出 | 下载为 `.log` 格式文件，单次导出最大 10000 条 |
| 分页展示 | 简洁数字分页，每页显示固定条数 |

### 5.3 日志级别标签颜色

| 级别 | 颜色 |
|------|------|
| ERROR | `#DC3545`（红色背景） |
| WARN | `#FFC107`（橙色背景） |
| INFO | `#17A2B8`（蓝色背景） |
| DEBUG | `#9AA0A6`（灰色背景） |

### 5.4 WebSocket 实时推送规范

- WebSocket 连接状态显示在日志页面顶部
- 连接成功：绿色文字"实时日志已连接"
- 连接断开：红色文字"实时日志已断开，正在重连..."
- 日志自动滚动到最新（除非用户手动滚动到上方查看历史）
- 手动滚动到上方时停止自动滚动，显示"滚动到最新"按钮

### 5.5 验收标准

- [ ] 实时日志通过 WebSocket 推送，延迟 ≤ 2 秒
- [ ] 日志级别筛选支持多选，过滤结果实时更新
- [ ] 关键字搜索结果高亮显示匹配内容
- [ ] 日志导出为 `.log` 格式，单次导出不超过 10000 条
- [ ] 表格使用斑马纹（奇偶行不同背景色），行高 40px
- [ ] WebSocket 断开后自动重连

## 6. AI 决策可视化

### 6.1 实时预测曲线展示（路由 `/ai/predictions`）

#### 6.1.1 功能描述

展示 LSTM 模型输出的未来 15-30 分钟预测曲线，包括光伏出力预测和负荷预测两个独立视图。

#### 6.1.2 显示内容

| 数据项 | 说明 | 单位 | 更新频率 |
|--------|------|------|----------|
| 光伏出力预测曲线 | 未来 N 个时间步的光伏出力预测值，叠加实际历史曲线 | kW | 每 60 秒 |
| 负荷预测曲线 | 未来 N 个时间步的负荷预测值，叠加实际历史曲线 | kW | 每 60 秒 |
| 置信度区间 | 每条预测曲线的置信度范围（阴影区域表示） | — | 随预测数据同时更新 |
| 预测时间范围 | 显示预测起始时间和终止时间 | — | 随预测数据同时更新 |

#### 6.1.3 验收标准

- [ ] 光伏出力预测曲线和负荷预测曲线分别在独立图表区域展示
- [ ] 预测曲线叠加在过去 60 分钟的实际数据曲线上，形成时间轴连续的视图
- [ ] 置信度以阴影区域形式展示在预测曲线两侧
- [ ] 预测数据每 60 秒自动刷新一次
- [ ] 页面加载时显示当前最新一次的预测结果，无需等待完整周期
- [ ] 预测时间轴标注清晰的最小刻度单位（1 分钟）
- [ ] 鼠标悬停在曲线上时显示该时刻的具体数值
- [ ] 当 LSTM 模型未加载时，页面显示"预测模型未加载"提示

### 6.2 AI 决策逻辑展示（路由 `/ai/decision`）

#### 6.2.1 功能描述

展示 AI 引擎当前的决策状态、决策动作和决策依据，帮助运维人员理解 AI "为什么做出这个决策"。

#### 6.2.2 显示内容

| 区域 | 内容 | 更新频率 |
|------|------|----------|
| 当前系统状态 | SOC、光伏功率、负荷功率、电网功率、变压器负载 | 每 1 秒 |
| 决策动作 | 电池功率设定、负荷切除量、PV 限功率比例、置信度 | 每决策周期 |
| 决策依据 | 当前场景模式 + 各优化目标的实时贡献值 | 每决策周期 |

#### 6.2.3 决策依据展示规则

- 展示当前预设运行模式名称（如"农网灌溉模式"、"自主套利模式"等）
- 展示模式切换来源（远程调度/本地Web/配置文件）
- 列出当前模式下的奖励函数细分项及其实时值
- 每个细分项以进度条或数值卡片形式展示其在总奖励中的占比
- 决策置信度值以百分比形式展示（如 87.3%），并附带色标指示

#### 6.2.4 置信度色标

| 区间 | 颜色 |
|------|------|
| ≥ 80% | 绿色 |
| 60% ~ 80% | 黄色 |
| < 60% | 红色 |

#### 6.2.5 验收标准

- [ ] 当前系统状态数据每 1 秒刷新一次（与遥测频率一致）
- [ ] 决策动作数据随 AI 引擎决策周期同步更新
- [ ] 决策依据区域明确显示当前场景模式名称
- [ ] 奖励函数各细分项的数值实时更新，显示精确到小数点后 2 位
- [ ] 置信度值以百分比展示，附带色标指示
- [ ] 当 AI 引擎未启用时，页面显示"AI 引擎当前未启用，系统运行于本地策略模式"
- [ ] 当 AI 引擎推理异常时，页面显示错误信息及最后一次成功决策的时间戳

### 6.3 实时奖励值展示与历史趋势

#### 6.3.1 功能描述

在 AI 决策面板中展示实时奖励值及其历史趋势，评估模型收敛状态和决策质量变化。

#### 6.3.2 显示内容

| 数据项 | 说明 | 更新频率 |

## 8. A/B 测试管理

### 8.1 模型版本管理

#### 8.1.1 功能描述

支持多版本 AI 模型并存存储、版本元信息查询和状态管理。

#### 8.1.2 模型状态枚举

| 状态 | 说明 |
|------|------|
| active | 当前在线运行的模型版本（每个模型类型仅一个） |
| standby | 已加载但未激活，可作为 A/B 测试实验组 |
| archived | 已归档的历史版本，不可直接切换但可查询 |
| failed | 加载失败的版本（保留记录供分析） |

#### 8.1.3 数据模型

```json
{
  "model_id": "lstm_v1.2.0",
  "model_type": "lstm",
  "version": "1.2.0",
  "description": "使用 2026Q1 数据训练的光伏预测模型",
  "file_path": "/models/current/lstm/model.rknn",
  "file_size": 4587520,
  "md5": "a1b2c3d4e5f6...",
  "status": "active",
  "deployed_at": "2026-05-28T10:00:00Z",
  "metrics": { "mae": 0.15, "rmse": 0.22, "mape": 8.5 }
}
```

#### 8.1.4 验收标准

- [ ] 每个模型类型（lstm / maddpg / ppo）最多同时保留 5 个版本（active + standby）
- [ ] 版本信息持久化存储在 `/etc/mupc/models/manifest.json`
- [ ] 新增版本时自动检查可用磁盘空间，空间不足 200MB 时拒绝添加
- [ ] 版本查询接口响应时间 < 100ms
- [ ] 同一模型类型同一时刻只能有一个 active 版本
- [ ] 归档版本保留至少 30 天后方可物理删除

### 8.2 A/B 流量分配配置

#### 8.2.1 功能描述

支持选择实验组和对照组的模型版本、设置流量分配比例、启动和停止测试。

#### 8.2.2 配置参数

| 参数 | 类型 | 说明 |
|------|------|------|
| 模型类型 | enum | lstm / maddpg / ppo |

| 实验组版本 | string | 从 standby 版本中选择 |
| 流量分配比例 | integer | 实验组流量百分比（1-50） |
| 测试时长 | integer | 预计运行小时数（1-168） |

- 同一决策周期内，指定设备始终分配到同一模型版本

#### 8.2.4 验收标准

- [ ] 流量分配比例支持 1% 步进调节，上限 50%

- [ ] 测试启动后 5 秒内流量分配规则生效
- [ ] 可随时手动停止测试，停止后 5 秒内所有流量恢复至对照组

| 电池循环次数 | 实验组和对照组分别统计 |

### 8.4 模型安全回滚

#### 8.4.1 功能描述

提供一键回滚到指定历史版本的功能，支持手动和自动触发两种模式。

#### 8.4.2 回滚操作流程

```
1. AI 运维专家选择目标回滚版本
2. 点击"回滚到该版本"按钮
3. 三级确认：确认回滚 → 确认版本 → 输入密码
4. 系统执行回滚：
   a. 备份当前 active 模型到 rollback 目录
   b. 从目标版本目录复制模型到 current 目录
   c. 通知 AiIntegrator 重新加载模型
   d. 执行模型预热推理
   e. 更新版本记录和 manifest.json
5. 页面显示回滚进度和结果
6. 操作记录写入审计日志
```

#### 8.4.3 自动回滚触发条件

| 条件 | 阈值 |
|------|------|
| 模型加载失败 | 1 次 |
| 模型推理失败 | 连续 3 次 |
| 模型预热超时 | 30 秒 |

#### 8.4.4 验收标准

- [ ] 手动回滚操作需要三级确认 + 密码二次身份验证
- [ ] 回滚执行时间 < 60 秒（含模型加载和预热）
- [ ] 回滚成功后模型恢复正常推理
- [ ] 回滚失败时自动触发恢复机制，恢复到回滚前的版本
- [ ] 连续自动回滚 3 次后触发安全模式（使用本地兜底策略）
- [ ] 回滚操作记录完整审计日志
- [ ] 权限不足的用户无法看到回滚按钮
- [ ] 回滚不影响正在运行的 A/B 测试

| 场景 | 处理方式 |
|------|----------|
| 权重输入 < 0.0 或 > 5.0 | 红色边框 + 错误提示 |
| 权重提交失败 | 显示"提交失败，请重试"，保留用户修改 |
| AI 引擎繁忙（正在推理） | 模式切换请求排队，当前推理完成后执行 |
| 模式切换失败 | 保持原模式不变，显示"切换失败"及原因 |

### 9.4 A/B 测试异常

| 场景 | 处理方式 |
|------|----------|
| 实验组模型推理异常 | 该设备流量自动回退至对照组 |
| 实验组模型连续失败 | 自动暂停 A/B 测试，所有流量切回对照组 |
| 对照组模型异常 | A/B 测试自动停止，AI 引擎降级至本地策略模式 |
| 测试时长到期 | 自动停止测试，生成最终对比报告 |

### 9.5 微调异常

| 场景 | 处理方式 |
|------|----------|
| 缓冲区数据不足 | 状态显示"数据收集中"和当前数据量 |
| 微调过程中断 | 状态更新为"微调失败"，显示中断原因 |
| 微调后模型效果下降 | 自动放弃本次微调权重，回退至微调前版本 |
| 磁盘空间不足 | 阻止新数据点加入缓冲区，显示"缓冲区已满"告警 |
