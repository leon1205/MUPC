## 2. 需求1：自适应权重优化器

### 2.1 背景（Why）

**现状：** 奖励函数权重表（w1~w7）需人工配置，缺乏自适应调整能力。

**风险：**
- 不同台区工况差异大，固定权重难以普适
- 人工调参成本高，依赖专家经验
- 权重配置不当可能导致目标冲突或次优解

**专家原文：**
> "权重表（w1~w7）需人工配置，缺乏自适应调整能力。不同台区工况差异大，固定权重难以普适。人工调参成本高，依赖专家经验。权重配置不当可能导致目标冲突或次优解。"

### 2.2 现状分析

**当前权重配置（SceneWeights）：**


**问题：** 权重在整个运行周期内保持不变，无法根据台区实际表现动态调整。

### 2.3 方案（How）

#### 2.3.1 方案选型

| 方案 | 原理 | 优点 | 缺点 | 推荐 |
|------|------|------|------|------|
| **方案1：元学习（MetaRL）** | 基于历史性能数据训练元学习器，学习最优权重调整策略 | 可迁移到新台区，无需人工干预 | 需要离线训练数据和验证环境 | ✅ 推荐 |
| **方案2：NSGA-II 多目标优化** | Pareto 前沿搜索，同时优化多个目标（光伏消纳、电池寿命、变压器安全） | 多目标平衡，可解释性强 | 计算复杂度高，权重更新频率受限 | 待定 |

**推荐方案：方案1（MetaRL）+ 方案2（NSGA-II）双轨并行**

理由：
1. MetaRL 适合在线快速调整（周级更新）
2. NSGA-II 适合离线批量优化（离线验证环境）
3. 两者互补，形成"离线优化 + 在线微调"的闭环

#### 2.3.2 MetaRL 自适应权重优化器设计

```rust
/// 自适应权重优化器（v2.11 新增）
pub struct AdaptiveWeightOptimizer {
    /// 元学习器：基于历史性能数据学习最优权重调整方向
    meta_learner: MetaLearner,
    /// 当前权重快照（用于计算调整量）
    current_weights: RwLock<SceneWeights>,
    /// 权重调整历史（用于训练元学习器）
    adjustment_history: Vec<WeightAdjustment>,
    /// 性能指标收集器
    performance_collector: PerformanceCollector,
}

impl AdaptiveWeightOptimizer {
    /// 基于元学习优化权重
    /// 输入：历史性能指标（光伏消纳率、电池损耗、变压器负载、需量超标次数）
    /// 输出：优化后的权重配置
    pub async fn optimize_weights(&self, historical_performance: &HistoricalPerformance) -> SceneWeights {
        // 1. 提取性能特征
        let features = self.extract_features(historical_performance);

        // 2. 元学习器预测最优权重调整方向
        let adjustment = self.meta_learner.predict(&features);

        // 3. 应用调整（带约束剪裁）
        let new_weights = self.apply_adjustment(&adjustment);

        // 4. 记录调整历史
        self.record_adjustment(historical_performance, &adjustment);

        new_weights
    }

    /// 提取性能特征（用于元学习器输入）
    fn extract_features(&self, perf: &HistoricalPerformance) -> PerformanceFeatures {
        PerformanceFeatures {
            pv_utilization_rate: perf.pv_consume_rate(),      // 光伏消纳率
            battery_cycle_count: perf.battery_cycles(),      // 电池循环次数
            trafo_load_avg: perf.trafo_avg_load(),          // 变压器平均负载率
            demand_violation_count: perf.demand_violations(), // 需量超标次数
            reward_sum: perf.cumulative_reward(),           // 累积奖励
        }
    }

    /// 应用权重调整（带物理约束剪裁）
    fn apply_adjustment(&self, adjustment: &WeightAdjustment) -> SceneWeights {
        let current = self.current_weights.read().unwrap();
        let mut new_weights = current.clone();

        // 约束：权重必须为正
        for (i, w) in adjustment.delta.iter().enumerate() {
            new_weights.seasonal_load_management[i] =
                (current.seasonal_load_management[i] + w).max(0.01);
        }

        // 约束：权重比例合理性（w1 + w2 + ... + w8 = 8.3 基准）
        let sum: f64 = new_weights.seasonal_load_management.iter().sum();
        if sum > 0.0 {
            let scale = 8.3 / sum; // 归一化到基准权重和
            for w in &mut new_weights.seasonal_load_management {
                *w *= scale;
            }
        }

        new_weights
    }
}
```

## 3. 需求2：冲击负荷概率预测

### 3.1 背景（Why）

**现状：** 负荷预测为确定性格点预测（单一均值），无法捕捉概率分布特征。

**风险：**
- 农网台区灌溉水泵等冲击负荷具有随机性
- 确定性预测难以捕捉概率分布特征
- 可能导致需量控制失效

**专家原文：**
> "农网台区灌溉水泵等冲击负荷具有随机性。确定性预测难以捕捉概率分布特征。可能导致需量控制失效。"

### 3.2 现状分析

**当前 LSTM 预测输出（确定性）：**

```rust
// ai-engine/src/lstm_model.rs
pub struct LstmOutput {
    /// 预测值（未来 N 个时间步）
    pub predictions: Vec<f32>,
    /// 置信度 (0.0-1.0)
    pub confidence: f64,
}
```

**问题：** 仅输出单一预测值，无法反映负荷的不确定性。当冲击负荷（如灌溉水泵）启动时，实际负荷可能远高于预测均值，导致需量超标。

### 3.3 方案（How）

#### 3.3.1 分位数预测模型设计

将 LSTM 输出层从单一预测值扩展为多分位数预测：

```rust
/// 概率负荷预测输出（v2.11 新增）
#[derive(Debug, Clone)]
pub struct ProbabilisticLoadOutput {
    /// 预测时间戳
    pub timestamp: i64,
    /// 各分位数预测值
    pub quantiles: Vec<QuantilePrediction>,
    /// 基础负荷（50% 分位数）
    pub base_load: f32,
    /// 冲击负荷发生概率
    pub shock_probability: f64,
    /// 预测置信度
    pub confidence: f64,
}

/// 分位数预测
#[derive(Debug, Clone)]
pub struct QuantilePrediction {
    /// 分位数（0.0 ~ 1.0）
    pub quantile: f32,
    /// 预测值 (kW)
    pub value: f32,
}

impl LstmModel {
    /// 分位数预测（v2.11 新增）
    /// 输入：历史时间序列 + 协变量（温度、日期类型等）
    /// 输出：多分位数预测结果
    pub async fn predict_quantiles(
        &self,
        input: &LstmInput,
        covariates: &LoadCovariates,
    ) -> Result<ProbabilisticLoadOutput, AiEngineError> {
        // 1. 获取多个分位数的预测值
        let quantile_values = self.predict_multi_quantile(input, covariates).await?;

        // 2. 提取基础负荷（50% 分位数）
        let base_load = quantile_values
            .iter()
            .find(|q| (q.quantile - 0.5).abs() < 0.01)
            .map(|q| q.value)
            .unwrap_or(0.0);

        // 3. 计算冲击负荷概率
        let high_quantile = quantile_values
            .iter()
            .find(|q| (q.quantile - 0.9).abs() < 0.01)
            .map(|q| q.value)
            .unwrap_or(base_load);

        let shock_probability = self.calculate_shock_probability(base_load, high_quantile);

        // 4. 计算置信度
        let confidence = self.calculate_confidence(&quantile_values);

        Ok(ProbabilisticLoadOutput {
            timestamp: input.timestamp,
            quantiles: quantile_values,
            base_load,
            shock_probability,
            confidence,
        })
    }

    /// 计算冲击负荷发生概率
    /// P(shock) = 1 - Φ((median - mean) / std)
    /// 其中 std ≈ P90 - P50（高分位数与中位数的差值反映不确定性）
    fn calculate_shock_probability(&self, base_load: f32, high_quantile: f32) -> f64 {
        let spread = (high_quantile - base_load).max(1e-6);

        // 假设负荷服从正态分布，spread ≈ 1.28 * std（P90 对应 1.28σ）
        let std_approx = spread / 1.28;

        // 冲击阈值：超过 base_load + 2σ 视为冲击负荷
        let shock_threshold = base_load + 2.0 * std_approx;

        // 计算 P(load > shock_threshold)
        // P(X > x) = 1 - Φ((x - μ) / σ)
        let z_score = (shock_threshold - base_load) / std_approx.max(1e-6);

        // 使用误差函数近似正态分布 CDF
        // P(X > threshold) ≈ 0.5 * erfc(z_score / sqrt(2))
        let shock_prob = 0.5 * Self::erfc(z_score / 1.41421356);

        shock_prob as f64
    }

    /// 误差函数近似（用于正态分布 CDF 计算）
    fn erfc(x: f32) -> f32 {
        // 使用近似公式：erfc(x) ≈ exp(-x²) / (π * x + sqrt(π*x²+4))
        let abs_x = x.abs();
        if abs_x > 8.0 {
            return 0.0;
        }
        let exp_term = (-x * x).exp();
        let denom = std::f32::consts::PI * abs_x + (std::f32::consts::PI * x * x + 4.0).sqrt();
        exp_term / denom
    }
}

/// 负荷预测协变量
#[derive(Debug, Clone)]
```

#### 3.3.3 奖励函数集成

**需量控制场景应用冲击负荷概率预测：**

```rust
/// SCENE-B2: 需量控制 — R = w1*R_demand - w2*P_comfort（v2.11 扩展）
fn calc_demand_with_uncertainty(
    &self,
    action: &ActionOutput,
    state: &FusedSystemState,
    load_forecast: &ProbabilisticLoadOutput,
) -> f64 {
    let w = &self.weights.demand_control;

    // 基础需量控制奖励
    let demand_saved = (state.contract_demand - state.current_demand).max(0.0);
    let r_avoid = demand_saved * self.demand_penalty_rate;

    // 风险感知调整（v2.11 新增）
    // 考虑冲击负荷概率，预留额外安全裕度
    let risk_adjusted_demand = state.current_demand + 2.0 * (load_forecast.high_quantile - load_forecast.base_load);
    let risk_margin = if risk_adjusted_demand > state.contract_demand * 0.95 {
        // 预留 5% 安全裕度不足，产生风险惩罚
        -20.0 * ((risk_adjusted_demand - state.contract_demand * 0.95) / state.contract_demand)
    } else {
        0.0
    };

    let p_comfort = action.load_shedding * 0.5;

    w[0] * (r_avoid + risk_margin) - w[1] * p_comfort
}
```

## 4. 非功能性需求

### 4.1 性能

| 指标 | 要求 | 说明 |
|------|------|------|
| 权重优化推理延迟 | < 100ms | 元学习器单次推理 |
| 权重优化更新周期 | >= 1 小时 | 防止频繁更新 |
| 分位数预测延迟 | <= 1s | LSTM 分位数推理 |
| 冲击负荷概率计算延迟 | <= 10ms | 后处理计算 |
| 分位数预测精度 | P90 误差 < 15% | 概率预测准确性 |

### 4.2 可靠性

| 指标 | 要求 |
|------|------|
| 权重优化失败处理 | 使用上一有效权重，回退告警 |
| 分位数预测失败处理 | 回退到确定性预测（50% 分位数）|
| 元学习器训练失败处理 | 保持当前权重，不更新 |

### 4.3 安全性

| 需求 | 说明 |
|------|------|
| 权重边界约束 | 所有权重必须 > 0.01 且 < 10.0 |
| 权重调整幅度限制 | 单次更新变化不超过 20% |
| 权重和归一化 | 季节性负荷权重和保持 8.3 基准 |
| 分位数合法性校验 | 分位数预测值必须在 [0, max_capacity] 范围内 |

### 4.4 可解释性

| 需求 | 说明 |
|------|------|
| 权重调整日志 | 每次权重更新记录调整量、原因、效果 |
| 概率预测日志 | 记录冲击负荷概率、阈值、触发条件 |
