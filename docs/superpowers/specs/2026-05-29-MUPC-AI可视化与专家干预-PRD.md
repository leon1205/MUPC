## 1. 产品概述

### 1.1 产品定位

本 PRD 定义 MUPC 通信管理模块中 **AI 决策可视化与专家干预** 功能的完整需求。该功能是 Phase 3C AI 优化引擎的配套人机交互能力，主要解决以下三个缺口：

| 缺口编号 | 缺口名称 | 优先级 | 来源 |
|----------|----------|--------|------|
| M-05 | AI 决策可视化 | 中 | 功能清单 6.4 |
| M-07 | 手动调整优化目标权重 | 中 | 功能清单 6.4 |
| M-08 | A/B 测试框架 | 中 | Phase 3C.2 延迟项 |

### 1.2 核心价值

1. **可解释性**：将 AI 引擎的"黑盒"决策过程（预测曲线、决策动作、置信度）转化为可读可视化信息，使运维人员理解和信任 AI 输出。
2. **可控性**：提供专家手动干预途径，在 AI 决策不符合现场需求时，允许人工修正优化目标或强制切换运行模式。
3. **可验证性**：通过 A/B 测试框架，在灰度场景中验证模型更新效果后再全量推广，降低模型更新风险。
4. **可追溯性**：所有干预操作和模型变更均有完整审计日志，满足电力系统安全审计要求。

### 1.3 适用范围

| 项目 | 说明 |
|------|------|
| 设备 | MUPC 微电网特种调控装置 |
| 平台 | Linux (openEuler)、RK3588 |
| 硬件 | ARM64、NPU (RKNN) |
| 访问方式 | Web UI 浏览器访问（Chrome 90+、Firefox 88+、Edge 90+） |
| 后端模块 | ai-engine、strategy-engine、web-api、Web UI |

## 2. 用户角色

### 2.1 角色定义

| 角色 | 描述 | 核心职责 | 权限等级 |
|------|------|----------|----------|
| **AI 运维专家** | 具备 AI 模型知识和微电网背景的高级运维人员 | 可视化分析 AI 决策质量、触发 A/B 测试、执行模型回滚、监控在线微调进度 | 最高级（可操作所有功能） |
| **策略管理员** | 负责微电网日常策略配置和优化的运维人员 | 查看预测曲线和决策结果、手动调整优化目标权重、手动切换运行模式 | 中级（可操作权重和模式切换，不可操作 A/B 测试和模型回滚） |
| **调度人员** | 值班调度人员，负责监控系统实时运行状态 | 只读查看 AI 决策面板、实时奖励值和运行模式状态 | 只读（不可执行任何干预操作） |

### 2.2 权限分级规则

| 操作类型 | AI 运维专家 | 策略管理员 | 调度人员 |
|----------|-------------|------------|----------|
| 查看 AI 决策面板 | 允许 | 允许 | 允许 |
| 查看预测曲线 | 允许 | 允许 | 允许 |
| 查看实时奖励值 | 允许 | 允许 | 允许 |
| 手动调整优化目标权重 | 允许 | 允许 | 拒绝 |
| 强制切换运行模式 | 允许 | 允许 | 拒绝 |
| 配置 A/B 测试 | 允许 | 拒绝 | 拒绝 |
| 执行模型回滚 | 允许 | 拒绝 | 拒绝 |
| 监控在线微调 | 允许 | 允许 | 拒绝 |
| 查看审计日志 | 允许 | 允许（仅自身操作）| 拒绝 |

### 2.3 认证与授权机制

- 用户登录使用已有的 Session 登录模式（`POST /api/auth/login`）
- 权限模型通过角色（Role）实现，每个用户绑定一个角色
- 角色定义存储在配置文件 `/etc/mupc/auth/roles.toml` 中
- 所有写操作（调整权重、切换模式、启动 A/B 测试、回滚模型）均需要二次确认对话框确认
- 权限检查在 web-api 层执行，后端模块不重复校验

### 3.1 AI 决策可视化面板

#### 功能 3.1.1：实时预测曲线展示

**User Story：**
> 作为策略管理员，我需要在 Web UI 上实时查看光伏出力预测曲线和负荷预测曲线，以便了解 AI 引擎对未来短时工况的判断。

**描述：**
Web UI 新增 `/ai/predictions` 路由页面，展示 LSTM 模型输出的未来 15-30 分钟预测曲线。预测曲线包括光伏出力预测和负荷预测两个独立视图。

**数据来源：**
- LSTM 模型的 `predict()` 输出（`LstmOutput.predictions` 和 `LstmOutput.confidence`）
- data-processing 模块提供的实时遥测数据作为历史基线

**显示内容：**
| 数据项 | 说明 | 单位 | 更新频率 |
|--------|------|------|----------|
| 光伏出力预测曲线 | 未来 N 个时间步的光伏出力预测值，叠加实际历史曲线 | kW | 每 60 秒刷新一次 |
| 负荷预测曲线 | 未来 N 个时间步的负荷预测值，叠加实际历史曲线 | kW | 每 60 秒刷新一次 |
| 置信度区间 | 每条预测曲线的置信度范围（阴影区域表示） | - | 随预测数据同时更新 |
| 预测时间范围 | 显示预测起始时间和终止时间 | - | 随预测数据同时更新 |

**验收标准：**
- [ ] 光伏出力预测曲线和负荷预测曲线分别在独立图表区域展示
- [ ] 预测曲线叠加在过去 60 分钟的实际数据曲线上，形成时间轴连续的视图
- [ ] 置信度以阴影区域形式展示在预测曲线两侧
- [ ] 预测数据每 60 秒自动刷新一次
- [ ] 页面加载时显示当前最新一次的预测结果，无需等待完整周期
- [ ] 预测时间轴标注清晰的最小刻度单位（1 分钟）
- [ ] 鼠标悬停在曲线上时显示该时刻的具体数值
- [ ] 当 LSTM 模型未加载时，页面显示"预测模型未加载"提示

#### 功能 3.1.2：AI 决策逻辑展示

**User Story：**
> 作为 AI 运维专家，我需要查看 AI 引擎的当前决策状态和决策依据，以便评估决策的合理性。

**描述：**
Web UI 新增 `/ai/decision` 路由页面，展示 AI 引擎当前的决策状态、决策动作和决策依据。该页面帮助运维人员理解 AI "为什么做出这个决策"。

**显示内容：**

| 区域 | 内容 | 说明 |
|------|------|------|
| 当前状态 | SystemState 的实时值：SOC、光伏功率、负荷功率、电网功率、变压器负载 | 显示当前系统工况快照 |
| 决策动作 | ActionOutput 的实时值：电池功率设定、负荷切除量、PV 限功率比例、置信度 | 显示 AI 引擎最近一次输出的决策 |
| 决策依据 | 当前场景模式 + 各优化目标的实时贡献值 | 展示决策的量化依据 |

**决策依据展示规则：**
- 展示当前场景识别结果（如"农网灌溉模式"、"工商业自主套利模式"等）
- 列出当前场景下的奖励函数细分项及其实时值，例如：
  - 农网模式：光伏消纳奖励 +X.XX / 电压治理奖励 +X.XX / 电池损耗惩罚 -X.XX / 变压器过载惩罚 -X.XX
  - 工商业模式-自主套利：电价差收益 +X.XX / 电池损耗成本 -X.XX
- 每个细分项以进度条或数值卡片形式展示其在总奖励中的占比

**验收标准：**
- [ ] 当前系统状态数据每 1 秒刷新一次（与遥测频率一致）
- [ ] 决策动作数据随 AI 引擎决策周期同步更新
- [ ] 决策依据区域明确显示当前场景模式名称
- [ ] 奖励函数各细分项的数值实时更新，显示精确到小数点后 2 位
- [ ] 置信度值以百分比形式展示（如 87.3%），并附带色标指示（绿 > 80%、黄 60-80%、红 < 60%）
- [ ] 当 AI 引擎未启用时，页面显示"AI 引擎当前未启用，系统运行于本地策略模式"
- [ ] 当 AI 引擎推理异常时，页面显示错误信息及最后一次成功决策的时间戳

#### 功能 3.1.3：实时奖励值展示与历史趋势

**User Story：**
> 作为 AI 运维专家，我需要查看 AI 引擎的实时奖励值及其历史趋势，以便评估模型收敛状态和决策质量变化。

**描述：**
在 AI 决策面板中包含实时奖励值展示和历史趋势图，展示总奖励值及各项子奖励的时序变化。

**显示内容：**
| 数据项 | 说明 | 更新频率 |
|--------|------|----------|
| 当前总奖励值 | 最近一次 RL 决策的总奖励数值 | 每决策周期更新 |
| 各子奖励值 | 光伏消纳奖励、电压治理奖励、电池损耗惩罚等细分项 | 每决策周期更新 |
| 奖励趋势图 | 过去 24 小时的总奖励时序曲线 | 每 5 分钟聚合一次 |
| 子奖励趋势图 | 过去 24 小时各子奖励项的堆叠或分组时序曲线 | 每 5 分钟聚合一次 |

**数据存储：**
- 奖励值历史记录存储在 SQLite 数据库中（复用 data-processing 的存储机制）
- 保留最近 30 天的奖励值历史
- 采样粒度：近 1 小时每决策周期记录一次，超过 1 小时每 5 分钟聚合为平均值

**验收标准：**
- [ ] 当前总奖励值以醒目数值卡片展示，颜色依据正负区分（正值绿色、负值红色）
- [ ] 各子奖励值以列表形式展示，按绝对值从大到小排序
- [ ] 奖励趋势图时间轴跨度支持 1 小时 / 6 小时 / 24 小时 / 7 天切换
- [ ] 趋势图中标注奖励值的最大值、最小值和平均值
- [ ] 历史数据查询响应时间 < 1 秒（查询范围 7 天内）
- [ ] 当历史数据不足时，趋势图显示"数据收集中"提示

#### 功能 3.1.4：场景识别状态展示

**User Story：**
> 作为调度人员，我需要查看系统当前运行模式，以便了解 AI 引擎采用何种策略进行优化。

**描述：**
在 AI 决策面板顶部显示当前场景识别状态和运行模式，包括自动识别结果和手动切换状态。

**显示内容：**
| 数据项 | 说明 |
|--------|------|
| 当前运行模式 | 自动识别或手动指定的模式名称（农网灌溉模式 / 工商业模式-自主套利 / 工商业模式-需量控制 / 工商业模式-虚拟电厂 / 工商业模式-极致绿色 / 本地兜底模式） |
| 识别置信度 | 场景识别模型的置信度百分比（自动识别模式时有效） |
| 模式来源 | 自动识别 / 手动指定 / 兜底模式 |
| 手动切换标记 | 若当前模式由专家手动指定，显示"手动"标签 |

**验收标准：**
- [ ] 当前运行模式名称在面板顶部居中展示，字号大于其他内容
- [ ] 自动识别模式下显示识别置信度百分比
- [ ] 手动切换的模式带有"手动"标签，与自动识别模式在视觉上区分
- [ ] 兜底模式使用特殊颜色（橙色背景）突出显示，提示运维人员需关注
- [ ] 模式切换事件记录时间戳，可供审计查询

### 3.2 专家干预功能

#### 功能 3.2.1：手动调整优化目标权重

**User Story：**
> 作为策略管理员，我需要在特定场景下手动调整各优化目标的权重，以便在 AI 自动优化无法满足现场需求时进行人工修正。

**描述：**
Web UI 新增 `/ai/intervention` 路由页面中的"优化目标权重调整"区域，提供滑块/数值输入方式修改各优化目标的权重参数。权重调整实时生效，由 web-api 转发至 strategy-engine 的 AiIntegrator。

**可调整的优化目标权重：**

| 权重参数 | 适用模式 | 默认值 | 调整范围 | 说明 |
|----------|----------|--------|----------|------|
| 光伏消纳权重 | 全部模式 | 1.0 | 0.0 - 5.0 | 光伏消纳的重要性 |
| 电压治理权重 | 农网模式 | 1.0 | 0.0 - 5.0 | 电压质量的重要性 |
| 电池损耗权重 | 全部模式 | 1.0 | 0.0 - 5.0 | 电池寿命保护的重要性 |
| 变压器过载权重 | 全部模式 | 1.0 | 0.0 - 5.0 | 变压器保护的重要性 |
| 电价差收益权重 | 工商业-自主套利 | 1.0 | 0.0 - 5.0 | 套利收益的重要性 |
| 需量罚金减免权重 | 工商业-需量控制 | 1.0 | 0.0 - 5.0 | 需量控制的重要性 |
| 绿电消纳权重 | 工商业-极致绿色 | 1.0 | 0.0 - 5.0 | 绿电比例的重要性 |

**调整方式：**
- 每个权重参数提供滑块控件（连续滑动）和数值输入框（手动输入）
- 滑块和输入框双向绑定：滑动滑块时数值框同步更新，输入数值时滑块同步移动
- 权重参数列表根据当前运行模式动态展示（不相关参数隐藏或置灰禁用）

**操作流程：**
```
1. 策略管理员打开干预页面
2. 页面显示当前运行模式下可调整的权重参数列表及当前值
3. 管理员通过滑块或输入框调整一个或多个权重参数
4. 调整完成后点击"应用"按钮
5. 系统弹出二次确认对话框："确认修改优化目标权重？修改将实时生效"
6. 管理员确认后，权重参数通过 API 提交到 web-api
7. web-api 将新的权重配置转发至 strategy-engine 的 AiIntegrator
8. AI 引擎在下一次决策循环中使用新权重
9. 页面显示"权重已更新"提示
10. 操作记录写入审计日志
```

**验收标准：**
- [ ] 权重参数列表根据当前运行模式动态展示，仅显示该模式下有效的参数
- [ ] 每个权重参数均提供滑块（连续）和数值输入框（支持小数输入）两种操作方式
- [ ] 滑块两端标注参数名称和当前数值
- [ ] 数值输入框校验输入范围，越界时显示红色错误提示"权重值必须在 0.0 ~ 5.0 之间"
- [ ] 修改未应用时，参数显示为"已修改未应用"状态（视觉标记如黄色感叹号）
- [ ] 应用操作需要二次确认对话框确认
- [ ] 确认后 2 秒内权重参数生效，页面显示成功提示
- [ ] 操作记录写入审计日志，包含：操作人、操作时间、调整前权重值、调整后权重值
- [ ] 权限不足的用户（调度人员）无法看到滑块和按钮，仅看到只读的当前值
- [ ] 每次权重修改操作记录独立审计条目
- [ ] 权重值在设备重启后保持最后一次手动设置的值（持久化到配置文件）

#### 功能 3.2.2：强制切换运行模式

**User Story：**
> 作为策略管理员，当 AI 自动场景识别结果不符合现场实际工况时，我需要能手动强制切换运行模式。

**描述：**
在专家干预页面中提供"运行模式切换"区域，支持在合法模式之间手动切换。手动切换后的模式将替代自动识别结果，直到管理员取消手动指定。

**可切换的运行模式：**

| 模式名称 | 说明 | 适用场景 |
|----------|------|----------|
| 农网灌溉模式 | 以光伏消纳和电压治理为主要目标 | 农网台区灌溉季节 |
| 工商业-自主套利 | 以电价差套利为主要目标 | 工商业储能峰谷套利 |
| 工商业-需量控制 | 以减少需量罚金为主要目标 | 变压器容量受限场景 |
| 工商业-虚拟电厂 | 以辅助服务收益为主要目标 | 参与 VPP 聚合调度 |
| 工商业-极致绿色 | 以绿电消纳最大化为主要目标 | 绿色认证要求高的场景 |
| 本地兜底模式 | 降级至本地策略引擎 | AI 异常或特殊维护场景 |

**操作流程：**
```
1. 策略管理员打开干预页面
2. 页面显示当前运行模式（标注为"自动识别"或"手动指定"）
3. 管理员从模式下拉列表中选择目标模式
4. 点击"切换模式"按钮
5. 系统弹出二次确认对话框："确认切换至 [模式名称]？切换后 AI 将采用新模式对应的优化目标"
6. 管理员确认后，模式切换指令通过 API 提交
7. web-api 将指令转发至 strategy-engine，后者通知 ai-engine 更新场景配置
8. AI 引擎从下一次决策循环开始使用新模式
9. 页面显示"模式已切换至 [模式名称]"提示，模式来源标记更新为"手动指定"
10. 操作记录写入审计日志
```

**取消手动指定：**
- 干预页面提供"恢复自动识别"按钮
- 点击后自动场景识别恢复，模式来源标记更新为"自动识别"
- 该操作同样需要二次确认和审计记录

**验收标准：**
- [ ] 模式切换下拉列表仅展示当前模式下可切换的选项（不包含当前模式自身）
- [ ] 切换操作需要二次确认对话框确认
- [ ] 确认后 2 秒内新模式生效
- [ ] 切换后当前运行模式显示"手动"标记

#### 功能 3.3.1：模型版本管理

**User Story：**
> 作为 AI 运维专家，我需要管理多个版本的 AI 模型，以便在 A/B 测试中对比不同版本的效果。

**描述：**
新增模型版本管理功能，支持多版本模型并存存储、版本元信息查询。

**数据模型：**

```json
{
  "model_id": "lstm_v1.2.0",
  "model_type": "lstm",
  "version": "1.2.0",
  "description": "使用 2026Q1 数据训练的光伏预测模型",
  "file_path": "/models/current/lstm/model.rknn",
  "file_size": 4587520,
  "md5": "a1b2c3d4e5f6...",
  "status": "active",
  "deployed_at": "2026-05-28T10:00:00Z",
  "metrics": {
    "mae": 0.15,
    "rmse": 0.22,
    "mape": 8.5
  }
}
```

**模型状态枚举：**

| 状态 | 说明 |
|------|------|
| active | 当前在线运行的模型版本（每个模型类型仅一个） |
| standby | 已加载但未激活，可作为 A/B 测试实验组（每个模型类型可多个） |
| archived | 已归档的历史版本，不可直接切换但可查询 |
| failed | 加载失败的版本（保留记录供分析） |

**验收标准：**
- [ ] 每个模型类型（lstm / maddpg / ppo）最多同时保留 5 个版本（active + standby）
- [ ] 版本信息持久化存储在 `/etc/mupc/models/manifest.json`
- [ ] 新增版本时自动检查可用磁盘空间，空间不足 200MB 时拒绝添加
- [ ] 版本查询接口响应时间 < 100ms
- [ ] 同一模型类型同一时刻只能有一个 active 版本
- [ ] 归档版本保留至少 30 天后方可物理删除

#### 功能 3.3.2：A/B 流量分配配置

**User Story：**
> 作为 AI 运维专家，我需要配置 A/B 测试的流量分配比例，以便在真实运行环境中验证新模型效果。

**描述：**
在专家干预页面中提供"A/B 测试配置"区域，支持选择实验组和对照组的模型版本、设置流量分配比例、启动和停止测试。

**配置参数：**

| 参数 | 类型 | 说明 |
|------|------|------|
| 模型类型 | enum | lstm / maddpg / ppo |
| 对照组版本 | string | 当前 active 版本（自动填充，不可修改） |
| 实验组版本 | string | 从 standby 版本中选择 |
| 流量分配比例 | integer | 实验组流量百分比（1-50），对照组自动为 100-实验组比例 |
| 测试时长 | integer | 预计运行小时数（1-168） |
| 评估指标 | array | 选择用于效果对比的指标列表 |

**流量分配机制：**
- 流量分配基于决策请求的 hash 值（如按照 device_id + 时间戳的 hash 取模）
- 同一决策周期内，指定设备始终分配到同一模型版本（确定性的 hash 路由）
- 实验组流量比例上限为 50%（确保多数设备运行稳定版本）

**操作流程：**
```
1. AI 运维专家打开 A/B 测试配置区域
2. 系统自动列出待选的 standby 模型版本及其离线评估指标
3. 专家选择实验组版本、设置流量比例（如 20%）、选择评估指标
4. 点击"启动测试"按钮
5. 系统校验：实验组版本与对照组版本属于同一模型类型
6. 系统校验：实验组版本不为空且状态为 standby
7. 系统弹出二次确认对话框"
8. 专家确认后，A/B 测试开始
9. AiIntegrator 根据流量分配规则将指定比例的决策请求路由到实验组模型
10. 页面显示测试运行中状态和时间进度
```

**验收标准：**
- [ ] 实验组版本只能从 standby 状态中选择
- [ ] 流量分配比例支持 1% 步进调节，上限 50%
- [ ] 启动测试时校验实验组与对照组属于同一模型类型，不匹配时拒绝启动
- [ ] 同一时刻每个模型类型只能有一个运行中的 A/B 测试
- [ ] 流量分配基于确定性 hash，同一设备在测试期间始终分配到同一组
- [ ] 测试启动后 5 秒内流量分配规则生效
- [ ] 可随时手动停止测试，停止后 5 秒内所有流量恢复至对照组
- [ ] 测试启动和停止操作均记录审计日志

#### 功能 3.3.3：效果对比指标展示

**User Story：**
> 作为 AI 运维专家，我需要实时查看 A/B 测试的对比指标，以便判断新模型是否优于当前模型。

**描述：**
A/B 测试运行期间和结束后，在测试详情页面展示实验组与对照组的各项效果指标对比。

**对比指标：**

| 指标 | 说明 | 计算方式 |
|------|------|----------|
| 平均奖励值 | 决策周期内的平均总奖励 | 实验组和对照组分别统计 |
| 光伏消纳率 | 光伏出力中被有效利用的比例 | 实验组和对照组分别统计 |
| 电压合格率 | 电压在合格范围内的时段占比 | 实验组和对照组分别统计 |
| 变压器负载率峰值 | 变压器最大负载率 | 实验组和对照组分别统计 |
| 电池循环次数 | 等效满充放电循环次数 | 实验组和对照组分别统计 |
| 平均决策置信度 | AI 输出置信度的平均值 | 实验组和对照组分别统计 |

**展示方式：**
- 每个指标以并排双柱图展示（左侧：对照组，右侧：实验组）
- 指标差异以百分比变化标注（如 "+5.2%" 或 "-3.1%"）
- 统计显著性标记（p-value < 0.05 时标注"显著"，否则标注"不显著"）
- 支持导出对比报告为 JSON 格式

**验收标准：**
- [ ] 对比指标在测试启动后 5 分钟内开始展示初始数据
- [ ] 指标数据每分钟更新一次
- [ ] 每个指标以并排柱状图展示，颜色区分：对照组蓝色、实验组绿色
- [ ] 指标变化百分比以红色（下降）或绿色（上升）标注
- [ ] 统计显著性标记在数据量达到统计学要求后自动显示
- [ ] 对比报告支持导出为 JSON 格式
- [ ] 测试结束后，页面自动生成最终对比报告摘要

#### 功能 3.3.4：模型安全回滚

**User Story：**
> 作为 AI 运维专家，当 A/B 测试中新模型效果不如当前模型，或模型上线后出现异常时，我需要能一键回滚到指定历史版本。

**描述：**
在模型版本管理页面和 A/B 测试结果页面提供模型回滚操作入口，支持回滚到任意已归档的历史版本。

**回滚操作流程：**
```
1. AI 运维专家打开模型管理页面或 A/B 测试结果页面
2. 选择目标回滚版本（从历史版本列表中选择）
3. 点击"回滚到该版本"按钮
4. 系统弹出三级确认对话框：
   第一级："确认回滚？"
   第二级："回滚将切换至 [版本号]，确定？"
   第三级：需要输入操作人密码进行二次身份验证
5. 确认后，系统执行回滚流程：
   a. 备份当前 active 模型到 rollback 目录
   b. 从目标版本的存储目录复制模型到 current 目录
   c. 通知 AiIntegrator 重新加载模型
   d. 执行模型预热推理
   e. 更新版本记录和 manifest.json
6. 页面显示回滚进度和结果
7. 操作记录写入审计日志
```

**自动回滚触发条件（复用 Phase 3C.2 OTA 回滚机制）：**

| 条件 | 阈值 | 说明 |
|------|------|------|
| 模型加载失败 | 1 次 | RKNN Runtime 加载异常时自动触发 |
| 模型推理失败 | 连续 3 次 | 推理结果异常时自动触发 |
| 模型预热超时 | 30 秒 | 预热推理超时自动触发 |

**验收标准：**
- [ ] 手动回滚操作需要三级确认 + 密码二次身份验证
- [ ] 回滚执行时间 < 60 秒（含模型加载和预热）
- [ ] 回滚成功后模型恢复正常推理
- [ ] 回滚失败时自动触发恢复机制，恢复到回滚前的版本
- [ ] 连续自动回滚 3 次后触发安全模式（使用本地兜底策略）
- [ ] 回滚操作记录完整审计日志，包含回滚原因、源版本、目标版本、操作人、操作时间
- [ ] 权限不足的用户无法看到回滚按钮
- [ ] 回滚不影响正在运行的 A/B 测试（测试流量仍按原规则分配）

## 5. 边界条件与异常处理

### 5.1 AI 引擎未启用

| 场景 | 处理方式 |
|------|----------|
| AI 引擎未加载（ModelStatus = Unloaded / Error） | AI 决策面板首页显示全页提示："AI 引擎当前未启用，系统运行于本地策略模式" |
| AI 决策面板所有数据区域 | 显示"暂无数据"替代实时数据 |
| 干预功能 | 权重调整区域和模式切换区域置灰禁用，显示"AI 引擎未启用，请先加载模型" |
| A/B 测试 | 测试配置入口隐藏 |
| 在线微调监控 | 显示"AI 引擎未启用" |

### 5.2 模型未加载或加载失败

| 场景 | 处理方式 |
|------|----------|
| LSTM 模型未加载 | 预测曲线区域显示"预测模型未加载"，不展示曲线 |
| RL 模型未加载 | 决策动作区域显示"决策模型未加载"，不展示决策数据 |
| 模型加载失败 | 对应区域显示红色错误提示，展示失败原因 |
| 推理失败 | 对应数据区域显示"推理异常"，展示最后成功推理的时间戳 |
| 模型预热失败 | 页面显示"模型预热失败"，AI 引擎降级至本地策略模式 |

### 5.3 权重参数越界

| 场景 | 处理方式 |
|------|----------|
| 用户输入值 < 0.0 | 输入框显示红色边框和错误提示："最小值 0.0" |
| 用户输入值 > 5.0 | 输入框显示红色边框和错误提示："最大值 5.0" |
| 用户输入非数字字符 | 输入框拒绝输入非数字字符（小数点和小数位除外） |
| 网络异常导致提交失败 | 显示"提交失败，请重试"提示，保留用户修改不丢失 |
| 后端权重持久化失败 | API 返回错误码 500，页面显示"保存失败，请重试" |

### 5.4 模式切换异常

| 场景 | 处理方式 |
|------|----------|
| AI 引擎繁忙（正在推理） | 模式切换请求排队，当前推理完成后执行 |
| 模式切换失败 | 保持原模式不变，页面显示"切换失败"及失败原因 |
| 切换到兜底模式 | 需要三级确认，防止误操作导致 AI 功能关闭 |
| 恢复自动识别时 AI 引擎异常 | 提示"AI 引擎异常，无法恢复自动识别，请先修复 AI 引擎" |

### 5.5 A/B 测试异常

| 场景 | 处理方式 |
|------|----------|
| 实验组模型推理异常 | 该设备流量自动回退至对照组（不影响其他设备） |
| 实验组模型连续失败 | 自动暂停 A/B 测试，所有流量切回对照组 |
| 对照组模型异常 | A/B 测试自动停止，AI 引擎降级至本地策略模式 |
| 测试时长到期 | 自动停止测试，生成最终对比报告 |
| 流量分配比例校验不通过 | 启动时立即拒绝，页面显示具体错误原因 |

### 5.6 微调异常

| 场景 | 处理方式 |
|------|----------|
| 缓冲区数据不足 | 微调触发条件未满足，状态显示"数据收集中"和当前数据量 |
| 微调过程中断 | 状态更新为"微调失败"，显示中断原因 |
| 微调后模型效果下降 | 自动放弃本次微调权重，回退至微调前版本，记录失败日志 |
| 磁盘空间不足 | 阻止新数据点加入缓冲区，显示"缓冲区已满"告警 |

/// 优化目标权重参数
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct WeightParam {

    pub value: f64,

    PvConsumption,

    BatteryDegradation,
    TransformerOverload,
    PriceArbitrage,
    DemandPenalty,
    GreenEnergyRatio,

/// 场景模式枚举

    Agriculture,
    CommercialArbitrage,
    CommercialDemand,
    CommercialVpp,
    CommercialGreen,
    LocalFallback,
}

#[derive(Debug, Clone, Serialize, Deserialize)]

    pub current_mode: SceneMode,
    pub confidence: f64,
    pub source: ModeSource,  // AutoDetected | ManualOverride | Fallback
    pub switched_at: Option<DateTime<Utc>>,
}

/// 奖励值
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct RewardValue {
    pub total: f64,
    pub components: Vec<RewardComponent>,
    pub timestamp: DateTime<Utc>,
}

/// 奖励细分项
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct RewardComponent {
    pub name: String,
    pub value: f64,
    pub weight: f64,
}

/// 奖励历史记录
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct RewardRecord {
    pub timestamp: DateTime<Utc>,
    pub total_reward: f64,
    pub components: Vec<RewardComponent>,

#[derive(Debug, Clone, Serialize, Deserialize)]

    pub model_type: ModelType,

    pub metrics: Vec<EvalMetric>,

#[derive(Debug, Clone, Serialize, Deserialize)]

    pub test_id: AbTestId,
    pub status: AbTestStatus,
    pub started_at: DateTime<Utc>,
    pub ended_at: Option<DateTime<Utc>>,
    pub metrics: Vec<MetricComparison>,
}

    pub significant: bool,
}

    pub version: String,

    pub file_size: u64,
    pub md5: String,
    pub deployed_at: DateTime<Utc>,
}

    pub progress_percent: Option<u8>,
    pub total_epochs: u32,
    pub last_update: Option<DateTime<Utc>>,
