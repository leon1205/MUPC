## 1. 产品概述与核心价值

### 1.1 背景

MUPC 通信管理模块已经覆盖 SM2/SM4 国密算法实现（见 `2026-05-28-SM2-SM4-国密真正实现-设计文档.md`）和双向证书认证机制。然而，电力行业对通信安全有专门的法律法规和技术标准要求，现有设计存在以下合规缺口：

- **纵向加密认证**没有明确对接方案，缺少与电力专用纵向加密认证装置的集成设计
- **MQTT over TLS + SM2/SM4 集成**未经证书格式兼容性验证
- **控制指令全程加密**缺少从调度主站到实时控制模块的全链路加密审计
- **证书生命周期管理**缺少颁发、更新、吊销的标准化流程

上述缺口构成合规风险：依据国家发改委 2014 年第 14 号令《电力监控系统安全防护规定》第十四条，"电力监控系统应当采用纵向加密认证等安全措施，实现对远程通信的身份认证、数据加密和完整性保护"。

### 1.2 核心价值

| 维度 | 价值 |
|------|------|
| **合规必要性** | 满足国家发改委 2014 年第 14 号令、国家能源局 2015 年第 36 号文、GB/T 36572-2018《电力监控系统网络安全防护导则》的强制性要求 |
| **安全必要性** | 防止控制指令被篡改、重放、伪造，防止未授权访问导致电力事故 |
| **可审计性** | 所有控制指令全链路加密并记录审计日志，满足等保 2.0 三级对"通信加密"和"安全审计"的要求 |
| **可运维性** | 证书生命周期管理机制确保加密体系可持续运行，避免证书过期导致通信中断 |

### 1.3 适用范围

| 项目 | 说明 |
|------|------|
| 设备 | MUPC 微电网特种调控装置 |
| 平台 | Linux (openEuler)、RK3588 |
| 通信协议 | IEC 60870-5-104、IEC 61850 MMS、MQTT over TLS |
| 安全标准 | GM/T 0002-2012/SM4、GM/T 0003-2012/SM2、RFC 8998 |
| 行业标准 | 发改委 2014 年第 14 号令、GB/T 36572-2018、等保 2.0 三级 |

### 1.4 术语定义

| 术语 | 定义 |
|------|------|
| 纵向加密认证 | 电力调度数据网中，上下级系统之间的身份认证、数据加密和完整性保护机制，通常由专用加密认证装置实现 |
| 纵向加密认证装置 | 部署于电力监控系统边界，实现 IPSec VPN + 国密算法的专用硬件设备，双向验证身份并加密通信 |
| 全链路加密审计 | 从调度主站下发控制指令、经 MUPC 转发到实时控制模块的完整链条中，每个环节的加密操作和密钥使用均有日志记录可追溯 |
| 证书生命周期管理 | CA 证书从颁发、部署、使用、更新到吊销的全过程管理 |
| SM2 TLS 握手 | 使用 SM2 证书和 SM2 签名算法进行 TLS 1.2/1.3 握手（RFC 8998） |

## 2. 目标用户角色

| 角色 | 描述 | 权限范围 | 优先级 |
|------|------|----------|--------|
| **安全管理员** | 负责 MUPC 装置的安全策略配置、密钥管理、证书维护 | 证书导入/导出/吊销、加密策略开关、安全参数配置 | 高 |
| **合规审计人员** | 负责检查系统是否符合电力行业安全法规要求 | 只读访问所有审计日志、加密策略配置、证书状态 | 高 |
| **系统集成工程师** | 负责将 MUPC 接入电力调度数据网，与纵向加密认证装置对接 | 加密装置参数配置、通信调试、兼容性测试 | 高 |
| **调度主站运维人员** | 通过调度主站远程监控和下发控制指令 | 正常调度操作（非安全配置） | 中 |
| **本地运维人员** | 通过本地运维界面进行配置管理 | 系统管理员级别，可更新安全策略 | 中 |

**安全职责分离原则**：
- 安全管理员和合规审计人员必须为不同人员担任
- 安全管理员的操作必须被合规审计人员可追溯
- 任何安全策略变更必须记录审计日志

## 3. 核心功能列表

### 3.1 纵向加密认证合规

#### 功能 3.1.1：纵向加密认证策略管理与合规

**User Story：**
> 作为安全管理员，我需要确保 MUPC 与调度主站之间的所有通信都经过纵向加密认证，满足国家发改委 2014 年第 14 号令第十四条和 GB/T 36572-2018 第 6.3 节的要求。

**验收标准：**

| ID | 验收内容 | 验证方法 |
|----|----------|----------|
| LEA-01 | MUPC 与调度主站（IEC 104）之间的通信通道支持在应用层进行 SM2 签名和 SM4 加密 | 抓包验证 IEC 104 应用层报文包含 SM2 签名字段和 SM4 加密载荷 |
| LEA-02 | 每一条从调度主站下发的控制指令（遥控、遥调、设点）必须通过 SM2 签名验证，验签失败时指令被拒绝执行 | 构造无效签名指令发送至 MUPC，验证指令被拒绝并产生告警 |
| LEA-03 | MUPC 返回的遥测、遥信数据必须附带 SM2 数字签名，接收方可验证数据完整性 | 截获 MUPC 上行的 IEC 104 报文，验证 SM2 签名字段存在且有效 |
| LEA-04 | 支持对 IEC 104 应用数据单元（APDU）整体进行国密加密，满足 GB/T 36572-2018 第 6.3.2 条"重要数据应采用加密传输"要求 | 配置加密启用后，抓取通信报文验证 APDU 载荷为 SM4 加密密文 |
| LEA-05 | 支持按通道粒度配置加密策略（开启/关闭加密、选择签名算法、选择加密算法） | 通过 web API 修改通道加密策略，验证通信行为符合配置 |

#### 功能 3.1.2：符合电力监控系统安全防护规定的合规自检

**User Story：**
> 作为合规审计人员，我需要 MUPC 提供合规自检功能，以自动验证系统的安全配置是否符合电力监控系统安全防护规定要求。

**验收标准：**

| ID | 验收内容 | 验证方法 |
|----|----------|----------|
| LEA-06 | MUPC 启动时自动执行安全合规自检，检查项包括但不限于：国密算法可用性、加密策略完整性、证书有效性 | 查看启动日志，自检结果包含每项检查的通过/失败状态 |
| LEA-07 | 自检不通过时输出详细报告，明确列出未通过项和解决建议 | 模拟证书过期场景，自检报告明确指出"证书已过期"及过期时间 |
| LEA-08 | 支持通过管理接口按需触发合规自检，返回结构化 JSON 报告 | 调用自检 API，验证返回 JSON 包含所有检查项的状态、描述和解决方案 |
| LEA-09 | 合规自检覆盖以下法规要求的检查点：
  - 发改委 2014 年第 14 号令第十四条（纵向加密认证）
  - GB/T 36572-2018 第 6.3 节（通信安全）
  - 等保 2.0 第三级安全通信网络要求（网络架构、通信加密、边界防护） | 逐一检查每个法规条文的对应检查项是否在自检清单中 |

### 3.2 纵向加密认证装置对接

#### 功能 3.2.1：与电力专用纵向加密认证装置的 IPSec VPN 对接

**User Story：**
> 作为系统集成工程师，我需要 MUPC 能够与电力调度数据网中已有的纵向加密认证装置（如卫士通、江南科友等厂商产品）对接，建立符合国密标准的 IPSec VPN 隧道。

**验收标准：**

| ID | 验收内容 | 验证方法 |
|----|----------|----------|
| LEA-10 | MUPC 支持作为 IPSec VPN 客户端，与符合 GM/T 0022-2014《IPSec VPN 技术规范》的加密认证装置建立 VPN 隧道 | 使用标准 IPSec 测试工具（如 strongSwan）模拟加密装置，验证 IKEv2 握手成功 |
| LEA-11 | IPSec 协商使用 SM2 证书进行双向身份认证，而非预共享密钥 | 抓包验证 IKE_AUTH 交换中使用的证书类型为 SM2 证书 |
| LEA-12 | IPSec 加密算法优先使用 SM4（IKE 加密 + ESP 加密），完整性校验优先使用 SM3 | 验证 SA 协商结果中加密算法为 SM4-GCM-128，完整性算法为 HMAC-SM3 |
| LEA-13 | 支持 IKEv2 协议（RFC 7296）中定义的分支地址、NAT 穿透、DDoS 防御机制 | 测试 NAT 场景下的 IPSec 隧道建立和报文转发 |
| LEA-14 | 加密隧道建立超时默认 30 秒，可配置（10-120 秒） | 配置超时时间为 10 秒，验证隧道建立超时后触发重连逻辑 |
| LEA-15 | 加密隧道断开后自动重连，重连间隔指数退避（1 秒、2 秒、4 秒...最大 60 秒） | 手动断开隧道连接，验证自动重连机制和退避时间符合预期 |
| LEA-16 | 支持同时维护至少 2 条独立加密隧道（分别对应不同调度主站或不同安全分区） | 配置两个不同的加密装置地址，验证两条隧道同时建立并维持 |

#### 功能 3.2.2：加密装置状态监控

**User Story：**
> 作为安全管理员，我需要实时了解纵向加密认证装置的运行状态和隧道健康度，以便在加密装置故障时及时响应。

**验收标准：**

| ID | 验收内容 | 验证方法 |
|----|----------|----------|
| LEA-17 | 系统提供加密隧道状态查询接口，返回每条隧道的：连接状态（已连接/正在连接/已断开）、协商算法、已运行时间、收发字节数 | 调用查询接口，验证返回信息完整性 |
| LEA-18 | 加密隧道状态变化（建立/断开/重连）产生 syslog 告警 | 模拟隧道断开，验证 syslog 中记录相应事件 |
| LEA-19 | 加密隧道持续断开超过配置阈值（默认 5 分钟）触发运行告警（蜂鸣器或 LED 指示） | 保持隧道断开 5 分钟以上，验证告警触发 |

### 3.3 SM2 证书在 TLS 中的应用

#### 功能 3.3.1：SM2 证书格式兼容性验证

**User Story：**
> 作为安全管理员，我需要确保系统使用的 SM2 证书符合 X.509 v3 标准，并在 TLS 握手过程中被正确识别和验证。

**验收标准：**

| ID | 验收内容 | 验证方法 |
|----|----------|----------|
| LEA-20 | SM2 证书必须使用 SM2-with-SM3 签名算法（OID 1.2.156.10197.1.501） | 使用 `openssl` 解析证书，验证签名算法 OID |
| LEA-21 | SM2 证书的公钥算法为 id-ecPublicKey（OID 1.2.840.10045.2.1）且曲线为 sm2p256v1（OID 1.2.156.10197.1.301） | 使用 `openssl` 解析证书，验证公钥算法 OID 和曲线 OID |
| LEA-22 | TLS 1.3 握手中 SM2 证书被用于支持 sig_sm2_sign_sm3 签名算法（依据 RFC 8998 Section 2.2） | 抓包验证 TLS 1.3 CertificateVerify 消息中使用 sm2sig_sm3 算法标识 |
| LEA-23 | MUPC 加载 SM2 证书时报错信息明确区分以下场景：证书格式错误、签名算法不匹配、证书已过期、证书链不完整 | 分别构造上述四种错误场景的证书，验证错误信息内容 |
| LEA-24 | MUPC 支持同时管理至少 3 张 SM2 证书（用于不同用途：TLS 服务器证书、TLS 客户端证书、IPSec 证书） | 加载 3 张证书并分别配置到三个通道，验证各通道使用对应证书正常工作 |

#### 功能 3.3.2：SM2 TLS 握手流程

**User Story：**
> 作为系统集成工程师，我需要 SM2 TLS 握手能够与主流的国密 TLS 实现（如 GmSSL、铜锁(Tongsuo)）互操作，确保 MUPC 能接入使用国密 TLS 的调度主站和物联平台。

**验收标准：**

| ID | 验收内容 | 验证方法 |
|----|----------|----------|
| LEA-25 | TLS 1.2 握手支持 SM2-SM4-SM3 密码套件：`TLS_ECDHE_SM2_WITH_SM4_GCM_SM3`（0x00,0xC6）（依据 RFC 8998） | 配置 TLS 1.2 国密套件，与支持 SM4-GCM 的服务端握手，验证协商结果 |
| LEA-26 | TLS 1.3 握手支持 SM2 签名算法和 SM4-GCM 记录加密 | 配置 TLS 1.3，抓包验证握手协商和记录层加密 |
| LEA-27 | MUPC 作为 TLS 客户端和服务端均可使用 SM2 证书完成双向认证 | 分别在客户端模式和服务端模式下测试双向认证，验证握手成功 |
| LEA-28 | SM2 TLS 握手性能：完整握手 ≤ 100ms（RK3588 平台，SM2 签名运算 + SM4 加密），会话恢复握手 ≤ 10ms | 连续执行 1000 次握手，取 P99 延迟 |
| LEA-29 | 与以下国密 TLS 实现互操作测试通过：GmSSL 3.x、铜锁(Tongsuo) 8.x、OpenSSL 3.x + SM2 patch | 分别与上述实现进行 TLS 握手连通性测试 |

### 3.4 MQTT over TLS + 国密算法端到端加密

#### 功能 3.4.1：MQTT over SM2 TLS 连接

**User Story：**
> 作为系统集成工程师，我需要 MUPC 的 MQTT 插件能够使用 SM2 证书建立 TLS 连接，并支持 SM4 加密 MQTT 消息载荷，实现对物联平台的安全数据上报。

**验收标准：**

| ID | 验收内容 | 验证方法 |
|----|----------|----------|
| LEA-30 | MQTT 客户端支持配置 SM2 证书作为客户端证书，使用 SM2 签名算法完成 TLS 双向认证 | 配置 SM2 证书进行 MQTT 连接，抓包验证 TLS 握手使用 SM2 证书 |
| LEA-31 | MQTT 发布消息支持 SM4-GCM 对 Payload 进行应用层加密，加密密钥由 SM2 密钥交换派生 | 发布加密消息，验证 Broker 收到的 Payload 为 SM4 密文（不可读） |
| LEA-32 | 加密/解密操作对应用程序透明：MqttClient 内部自动完成加密发送和解密接收 | 发布消息后订阅同一主题，验证接收端解密后的明文与原始消息一致 |
| LEA-33 | 支持 MQTT 5.0 的用户属性字段携带国密协商参数（加密算法标识、密钥标识等） | 抓包验证 MQTT CONNECT 和 PUBLISH 报文中的用户属性字段 |
| LEA-34 | 端到端加密延迟开销（TLS 握手开销不计）≤ 5ms（每 1KB 消息） | 计时测试 1000 次加密发布，取平均延迟 |
| LEA-35 | TLS 连接断开时自动重连，重连必须重新完成 SM2 证书认证，不允许跳过认证重用旧会话 | 模拟 TLS 连接中断，验证重连时重新进行完整握手 |

### 3.5 控制指令全链路加密审计

#### 功能 3.5.1：控制指令端到端加密

**User Story：**
> 作为安全管理员，我需要确保从调度主站下发的控制指令在整个传输链路中始终保持加密状态，直到实时控制模块执行前才解密。

**验收标准：**

| ID | 验收内容 | 验证方法 |
|----|----------|----------|
| LEA-36 | 控制指令在 MUPC 内部转发（gateway -> strategy-engine -> intercore）全链路保持 SM4 加密状态，除目的模块外的任何中间模块无法读取明文 | 在 strategy-engine 层抓取消息总线上的指令流，验证为 SM4 密文 |
| LEA-37 | intercore 模块将控制指令下发至实时控制模块时，使用 SM4-GCM 进行物理层加密传输（TCP 会话层加密） | 抓取 RJ45 网线 TCP 报文，验证 payload 为 SM4 密文 |
| LEA-38 | 每一条控制指令携带唯一序列号（递增的 64 位整数），防重放攻击窗口 ≥ 5 分钟 | 记录已处理的序列号，验证 5 分钟内同一序列号的重复指令被拒绝 |
| LEA-39 | 解密失败、验签失败、序列号重复的控制指令被拒绝执行，并记录告警日志 | 分别构造上述三种异常指令发送至 MUPC，验证拒绝和告警 |
| LEA-40 | 控制指令全链路延迟增量（加密/解密开销）≤ 10ms（单条指令，不含网络传输） | 测量从 gateway 接收到指令到 intercore 发出加密指令的时延 |

#### 功能 3.5.2：加密审计日志

**User Story：**
> 作为合规审计人员，我需要完整的加密操作日志，以便在安全事件发生时追溯指令的加密状态和路径。

**验收标准：**

| ID | 验收内容 | 验证方法 |
|----|----------|----------|
| LEA-41 | 每条控制指令的加密审计日志包含以下字段：指令唯一 ID、时间戳（精度毫秒）、指令类型、源模块、目标模块、加密算法、加密密钥 ID、签名算法、签名密钥 ID、序列号、处理结果 | 下发一条控制指令，查询对应审计日志，验证所有字段完整 |
| LEA-42 | 审计日志不可篡改：日志文件每 5 分钟计算一次 SM3 哈希并将哈希值写入 TPM（若有）或加密存储区 | 修改审计日志文件，验证哈希校验失败告警 |
| LEA-43 | 审计日志支持按时间范围、指令类型、处理结果、模块名称等维度查询和导出 | 通过日志查询接口输入过滤条件，验证返回结果精确匹配 |
| LEA-44 | 审计日志存储容量不低于 1GB，日志滚动保留策略：最新 30 天在线，历史日志归档压缩 | 持续产生日志至超过 1GB，验证日志滚动行为符合配置 |

### 3.6 安全事件告警与合规审计日志

#### 功能 3.6.1：安全事件告警

**User Story：**
> 作为安全管理员，我需要系统在安全事件发生时立即产生明确的告警，包括告警分类、严重级别和处理建议。

## 5. 边界条件与异常处理

### 5.1 加密装置故障

| 场景 | 行为 | 恢复策略 |
|------|------|----------|
| 加密装置完全不可用 | 切断加密通信通道，10秒内触发 CRITICAL 告警 | 尝试连接到备用加密装置（若有配置）；备用不可用时每 30 秒重试 |
| 加密隧道间歇性断开 | 触发 WARNING 告警，自动重连 | 指数退避重连，最大间隔 60 秒 |
| 加密装置性能不足 | 触发 WARNING 告警（加密延迟超过 2 倍基线值） | 不影响现有加密策略，仅告警通知 |
| 加密装置配置不匹配 | 隧道协商失败，生成 ERROR 告警，记录协商失败的原因（算法不匹配、证书问题） | 等待管理员修复配置后手动重试 |

### 5.2 证书异常

| 场景 | 行为 | 恢复策略 |
|------|------|----------|
| 证书已过期 | 拒绝使用该证书建立新连接，触发 CRITICAL 告警 | 导入新证书后自动生效 |
| 证书链不完整 | 证书加载失败，触发 ERROR 告警 | 导入完整的证书链（含中间 CA 证书） |
| 私钥与证书不匹配 | 证书加载失败，触发 CRITICAL 告警 | 导入匹配的正确私钥 |
| CRL 查询失败 | 允许连接继续（不拒绝），触发 WARNING 告警 | 重新尝试获取 CRL，成功后自动更新 |
| 私钥文件权限错误 | 证书加载失败，触发 ERROR 告警 | 修正文件权限（600）后自动加载 |

### 5.3 TLS 握手失败降级策略

| 场景 | 降级行为 | 安全约束 |
|------|----------|----------|
| SM2 TLS 握手失败（服务端不支持国密套件） | 不允许降级至 RSA TLS | 必须要求双向证书认证；协商的加密算法强度不得低于 AES-128-GCM |
| 双向认证失败（客户端证书无效） | 连接被拒绝，不允许降级到单向认证 | 无降级路径 |
| 协议版本协商失败（服务端仅支持 TLS 1.1 及以下） | 连接被拒绝，不允许降级至 TLS 1.1 | 必须 TLS 1.2+ |
| 证书链验证失败 | 连接被拒绝，不允许跳过证书验证 | 无降级路径 |

**核心原则**：加密强度只可升级不可降级。当 SM2/SM4 协商失败时，不允许降级到 RSA/AES，必须等待配置修复或切换到支持国密的通信对端。

### 5.4 其他边界条件

| 场景 | 行为 |
|------|------|
| 磁盘空间不足导致审计日志无法写入 | 保留最后 100MB 日志，删除最旧日志，触发 CRITICAL 告警 |
| 系统时间错误导致证书验证异常 | 在证书验证时记录系统时间，若系统时间与证书有效期偏差超过 24 小时，触发 WARNING 告警 |
| 加密引擎初始化失败（gmsm 库加载失败） | 系统启动失败，触发 CRITICAL 告警，禁止以无加密模式运行 |

## 6. 与现有系统的集成点

### 6.1 security crate

当前 `security` crate 已经定义了 SM2/SM4 加密接口和 TLS 连接器（见 `2026-05-28-SM2-SM4-国密真正实现-设计文档.md`），本 PRD 要求在现有接口基础上扩展以下功能：

| 新增模块 | 功能 | 现有依赖 |
|----------|------|----------|
| `security/src/lea.rs` | 纵向加密认证管理：IPSec VPN 客户端（IKEv2 + SM2/SM4/SM3） | 依赖 `gmsm`、`ipsec`（新增依赖） |
| `security/src/audit.rs` | 加密审计日志：记录所有加密/解密/签名/验签操作的日志 | 依赖 `common` 的日志模块 |
| `security/src/cert_mgr.rs` | 证书生命周期管理：证书校验、热更新、CRL 验证 | 依赖 `gmsm::x509` |
| `security/src/policy.rs` | 加密策略管理：通道级加密策略配置、合规自检 | 独立模块 |
| `security/src/alarm.rs` | 安全事件告警：告警生成、分类、推送 | 依赖 `common` 的告警通道 |

### 6.2 gateway crate

`gateway` crate 实现 IEC 104 协议北向通信，需要集成 `security` 模块以支持控制指令加密和纵向加密认证：

| 集成点 | 说明 |
|--------|------|
| IEC 104 APDU 加密 | gateway 发送/接收 APDU 时调用 `security::sm4` 加密/解密 |
| 控制指令签名验证 | gateway 接收到调度指令后调用 `security::sm2` 验签 |
| 上行数据签名 | gateway 发送遥测/遥信数据时调用 `security::sm2` 签名 |
| 加密隧道绑定 | gateway 的通信通道绑定到 `security::lea` 的 IPSec 隧道 |

### 6.3 mqtt-plugin crate

`mqtt-plugin` crate 需要集成 SM2 TLS 和端到端 SM4 加密：

| 集成点 | 说明 |
|--------|------|
| SM2 TLS 配置 | MQTT 配置中的 `use_tls` 分支支持 `cipher_suite: "SM2-SM4-SM3"` 选项 |
| SM4 应用层加密 | MQTT publish 前加密 Payload，subscribe 收到后解密 |
| 密钥协商 | 使用 SM2 密钥交换派生 SM4 会话密钥 |

### 6.4 strategy-engine crate

`strategy-engine` crate 负责控制指令的安全校验和转发：

| 集成点 | 说明 |
|--------|------|
| 指令解密 | 从消息总线接收加密指令后调用 `security::sm4` 解密 |
| 重放防护 | 检查指令序列号是否存在重复 |
| 指令签名 | 转发至 intercore 前附加 SM2 签名 |

### 6.5 intercore crate

`intercore` crate 将指令下发给实时控制模块：

| 集成点 | 说明 |
|--------|------|
| TCP 会话加密 | 使用 SM4-GCM 加密 RI45 TCP 报文 |
| 共享密钥管理 | 与实时控制模块协商共享密钥（SM2 密钥交换派生） |

### 6.6 集成架构总览

```
调度主站
    │
    │ IPSec VPN（纵向加密认证装置）
    │ SM2 证书双向认证 + SM4 加密（IPSec ESP）
    ▼
┌─────────────────────────────────────────────────────────┐
│ gateway（IEC 104）                                       │
│   - APDU SM4 加密/解密（security::sm4）                  │
│   - APDU SM2 签名/验签（security::sm2）                  │
│   - IPSec 隧道绑定（security::lea）                      │
└────────────────────┬────────────────────────────────────┘
                     │ 消息总线（加密指令流转）
                     ▼
┌─────────────────────────────────────────────────────────┐
│ strategy-engine                                         │
│   - 指令 SM4 解密（security::sm4）                       │
│   - 重放防护（序列号检查）                                │
│   - 指令 SM2 签名（security::sm2）                       │
└────────────────────┬────────────────────────────────────┘
                     │ 消息总线（加密指令流转）
                     ▼
┌─────────────────────────────────────────────────────────┐
│ intercore                                               │
│   - TCP 会话 SM4-GCM 加密                               │
│   - 共享密钥派生（security::sm2 密钥交换）               │
└────────────────────┬────────────────────────────────────┘
                     │ RJ45 TCP（SM4 加密密文）
                     ▼
实时控制模块
```

### 6.7 外部依赖新增

| 依赖 | 用途 | 建议库 | 说明 |
