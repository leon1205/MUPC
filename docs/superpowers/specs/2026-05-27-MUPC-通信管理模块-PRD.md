## 1. 产品概述

### 1.1 产品定位

MUPC 微电网特种调控装置通信管理模块是"异构双核心模块主控架构"中的**非实时处理核心**（大脑），与"实时控制核心模块"（小脑）协同工作。

**核心职责：**
- 承担"大脑"决策角色，负责北向通信、策略计算、AI优化、OTA升级等非实时任务
- 将指令下达给负责"小脑"执行的实时控制模块
- **不参与任何硬实时控制**（如10kHz电流环）

### 1.2 目标平台

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux (openEuler) |
| 硬件 | RK3588 |
| 编程语言 | Rust |
| 异步运行时 | Tokio |
| 网络框架 | Tower + tokio-net |

### 1.3 开发范围

本次开发范围：**完整 Phase 1**

包含模块：
1. **common** - 公共库：日志、错误类型
2. **gateway** - 北向通信网关（IEC 104）
3. **intercore** - 核间通信（TCP/RJ45）
4. **data-processing** - 数据处理（接口预留 Phase 1）
5. **strategy-engine** - 本地策略引擎（接口预留 Phase 1）
6. **Web UI** - 本地运维界面

> **说明**：IEC 61850-7-420、MQTT over TLS、国密SM2/SM4、AI优化引擎（LSTM/TCN、MADDPG/PPO）、南向通信（RS485/HPLC）、OTA升级、安全启动等功能属于 Phase 2+，不在本PRD范围内。

## 2. 用户角色

| 角色 | 描述 | 权限范围 | 优先级 |
|------|------|----------|--------|
| **调度主站运维人员** | 通过IEC 104协议远程监控和控制MUPC装置 | 只读监控权限，可下发调度指令但需经过本地策略引擎校验 | 低（次优先） |
| **配电自动化操作员** | 通过IEC 61850协议（Phase 2+）管理配电自动化设备 | 设备状态监控、遥控操作 | 低（Phase 2+） |
| **物联平台管理员** | 通过MQTT协议（Phase 2+）接入虚拟电厂或物联平台 | 数据上报、指令接收 | 低（Phase 2+） |
| **本地运维人员** | 通过Web UI或星闪/Wi-Fi/蓝牙进行本地运维 | 最高权限，可覆盖调度指令，可下发任意控制指令 | 高（最高优先） |
| **系统管理员** | 负责系统整体运维和OTA升级 | 所有配置权限、固件管理 | 高 |

**权限优先级规则：**
- 权限冲突时，本地运维人员指令优先于调度主站指令
- 本地运维人员可覆盖调度主站下发的任何指令

## 3. 核心功能列表

### 3.1 common - 公共库

#### 功能 3.1.1：统一日志模块

**User Story：**
> 作为开发者和运维人员，我需要统一的日志模块，以便追踪系统运行状态、定位故障原因。

**验收标准：**
- 基于 `tracing` crate 实现日志记录
- 日志级别支持：ERROR、WARN、INFO、DEBUG、TRACE
- 日志输出支持：标准输出（stdout）、文件滚动
- 日志格式包含：时间戳、模块名、级别、消息
- 日志文件路径：`/var/log/mupc/`
- 单日志文件大小上限：10MB，超过后自动滚动
- 保留最近10个日志文件

#### 功能 3.1.2：统一错误类型

**User Story：**
> 作为开发者，我需要统一的错误类型定义，以便实现跨模块的错误传递和一致的错误处理。

**验收标准：**
- 实现 `std::error::Error` trait
- 错误类型包含：错误码、错误描述、错误来源模块
- 支持错误链（`error.source()`）
- 所有模块返回的错误统一封装为 `MupcError` 枚举

### 3.2 gateway - 北向通信网关（IEC 104）

#### 功能 3.2.1：IEC 104 协议通信

**User Story：**
> 作为调度主站运维人员，我需要通过IEC 104协议与MUPC装置通信，以便实现远程监控和控制。

**验收标准：**
- 全面兼容 IEC 60870-5-104 协议
- 支持 TCP 连接建立、保持（心跳）
- 支持 U 帧：STARTDT、STOPDT、TESTFR
- 支持 S 帧：确认收到的 I 帧
- 支持 I 帧：发送/接收应用数据
- 默认端口：2404

#### 功能 3.2.2：连接管理

**User Story：**
> 作为系统，我需要管理IEC 104连接状态，以便在连接异常时自动重连。

**验收标准：**
- 连接状态机：断开、连接中、已连接、等待激活
- 心跳间隔：**默认 10 秒，支持运行时配置**，配置范围：1秒 ~ 60秒
- 连接超时：30 秒无响应则判定超时
- 自动重连机制：断连后 5 秒开始重连，最多重试 10 次
- 支持最多 5 个并发连接
- 心跳间隔配置方式：通过 Web UI（3.6.1）配置

#### 功能 3.2.3：数据收发

**User Story：**
> 作为调度主站运维人员，我需要通过IEC 104协议收发遥测、遥信、遥控数据。

**验收标准：**
- **类型标识（TypeID）支持：**
  - M_SP_TA_1（单点遥信，带时标）
  - M_DP_TA_1（双点遥信，带时标）
  - M_ME_TA_1（测量值，归一化值，带时标）
  - M_ME_TD_1（测量值，归一化值，带时标）
  - C_SC_TA_1（单点遥控，带时标）
  - C_DC_TA_1（双点遥控，带时标）
  - C_SE_TA_1（调节命令，带时标）
- **数据上行（MUPC → 调度主站）：**
  - 周期性发送遥测数据，周期可配置（默认 1 秒）
  - 告警时立即上送
  - 时标采用 UTC 时间
- **数据下行（调度主站 → MUPC）：**
  - 接收并确认收到的数据
  - 遥控命令需经过本地策略引擎（3.3）校验后才转发

#### 功能 3.2.4：调度指令接收与转发

**User Story：**
> 作为调度主站，我需要下发有功/无功设定值、一次调频参数、远程启停命令给MUPC。

**验收标准：**
- 接收调度主站下发的控制指令
- 指令类型：
  - 有功设定值（P_set）：范围 -1000kW ~ 1000kW
  - 无功设定值（Q_set）：范围 -1000kVar ~ 1000kVar
  - 电池启停命令：启动/停止
  - 一次调频参数：K值、Deadband
- 指令校验：检查数据范围、格式有效性
- **权限分级：**
  - 调度主站下发的指令需经过本地策略引擎（3.3）校验后才转发
  - 如本地运维人员下发冲突指令，本地运维人员指令优先
- 校验通过后，通过 intercore 转发给实时控制模块
- 响应时间：从接收到转发 ≤ 100ms

### 3.3 intercore - 核间通信（TCP/RJ45）

#### 功能 3.3.1：TCP 网络通信

**User Story：**
> 作为通信管理模块，我需要通过TCP Socket与实时控制模块通信。

**验收标准：**
- 使用 TCP Socket（RJ45 网线）
- 默认本地端口：2500
- 默认对端端口：2501
- 支持长连接
- 帧格式：自定义二进制协议（帧头 + 数据 + CRC16校验）
- 帧头格式：`0xAA 0x55 + 长度(2字节) + 类型(1字节) + 序号(2字节)`

#### 功能 3.3.2：指令下发

**User Story：**
> 作为通信管理模块，我需要将经过策略校验的指令下发到实时控制模块。

**验收标准：**
- 支持指令类型：
  - 电池有功设定（P_batt_set）
  - 电池无功设定（Q_batt_set）
  - 分相补偿系数
  - 启停命令
- 指令下发延迟 ≤ 50ms
- 支持指令确认机制（收到执行结果后更新状态）
- 指令超时时间：5 秒

#### 功能 3.3.3：数据读取

**User Story：**
> 作为通信管理模块，我需要从实时控制模块读取实时电气量、电池数据。

**验收标准：**
- 读取数据类型：
  - 电气量：U、I、P、Q、cosφ、频率
  - 电池数据：SOC、SOH、温度
  - 逆变器状态：运行/停机/故障
  - 功率：光伏、负荷、充电桩
- 读取周期：≥ 1Hz（默认 1 秒）
- 数据带 UTC 时标

#### 功能 3.3.4：心跳与看门狗

**User Story：**
> 作为系统，我需要通过心跳和看门狗机制监控实时控制模块的运行状态。

**验收标准：**
- 心跳周期：1 秒
- 看门狗超时：10 秒（连续 10 次心跳无响应）
- 超时处理：
  - 触发系统告警
  - 记录故障日志
  - 可选：触发实时控制模块复位
- 心跳帧包含：状态码、CPU温度、内存使用率

### 3.4 data-processing - 数据处理（接口预留 Phase 1）

> **说明**：Phase 1 仅定义接口，实现延后至 Phase 2。

#### 功能 3.4.1：数据汇聚接口

**User Story：**
> 作为系统，我需要汇聚来自实时控制模块的各类数据，为上层应用提供统一数据源。

**验收标准（Phase 1 仅接口）：**
- 定义数据汇聚抽象接口 `DataCollector`
- 接口方法：`collect() -> DataPackage`
- 数据包包含：电气量、电池数据、设备状态、时间戳

#### 功能 3.4.2：高频遥测接口

**User Story：**
> 作为系统，我需要支持≥1Hz的高频遥测数据采集和上报。

**验收标准（Phase 1 仅接口）：**
- 定义高频遥测抽象接口 `HighFrequencyTelemetry`
- 接口方法：`start(period_ms: u64)`、`stop()`
- 支持动态调整采集周期

#### 功能 3.4.3：数据上报接口

**User Story：**
> 作为系统，我需要通过IEC 104、MQTT等协议将处理后的数据上报给调度主站或物联平台。

**验收标准（Phase 1 仅接口）：**
- 定义数据上报抽象接口 `DataReporter`
- 接口方法：`report(data: &DataPackage) -> Result<()>`
- 支持协议配置：IEC 104、MQTT（Phase 2+）

#### 功能 3.4.4：故障录波接口

**User Story：**
> 作为系统，我需要记录故障前后特定时间段的波形数据。

**验收标准（Phase 1 仅接口）：**
- 定义故障录波抽象接口 `FaultRecorder`
- 接口方法：`trigger(condition: &FaultCondition)`、`get_waveform() -> WaveformData`
- 录波条件：过压、欠压、过流、频率异常

### 3.5 strategy-engine - 本地策略引擎（接口预留 Phase 1）

> **说明**：Phase 1 仅定义接口，实现延后至 Phase 2。AI优化引擎功能（6.x）属于 Phase 2+。

#### 功能 3.5.1：兜底策略接口

**User Story：**
> 作为系统，我需要本地策略引擎作为AI失效时的兜底机制，确保系统安全可靠运行。

**验收标准（Phase 1 仅接口）：**
- 定义兜底策略抽象接口 `FallbackStrategy`
- 策略类型：削峰填谷、需量控制、防逆流保护
- 接口方法：`evaluate(data: &DataPackage) -> ControlCommand`
- 与AI引擎采用"AI优先，本地兜底"机制

#### 功能 3.5.2：AI指令校验接口

**User Story：**
> 作为系统，我需要对AI引擎输出的指令进行安全校验，防止异常指令影响系统安全。

**验收标准（Phase 1 仅接口）：**
- 定义AI指令校验抽象接口 `AiCommandValidator`
- 接口方法：`validate(cmd: &AiCommand) -> ValidationResult`
- 校验规则：
  - 有功设定值范围：-1000kW ~ 1000kW
  - 无功设定值范围：-1000kVar ~ 1000kVar
  - 变化率限制：每周期不超过10%
- 校验不通过时，自动降级至本地策略模式

### 3.6 Web UI - 本地运维界面

#### 功能 3.6.1：本地配置管理

**User Story：**
> 作为本地运维人员，我需要通过Web UI配置和管理MUPC装置。

**验收标准：**
- 支持浏览器访问（Chrome、Firefox、Edge）
- 默认端口：8080
- HTTP服务独立运行，不影响核心通信功能
- 配置项：
  - IEC 104连接参数（IP地址、端口、心跳间隔**（范围：1秒~60秒）**）
  - intercore通信参数（本地端口、对端端口）
  - 遥测上报周期
  - 日志级别
- 配置保存后自动生效，无需重启

#### 功能 3.6.2：日志查看与导出

**User Story：**
> 作为本地运维人员，我需要查看和导出系统日志，以便排查问题。

**验收标准：**
- 实时日志查看：WebSocket推送，支持 ERROR、WARN、INFO 级别过滤
- 日志搜索：支持按时间范围、关键字搜索
- 日志导出：支持下载为文件（.log格式）
- 单次导出最大条数：10000条

#### 功能 3.6.3：固件版本与状态

**User Story：**
> 作为本地运维人员，我需要查看当前固件版本和系统运行状态。

**验收标准：**
- 显示内容：
  - 固件版本号
  - 编译时间
  - 运行时间（uptime）
  - CPU温度、内存使用率
  - 各模块连接状态（IEC 104、intercore）
- 页面自动刷新周期：5 秒

#### 功能 3.6.4：用户认证

**User Story：**
> 作为本地运维人员，我需要通过用户认证登录Web UI，以保护系统安全。

**验收标准：**
- Phase 1 Web UI **必须实现用户认证**
- 认证方式：Session 登录模式
- 登录接口：`POST /api/auth/login`，请求体包含用户名和密码
- 默认用户：admin（密码可配置，初始密码由配置文件中读取）
- 登录成功后使用 Session/Cookie 维护登录状态
- 后续 API 调用携带 Session Cookie 验证身份
- 敏感操作（配置修改、固件升级）需要再次确认
- 认证失败时返回 401 状态码
- 支持"记住登录状态"功能（可选）

#### 功能 3.7.4：服务协调器

**User Story：**
> 作为系统，我需要服务协调器统一管理各模块生命周期。

**验收标准（Phase 1 仅接口）：**
- 定义服务协调抽象接口 `ServiceCoordinator`
- 接口方法：`start()`、`stop()`、`status() -> ServiceStatus`
- 协调 gateway、intercore、data-processing、strategy-engine 的启动顺序
- Phase 1 仅定义接口，实现延后至 Phase 2

## 4. 非功能性需求

### 4.1 性能需求

| 指标 | 要求 |
|------|------|
| 系统启动时间 | ≤ 30 秒 |
| IEC 104 数据上报周期 | ≥ 1Hz（可配置） |
| 核间指令下发延迟 | ≤ 50ms |
| 核间数据读取周期 | ≥ 1Hz |
| 调度指令处理延迟 | ≤ 100ms（接收到转发） |
| Web UI 页面响应时间 | ≤ 2 秒 |
| 并发连接数 | ≤ 5 个（IEC 104） |
| 消息总线吞吐量 | ≥ 1000 msg/s（Phase 1 接口预留） |

### 4.2 可靠性需求

| 指标 | 要求 |
|------|------|
| 系统 MTBF | ≥ 50,000 小时 |
| 心跳周期 | 1 秒 |
| 看门狗超时 | 10 秒 |
| 自动重连次数 | 最多 10 次 |
| 日志文件滚动 | 单文件 10MB，保留 10 个 |

### 4.3 安全需求

| 需求 | 说明 |
|------|------|
| 通信安全（Phase 2+） | 支持国密SM2/SM4算法、双向证书认证、纵向加密认证 |

| 配置安全 | 敏感配置（如有）不得明文存储 |
| 日志安全 | 日志中不得记录明文密码、密钥 |

|------|------|
| 操作系统 | openEuler 22.03+ |

| Web 浏览器 | Chrome 90+、Firefox 88+、Edge 90+ |

## 5. 异常流程与降级机制

### 5.1 AI失效降级流程

```
AI引擎异常
    ↓
检测异常（心跳/状态码）
    ↓
自动切换至本地策略引擎
    ↓
系统发出告警（AI模式降级）
    ↓
本地策略接管控制
    ↓
AI引擎恢复后，自动切回AI模式
```

### 5.2 实时控制模块异常

```
实时控制模块无响应（看门狗超时）
    ↓
触发系统告警
    ↓
记录故障日志
    ↓
可选：触发实时控制模块复位
    ↓
持续告警，直至恢复
```

### 5.3 IEC 104连接异常

```
连接断开
    ↓
等待5秒后自动重连
    ↓
最多重试10次
    ↓
重试失败后，每1分钟尝试一次
    ↓
恢复后自动建立连接
```

## 6. 功能索引与控制流

### 6.1 基础控制流

```
[core] → 通信网关(3.2) → 数据汇聚(3.4) → 本地策略引擎(3.5) → 指令下发(3.3) → 实时控制模块
         ↑                                              ↑
      服务协调(3.7.4)                               指令校验(3.5.2)
```

### 6.2 Phase 2 智能优化流（预留接口）

```
[core] → 通信网关(3.2) + 数据汇聚(3.4) → AI数据融合(6.1) → AI预测(6.2) → AI决策(6.3) → (经本地策略引擎3.5安全校验) → 指令下发(3.3) → 实时控制模块
         ↑                                              ↑
      服务协调(3.7.4)                               指令校验(3.5.2)
```

### 6.3 保底机制

当AI引擎失效时，系统自动、无缝地降级至本地策略引擎(3.5)接管控制，保障台区基本安全与运行。
