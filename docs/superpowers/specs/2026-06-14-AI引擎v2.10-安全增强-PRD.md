## 1. 产品概述

### 1.1 定位

v2.10 是 AI 引擎的安全增强版本，在 v2.9（P-Q 协同度奖励）基础上，进一步完善实时模块与 AI 引擎之间的状态反馈闭环，并新增安全触发覆盖机制接口规范，确保极端工况下电网安全。

### 1.2 核心新增功能

| 功能 | 说明 |
|------|------|
| **无功裕度数据通道** | 明确 `q_realtime_margin` 数据获取路径，通过核间 DataUpload 帧实时同步 |

```

```

## 2. 需求1：状态空间扩展 — 实时模块无功裕度反馈

### 2.1 背景（Why）

v2.8/v2.9 已实现 P-Q 协同度奖励（`R_PQ_coordination`），AI 通过 `q_realtime_margin` 字段判断"是否需要用有功换电压"。但 **v2.5 只是预留了字段，数据来源未明确**。

专家原文：
> "AI引擎的状态向量必须增加'实时模块无功输出占比'或'剩余可用无功容量'。这是AI判断'是否需要用有功换电压'的关键依据。"

### 2.2 现状分析

**已有字段（v2.5）：**

```rust
// ai-engine/src/data_fusion.rs
pub struct FusedSystemState {
    /// 实时模块剩余无功容量比例 [0.0, 1.0]
    /// 0 = 无功打满，1 = 完全空闲
    pub q_realtime_margin: f64,
}
```

**默认值行为（问题）：**

```rust
// data_fusion.rs Default impl
q_realtime_margin: 0.5,  // 固定默认值，无实际数据来源
```

**结论：** `q_realtime_margin` 字段已存在，但**数据来源于默认值 0.5，未建立与实时控制模块的通信通道**。

### 2.3 方案（How）

#### 2.3.1 数据获取路径

```
实时控制模块
    ↓ (DataUpload 帧, 1Hz)
核间 TCP 通信 (intercore)
    ↓ (解析 JSON payload)
DataFusionEngine
    ↓ (填充 q_realtime_margin)
FusedSystemState
    ↓
RL 模型决策 + 奖励函数
```

#### 2.3.2 DataUpload 帧格式扩展

现有 `DataUpload` 帧类型（0x0030）目前未解析 payload，需扩展 JSON 数据格式：

```json
{
  "frame_version": 1,
  "timestamp_ms": 1750000000000,
  "q_realtime_margin": 0.35,      // 新增：实时模块剩余无功容量比例 [0.0, 1.0]
  "battery_soc": 0.65,           // 现有字段（供参考）
  "voltage_phase_a": 1.02,        // 现有字段
  "voltage_phase_b": 1.01,
  "voltage_phase_c": 1.03,
  "battery_power": 5.2           // kW
}
```

**字段说明：**

| 字段 | 类型 | 取值范围 | 说明 |
|------|------|----------|------|
| q_realtime_margin | f64 | [0.0, 1.0] | 实时模块剩余无功容量比例，0=打满，1=空闲 |

#### 2.3.3 核间通信协议变更

**文件：** `mupc/crates/intercore/src/protocol.rs`

```rust
IntercoreFrameType::DataUpload => {
    info!("Received data upload from {}", addr);
    if !frame.data.is_empty() {
        match DataUploadPayload::from_json(&frame.data) {
            Ok(payload) => {
                // 更新共享状态中的 q_realtime_margin
                // 注意：update_q_margin() 方法为 AI 引擎侧待实现方法（见 Section 2.7 接口协议待确认）

                    intercore_state.update_q_margin(q_margin).await;
                }
            }
            Err(e) => {
                warn!("Failed to parse DataUpload JSON payload: {}", e);
            }
        }
    }
}
```

## 3. 需求2：安全触发覆盖机制接口规范

### 3.1 背景（Why）

专家原文：
> "当实时模块检测到电压越限超阈值且自身无功耗尽时，可临时覆盖AI有功指令，强制以预设安全功率放电，并在下一AI调度周期将该事件作为'紧急状态'反馈给AI。"

**场景描述：**
1. 实时控制模块检测到电压越限（如 < 0.90 p.u. 或 > 1.10 p.u.）
2. 实时模块无功已打满（q_realtime_margin ≈ 0）
3. 实时模块临时覆盖 AI 的 p_ref 指令，强制以安全功率放电
4. 在下一 AI 调度周期，将该事件作为"紧急状态"反馈给 AI

### 3.2 方案（How）

#### 3.2.1 触发架构选项分析

> **背景：** PRD 描述触发逻辑由实时控制模块执行（"实时控制模块检测到电压越限...可临时覆盖 AI 有功指令"），但未确认：实时控制模块是否具备独立判断能力？还是需要 AI 引擎参与决策？这影响接口规范的完整性。

**选项 A（实时控制模块独立触发）- 推荐**

| 特性 | 说明 |
|------|------|
| 触发判断 | 实时控制模块本地判断电压越限 + 无功耗尽，独立执行覆盖 |
| AI 引擎角色 | 仅接收覆盖事件通知，不参与决策 |
| 优点 | 响应最快（实时控制模块本地判断），符合安全优先原则 |
| 缺点 | 实时控制模块需实现判断逻辑 |
| 通信流程 | 实时控制模块 →（SafetyOverride 帧）→ AI 引擎（通知用） |

**选项 B（混合模式）**

| 特性 | 说明 |
|------|------|
| 触发判断 | 实时控制模块上报电压越限事件，AI 引擎参与决策 |
| AI 引擎角色 | 根据实时控制模块上报的数据，参与覆盖决策 |
| 优点 | AI 引擎可综合全局信息做更优决策 |
| 缺点 | 响应延迟增加，复杂度高 |
| 通信流程 | 实时控制模块 →（事件上报）→ AI 引擎 →（覆盖指令）→ 实时控制模块执行 |

**推荐方案：选项 A（实时控制模块独立触发）**

理由：
1. **安全优先**：极端工况下响应速度至关重要，实时控制模块本地判断更快
2. **职责清晰**：实时控制模块负责实时安全，AI 引擎负责优化调度
3. **解耦设计**：AI 引擎无需参与实时安全判断，降低系统复杂度

> **最终方案取决于实时控制模块的能力**，Section 6 中列出待确认问题需在实现前与实时控制模块团队确认。

#### 3.2.2 SafetyOverride 帧格式

```json
{
  "frame_version": 1,
  "timestamp_ms": 1750000000000,
  "trigger_reason": "voltage_violation",      // 触发原因
  "voltage_phase_a": 0.88,                    // 当前 A 相电压
  "voltage_phase_b": 0.89,
  "voltage_phase_c": 0.87,
  "q_realtime_margin": 0.02,                  // 无功裕度（几乎耗尽）
  "override_p_ref": 30.0,                      // 强制放电功率 (kW)
  "override_duration_ms": 5000,              // 覆盖持续时间 (ms)
  "recovery_condition": "voltage_recovered"   // 恢复条件
}
```

**字段说明：**

| 字段 | 类型 | 取值范围 | 说明 |
|------|------|----------|------|
| trigger_reason | String | voltage_violation / q_exhausted / emergency | 触发原因 |
| voltage_phase_a/b/c | f64 | [0.8, 1.2] | 当前三相电压 |
| q_realtime_margin | f64 | [0.0, 0.1] | 无功裕度（几乎耗尽）|
| override_p_ref | f64 | [-50.0, 50.0] | 强制有功基准点 (kW) |
| override_duration_ms | u64 | > 0 | 覆盖持续时间 (ms) |
| recovery_condition | String | voltage_recovered / timer_expired / manual | 恢复条件 |

#### 3.2.3 触发阈值定义

| 参数 | 默认值 | 说明 | 可配置 |
|------|--------|------|--------|
| 电压越限阈值 | < 0.90 或 > 1.10 p.u. | 三相中任一相越限 | 是 |
| 无功耗尽阈值 | q_realtime_margin <= 0.05 | 几乎无裕度 | 是 |
| 覆盖持续时间 | 5000 ms | 5 秒后尝试恢复 | 是 |
| 强制放电功率 | min(30kW, max_batt_discharge_power) | 不超过电池最大放电功率 | 是 |

#### 3.2.7 AI 引擎感知"被覆盖"事件

**流程：**

```
1. intercore 收到 SafetyOverride 帧
2. 解析 payload，提取 q_realtime_margin + safety_override 信息
3. 更新 intercore_state 中的 q_realtime_margin（用于数据融合）
4. 发布 "ai/safety_override" 事件到消息总线
5. DataFusionEngine 在下一周期读取到 safety_override_active=true
6. FusedSystemState 包含 safety_override_active=true
7. RL 模型感知"紧急状态"，在奖励函数中获得额外惩罚或调整策略
```

**奖励函数扩展（SCENE-01）：**

```rust
/// 安全覆盖感知奖励调整（v2.10 新增）
fn safety_override_penalty(&self, state: &FusedSystemState) -> f64 {
    if !state.safety_override_active {
        return 0.0;
    }

    // 被覆盖期间，AI 应记录此次事件并学习避免触发
    // 惩罚值 = -50.0（一次性紧急惩罚）
    let reason = state.safety_override_reason.as_deref().unwrap_or("unknown");

    match reason {
        "voltage_violation" => -50.0,  // 电压越限触发
        "q_exhausted" => -30.0,       // 无功耗尽触发
        "emergency" => -100.0,         // 紧急情况（最高惩罚）
        _ => -20.0,
    }
}
```

## 4. 非功能性需求

### 4.1 性能

| 指标 | 要求 | 说明 |
|------|------|------|
| q_realtime_margin 更新延迟 | <= 1.5s | 从实时控制模块发出到 FusedSystemState 更新 |

| 指标 | 要求 |

| SafetyOverride 帧丢失处理 | 默认覆盖持续时间后自动恢复 |
| 通信完全中断 | 触发 AI 降级（兜底策略接管） |

### 4.3 安全性

| 需求 | 说明 |
|------|------|
| 强制放电功率限制 | override_p_ref <= max_batt_discharge_power |
| 覆盖持续时间限制 | max 10 秒（防止长时间强制指令）|
| 覆盖次数限制 | 1 分钟内最多触发 3 次（防止频繁覆盖）|

## 5. 边界条件和异常流程

### 5.1 q_realtime_margin 数据异常

| 场景 | 检测条件 | 处理措施 |
|------|----------|----------|
| 数据越界 | q_realtime_margin < 0.0 或 > 1.0 | clamp 至 [0.0, 1.0]，记录 WARN 日志 |
| 数据缺失 | DataUpload 帧无此字段 | 使用上一有效值 |
| 通信中断 | 连续 3 个周期无 DataUpload | 使用上一有效值 + WARN 告警 |
| 通信完全中断 | 连续 10 个周期无 DataUpload | 触发 AI 降级 |

### 5.2 SafetyOverride 异常

| 场景 | 检测条件 | 处理措施 |
|------|----------|----------|
| 帧格式错误 | JSON 解析失败 | 丢弃帧 + WARN 日志 |
| 功率超限 | override_p_ref > max_batt_discharge_power | clamp + WARN 日志 |
| 持续时间超限 | override_duration_ms > 10000 | clamp 至 10000ms + WARN 日志 |
| 频率过高 | 1 分钟内触发 > 3 次 | 拒绝后续覆盖 + ERROR 日志 + 告警 |
