**版本**: v1.0
**日期**: 2026-06-11
**状态**: 待评审

---

## 1. 产品概述

### 1.1 背景

MUPC 微电网调控装置的 AI 优化引擎通过强化学习（RL）输出动作指令，包含三个核心控制量：

| 动作 | 说明 | 当前实现 |
|------|------|----------|
| `p_batt_set` | 储能有功功率设定 (kW) | 硬编码值域 `[-50, 50]` |
| `load_shedding` | 可中断负荷调节量 (kW) | 硬编码值域 `[0, 60]` |
| `pv_limit` | 光伏限功率比例 | 已可配置（`pv_limit_min`） |

当前 `p_batt_set` 和 `load_shedding` 的取值范围在 `ai-engine/src/action_validator.rs` 中硬编码为固定值，无法适配不同台区的差异化配置。

### 1.2 问题

农网台区参数示例（当前硬编码基于此设计）：

| 参数 | 值 |
|------|-----|
| 变压器容量 | 200 kVA |
| 电池最大充放电功率 | 50 kW |
| 可中断负荷峰值 | 60 kW |

但实际部署中，不同台区的储能配置和可调负荷规模存在显著差异：

- 小型台区：电池 20 kW，可调负荷 30 kW
- 中型台区：电池 100 kW，可调负荷 80 kW
- 大型台区：电池 200 kW，可调负荷 150 kW

硬编码导致 AI 输出动作超出设备实际能力，引发控制失效或设备损坏。

### 1.3 目标

建立动作空间参数可配置系统，使 AI 输出的 `p_batt_set` 和 `load_shedding` 取值范围与台区实际设备能力匹配，确保 RL 动作始终在物理可行域内。

## 2. 用户角色

| 角色 | 职责 | 交互方式 |
|------|------|----------|
| **AI运维人员** | 部署时配置台区参数；巡检时核查配置合理性 | 配置文件 / Web UI |
| **策略管理员** | 根据台区负荷特性调整可调负荷参数；验证配置变更后 AI 行为 | Web UI |
| **系统** | 运行时加载配置、校验参数、注入 ActionValidator | 代码自动执行 |

## 3. 核心功能

### 3.1 配置参数定义

#### 3.1.1 动作空间参数结构

新增 `ActionSpaceConfig` 配置块，包含以下参数：

| 参数名 | 类型 | 说明 | 约束 |
|--------|------|------|------|
| `max_batt_charge_power` | f64 (kW) | 电池最大充电功率（正值） | > 0 |
| `max_batt_discharge_power` | f64 (kW) | 电池最大放电功率（正值） | > 0 |
| `max_load_shedding` | f64 (kW) | 最大可中断负荷量 | >= 0 |

#### 3.1.2 配置层级

```
AiEngineConfig
└── action_space: ActionSpaceConfig   # 新增
    ├── max_batt_charge_power: 50.0   # 充电功率上限
    ├── max_batt_discharge_power: 50.0 # 放电功率上限
    └── max_load_shedding: 60.0       # 可中断负荷上限
```

#### 3.1.3 与现有 ActionConstraintConfig 的关系

| 现有配置 | 用途 | 与 ActionSpaceConfig 的关系 |
|----------|------|----------------------------|
| `p_batt_ramp_limit_kw` | 变化率限制 | 独立参数，不依赖 ActionSpaceConfig |
| `q_batt_ramp_limit_kvar` | 无功变化率 | 独立参数 |
| `max_apparent_power_kva` | 视在功率上限 | 独立参数（变压器容量相关） |
| `pv_limit_min` | 光伏限功率下限 | 独立参数 |
| **`max_batt_charge_power`** | **电池充电上限** | **新增，替换硬编码 -50** |
| **`max_batt_discharge_power`** | **电池放电上限** | **新增，替换硬编码 +50** |
| **`max_load_shedding`** | **可中断负荷上限** | **新增，替换硬编码 60** |

### 3.2 配置存储

#### 3.2.1 配置文件格式

在 `ai_engine.toml` 中新增 `action_space` 节：

```toml
[action_space]
max_batt_charge_power = 50.0    # kW，正值
max_batt_discharge_power = 50.0 # kW，正值
max_load_shedding = 60.0        # kW
```

#### 3.2.2 数据库存储

在 `storage` crate 中新增 `action_space_config` 表：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PRIMARY KEY | 主键 |
| transformer_id | TEXT NOT NULL | 台区ID |
| max_batt_charge_power | REAL NOT NULL | 电池最大充电功率 |
| max_batt_discharge_power | REAL NOT NULL | 电池最大放电功率 |
| max_load_shedding | REAL NOT NULL | 最大可中断负荷 |
| created_at | TEXT NOT NULL | 创建时间（ISO 8601） |
| updated_at | TEXT NOT NULL | 更新时间（ISO 8601） |

**唯一约束**: `(transformer_id)` 唯一索引。

### 3.3 配置加载与校验

#### 3.3.1 启动加载流程

```
1. 系统启动
2. 读取 ai_engine.toml 的 action_space 配置
3. 连接 SQLite 数据库，查询 action_space_config 表
4. 数据库配置优先于文件配置（支持运行时动态调整）
5. 执行参数校验（见 3.3.2）
6. 构建 ActionSpaceConfig 实例
7. 注入 ActionValidator
```

#### 3.3.2 参数校验规则

| 规则ID | 条件 | 失败处理 |
|--------|------|----------|
| ASC-01 | `max_batt_charge_power > 0` | 拒绝启动，记录错误日志 |
| ASC-02 | `max_batt_discharge_power > 0` | 拒绝启动，记录错误日志 |
| ASC-03 | `max_load_shedding >= 0` | 拒绝启动，记录错误日志 |
| ASC-04 | `max_batt_charge_power <= max_apparent_power_kva` | 拒绝启动，记录错误日志 |
| ASC-05 | `max_batt_discharge_power <= max_apparent_power_kva` | 拒绝启动，记录错误日志 |

校验失败时，系统必须拒绝启动，不得使用默认值降级。

#### 3.3.3 配置热更新

支持运行时通过 Web API 更新配置：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/ai/action-space` | GET | 查询当前配置 |
| `/api/v1/ai/action-space` | PUT | 全量更新配置 |
| `/api/v1/ai/action-space` | PATCH | 部分更新配置 |

**热更新影响范围**: 新产生的 RL 动作立即使用新配置，已下发但未执行的动作不受影响。

### 3.4 与 ActionValidator 集成

#### 3.4.1 集成点

`ai-engine/src/action_validator.rs` 第163-166行的硬编码 clamp 替换为动态配置：

```rust
// 替换前（硬编码）
validated.p_batt_set = validated.p_batt_set.clamp(-50.0, 50.0);
validated.load_shedding = validated.load_shedding.clamp(0.0, 60.0);

// 替换后（配置驱动）
validated.p_batt_set = validated.p_batt_set.clamp(
    -self.config.action_space.max_batt_charge_power,
     self.config.action_space.max_batt_discharge_power
);
validated.load_shedding = validated.load_shedding.clamp(0.0, self.config.action_space.max_load_shedding);
```

#### 3.4.2 ActionConstraintConfig 变更

`ActionConstraintConfig` 新增字段：

```rust
pub struct ActionConstraintConfig {
    // 现有字段...
    pub action_space: ActionSpaceConfig,  // 新增
}
```

#### 3.4.3 向后兼容

若配置文件未指定 `action_space` 节，系统必须：

1. 使用默认值（与原硬编码一致）：`max_batt_charge_power = 50.0`, `max_batt_discharge_power = 50.0`, `max_load_shedding = 60.0`
2. 记录 WARN 日志：`action_space not configured, using defaults`

## 4. 非功能性需求

### 4.1 性能

| 指标 | 要求 |
|------|------|
| 配置加载时间 | <= 100ms（启动阶段，无性能要求） |
| 配置查询响应时间 | <= 50ms（Web API） |
| 配置更新生效时间 | <= 1s（热更新后） |

### 4.2 可用性

- 配置文件损坏或缺失时，系统必须使用默认值启动，不得中断
- 数据库连接失败时，回退到配置文件配置
- 单一台区配置失败不影响其他台区

### 4.3 安全性

- 配置更新需管理员权限（Role = "admin"）
- 配置变更记录完整审计日志
- 敏感操作（如批量重置）需二次确认

### 4.4 可观测性

| 事件 | 日志级别 | 记录内容 |
|------|----------|----------|
| 配置加载成功 | INFO | 台区ID、加载的参数值 |
| 配置加载失败 | ERROR | 台区ID、失败原因 |
| 配置更新 | INFO | 操作人、台区ID、变更前后值 |
| 参数校验失败 | ERROR | 台区ID、校验规则ID、失败原因 |
| 使用默认值 | WARN | 台区ID、使用的默认值 |

## 5. 边界条件和异常流程

### 5.1 配置缺失

**场景**: `ai_engine.toml` 中无 `action_space` 节

**处理**:
1. 记录 WARN 日志
2. 使用默认值初始化
3. 系统正常启动

### 5.2 配置格式错误

**场景**: TOML 格式错误、类型不匹配

**处理**:
1. 记录 ERROR 日志，包含具体解析错误
2. 拒绝启动（不同于缺失场景，格式错误表明配置意图明确但存在笔误）

### 5.3 参数超出物理范围

**场景**: `max_batt_charge_power = 300.0`，但 `max_apparent_power_kva = 200.0`

**处理**:
1. 记录 ERROR 日志，包含校验规则 ASC-04
2. 拒绝启动

### 5.4 数据库与配置文件冲突

**场景**: 数据库和配置文件同时存在同一台区的配置

**处理**:
1. 数据库配置优先
2. 记录 INFO 日志，说明使用了数据库配置

### 5.5 热更新并发

**场景**: 多个管理员同时提交配置更新

**处理**:
1. 使用数据库事务保证原子性
2. 后提交者覆盖先提交者（last-write-wins）
3. 记录所有变更的审计日志

### 5.6 配置重置

**场景**: 管理员点击"重置默认值"

**处理**:
1. 弹出确认对话框："确定要将 {台区名} 的动作空间参数重置为默认值吗？"
2. 确认后，将该台区配置恢复为默认值（不是删除配置记录）
3. 记录审计日志

### 5.7 台区删除

**场景**: 台区被移除，但数据库中仍有配置记录

**处理**:
1. 配置记录保留（软删除，设置 `deleted_at` 时间戳）
2. 查询时忽略已删除台区

## 6. 验收标准

### 6.1 配置管理

- [ ] 可通过配置文件加载动作空间参数
- [ ] 可通过数据库存储动作空间参数
- [ ] 可通过 Web API 查询当前配置
- [ ] 可通过 Web API 更新配置（PUT/PATCH）
- [ ] 配置变更后 AI 动作立即使用新参数

### 6.2 参数校验

- [ ] 零值参数被拒绝（ASC-01, ASC-02, ASC-03）
- [ ] 超出变压器容量被拒绝（ASC-04, ASC-05）
- [ ] 格式错误导致启动失败

### 6.3 ActionValidator 集成

- [ ] `p_batt_set` 值域变为 `[-max_batt_charge_power, max_batt_discharge_power]`
- [ ] `load_shedding` 值域变为 `[0, max_load_shedding]`
- [ ] 默认值与原硬编码行为一致

### 6.4 前端 UI

- [ ] 显示当前配置值
- [ ] 输入校验提示
- [ ] 保存后配置立即生效
- [ ] 变更历史可查询

### 6.5 向后兼容

- [ ] 无 `action_space` 节时使用默认值启动
- [ ] 现有 `ActionConstraintConfig` 使用者不受影响
