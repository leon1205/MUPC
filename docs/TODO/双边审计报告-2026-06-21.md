## 🔴 P0-1: RL ONNX 观测归一化不一致

**位置**: 
- 训练: `mupc_env/observation.py:normalize_obs()` 
- 部署: `export_onnx.py:_build_rl_export_model._normalize()`

**问题**: 训练 RL agent 观测使用 **MinMax 归一化**，ONNX 导出使用 **简单乘法归一化**，两者公式不同。

| 维度 | 训练 normalize_obs (MinMax) | ONNX _normalize (乘法) | 是否一致 |
|------|------|------|:--:|
| D1[0] SOC | `(x-0)/(1-0) = x` (恒等) | `x × 0.5` | ❌ |
| D1[3] grid_power | `(x+200)/400` | `x × 1/200` | ❌ |
| D1[5] battery_power | `(x+50)/100` | `x × 1/50` | ❌ |
| D5[45] solar_irradiance | `x/1500` | **不归一化** (d1_norm 仅 8 元素) | ❌ |
| D1[8] V_c | `(x-0.85)/(1.15-0.85)` | **不归一化** (d1_norm 缺第9元素) | ❌ |

**根因**: `_normalize()` 用 `x × 1/max` (假设 min=0)，但训练用 `(x-min)/(max-min)` (min 可能为负)。MinMax 和乘法归一化在 min≠0 时完全不等价。

**修复建议**: 
- 方案 A: 删除 ONNX 内部归一化，Rust 侧在 `to_input_vector()` 前做 MinMax 归一化（与训练一致）
- 方案 B: 修改 ONNX _normalize 为 MinMax 公式（需 ONNX 支持 Sub/Div 算子）

## 🔴 P0-2: RL 动作输出维度不一致

**位置**:
- 训练: `export_onnx.py:61` — `act_dim = 2`，输出 `[p_ref(tanh), k_droop(tanh)]`
- 部署: `rl_model.rs:102` — `parse_action_output()` 期望 `raw.len() >= 5`

```rust
// Rust 期望 5 维输出
pub fn parse_action_output(raw: &[f32], ...) -> Option<ActionOutput> {
    if raw.len() < 5 { return None; }  // ← ONNX 只输出 2 维，永远为 None!
    ActionOutput {
        p_ref: raw[0]...,           // 有
        k_droop: raw[1]...,         // 有
        load_shedding: raw[2]...,   // ONNX 不存在!
        pv_limit: raw[3]...,        // ONNX 不存在!
        confidence: raw[4]...,      // ONNX 不存在!
    }
}
```

**影响**: 部署时 `parse_action_output` 永远返回 `None` → `decide_fused()` 返回 `InferenceFailed("输出维度不足")` → RL 决策不可用。

**根因**: v2.15 PRD 要求动作空间精简为 2 维（load_shedding/pv_limit 下沉至策略引擎），训练侧已实施，但 Rust `parse_action_output` 未同步更新，仍保留 5 维解析逻辑。

**修复建议**: 重写 `parse_action_output` 为 2 维模式：
```rust
pub fn parse_action_output(raw: &[f32], config: &ActionSpaceConfig) -> Option<ActionOutput> {
    if raw.len() < 2 { return None; }
    let p_ref_norm = raw[0] as f64;   // tanh ∈ [-1, 1]
    let k_norm = raw[1] as f64;       // tanh ∈ [-1, 1]
    Some(ActionOutput {
        p_ref: p_ref_norm * config.max_batt_charge_power,  // 反归一化
        k_droop: k_norm * config.k_droop_max.unwrap_or(100.0),
        load_shedding: 0.0,   // 下沉至策略引擎
        pv_limit: 1.0,        // 下沉至策略引擎
        confidence: 0.5,      // 无
    })
}
```

## 🔴 P0-3: RL 动作反归一化缺失

**位置**: 
- 训练: `mupc_env/core.py:461` — `p_ref = tanh_output × P_BATT_MAX_KW`
- 部署: `rl_model.rs:111` — `p_ref = raw[0].clamp(-max_discharge, max_charge)` (直接 clamp，无反归一化)

```python
# 训练侧: tanh 输出反归一化到物理值
p_ref = float(clamped[0] * constants.P_BATT_MAX_KW)  # [-1,1] → [-50,50] kW
k_droop = float(clamped[1] * (K_DROOP_MAX - K_DROOP_MIN) / 2 + ...)
```

```rust
// 部署侧: tanh 输出直接 clamp，未反归一化
p_ref: (raw[0] as f64).clamp(-50.0, 50.0)  // tanh 0.5 → 0.5 kW 而非 25 kW!
```

**影响**: tanh 输出范围 [-1, 1]，直接 clamp 获得的是 [-1, 1] kW → 实际只有 ±1kW 调节范围，严重不足。

**修复**: 与 P0-2 合并修复。

## 🟡 P1-1: LSTM 输出 confidence 字段回退

**位置**: `lstm_model.rs:22-28`

```rust
pub struct LstmOutput {
    pub predictions: Vec<f32>,
    pub confidence: f64,  // ← v2.16 已删除，v3.0 远程更新又加回
}
```

**问题**: v2.16 PRD 删除了 `confidence` 字段（`grep` 全工程无代码读取），但远程更新 (6/21) 在 `LstmOutput` 中重新添加了该字段。当前 Rust 预测管线未填充该字段，值始终为默认 0.0。

**修复**: 确认 confidence 是否需要；若需要，在 `predict()` 中从 ONNX 输出计算填充；若不需要，删除该字段。
