### P1 — 严重（功能不可用/正确性）

- **01**：帧解析两处 panic（下溢/越界）、无 TCP 粘包重组、MQTT 桥接/插件在启动编排中从不运行（`startup.rs:313-324`）。
- **02**：Modbus CRC 字节序不一致（小端 vs 大端）、半双工 DE/RE 只翻单脚、pv_limit/load_shedding 绕过锁。
- **03**：触发回差字段未用、多触发条件丢失；COMTRADE `.dat` 时间戳计算错误；故障类型映射语义错误（过压→GridOverload）。
- **04**：ControlCommand 字段名与双参数模式不符（`p_batt_set` vs `p_ref/k_droop`）；AiValidator 仍 Mock；降级状态不复位。
- **05**：生产用 `validate()` 非 `validate_dual()`，k_droop clamp [-300,300] 违反 PRD [0,30]；冲击概率硬编码 0.0228。
- **06**：SmCryptoProvider 未实现 rustls trait；sm3_hash 用 `from_utf8_lossy` 破坏二进制哈希；LEA 用 PSK 违背 SM2 证书要求。
- **07**：模型 OTA 核心链路断裂（服务器请求 mock、签名空串）；自愈引擎 `execute` 仅打日志；MTBF 公式不符。
- **08**：SSE/WS 整链死（无生产者）、前端未服务、日志读取/导出 stub、审计清理未实现。
- **09**：crate 命名/曲线不一致（X25519 vs P-256）。
- **10**：ai_ready 硬编码 true、strategy_mode 值不符、control_cmd 无生产者、收发帧版本不匹配（V2 发 V1 收）。

## 三、风险等级评定

**整体风险等级：🔴 高风险**

评定依据：
1. **P0 编译阻断 ×2**（主二进制不在 workspace、core 模块未接线）——当前 `mupcd` 实际处于无法编译状态。
2. **核心业务链路系统性断裂**：AI 决策→策略引擎→南向下发、数据采集→遥测/录波→北向上报、核间指令、SSE 推送等全部未接线，代码大量以「库对象 + 单元测试」形态存在，运行态为空壳。
3. **安全合规缺口**：SM2/SM4-GCM 在默认 feature 下仍是非国密算法，属合规级 P0。

**第一批 P0（编译阻断，0.5d）**

3. 修复模块 07 `verifier.rs` 的未定义变量（若确为编译错误）。

**第二批 P0（功能闭环，3-5d）**
4. 核间通信：修 CRC16 往返 + 部署形态（服务端监听 vs 客户端）+ 长连接。
5. 策略引擎：接线 `initialize()`/`set_south_dispatcher`，修防逆流 count。
6. 南向通信：修 plugin-loader `Arc::from_raw` UB + cdylib/FFI 接线 + Modbus CRC 字节序。
7. AI 引擎：DataFusionEngine 落地 + k_droop 校验走 `validate_dual`。
8. 安全：SM2/SM4-GCM 门控到真国密，默认 feature 不得暴露非国密。**（决策 2026-08-14：门控停损项暂不实施，待 gmsm 0.14 可用后再处理）**

**第四批（需硬件/SDK，非阻塞）**

## 五、审查总结

**架构优势**：文档层（PRD/Design）体系完整、覆盖率高、编号规范；抽象设计（trait 分层、状态机、帧协议、配置分层）质量较好；模块划分与 crate 边界清晰；78 维状态/2 维动作/RKNN feature 切换等 AI 核心数据结构已正确落地。

**核心问题**：典型的「文档先行、代码滞后，且接线层缺失」。大量 crate 内部逻辑完整（有实现、有单测），但运行态接线（startup 编排、生产者-消费者闭链、独立入口）系统性缺失——最直接证据是主二进制本身无法编译，而 `cargo check --workspace` 却因 members 缺项而静默通过。

**后续改进方向**：
1. 建立「编译门禁」防回归——把 `cargo build -p mupc-core-bin`（而非仅 `--workspace`）纳入 CI 必检项。
2. 建立「接线审计」——每个跨 crate 通道必须验证「生产者 + 消费者 + 消费者被实际调用」三点闭环。
3. 上一轮审计「修复记录」需逐条反查真伪。
