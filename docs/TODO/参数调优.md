# 自动化超参数搜索框架与默认权重模板详细设计

## 一、背景与动机

当前MUPC AI引擎的自适应权重优化器（v2.11）已集成NSGA-II多目标优化器，用于在离线回放数据上搜索奖励函数权重（w1\~w7等）的Pareto前沿。然而，NSGA-II作为一种进化算法，在处理高维、非凸、带约束的参数空间时，收敛速度和全局搜索能力仍有局限。此外，新台区上线时缺乏历史数据，权重需要从默认值开始调优，冷启动成本高。

为解决上述问题，提出两项增强：

1. **集成贝叶斯优化（Bayesian Optimization, BO）和CMA-ES（Covariance Matrix Adaptation Evolution Strategy）**，与NSGA-II形成互补，覆盖不同参数维度和优化目标的需求。
2. **构建默认权重模板库**，基于典型台区数据预计算通用权重，新台区上线时自动匹配最佳模板，大幅缩短调参周期。

## 二、自动化超参数搜索框架

### 2.1 优化器选择策略


| 优化器         | 适用场景                                                             | 特点                                               | 参数维度推荐                         |
| -------------- | -------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------ |
| **NSGA-II**    | 多目标优化（如同时最大化光伏消纳、最小化电池损耗、最小化变压器过载） | 进化算法，维护Pareto前沿，适合2\~3个目标           | 任意维度，但收敛速度随维度增加而下降 |
| **贝叶斯优化** | 单目标或标量化多目标（如加权和），参数维度≤20                       | 基于高斯过程代理模型，采样效率高，适合低维连续参数 | ≤20维，尤其适合5\~10维              |
| **CMA-ES**     | 单目标或标量化多目标，参数维度较高（10\~50），非凸、病态条件         | 自适应协方差矩阵，鲁棒性强，无需梯度               | 10\~50维，甚至更高                   |

**互补关系**：

* 对于**低维参数空间**（如SCENE-01的7个权重），优先使用贝叶斯优化，因其采样效率高，可在较少的评估次数内找到最优解。
* 对于**高维参数空间**（如未来扩展到更多子项），使用CMA-ES，其不依赖梯度，对参数相关性建模能力强。
* **多目标场景**仍然使用NSGA-II，但可利用贝叶斯优化或CMA-ES对每个目标进行单目标优化，然后将结果作为NSGA-II的初始种群，加速收敛。

#### 2.3.3 评估流水线

```
/// 目标函数（单目标或标量化多目标）
pub type ObjectiveFn = Arc<dyn Fn(&[f64]) -> f64 + Send + Sync>;

/// 构建评估流水线
pub async fn build_evaluation_pipeline(
    scene: RunningMode,
    replay_data: &ReplayDataset,
    reward_calculator: &RewardCalculator,
) -> ObjectiveFn {
    let data = replay_data.clone();
    let calc = reward_calculator.clone();
    Arc::new(move |weights: &[f64]| -> f64 {
        // 1. 设置权重
        calc.set_scene_weights(scene, weights);
        // 2. 遍历回放数据，计算累积奖励
        let mut total_reward = 0.0;
        for sample in &data.samples {
            let reward = calc.calculate(scene, &sample.action, &sample.state);
            total_reward += reward;
        }
        // 3. 返回平均奖励（或折扣累积奖励）
        total_reward / data.samples.len() as f64
    })
}
```

#### 2.3.4 推荐引擎

```
/// 优化结果
pub struct OptimizationResult {
    pub best_params: Vec<f64>,
    pub best_value: f64,
    pub pareto_front: Option<Vec<Vec<f64>>>, // 仅NSGA-II有
    pub evaluation_count: usize,
    pub convergence_curve: Vec<f64>,
    pub timestamp: i64,
}

/// 推荐引擎
pub struct RecommendationEngine {
    result_store: Arc<RwLock<HashMap<String, Vec<OptimizationResult>>>>,
    /// 当前生产环境中使用的权重（用于对比）
    production_weights: Arc<RwLock<SceneWeights>>,
}

impl RecommendationEngine {
    /// 生成推荐报告
    pub async fn generate_report(&self, scene: RunningMode) -> RecommendationReport {
        let results = self.result_store.read().await.get(&scene.to_string()).cloned().unwrap_or_default();
        let current = self.production_weights.read().await.lookup(scene).to_vec();
      
        // 选择最佳结果（根据平均奖励或Pareto前沿的折衷解）
        let best = self.select_best(&results, &current);
      
        RecommendationReport {
            scene,
            current_weights: current,
            recommended_weights: best.params,
            expected_improvement: best.value - self.evaluate_weights(&current, scene),
            optimization_details: results,
            generated_at: chrono::Utc::now(),
        }
    }
}
```

### 2.4 与现有自适应权重优化器的关系


| 组件                              | 职责                                                  | 运行频率     | 数据来源                   |
| --------------------------------- | ----------------------------------------------------- | ------------ | -------------------------- |
| **MetaRL（在线）**                | 基于近期性能数据，实时微调权重（每次更新周期≥1小时） | 每小时\~每天 | 最近几天的运行数据         |
| **贝叶斯/CMA-ES/NSGA-II（离线）** | 定期全局搜索最优权重，提供推荐值                      | 每周\~每月   | 过去1\~3个月的离线回放数据 |
| **运维人员**                      | 审核推荐报告，决定是否采纳                            | 手动触发     | Web UI展示                 |

**协作流程**：

1. 离线优化器每月自动运行一次，对每个场景搜索最优权重组合。
2. 推荐引擎生成对比报告，展示当前权重与推荐权重的性能差异（如综合奖励提升百分比）。
3. 运维人员在Web UI上查看报告，可选择“一键应用”或手动调整。
4. 应用后，在线MetaRL继续在推荐权重的基础上进行微调。

## 三、默认权重模板

### 3.1 动机

新台区上线时，没有历史运行数据，自适应权重优化器无法工作。若使用固定默认权重（如PRD中给出的`[1.0, 0.5, 2.0, ...]`），可能因台区特性差异（如光伏渗透率、负荷类型、变压器容量）导致初期性能不佳。因此，需要基于典型台区数据预计算一组通用权重模板，新台区上线时自动匹配最相似的模板，作为初始权重。

### 3.2 方法

#### 3.2.1 台区特征提取

选取影响最优权重的关键特征：


| 特征              | 类型        | 取值范围                              | 说明                    |
| ----------------- | ----------- | ------------------------------------- | ----------------------- |
| 变压器容量 (kVA)  | 连续        | [50, 1000]                            | 决定过载惩罚的敏感度    |
| 光伏渗透率 (%)    | 连续        | [0, 200]                              | 光伏装机容量/变压器容量 |
| 负荷曲线类型      | 枚举        | 居民/商业/农业/混合                   | 影响季节性负荷模式      |
| 峰谷价差 (元/kWh) | 连续        | [0.2, 1.5]                            | 影响自主套利模式权重    |
| 需量合同值 (kW)   | 连续        | [50, 10000]                           | 影响需量控制模式        |
| 是否注册VPP       | 布尔        | true/false                            | 影响VPP模式             |
| 季节特征          | one-hot 6维 | 灌溉季/炒茶季/空调季/常规季/保留/保留 | 影响季节性负荷模式      |
| 储能容量 (kWh)    | 连续        | [50, 500]                             | 影响电池损耗惩罚        |

#### 3.2.2 台区聚类

使用K-means或DBSCAN对现有台区进行聚类，得到K个典型类别（建议K=5\~10）。每个聚类内部的台区具有相似的特征分布。

```
pub struct TaiQuCluster {
    pub cluster_id: u32,
    pub center: Vec<f64>,           // 聚类中心特征向量
    pub member_count: usize,
    pub optimal_weights: SceneWeights, // 该聚类的最优权重
    pub confidence: f64,            // 基于成员数量的置信度
}
```

#### 3.2.3 权重计算

对每个聚类，使用第二节中的超参数搜索框架（贝叶斯优化或NSGA-II）在该聚类所有台区的联合回放数据上搜索最优权重。由于聚类内台区特性相似，搜索得到的权重具有良好的泛化性。

```
/// 计算聚类最优权重
pub async fn compute_cluster_optimal_weights(
    cluster: &TaiQuCluster,
    all_replay_data: &HashMap<String, ReplayDataset>, // 按台区ID索引
    reward_calculator: &RewardCalculator,
    optimizer_manager: &HyperparamOptimizerManager,
) -> Result<SceneWeights, AiEngineError> {
    // 聚合该聚类下所有台区的回放数据
    let merged_dataset = merge_datasets(cluster.member_ids.iter().map(|id| &all_replay_data[id]));
  
    // 对每个场景分别优化
    let mut weights = SceneWeights::default();
    for scene in [RunningMode::SeasonalLoadManagement, RunningMode::CommercialArbitrage, ...] {
        let param_space = get_param_space_for_scene(scene);
        let objective = build_evaluation_pipeline(scene, &merged_dataset, reward_calculator).await;
        let optimizer = optimizer_manager.select_optimizer(&param_space);
        let result = optimizer.optimize(&param_space, objective, &OptimizerConfig::default()).await?;
        weights.set_scene_weights(scene, &result.best_params);
    }
    Ok(weights)
}
```

### 3.3 模板库结构

```
/// 权重模板库
pub struct WeightTemplateLibrary {
    clusters: Vec<TaiQuCluster>,
    /// 默认模板（当无法匹配任何聚类时使用）
    default_weights: SceneWeights,
}

impl WeightTemplateLibrary {
    /// 根据台区特征匹配最佳模板
    pub fn match_template(&self, tai_qu_features: &[f64]) -> (SceneWeights, f64) {
        // 计算欧氏距离或余弦相似度，找到最近的聚类
        let mut best_dist = f64::MAX;
        let mut best_weights = self.default_weights.clone();
        let mut best_similarity = 0.0;
      
        for cluster in &self.clusters {
            let dist = euclidean_distance(tai_qu_features, &cluster.center);
            if dist < best_dist {
                best_dist = dist;
                best_weights = cluster.optimal_weights.clone();
                best_similarity = 1.0 / (1.0 + dist);
            }
        }
        (best_weights, best_similarity)
    }
}
```

### 3.4 新台区上线流程

```
1. 新台区安装完毕，录入基本信息（变压器容量、光伏容量、负荷类型等）
2. 系统自动提取特征向量
3. 匹配权重模板库，获得推荐权重和相似度
4. 若相似度 > 阈值（如0.8），直接应用推荐权重
5. 若相似度较低，应用推荐权重 + 标注“低置信度”，提醒运维人员关注
6. 运行一周后，在线MetaRL开始微调权重
7. 三个月后，该台区数据可纳入下一次模板更新
```

## 六、风险与注意事项

1. **计算资源消耗**：离线搜索需要大量算力（特别是CMA-ES和NSGA-II），建议在x86服务器上运行，避免占用RK3588资源。可配置为仅在夜间或闲时执行。
2. **过拟合风险**：搜索出的权重可能过度适配历史回放数据，导致在真实新数据上泛化差。解决方案：使用交叉验证，并保留一部分最新数据作为验证集。
3. **运维人员认知负担**：过多的推荐选项可能让运维人员困惑。建议UI只展示“推荐权重”和“当前权重”两个选项，并提供一键应用按钮，高级选项折叠。
4. **模板时效性**：随着电网结构变化（如新增光伏、更换变压器），模板可能需要更新。建议每季度自动重新聚类和搜索。

---

**总结**：通过集成贝叶斯优化/CMA-ES与NSGA-II，构建了多层次、自动化的超参数搜索框架，能够高效地为每个场景搜索最优权重组合。同时，基于台区聚类的默认权重模板库，解决了新台区冷启动难题，大幅降低了调参成本。这两项增强将使MUPC AI引擎在工程实践中更具实用性和适应性。
